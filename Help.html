Introduction: How it Works

Genizah Search Pro provides fast and advanced access to the transcription corpus of the "MiDRASH" project. The software is based on a high-speed search engine (Tantivy) and integrates unique algorithms to handle the Hebrew spelling variations typical of Genizah manuscripts.

The software runs locally on your computer but uses an internet connection to fetch bibliographic data and images from the National Library of Israel.

Search Tab

This is the entry point for free text or metadata searches within the corpus.

Search Modes

  • Exact: Matches only the exact word as typed.
  • Variants: Accounts for common letter substitutions in these texts (e.g., Dalet/Resh, He/Het, Vav/Yod). This is the recommended default mode.
  • Extended / Maximum: Allows for greater flexibility in letter substitutions (e.g., Qof/Kaf, Tet/Tav), but may return less relevant results ("noise").
  • Fuzzy: Uses Levenshtein distance to find similar words even with typos or decoding errors.
  • Regex: Advanced search for experienced users. For example, \bא[א-ת]{3}\b finds 4-letter words starting with Aleph.
  • Title: Searches within the catalog titles of compositions (e.g., "Midrash Rabbah").
  • Shelfmark: Fast search for shelfmarks (e.g., "T-S 13.15").

Additional Options

  • Gap: Defines how many words can separate search terms. A value of 0 requires an exact sequence.
  • Select All: A checkbox at the top of the table allows you to select all results (or currently displayed results) for focused export.
  • Preview: Double-clicking a row opens the full Manuscript Viewer on that page.

Composition Search

This tool is designed for researchers wishing to find parallels for a complete literary text (such as a Piyyut, Mishnah chapter, or Midrash) within the Genizah.

How it Works (The Mechanism)

Unlike a regular search, the engine does not search for the entire text as a single unit. The process works as follows:

  1. The software splits the source text you entered into small segments ("Chunks").
  2. Each chunk is searched separately in the Genizah database.
  3. If a specific chunk is found in a manuscript, it receives a "score".
  4. At the end of the process, the software aggregates the results: if a manuscript contains many found chunks, it receives a high score and appears at the top of the list.

Important Parameters

  • Chunk: The number of words in each search unit. The recommendation is 5-7 words. A value too low returns many false positives; too high might miss results with slight wording variations.
  • Max Freq: A tool to filter "common words". If the engine detects that a sequence appears thousands of times (e.g., "And the Lord spoke to Moses saying"), it ignores it to avoid polluting results.
  • Filter >: If a specific title (e.g., "Siddur Rav Saadia Gaon") appears more than X times in the results, the software groups these results under a single "Group" in the Appendix to avoid flooding the main list.
  • Sort by shelfmark only: Disables smart grouping and displays a flat, sorted list of all found manuscripts.

Advanced Options

  • Exclude Manuscripts: Allows you to enter a list of known manuscripts to hide from results (they will appear under the "Excluded" category).
  • Filter Text: Allows entering specific texts to mark as "Filtered" in the results.
  • Recursive Search: After getting results, this button searches again using the texts of the found manuscripts as a basis for further searching.

Browse Manuscript

This tab enables convenient continuous reading of a full manuscript, synchronized with source images.

  • Load: Enter a System ID or Shelfmark. The search is flexible and ignores spaces or punctuation (e.g., TS 13 15 finds T-S 13.15).
  • Navigate Pages: Use the arrows < > to flip between pages within the current manuscript.
  • Navigate Manuscripts: Use the arrows ◀ ▶ at the top left to move to the previous or next manuscript in the database file order.
  • Images: An image viewer is displayed on the side. You can rotate, zoom, and select the image source (NLI or Cambridge where supported).
  • View All: Displays all manuscript pages in one long sequence for easy scrolling.

Lab Mode

The Lab Mode button activates an experimental and more advanced search engine ("LabEngine").

  • Deep Scan: A much deeper and thorough scan. Significantly slower, but recommended for finding rare phrases or ensuring nothing is missed.
  • Fingerprint Algorithm: In this mode, the engine uses a different method for identifying words based on rare letters, allowing greater flexibility in identifying corruptions.

Lab Mode Parameters

When Lab Mode is active, a settings panel appears. The available settings depend on the active tab.

Search Tab Parameters

  • Min Match %: Minimum percentage of query terms required to consider a result relevant.
  • Max Results to Process: Maximum number of raw candidates to fetch from the index before detailed scoring.
  • Deep Limit: Maximum number of documents to scan in Deep Scan mode.

Composition Tab Parameters

  • Max Candidates per Chunk: Maximum number of index hits to process per text chunk.
  • Min Chunk Score: Minimum score required for a chunk to be considered a match.
  • Max Final Results: Maximum number of results to display in the tree to prevent freezing (all results are still exported).

Advanced Scoring

Accessible via the "Advanced Scoring..." button:

  • Sequential Order Bonus: Bonus points for finding words in the correct order.
  • Coverage Penalty Power: Penalizes results that do not contain all search terms.
  • Stop-Word Suppression: Lowers the score for very short or common words to reduce noise.
  • Long Word Bonus: Gives higher weight to longer words.
  • Unique Match Base Score: The base score for finding a unique word.
  • Distance Penalty: Penalizes words found far apart from each other.
  • Repeated Word Factor: Reduces score for words appearing more often in the text than in the query.

Exporting Data

At any stage, you can export results for external use:

  • XLSX (Excel): Recommended format. Includes rich formatting, links, and color highlighting of found words within context.
  • CSV: Raw data format, suitable for importing into other databases.
  • TXT: Simple readable text report.

Note: Export applies to selected results (checkboxes). If nothing is selected, the software exports all available results in the table.

הקדמה: איך זה עובד?

תוכנת Genizah Search Pro מאפשרת גישה מהירה ומתקדמת לקורפוס התעתוקים של פרויקט "מדרש" (MiDRASH). התוכנה מבוססת על מנוע חיפוש מהיר (Tantivy) ומשלבת אלגוריתמים ייחודיים לטיפול בשונות הכתיב העברית המאפיינת את כתבי היד של הגניזה.

התוכנה פועלת באופן מקומי על המחשב שלכם, אך משתמשת בחיבור אינטרנט כדי למשוך מידע ביבליוגרפי ותמונות מהספרייה הלאומית.

לשונית חיפוש (Search)

זוהי נקודת הכניסה לחיפוש טקסט חופשי או מטא-דאטה בקורפוס.

סוגי חיפוש (Mode)

  • Exact (מדויק): מוצא רק את המילה בדיוק כפי שנכתבה.
  • Variants (וריאנטים): מתחשב בחילופי אותיות נפוצים בטקסטים אלו (למשל: ד/ר, ה/ח, ו/י). זהו מצב החיפוש המומלץ כברירת מחדל.
  • Extended / Maximum: מאפשרים גמישות רבה יותר בחילופי אותיות (כגון ק/כ, ט/ת), אך עלולים להחזיר תוצאות פחות רלוונטיות ("רעש").
  • Fuzzy (עמום): משתמש במרחק לווינשטיין (Levenshtein distance) למציאת מילים דומות גם אם יש שגיאות הקלדה/פענוח.
  • Regex (ביטוי רגולרי): חיפוש מתקדם למשתמשים מנוסים. לדוגמה, \bא[א-ת]{3}\b ימצא מילים בנות 4 אותיות המתחילות ב-א'.
  • Title (כותרת): חיפוש בתוך המידע הקטלוגי של הכותרות (למשל: "מדרש רבה"). דוגמה: חיפוש "משנה" יביא את כל כתבי היד המזוהים כמשנה.
  • Shelfmark (מספר מדף): חיפוש מהיר של מספר מדף (למשל: "T-S 13.15").

אפשרויות נוספות

  • Gap (פער): מגדיר כמה מילים יכולות להפריד בין מילות החיפוש. ערך 0 מחייב רצף מדויק.
  • Select All (בחר הכל): בראש הטבלה ישנה תיבת סימון המאפשרת לבחור את כל התוצאות (או את התוצאות המוצגות כרגע) לצורך ייצוא ממוקד.
  • תצוגה מקדימה: לחיצה כפולה על שורה תפתח את צפיין כתב היד המלא באותו עמוד.

חיפוש חיבורים (Composition Search)

כלי זה נועד לחוקרים המעוניינים למצוא מקבילות לטקסט ספרותי שלם (כגון פיוט, פרק במשנה, או מדרש) בתוך הגניזה.

איך זה עובד? (המנגנון)

בניגוד לחיפוש רגיל, המנוע לא מחפש את הטקסט כולו כמקשה אחת. התהליך מתבצע כך:

  1. התוכנה מחלקת את טקסט המקור שהזנתם למקטעים קטנים ("Chunks").
  2. כל מקטע נשלח לחיפוש בנפרד במאגר הגניזה.
  3. אם מקטע מסוים נמצא בכתב יד, הוא מקבל "ניקוד".
  4. בסוף התהליך, התוכנה מקשרת מחדש את התוצאות: אם כתב יד מכיל הרבה מקטעים שנמצאו, הוא יקבל ציון גבוה ויופיע בראש הרשימה.

פרמטרים חשובים

  • Chunk (גוש): מספר המילים בכל יחידת חיפוש. ההמלצה היא 5-7 מילים. ערך נמוך מדי יחזיר המון תוצאות שגויות; ערך גבוה מדי עלול לפספס אם יש שינויי נוסח קלים.
  • Max Freq (תדירות מקס'): כלי לסינון "מילים נפוצות". אם המנוע מגלה שרצף מילים מסוים מופיע אלפי פעמים בגניזה (למשל "וידבר ה' אל משה לאמר"), הוא יתעלם ממנו כדי לא לזהם את התוצאות.
  • Filter > (סינון): אם כותרת מסוימת (למשל "סידור רב סעדיה גאון") מופיעה בתוצאות יותר מ-X פעמים, התוכנה תקבץ את כל התוצאות הללו תחת "קבוצה" אחת בנספח, כדי לא להציף את הרשימה הראשית.
  • Sort by shelfmark only: מבטל את הקיבוץ החכם ומציג רשימה שטוחה וממוינת של כל כתבי היד שנמצאו.

אפשרויות מתקדמות

  • Exclude Manuscripts: מאפשר להזין רשימה של כתבי יד שאתם כבר מכירים ורוצים להסתיר מהתוצאות (יופיעו תחת קטגוריית "Excluded").
  • Filter Text: מאפשר להזין טקסטים ספציפיים שברצונכם לסמן כ"מסוננים" בתוצאות.
  • Recursive Search: לאחר קבלת תוצאות, כפתור זה יחפש שוב במאגר, הפעם תוך שימוש בטקסטים של כתבי היד שנמצאו כבסיס לחיפוש נוסף.

עיון בכתב יד (Browse Manuscript)

לשונית זו מאפשרת קריאה רציפה ונוחה של כתב יד שלם, עם סנכרון לתמונות המקור.

  • טעינה: הזינו מספר מערכת (System ID) או מספר מדף. החיפוש גמיש ומתעלם מרווחים או סימני פיסוק (למשל TS 13 15 ימצא את T-S 13.15).
  • דפדוף בעמודים: השתמשו בחיצים < > כדי לדפדף בין העמודים בתוך כתב היד הנוכחי.
  • דפדוף בין כתבי יד: השתמשו בחיצים ◀ ▶ בפינה העליונה כדי לעבור לכתב היד הבא או הקודם במאגר (לפי סדר הקבצים).
  • תמונות: בצד ימין (או שמאל, תלוי בשפה) מוצג צפיין תמונות. ניתן לסובב, להגדיל, ולבחור מקור תמונה (הספרייה הלאומית או ספריית קמברידג' במקרים נתמכים).
  • View All: כפתור המציג את כל עמודי כתב היד ברצף אחד ארוך לגלילה נוחה.

מצב מעבדה (Lab Mode)

כפתור ה-Lab Mode מפעיל מנוע חיפוש ניסיוני ומתקדם יותר ("LabEngine").

  • Deep Scan: סריקה מעמיקה ויסודית יותר. איטית משמעותית, אך מומלצת לחיפוש ביטויים נדירים או כשרוצים לוודא שלא פיספסתם כלום.
  • אלגוריתם טביעת אצבע: המנוע במצב זה משתמש בשיטה שונה לזיהוי מילים, המבוססת על האותיות הנדירות במילה, מה שמאפשר גמישות רבה יותר בזיהוי שיבושים.

פרמטרים של מצב מעבדה

כאשר מצב מעבדה פעיל, מופיע פאנל הגדרות. ההגדרות הזמינות משתנות בהתאם ללשונית הפעילה.

פרמטרים ללשונית חיפוש

  • Min Match % (סף התאמה): אחוז המילים המינימלי מהשאילתא שחייב להופיע כדי שהתוצאה תיחשב רלוונטית.
  • Max Results to Process (מגבלת עיבוד): מספר המועמדים הגולמיים המקסימלי שיישלף מהאינדקס לפני שלב הניקוד המפורט.
  • Deep Limit (מגבלת עומק): מספר המסמכים המקסימלי לסריקה במצב "Deep Scan".

פרמטרים ללשונית חיפוש חיבורים

  • Max Candidates per Chunk (מועמדים לגוש): מספר התוצאות המקסימלי שיעובדו עבור כל מקטע טקסט.
  • Min Chunk Score (ניקוד מינימלי לגוש): הניקוד המינימלי הנדרש כדי שמקטע ייחשב כ"נמצא".
  • Max Final Results (מקסימום תוצאות סופיות): מספר התוצאות שיוצגו בעץ כדי למנוע קיפאון של הממשק (כל התוצאות עדיין נשמרות בייצוא).

ניקוד מתקדם (Advanced Scoring)

זמין דרך כפתור "Advanced Scoring...":

  • Sequential Order Bonus (בונוס סדר): ניקוד נוסף על מציאת מילים בסדר הנכון.
  • Coverage Penalty Power (קנס כיסוי): קנס על תוצאות שאינן מכילות את כל מילות החיפוש.
  • Stop-Word Suppression (דיכוי מילים נפוצות): מפחית את הניקוד למילים קצרות או נפוצות מאוד כדי להפחית רעש.
  • Long Word Bonus (בונוס מילה ארוכה): נותן משקל רב יותר למילים ארוכות.
  • Unique Match Base Score (ניקוד בסיס): הניקוד הבסיסי למציאת מילה ייחודית.
  • Distance Penalty (קנס מרחק): מפחית ניקוד למילים שנמצאו רחוק זו מזו.
  • Repeated Word Factor (גורם מילה חוזרת): מפחית ניקוד למילים המופיעות בטקסט יותר פעמים מאשר בשאילתא.

ייצוא נתונים

בכל שלב ניתן לייצא את התוצאות לשימוש חיצוני:

  • XLSX (אקסל): הפורמט המומלץ. כולל עיצוב עשיר, קישורים, וסימון בצבע של המילים שנמצאו בתוך הקשר המשפט.
  • CSV: פורמט נתונים גולמי, מתאים לייבוא למסדי נתונים אחרים.
  • TXT: דוח טקסט פשוט וקריא.

שימו לב: הייצוא מתייחס לתוצאות שנבחרו (Checkbox). אם לא נבחר כלום, התוכנה תייצא את כל התוצאות הקיימות בטבלה.
