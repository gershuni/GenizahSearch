Introduction: How it Works

Dicta Genizah Search Pro provides fast and advanced access to the transcription corpus of the "MiDRASH" project. The software is based on a high-speed search engine (Tantivy) and integrates unique algorithms to handle the Hebrew spelling variations typical of Genizah manuscripts.

The software runs locally on your computer but uses an internet connection to fetch metadata and images from the National Library of Israel, Oxford Bodlean Library and Cambridge University Library. It will work without an internet connection, but without images and some extended information. Note: If your connection is not a home network (such as a mobile hotspot), library servers may block your access.

Search Tab

This is the entry point for free text or metadata searches within the corpus.

Search Modes

  • Exact: Matches only the exact word as typed.
  • Variants (?): Accounts for common letter substitutions in these texts. After selecting Variants mode, choose a level: Basic (e.g., Dalet/Resh, He/Het, Vav/Yod), Extended (adds Qof/Kaf, Tet/Tav, etc.), or Maximum (broadest flexibility). Higher levels may return less relevant results ("noise") and take longer. The ×1 / ×2 / ×3 box next to the level buttons sets how many letters in each word may be swapped; each level keeps its own (by default ×1 for Basic, ×2 for Extended and Maximum).
  • Responsa (R): Search syntax inspired by the Bar-Ilan Responsa Project, offering both a textual syntax with operators for prefixes, suffixes, plene/defective spelling, wildcards, and proximity gaps, and an intuitive tabular search interface that builds the query for you. See Responsa-Style Search below.
  • Fuzzy: Uses Levenshtein distance to find similar words even with decoding errors.
  • Regex: Advanced search for experienced users. For example, \bא[א-ת]{3}\b finds 4-letter words starting with Aleph.
  • Title: Searches within the catalog titles of compositions. Example: searching "Mishneh Torah" will retrieve all manuscripts identified as Maimonides' Mishneh Torah.
  • Shelfmark: Fast search for shelfmarks (e.g., "T-S 13.15").
  • PGP Tags: Browse manuscripts by topic tags from the Princeton Geniza Project. Tags are organized into categories and displayed with Hebrew translations. See PGP Data below.

Additional Options

  • Gap: Defines how many words can separate search terms. A value of 0 requires an exact sequence. At most 10 in Exact, Variants and Fuzzy searches; Responsa-style and Regex searches have no limit.
  • Select All: A checkbox at the top of the table allows you to select all results (or currently displayed results) for focused export.
  • Preview: Double-clicking a row opens the full Manuscript Viewer on that page. Clicking the "👁" button will lead to the same result.
  • Browse manuscript: Clicking the "📖" icon will open the manuscript in the "Browse by Shelfmark" tab. A similar browse button is also found in the Manuscript Viewer.
  • Column Filtering: Click on column headers (Shelfmark, Title, Snippet) to filter results by text. Check "Exclude" to hide matching results instead of showing them.

Stopping and Pausing a Search

While a search is running the Search button becomes Stop, and a pause button (⏸) appears beside it. The two together take up exactly the space the Search button used, so nothing shifts under the mouse when a search starts.

  • Stop ends the search and keeps every result it had already found. The results header marks the list as "Partial results" so you can see it was not a complete run.
  • ⏸ Pause suspends the search at its next checkpoint. Because it waits for a checkpoint rather than stopping instantly, the button shows ⌛ for a moment first; once the search has actually paused it becomes ▶. Hover over the button for a description of whichever state it is in.
  • ▶ Resume continues from exactly where the search stopped — nothing already scanned is scanned again. Time spent paused is not counted in the elapsed time, and in Composition Search it is excluded from the estimated time remaining.
  • A paused search releases the setting that keeps the computer awake, so a machine left paused can sleep normally.
  • A paused search is held in memory only. Closing the program ends it — there is nothing to resume when you next start up.

Pause is available for regular searches, Lab Mode searches and Composition Search. It is not offered during the grouping step at the end of a composition scan, which cannot currently be interrupted cleanly.

Search Settings (⚙)

Click the gear icon to open advanced search settings:

  • Limit Short Words: Words with ≤ N characters receive only 1 character change in variant modes.
  • Max Changes per Word: Maximum number of character substitutions allowed per word, one value for each level (default: ×1 for Basic, ×2 for Extended and Maximum).
  • Aggressive Mode: Ignores word length limits for variant generation.
  • Custom Variant Pairs: Define your own letter substitution pairs (e.g., "מ=נו", one per line).

Responsa-Style Search

This mode offers two search methods inspired by the Bar-Ilan Responsa Project (פרויקט השו"ת): a textual syntax with operators for prefixes, suffixes, plene/defective spelling and more; and an intuitive tabular search interface that builds the query for you.

Activating Responsa Mode

  • Select Responsa (R) from the search Mode dropdown, or
  • Type R (R followed by a space) at the beginning of your query

Syntax Reference

  • #word — Prefix expansion: adds 24 Hebrew prefix forms (ו, ה, ב, כ, ל, מ, ש + compounds). Example: #שלום finds ושלום, השלום, בשלום, etc.
  • word# — Suffix expansion: adds 25 Hebrew suffix forms (י, ו, ם, ן, ה, ך, כם, כן, etc.). Example: שלום# finds שלומם, שלומו, שלומך, etc.
  • #word# — Both prefix and suffix expansion. Example: #שלום# finds all 600 prefix+suffix combinations.
  • *word — Wildcard prefix: any characters before the word. Example: *שלום matches כבשלום, etc.
  • word* — Wildcard suffix: any characters after the word. Example: שלום* matches שלומות, etc.
  • %word — Plene/defective variants: inserts/removes ו/י for spelling variants. Example: %שלום finds שלום, שלם.
  • (a/b) — OR alternatives: matches any of the listed options. Example: (שלום/שלומות) matches either.
  • [N] — Gap of N words between terms. Example: שלום [3] עולם = up to 3 words between.

Tip: Modifiers can be combined, e.g. #%word* applies prefix expansion + plene variants + wildcard suffix.

Whole words: every word of the query is matched as a whole word, the first and the last too: כהנים גדול does not find כהנים גדולים. Brackets inside a word of the text do not get in the way: שלום finds של[ו]ם.

Note: You cannot search with wildcards on both sides (*word*) due to search engine limitations; such a query is automatically converted to #word# (grammatical prefixes and suffixes). A * inside a word (כ*נים), or a word made only of *, is not supported yet: the search says so instead of running.

Sub-Options

When Responsa mode is active, four checkboxes appear below the search field:

  • Variants: Enable letter-variant matching (same as Variants mode) on all expanded terms.
  • Judeo-Arabic: Expand words with the Arabic definite article אל- (8 forms per word).
  • Flex Spacing: Ignore erroneous spaces within words — very useful given the many spacing errors in automatic transcription, but adds load to the query.
  • Bidirectional: Search for terms in both forward and reverse order.

Tabular Search

The Tabular Search provides a visual interface for constructing Responsa queries:

  1. Click the Tabular Search button (visible when Responsa mode is active).
  2. Add 2–4 components, each representing a search term or group.
  3. Enter one or more words per component (multiple words = OR alternatives).
  4. Toggle per-word modifiers: prefix (#), suffix (#), wildcard (*), plene (%), negation.
  5. Set the distance (max words) between components using the spinners.
  6. Watch the live preview update as you modify the query.
  7. Click Search to generate the Responsa syntax and trigger a search.

Note: When a query expands beyond 500 terms, the system automatically downgrades options (variants, Judeo-Arabic, plene, etc.) to maintain speed, and displays a notification accordingly.

Line & Text Position Search

Use the position dropdown next to the search bar to constrain where matches appear: Start of text, End of text, Line starts, or Line ends. This is particularly useful for detecting joins between fragments — if you know how a manuscript ends, search for those words at “End of text” to find potential continuations.

In Responsa mode, position constraints can be applied per word using |_ (start of line) and _| (end of line). Combined with line-break syntax (|), you can build multi-line positional queries — for example, find specific words at the end of one line and other words at the beginning of a line 4 lines later. The Tabular Query Builder provides a visual interface for constructing these queries.

Note: This feature requires a rebuilt index. Please rebuild the index from Settings to use it.

Focus Search

Click Focus Search to open the Search only in... window and narrow the search by manuscript properties before searching. This focuses your search on specific subsets of the corpus.

Available Filters

  • Include / Exclude: Choose whether the Subject Domain, Author and Work selections below narrow the search to matching manuscripts, or rule them out instead
  • Subject Domain: Filter by scholarly classification (e.g., Bible, Talmud, Poetry); you can select more than one
  • Author: Filter by attributed author; you can select more than one
  • Work: Filter by specific work title; you can select more than one
  • Date Range: Filter by manuscript dating; the Include undated checkbox also includes manuscripts with no recorded date
  • Type: Filter by material type: Show all, Exclude printed, or Printed only
  • Catalog Data Text: Search the catalog's own descriptive text (not the manuscript's transcription) for words you add under All words, Any word, or Not these words
  • Measurements: Filter by a manuscript's physical measurements — Width (cm), Height (cm), Lines, Line Height (mm), and Text Density — and by Material (measured): Paper, Vellum, Papyrus, Mix, or Wood. This group, and the Line Height (mm) field within it, appear only when the loaded catalog data includes that information.

A running count of matching manuscripts is shown at the bottom of the window as you adjust filters, and Clear All resets them. Active filters appear as removable chips in this window; after you click OK, they also appear as chips above the results, except for the Measurements filters and Printed only. Filters apply to all search modes, but not in Lab Mode.

Catalog & Metadata Translations

Catalog data, titles, and scholarly descriptions are available in both Hebrew and English, powered by machine translation via Dicta Translation.

Use the Show Translations toggle in Settings to enable translated descriptions in search results, browse views, and catalog dialogs. When enabled, translated text appears with a clickable Translated/Original badge — click to toggle between the translated and original text.

Composition Search

This tool is designed for researchers wishing to find parallels for a complete literary text (such as a Piyyut, medieval commentary, or other rare work) within the Genizah, thereby locating additional textual witnesses, both direct and indirect.

Two Search Methods

Composition Search offers two ways to find parallels. They are complementary: neither replaces the other, and which one suits you depends on the text in front of you.

  • Chunk search is the original method. It compares blocks of words, and it is the only method that offers the Exact / Variants / Fuzzy modes and cross-paragraph filtering described below.
  • Letter-level search compares sequences of letters instead. It is much faster than chunk search and returns far fewer unrelated results, but it does not offer the chunk-mode parameters — when you select it, those controls are set aside and the letter-level controls appear in their place.

In a sample test at the default settings, letter-level search ran 8× to 22× faster than chunk search; the share of relevant results in the first 100 and first 500 was 3 to 25 percentage points higher; and chunk search's noisiest form (2-word chunks) did yield true results letter-level search missed — but only past its first 1,500 results, some of them fragments too short to be in the letter-level index at all.

Letter-level search runs on an index built on this computer from the transcriptions you already have. The program offers to build it once, and you can build or rebuild it at any time from Settings. The build takes about ten minutes, needs about 11 GB of free disk space while it runs, and produces an index of about 3.5 GB. Cancelling a build, or a build that fails, always leaves the index you already had intact and working.

Letter-level search also works on My Library, with an index of its own, built from the texts My Library has already extracted. When you choose letter-level search with the Local or ALL scope and that index has not been built yet, the program offers to build it; you can also build or rebuild it at any time from Settings. It does not update by itself: after a scan that changes My Library, a notice tells you to rebuild it. Unlike the Genizah index, it keeps short pages, catalog cards and stamps, since those filters are meant for the Genizah photographs, not your own documents. With the ALL scope, results from both indexes are ranked together in one list, and My Library results can be used as witnesses like any other. Quoting texts and conditions (see Filter Texts below) work only with the Genizah scope.

Once the Genizah index exists on this computer, letter-level search is the method the Composition Search tab starts on; if you have already chosen a method yourself, your choice is kept.

The Genizah letter-level index deliberately leaves some pages out. Three kinds are dropped when it is built: pages whose transcription holds fewer than about 80 Hebrew letters — a line or two, too little text to carry letter-level evidence; microfilm catalog cards; and library-stamp pages photographed alongside the manuscripts. On the current corpus that is about a quarter of the pages, almost all of them tiny scraps. The practical consequence: a very small fragment can be found by chunk search, which searches every transcribed page, and never by letter-level search — one more reason the two methods complement each other.

Several Witnesses of One Work

A work survives in many manuscripts, and no single copy of it finds every other. Letter-level search can be given more than one copy of the text you are looking for — each is searched on its own, and the results are merged into one list. Press Witnesses beside the letter-level controls to open the list.

There are three ways to add one:

  • Paste a text — one witness at a time.
  • Load from files... — choose one or more files. By default each whole file is one witness; tick Split each file on blank lines to split each file on blank lines as well. A message then tells you how many witnesses were added and how many were skipped as too short.
  • Promote from your results — tick manuscripts in the result list and press Search with these too. The text comes from the pages that actually matched, not from the manuscript record.

In letter-level search, do not join several copies into one box. Joining works in chunk search — that is how you would use several copies there — but letter-level search spends a fixed budget per query, so joining measurably harms it: measured against the 614 Birkat Hamazon census manuscripts that have any indexed text, the best single copy finds 348 and seventeen copies searched separately and merged find 455 — while the same seventeen joined into one query find 296, fewer than a single copy on its own.

The results list gains a Witnesses column saying how many distinct copies point at each manuscript, with a tooltip naming them, and two new orderings: by combined score and by number of witnesses.

Auto-expand repeats the search using the best results as new witnesses. It reaches further and it puts more to skim at the top of the list, so it is a button you press rather than something the search does on its own. In letter-level mode the same button reads Run auto-expand now and runs this expansion; in chunk mode it keeps its own name and behaviour, which is correct for that engine.

A multi-witness search can be stopped, which a single letter-level search still cannot: the copy being searched finishes first, and everything found so far is kept. Up to 25 witnesses can be held at once.

Letter-Level Controls

  • Match width: How far a manuscript may drift from your text and still count as a match. Wider settings find more damaged or variant witnesses; the strongest matches are always ranked first.
  • Passage length: Whether a short shared passage counts as a match. "Also short passages" roughly doubles what you have to read through, and finds witnesses that the normal setting does not reach.
  • Search depth: How much of the corpus the search may examine. Deeper searches take seconds longer and return more manuscripts, including badly damaged and reworked copies that a fast pass misses. Long texts benefit the most. A deep search cannot be interrupted once it has started — Stop, Escape and closing the window all wait for it to finish.

Opening a Result

Double-clicking a result opens the Manuscript Viewer on that page, with the matched text marked in red. Beside it the viewer shows your own text, with the part that matched marked there too.

In letter-level search the two sides are not the same letters — that is what approximate matching means. What is marked in the manuscript is what the manuscript has; what is marked in your text is what yours has. Where the copy that produced the match was not the text in the box — a promoted manuscript, or another witness — the panel shows that witness's own excerpt instead of your unmarked text.

A composition result list is made of pages, so several results in a row can belong to one manuscript. Next Manuscript and Prev Manuscript go to the nearest result belonging to a different one, skipping the remaining pages of the fragment you are reading. They appear only when some manuscript in the list holds more than one result.

How Chunk Search Works (The Mechanism)

Unlike a regular search, the engine does not search for the entire text as a single unit. The process works as follows:

  1. The software splits the source text you entered into small segments ("Chunks").
  2. Each chunk is searched separately in the Genizah database.
  3. If a specific chunk is found in a manuscript, it receives a "score".
  4. At the end of the process, the software aggregates the results: if a manuscript contains many found chunks, it receives a high score and appears at the top of the list.

Important Parameters (Chunk Search)

These apply to chunk search. In letter-level search they are set aside and replaced by the three controls described above.

  • Chunk: The number of words in each search unit. A value too low will return many irrelevant results; a value too high might miss true results.
  • Max Freq: A tool to filter common expressions. If the engine detects that a sequence appears many times in the corpus (like idioms or verses), it will filter it to the Appendix.
  • Filter >: If a specific title (e.g., "Siddur Rav Saadia Gaon") appears more than X times in the results, the software groups these results under a single "Group" in the Appendix to avoid flooding the main list.
  • Sort by shelfmark only: Disables smart grouping and displays a flat, sorted list of all found manuscripts.
  • Exact / Variants / Fuzzy: the search mode (see Search Modes above). In Variants mode a slider (Variant intensity) appears beside it instead of the Basic / Extended / Maximum buttons; it sets how many letter substitutions are tried. The number of changes is not shown here: Composition Search uses the ×1–×3 value set for the Basic level in the Search tab (Fuzzy: always ×2).
  • Min chunks: A manuscript is listed only if at least this many chunks matched in it (default 1; turning on Lab Mode sets it to 3). It applies with Full search; in the two cross-paragraph modes the Min. cross-paragraph matches setting (gear button) is used instead.

Advanced Options

  • Exclude Manuscripts: Allows you to enter a list of known manuscripts to hide from results (they will appear under the "Excluded" category).
  • Filter texts: A menu of three ways to keep other texts out of your results. See Filter Texts below.
  • Full Recursive Search / Recursive Search in Results: After getting results, this button searches again using the texts of the found manuscripts as a basis for further searching. Until you tick results the button reads Full Recursive Search; when you tick results it reads Recursive Search in Results and searches only those.

Filter Texts

The Filter texts button opens a menu of three items. Hover over an item to see an example.

  • Quoted texts... — texts that your composition quotes, such as Bible verses quoted in the Talmud. Results that match only these quotations are marked "Filtered", so this noise is not shown among the main results. The number after the item is how many quoted texts are switched on.
  • Quoting texts... — works that quote your composition, such as the Rif quoting the Talmud. A result page on which the quoting work is found moves to the "Removed by a condition" group, with the reason. Load from Sefaria... lets you choose a book and then the passage that discusses your text (for example Rif Berakhot 1a-2b). Choose a passage, not the whole book: a whole book is too long, and it quotes much more than your passage. You can also paste a text (Add Custom Text) or load it from files. All the texts you add form one condition; choose the item again to change them.
    Load or paste the passage as it is, quotations included. A page is removed only where the quoting work has on it one unbroken stretch of at least 40 letters that are not also in your main text (shorter stretches are not added together), so the manuscripts of your own composition are not removed just because the quoting work quotes it.
  • Add condition... — a text that must appear, for example to show only results where an adjacent image (before or after) includes a certain text. Pages without it move to the "Removed by a condition" group. To give several versions of the text, separate them with a blank line; any one of them counts.

For quoting texts and conditions you also choose where to look: on the same image, on an adjacent image, or anywhere in the manuscript. What you set is listed under the main text, where each row can be edited (✎) or removed (✕). Up to four can be set.

Quoting texts and conditions work only in letter-level search of the Genizah corpus. "Not found" means not found in the pages the letter-level index covers (see above). When a page could not be checked completely — the search was stopped or reached its limit, or the page could not be identified — it goes to a "Not fully checked" group instead of being counted as passing. The Manuscript Viewer shows, for each result, on which image each text was found. Results of a search with conditions are not kept between sessions, and Auto-expand is not available while conditions are set.

Understanding Results

Results are grouped by manuscript and sorted by score (Max Score / Avg Score). Click on a result to expand and see your source chunk alongside the matching manuscript text, with matching words highlighted for easy comparison.

Cross-Paragraph Search

When searching for parallels to a text that contains paragraph breaks (e.g., a piyyut with stanzas, or a text with section divisions), you can enable cross-paragraph search to specifically find manuscripts that preserve text spanning across these boundaries.

Why is this useful?

  • Text within paragraphs often contains citations from other sources (Mishnah, Talmud, known phrases) or sources that quote the composition you're searching for.
  • Text that crosses paragraph boundaries is much less likely to be a citation, since citations rarely span across structural breaks.
  • This effectively filters out most of the "noise" and helps you find genuine textual witnesses.

How to use

  1. Enter your text with paragraph breaks (or set a custom delimiter like period or colon).
  2. Select a Paragraph search mode:
    • Full search – All results (default behavior)
    • Cross-paragraph only – Only matches that span paragraph breaks
    • Full + Cross-paragraph boost – All results, with boundary-crossing matches ranked higher
  3. Choose a Paragraph separator: Line break, Blank line, Period (.), or Colon (:).
  4. The status label shows how many boundaries are detected and how many chunks will cross them.
  5. Results that cross paragraph boundaries are marked with a 🔗 indicator in the score column.

Advanced Settings (⚙)

Click the gear button (visible in non-full modes) to configure:

  • Cross-paragraph boost: Score multiplier for boundary-crossing matches (1.0–3.0).
  • Min. cross-paragraph matches: Filter out results with fewer boundary matches.
  • Min. words between separators: Ignore delimiters too close together.

Browse by Shelfmark

This tab enables convenient continuous reading of a full manuscript, synchronized with source images.

  • Load: Enter a System ID, Shelfmark, or FL ID. The search is flexible and ignores spaces or punctuation (e.g., TS NS 13 15 finds T-S NS 13.15). Autocomplete is available for shelfmarks.
  • Navigate Pages: Use the arrows < > to flip between pages within the current manuscript.
  • Navigate Manuscripts: Use the arrows ◀ ▶ at the top left to move to the previous or next manuscript in the database file order.
  • Images: An image viewer is displayed on the side. You can rotate, zoom, and select the image source (NLI or Cambridge/Oxford where supported). Use 🖼️ to show/hide the image panel.
  • View All: Displays all manuscript pages in one long sequence for easy scrolling and for saving as a text file.
  • Find in Text: Type in the search field to highlight matching text in real-time within the current manuscript.
  • Parallels: Sends the current page text to the Composition Search tab for finding parallels across the corpus.
  • View on Ktiv: Opens the manuscript in the National Library of Israel's online catalog.
  • PGP Info: If Princeton Geniza Project data is available, an information panel is displayed with transcriptions, description, tags, and dating.
  • Volume Selector: Manuscripts with multiple microfilm scans (~1.5% of the collection) show a volume dropdown. Previously, images could be mismatched with the text — the volume selector fixes this by displaying each volume's own images and transcription, with page navigation staying within the active volume.

Browse by Identification

Browse the scholarly catalog by domain classification, author, or work title.

  • Domain Hierarchy: The left panel shows the domain tree (e.g., Bible > Torah > Genesis). Click a domain to see all manuscripts classified under it. Counts show how many manuscripts belong to each category.
  • Author & Work Filters: Use the search dropdowns to filter by author name or work title. Filters combine — selecting a domain and an author shows only manuscripts matching both.
  • Date: Enter From year / To year or click a century button; check Include undated to keep undated items.
  • Text Filter: Type keywords to search across catalog titles, descriptions, and domain names. Choose ALL (all terms must match), ANY (any term matches), or NOT (exclude matching terms). Add multiple terms as color-coded chips.
  • Transcriptions and library: Filter PGP and Filter Scholarly Transcriptions cycle through all, has, and has not; Filter by library shows or hides libraries.
  • Filter Chips: Active filters appear as removable chips above the results.
  • Search in these results / Parallel search in these results run a search limited to the current list; Clear All clears the filters.
  • Pagination: Results display 50 per page with navigation controls.
  • Cross-links: Domain and author labels on the Browse by Shelfmark tab link directly here with the appropriate filter pre-set.

Princeton Geniza Project (PGP) Data

The system integrates data from the Princeton Geniza Project (PGP) — a scholarly database containing approximately 36,000 cataloged documents with transcriptions, translations, descriptions, and detailed subject tagging.

PGP Badge in Search Results

Manuscripts with available PGP data are marked with a green "PGP" badge in search results, so you can quickly identify manuscripts with scholarly transcriptions and additional research information.

PGP Information in Browse by Shelfmark

When a manuscript has PGP data, an information panel is displayed showing:

  • Document Type (e.g., Letter)
  • Tags — clicking a tag searches for all manuscripts with that topic
  • Description in English (with translation option)
  • Date
  • View on PGP — a link to the original document on the Princeton website

Transcriptions and Translations

When scholarly transcriptions or translations from the Princeton project are available, they appear in the version selector alongside the automatic transcription. The system automatically prefers a PGP edition (if available) over the automatic reading.

Search by Tags

Select PGP Tags from the search Mode dropdown to browse manuscripts by topic. Tags are organized into categories (Document Types, Law & Society, Medicine & Illness, Trade & Travel, and more) and displayed in a dropdown with Hebrew translations.

Reading Desk

A side-by-side view that allows you to examine multiple manuscripts together, with synchronized images and a version selector for each fragment.

The Reading Desk is useful for any researcher who wants to view multiple shelfmarks together — whether they are fragments that join into a single document (according to PGP or other joins) or any collection of manuscripts you wish to examine side by side.

How to use

  • Click the Add to View button (eye icon) on the Browse by Shelfmark tab
  • Add more manuscripts from search results or from browsing other manuscripts
  • In the Reading Desk toolbar, type a shelfmark and click Add to Desk, or click Add from List to open your personal lists and click an item to add it.
  • From the joins menu of the 🔗 button on the Browse by Shelfmark tab, Open in Reading Desk loads all joined fragments at once.
  • Each fragment is displayed with its source image, version selector (including PGP editions if available), and extended information
  • Click Exit Reading Desk when done

Fragment Puzzle

A visual canvas for arranging manuscript fragment images side by side to reconstruct physical joins between Genizah fragments.

Adding Fragments

  • Type a shelfmark in the input box and press Enter or click the add button
  • From a personal list: click the Add from personal list button (📋), pick a list in the window that opens, then select the fragments to add
  • From known joins: when PGP or FJMS joins are available for a fragment, click the joins button to load all related fragments at once

Canvas Controls

  • Zoom: Scroll to zoom in/out on the canvas; double-click to reset view
  • Rotate: Select a fragment and use the rotate controls (or keyboard arrows) to fine-tune the angle
  • Background removal: Adjust the threshold slider to remove parchment/paper background from fragment images, isolating the text
  • Background modes: Cycle through canvas backgrounds (Dark Gray, Black, White, Checkerboard, Light Table, Grid) to find the best contrast
  • Crop: Trim away empty margins from a fragment image
  • Flip: Mirror a fragment horizontally or vertically
  • Folio navigation: Use Previous/Next page controls to switch between recto and verso, or navigate to other folios of the same manuscript

Layer Controls

  • Bring Forward / Send Backward: When fragments overlap, use these controls to change the stacking order so you can position fragments on top of or behind each other

Fragment Selector

Use the combobox above the canvas to select a loaded fragment. The Browse button opens that fragment in the Browse by Shelfmark tab.

Saving & Loading

  • Click the Save button to save the current arrangement as a join document with a title and optional notes
  • After the first save, changes are auto-saved as you move, rotate, or resize fragments
  • Click the Open button to browse your saved joins; each entry shows a thumbnail preview
  • Select a saved join to load it back onto the canvas

Export

  • Click the Export button to generate a composite PNG image of all fragments as arranged on the canvas
  • Choose from multiple resolution levels: Draft, Standard, or Full resolution
  • The exported image includes a metadata banner listing all fragment shelfmarks

Recto / Verso

The ⇄ button (Flip all fragments) mirrors the entire canvas arrangement and navigates each fragment to its verso (or recto), so you can examine the reverse side of a reconstructed join.

Joins Lab

The Joins Lab is a dedicated workspace for hunting physical joins — fragments that were once part of the same leaf or codex and are now scattered across collections. You pin one fragment as the anchor, then search for and triage candidate fragments against it, side by side.

Opening the Joins Lab

  • The Joins Lab button in the top toolbar corner.
  • The Find joins button on the Browse by Shelfmark tab.
  • From any search result or Browse page — an action opens the Lab anchored on that page.

The window is modeless: it stays open alongside the main window, and you can re-anchor it on a new fragment at any time without closing it.

The anchor (left pane)

The pinned fragment — its shelfmark, brief metadata, and page image. Use the folio arrows to page through the anchor's images, and zoom in to inspect the script. Known joins for the anchor (saved by you or by the community) are listed in a collapsible section.

Building a query (right pane)

Build a line-by-line query describing the text you expect on the joining fragment:

  • Mode — Responsa (the structured line-by-line builder described here) or Exact / Variants / Fuzzy / Regex (a single free-text query, as in the main search).
  • + Add Line — add another manuscript line, and set how many lines to skip before it (0 = the very next line).
  • + or — add an alternative word that may appear instead on the same line.
  • Line options (⚙) — per-line modifiers: negation (−), plene/defective spelling (%), prefixes (#_), suffixes (_#), wildcards (*), and "⊢ starts line" / "⊣ ends line" position anchors.
  • Search options — global toggles: Variants, Judeo-Arabic, Flex Spacing and Bidirectional.
  • Position — restrict a line to the start or end of the page text.
  • Other side of the leaf (p ±1) — also require or include text on the adjacent page; Narrow keeps only candidates whose adjacent page also matches, Widen adds adjacent pages as extra candidates.
  • Visual Similarity — show only fragments that look alike, optionally combined with a text query.

⚠ About visual similarity: the visual-similarity index covers only about half of the Genizah, and the algorithm is not conclusive — so it can miss real matches. Do not assume that a fragment absent from the visual-similarity results is not a join. Use visual similarity to surface candidates, never to rule a fragment out.

Click Find Candidates to run the query.

Triaging candidates

Candidates appear as cards with their image and metadata. For each one you can:

  • Mark Yes / Maybe / No to triage it, then filter the list by triage state.
  • Browse — open the candidate in the Browse view.
  • Compare — view it side by side with the anchor.
  • Re-anchor — make the candidate the new anchor and keep hunting from there.
  • Add as Join — record a confirmed join between the candidate and the anchor.
  • Add to Puzzle — send the candidate, together with the anchor, to the Fragment Puzzle for visual reassembly.
  • Add to list — save it to one of your lists.

Browse results (the Browse results ▶ button on the results toolbar) opens a compare window that steps through the filtered candidates one at a time, each shown side by side with the anchor — the fastest way to review a long candidate list. If exactly one candidate is selected it opens there; otherwise it starts at the first result. This complements the per-card Compare action, which opens a single candidate against the anchor.

A ⚠ size mismatch note flags candidates whose physical dimensions differ from the anchor's, so you can spot unlikely joins at a glance. Use the filter bar to narrow candidates by shelfmark, text, title, material, dimensions, or triage state, and switch to a compact Table view when you have many results. ⬇ Export XLSX exports the checked candidates (or all shown, if none are checked) to an Excel workbook. Clear resets the anchor, query, candidates and triage state, and clears the text, material and triage filters.

Personal Lists

The Personal Lists tab lets you keep your own lists of manuscripts and local documents, group them into projects, add notes and tags, and sync them with your account on genizahsearch.com.

Lists and Projects

Lab Mode

The "Lab Mode" button activates an experimental and more advanced search engine.

  • Deep Scan: A much deeper and thorough scan. Significantly slower, but recommended for finding rare phrases or ensuring nothing is missed.

Lab Mode Parameters

When Lab Mode is active, a settings panel appears. The available settings depend on the active tab.

Search Tab Parameters

  • Minimum Match %: Minimum percentage of the query text required to consider a result relevant.
  • Max Results to Process: Maximum number of raw candidates to fetch from the index before detailed scoring. The software first retrieves potential candidates, then searches within them. More candidates result in better accuracy but slower performance.
  • Deep Limit: Maximum number of documents to scan in Deep Scan mode.

Composition Tab Parameters

  • Max Candidates per Chunk: Maximum number of index hits to process per text chunk.
  • Min Chunk Score: Minimum score required for a chunk to be considered a match.
  • Max Final Results: Maximum number of results to display in the tree to prevent freezing (all results are still exported).

Advanced Scoring

Accessible via the "Advanced Scoring..." button:

  • Sequential Order Bonus: Bonus points for finding words in the correct order.
  • Coverage Penalty Power: Penalizes results that do not contain all search terms.
  • Stop-Word Suppression: Lowers the score for very short or common words to reduce noise.
  • Long Word Bonus: Gives higher weight to longer words.
  • Unique Match Base Score: The base score for finding a unique word.
  • Distance Penalty: Penalizes words found far apart from each other.
  • Repeated Word Factor: Reduces score for words appearing more often in the text than in the query.

Public API & AI Tools

Dicta Genizah Search exposes a public HTTP/JSON API so that researchers and AI tools can work with the corpus programmatically. There are two ways to use it: a ready-made AI skill for conversational research, and the raw API for developers.

Use it from Claude and other AI agents

A ready-to-use Cairo Genizah Research skill lets you drive the search engine from Claude in plain language. Ask it to search intelligently for phrases or parallels — candidate witnesses for a phrase, piyyut, responsum, letter, or composition — and it returns a ranked list together with the transcription text, library attribution, and image links, so you can review and display the results without leaving the conversation. You can also point other AI engines, including local ones, at the same skill.

The skill is available here: github.com/gershuni/GenizahSearch → skills/cairo-genizah-research.

GenizahSearch is also available in ChatGPT, and as an MCP server (https://genizahsearch.com/mcp) for any assistant that supports MCP connectors. All the AI options are listed at genizahsearch.com/ai.

For developers

The same data is available directly over a public HTTP/JSON API:

  • POST /api/search — text search across the corpus.
  • GET /api/browse — fetch the transcription, metadata, and image for a manuscript.
  • POST /api/parallels — find Genizah manuscripts containing chunks that match a long source text.

The full API is described by an OpenAPI schema at genizahsearch.com/api/openapi.json.

My Library — Local Documents

The My Library tab lets you index your own .docx, .pdf, .txt, .html, .xlsx, and .csv files alongside the Genizah corpus. Your personal documents appear inline in Search, Composition Search, and Parallels results with a LOCAL badge and a three-state filter button.

What gets indexed

Word documents, PDF files (text-layer PDFs only — scanned PDFs without OCR are skipped), plain text files, HTML files, Excel spreadsheets, and CSV files. The indexer skips other file types.

Where data lives

%LOCALAPPDATA%\GenizahSearchPro\Index\LocalIndex\ on Windows.

Indexing large folders

If you add a folder with many files, you'll be warned that indexing may take a long time. At any point you can stop indexing and choose whether to cancel indexing for the files already scanned, keep the partial results, or resume indexing.

Adding, removing, and selecting folders and files to search

You can add folders to your local library, remove them, and also choose which of the indexed files are searched — by clicking the checkboxes next to each folder or file.

Rebuilding the index

Clicking Refresh rescans all your registered folders, not just the selected one, and looks for new files to index. To rebuild the index from scratch, click Re-index All. If you run into problems, you can click Reset My Library and the index will be deleted entirely. In every case, your original files remain safe.

Privacy

Details of your local documents are never uploaded to GenizahSearch's servers. Three boundaries enforce this:

  • The /api/search endpoint filters out local items defensively.
  • Lists cloud sync never uploads local items: an entry for one of your own documents stays on this computer.
  • Corrections submission rejects local document IDs with a clear error.

Note: the indexed text is stored in local_index.sqlite3 inside your LOCAL index folder, compressed with zstd (compression, not encryption) — the stored text is cleartext. Use OS-level disk encryption (BitLocker / FileVault) if you need encryption.

Pre-selection and post-search filtering

Both regular Search and Composition Search include a button that lets you choose where the search runs: Genizah, Local, or All. You can also use the three-state Filter Local button to show only local files, only Genizah, or all results.

Renaming your computer

Note: if you change your computer's name, the SQLite cache is invalidated and the next scan re-extracts all files.

The My Library feature was inspired by Yehuda Seewald's GenizahLocal prototype.

Exporting Data

  • XLSX (Excel) — Research workbook: for Search results, a bilingual research workbook with four sheets (Search Results, Manuscripts, Bibliography, Credits and Info) with clickable image links per row and clickable PGP, Library Viewer, and GenizahSearch URLs per manuscript. When the export includes My Library results, a Local Documents sheet is added for them; an export of My Library results alone has only the Local Documents and Credits and Info sheets. A Composition Search export has its own sheets instead: Report View, Raw Data and Query information, plus Excluded Manuscripts and Local Documents when they apply; one with only My Library results has Local Documents and Query information.
  • CSV: Raw data format, suitable for importing into other databases.
  • TXT: Simple readable text report.
  • DOCX (Word): Microsoft Word document with formatted report.

Note: Export applies to selected results (checkboxes). If nothing is selected, the software exports all available results in the table.

הקדמה: איך זה עובד?

תוכנת Dicta Genizah Search Pro מאפשרת גישה מהירה ומתקדמת לקורפוס התעתוקים של פרויקט "מדרש" (MiDRASH). התוכנה מבוססת על מנוע חיפוש מהיר (Tantivy) ומשלבת אלגוריתמים ייחודיים לטיפול בשונות הכתיב העברית המאפיינת את כתבי היד של הגניזה.

התוכנה פועלת באופן מקומי על המחשב שלכם, אך משתמשת בחיבור אינטרנט כדי למשוך מידע ותמונות מהספרייה הלאומית, מספריית אוקספורד ומספריית האוניברסיטה של קמברידג'. בלי חיבור לאינטרנט היא תעבוד, אך ללא התמונות וללא חלק מהמידע המורחב. שימו לב: אם החיבור שלכם אינו ביתי (כמו נקודה חמה מהטלפון הנייד שלכם) שרתי הספרייה יכולים לחסום אתכם מלקבל מידע.

לשונית חיפוש

זוהי נקודת הכניסה לחיפוש טקסט חופשי או מטא-דאטה בקורפוס.

סוגי חיפוש

  • מדויק: מוצא רק את המילה בדיוק כפי שנכתבה.
  • וריאנטים (?): מתחשב בחילופי אותיות נפוצים בטקסטים אלו. לאחר בחירת מצב וריאנטים, בחרו רמה: בסיסי (למשל ד/ר, ה/ח, ו/י), מורחב (מוסיף ק/כ, ט/ת וכו'), או מרבי (הגמישות הרחבה ביותר). רמות גבוהות יותר עלולות להחזיר תוצאות פחות רלוונטיות ("רעש") ולקחת יותר זמן. התיבה ×1 / ×2 / ×3 שליד כפתורי הרמה קובעת כמה אותיות בכל מילה אפשר להחליף; לכל רמה ערך משלה (ברירת מחדל: ×1 בבסיסי, ×2 במורחב ובמרבי).
  • פרויקט השו"ת (R): תחביר חיפוש בהשראת פרויקט השו"ת של אוניברסיטת בר-אילן, המציע הן תחביר טקסטואלי עם אופרטורים לתחיליות, סיומות, כתיב מלא/חסר, תווים כלליים ומרווחים, והן ממשק חיפוש טבלאי אינטואיטיבי שבונה את השאילתא עבורכם. ראו חיפוש בסגנון פרויקט השו"ת להלן.
  • מקורב: משתמש במרחק לווינשטיין (Levenshtein distance) למציאת מילים דומות גם אם יש שגיאות פענוח.
  • ביטוי רגולרי (Regex): חיפוש מתקדם למשתמשים מנוסים. לדוגמה, \bא[א-ת]{3}\b ימצא מילים בנות 4 אותיות המתחילות ב-א'.
  • כותרת: חיפוש בתוך המידע הקטלוגי של הכותרות. דוגמה: חיפוש "משנה תורה" יביא את כל כתבי היד המזוהים כמשנה תורה לרמב"ם.
  • מספר מדף: חיפוש מהיר של מספר מדף (למשל: "T-S 13.15").
  • תגיות PGP: עיון לפי נושאים בכתבי יד שקוטלגו על ידי פרויקט הגניזה של פרינסטון (Princeton Geniza Project). התגיות מאורגנות בקטגוריות ומוצגות עם תרגום לעברית. ראו מידע PGP להלן.

אפשרויות נוספות

  • מרחק: מגדיר כמה מילים יכולות להפריד בין מילות החיפוש. ערך 0 מחייב רצף מדויק. לכל היותר 10 בחיפוש מדויק, וריאנטים ומקורב; בחיפוש בסגנון פרויקט השו"ת ובביטוי רגולרי אין מגבלה.
  • בחר הכל: בראש הטבלה ישנה תיבת סימון המאפשרת לבחור את כל התוצאות (או את התוצאות המוצגות כרגע) לצורך ייצוא ממוקד.
  • תצוגה מקדימה: לחיצה כפולה על שורה תפתח את חלון צפייה בכתב יד באותו עמוד. לחיצה על לחצן ה"👁" תוביל לאותה תוצאה.
  • עיין בכתב יד: לחיצה על לחצן ה"📖" תוביל לפתיחת כתב היד בלשונית עיון לפי מספר מדף. לחצן עיון דומה נמצא גם בחלון צפייה בכתב יד.
  • סינון עמודות: לחיצה על כותרות העמודות (מספר מדף, כותרת, קטע) מאפשרת לסנן תוצאות לפי טקסט. סמנו "החרג" כדי להסתיר תוצאות תואמות במקום להציג אותן.

עצירה והשהיה של חיפוש

בזמן שחיפוש רץ, לחצן חיפוש הופך לעצור, ולצדו מופיע לחצן השהיה (⏸). שניהם יחד תופסים בדיוק את המקום שתפס לחצן החיפוש, כך ששום דבר לא זז מתחת לעכבר כשהחיפוש מתחיל.

  • עצור מסיים את החיפוש ושומר כל תוצאה שכבר נמצאה. כותרת התוצאות מסמנת את הרשימה כ"תוצאות חלקיות", כדי שיהיה ברור שהריצה לא הושלמה.
  • ⏸ השהיה משהה את החיפוש בנקודת הביקורת הבאה שלו. מכיוון שהוא ממתין לנקודת ביקורת ואינו נעצר מיידית, הלחצן מציג תחילה ⌛ לרגע; משעה שהחיפוש הושהה בפועל הוא הופך ל▶. רחפו מעל הלחצן לתיאור המצב שבו הוא נמצא.
  • ▶ המשך ממשיך בדיוק מהנקודה שבה החיפוש נעצר — שום דבר שכבר נסרק אינו נסרק שוב. זמן ההשהיה אינו נספר בזמן שחלף, ובחיפוש חיבורים הוא מוחרג גם מהערכת הזמן שנותר.
  • חיפוש מושהה משחרר את ההגדרה שמונעת מהמחשב לישון, כך שמחשב שנשאר מושהה יכול לישון כרגיל.
  • חיפוש מושהה נשמר בזיכרון בלבד. סגירת התוכנה מסיימת אותו — אין מה להמשיך בהפעלה הבאה.

השהיה זמינה בחיפוש רגיל, בחיפושים של מצב מעבדה ובחיפוש חיבורים. היא אינה מוצעת בשלב הקיבוץ שבסוף סריקת חיבורים, שכרגע אינו ניתן להפסקה נקייה.

הגדרות חיפוש (⚙)

לחצו על סמל גלגל השיניים לפתיחת הגדרות חיפוש מתקדמות:

  • הגבלת מילים קצרות: מילים עם ≤ N תווים יקבלו שינוי תו אחד בלבד במצבי וריאנטים.
  • מקסימום שינויים למילה: מספר החלפות התווים המרבי המותר למילה, ערך לכל רמה (ברירת מחדל: ×1 בבסיסי, ×2 במורחב ובמרבי).
  • מצב אגרסיבי: מתעלם ממגבלות אורך מילה ביצירת וריאנטים.
  • זוגות וריאנטים מותאמים אישית: הגדירו זוגות החלפת אותיות משלכם (למשל: "נו=מ", אחד בכל שורה).

חיפוש בסגנון פרויקט השו"ת

מצב זה מציע שתי דרכי חיפוש ברוח פרויקט השו"ת של אוניברסיטת בר-אילן: האחת בתחביר טקסטואלי עם אופרטורים לתחיליות, סיומות, כתיב מלא/חסר ועוד; והשנייה בצורת חיפוש טבלאי אינטואיטיבי, שבפועל בונה את השאילתא עבורכם.

הפעלת המצב

  • בחרו פרויקט השו"ת (R) מתפריט מצב החיפוש, או
  • הקלידו R (R ואחריו רווח) בתחילת השאילתה

מדריך תחביר

  • #word — הרחבת תחיליות: מוסיף 24 צורות תחילית עבריות (ו, ה, ב, כ, ל, מ, ש + צירופים). דוגמה: #שלום מוצא ושלום, השלום, בשלום וכו'.
  • word# — הרחבת סיומות: מוסיף 25 צורות סיומת עבריות (י, ו, ם, ן, ה, ך, כם, כן וכו'). דוגמה: שלום# מוצא שלומם, שלומו, שלומך וכו'.
  • #word# — הרחבת תחיליות וסיומות יחד. דוגמה: #שלום# מוצא את כל 600 הצירופים.
  • *word — תו כללי בתחילת מילה: כל תווים לפני המילה. דוגמה: *שלום מתאים לכבשלום וכו'.
  • word* — תו כללי בסוף מילה: כל תווים אחרי המילה. דוגמה: שלום* מתאים לשלומות וכו'.
  • %word — חלופות כתיב מלא/חסר: הוספת/הסרת ו/י. דוגמה: %שלום מוצא שלום, שלם.
  • (a/b) — חלופות OR: מתאים לכל אחת מהאפשרויות. דוגמה: (שלום/שלומות) מתאים לשתיהן.
  • [N] — מרווח של N מילים בין מונחים. דוגמה: שלום [3] עולם = עד 3 מילים ביניהם.

טיפ: ניתן לשלב מגדירים, למשל #%word* מפעיל הרחבת תחיליות + חלופות כתיב + תו כללי בסוף.

מילים שלמות: כל מילה בשאילתא נמצאת כמילה שלמה, גם הראשונה והאחרונה: כהנים גדול אינו מוצא כהנים גדולים. סוגריים בתוך מילה בטקסט אינם מפריעים: שלום מוצא של[ו]ם.

הערה: לא ניתן לחפש מילה עם כוכביות משני צידיה (*מילה*) בגלל מגבלות מנוע החיפוש; שאילתא כזו תומר אוטומטית ל-#מילה# (תוספות דקדוקיות לפני ואחרי). כוכבית בתוך מילה (כ*נים), או מילה שכולה כוכביות, עדיין אינה נתמכת: החיפוש מודיע על כך ואינו רץ.

אפשרויות משנה

כאשר מצב זה פעיל, מופיעות ארבע תיבות סימון מתחת לשדה החיפוש:

  • וריאנטים: הפעלת התאמת חלופי אותיות (כמו במצב וריאנטים) על כל המונחים המורחבים.
  • ערבית-יהודית: הרחבת מילים עם ה"א הידיעה הערבית אל- (8 צורות למילה).
  • ריווח גמיש: התעלמות מרווחים שגויים בתוך מילים — שימושי מאוד בגלל ריבוי הרווחים השגויים בקריאה האוטומטית, אך מכביד על השאילתא.
  • דו-כיווני: חיפוש מונחים גם בסדר קדימה וגם בסדר הפוך.

חיפוש טבלאי

החיפוש הטבלאי מספק ממשק ויזואלי לבניית שאילתות בתחביר השו"ת:

  1. לחצו על כפתור חיפוש טבלאי (גלוי כאשר מצב פרויקט השו"ת פעיל).
  2. הוסיפו 2–4 רכיבים, כל אחד מייצג מונח חיפוש או קבוצה.
  3. הזינו מילה אחת או יותר לכל רכיב (מספר מילים = חלופות OR).
  4. הפעילו מגדירים למילה: תחילית (#), סיומת (#), תו כללי (*), כתיב מלא/חסר (%), שלילה.
  5. הגדירו את המרחק (מספר מילים מרבי) בין רכיבים באמצעות הספינרים.
  6. צפו בתצוגה מקדימה חיה המתעדכנת בזמן שאתם משנים את השאילתה.
  7. לחצו על חפש כדי ליצור את שאילתת השו"ת ולהפעיל חיפוש.

הערה: כאשר שאילתא מתרחבת מעבר ל-500 מונחים, המערכת מורידה אוטומטית אפשרויות (וריאנטים, ערבית-יהודית, כתיב וכו') כדי לשמור על מהירות, ומציגה התראה בהתאם.

חיפוש לפי מיקום בשורה/טקסט

השתמשו בתפריט המיקום ליד שורת החיפוש כדי להגביל את מיקום ההתאמות: תחילת טקסט, סוף טקסט, תחילת שורה או סוף שורה. שימושי במיוחד לזיהוי צירופים בין קטעים — אם ידוע כיצד כתב יד מסתיים, חפשו את המילים האלה ב“סוף טקסט” כדי למצוא המשכים אפשריים.

במצב פרויקט השו"ת, ניתן להחיל אילוצי מיקום לכל מילה בנפרד באמצעות |_ (תחילת שורה) ו-_| (סוף שורה). בשילוב עם תחביר שבירת שורה (|), ניתן לבנות שאילתות מיקום רב-שורתיות — למשל, למצוא מילים מסוימות בסוף שורה אחת ומילים אחרות בתחילת שורה 4 שורות מאוחר יותר. בונה השאילתות הטבלאי מספק ממשק ויזואלי לבניית שאילתות אלה.

הערה: תכונה זו דורשת בניית אינדקס מחדש. בנו מחדש מההגדרות כדי להשתמש בה.

מקד חיפוש

לחצו על מקד חיפוש כדי לפתוח את החלון חפש רק ב... ולצמצם את החיפוש לפי מאפייני כתבי היד לפני החיפוש.

מסננים זמינים

  • כלול / שלילה: בחרו אם הבחירות בתחום הנושא, במחבר ובחיבור שלהלן מצמצמות את החיפוש לכתבי היד התואמים, או מוציאות אותם ממנו
  • תחום נושא: סינון לפי סיווג מדעי (כגון תנ"ך, תלמוד, שירה); ניתן לבחור בכמה תחומים
  • מחבר: סינון לפי מחבר מיוחס; ניתן לבחור בכמה מחברים
  • חיבור: סינון לפי שם חיבור; ניתן לבחור בכמה חיבורים
  • טווח תאריכים: סינון לפי תיארוך כתב היד; תיבת הסימון כלול לא מתוארכים מוסיפה גם כתבי יד ללא תיארוך רשום
  • סוג: סינון לפי סוג חומר: הצג הכל, ללא דפוסים או דפוסים בלבד
  • טקסט נתוני קטלוג: חיפוש בטקסט התיאורי של הקטלוג עצמו (לא בתעתוק של כתב היד), לפי מילים שתוסיפו תחת כל המילים, כל מילה או ללא מילים אלה
  • מידות: סינון לפי מידות פיזיות של כתב היד — רוחב (ס"מ), גובה (ס"מ), שורות, גובה שורה (מ"מ) וצפיפות טקסט — ולפי חומר: נייר, קלף, פפירוס, מעורב או עץ. קבוצה זו, ושדה גובה שורה (מ"מ) שבתוכה, מופיעים רק כאשר נתוני הקטלוג הטעון כוללים מידע זה.

ספירה מתעדכנת של כתבי היד התואמים מוצגת בתחתית החלון בזמן שאתם משנים מסננים, וכפתור ניקוי הכל מאפס אותם. מסננים פעילים מופיעים בחלון זה כצ'יפים ניתנים להסרה; לאחר שתלחצו על אישור הם מופיעים כצ'יפים גם מעל התוצאות, פרט למסנני מידות ולדפוסים בלבד. המסננים חלים על כל מצבי החיפוש, אך לא במצב מעבדה.

תרגומי קטלוג ומטא-נתונים

נתוני קטלוג, כותרות ותיאורים מדעיים זמינים גם בעברית וגם באנגלית, באמצעות תרגום דיקטה.

הפעילו את מתג הצג תרגומים בהגדרות כדי להציג תיאורים מתורגמים בתוצאות חיפוש, תצוגות עיון ודיאלוגי קטלוג. כאשר מופעל, טקסט מתורגם מופיע עם תג מתורגם/מקור לחיץ — לחצו כדי לעבור בין הטקסט המתורגם למקורי.

חיפוש חיבורים

כלי זה נועד לחוקרים המעוניינים למצוא מקבילות לטקסט ספרותי שלם (כגון פיוט, פירוש מימי הביניים או חיבור נדיר אחר) בתוך הגניזה, ובכך לאתר עדי נוסח נוספים, ישירים ועקיפים.

שתי שיטות חיפוש

חיפוש חיבורים מציע שתי דרכים למצוא מקבילות. הן משלימות זו את זו: אף אחת אינה מחליפה את השנייה, והמתאימה לכם תלויה בטקסט שלפניכם.

  • חיפוש מקטעים הוא השיטה המקורית. הוא משווה גושי מילים, והוא השיטה היחידה המציעה את מצבי מדויק / וריאנטים / מקורב ואת החיפוש חוצה-הפסקאות המתוארים להלן.
  • חיפוש ברמת האות משווה רצפי אותיות במקום זאת. הוא מהיר בהרבה מחיפוש מקטעים ומחזיר הרבה פחות תוצאות לא רלוונטיות, אך אינו מציע את הפרמטרים של חיפוש מקטעים — כשבוחרים בו, הפקדים ההם מוסטים הצידה ובמקומם מופיעים פקדי רמת האות.

בבדיקה מדגמית, עלה כי בהגדרות ברירת המחדל מהירות החיפוש ברמת האות גבוהה פי 8 עד פי 22 ממהירות חיפוש המקטעים; אחוז התוצאות הרלוונטיות ב־100 וב־500 התוצאות הראשונות גבוה יותר ב־3 עד 25 נקודות אחוז; וחיפוש המקטעים בגרסתו ה"רועשת" ביותר (מקטעים של 2 מילים) מניב תוצאות אמת שהחיפוש ברמת האות לא השיג — אך רק לאחר 1,500 התוצאות הראשונות, וחלקן קטעים קצרים שאינם כלולים באינדקס של רמת האות כלל.

חיפוש ברמת האות פועל על אינדקס הנבנה במחשב הזה מתוך התעתוקים שכבר נמצאים כאן. התוכנה מציעה לבנות אותו פעם אחת, ואפשר לבנות או לבנות מחדש בכל עת מתוך ההגדרות. הבנייה אורכת כעשר דקות, דורשת כ-11 ג'יגה-בייט מקום פנוי בזמן שהיא רצה, ומייצרת אינדקס בגודל כ-3.5 ג'יגה-בייט. ביטול בנייה, או בנייה שנכשלה, משאירים תמיד את האינדקס שכבר היה לכם שלם ופעיל.

חיפוש ברמת האות פועל גם על הספרייה המקומית, עם אינדקס משלה, שנבנה מהטקסטים שכבר חולצו מהספרייה המקומית. כשבוחרים חיפוש ברמת האות בהיקף "מקומי" או "הכול" והאינדקס הזה עדיין לא נבנה, התוכנה מציעה לבנות אותו; אפשר גם לבנות או לבנות מחדש בכל עת מתוך ההגדרות. האינדקס אינו מתעדכן מעצמו: אחרי סריקה ששינתה את הספרייה המקומית, תוצג הודעה לבנות אותו מחדש. בשונה מהאינדקס של הגניזה, הוא שומר גם עמודים קצרים, כרטיסי קטלוג וחותמות, כי הסינונים האלה נועדו לצילומי הגניזה ולא למסמכים שלכם. בהיקף "הכול" התוצאות משני האינדקסים מדורגות יחד ברשימה אחת, ואפשר להשתמש בתוצאות מהספרייה המקומית כעדים כמו בכל תוצאה אחרת. חיבורים מצטטים ותנאים (ראו סינון טקסטים בהמשך) פועלים רק בהיקף הגניזה.

ברגע שהאינדקס של הגניזה קיים במחשב הזה, חיפוש ברמת האות הוא השיטה שבה נפתחת לשונית חיפוש חיבורים; אם כבר בחרתם שיטה בעצמכם, הבחירה שלכם נשמרת.

האינדקס של רמת האות לגניזה משמיט חלק מהעמודים במכוון. שלושה סוגים נופלים בבנייתו: עמודים שבתעתוקם פחות מכ־80 אותיות — שורה או שתיים, מעט מדי טקסט לראָיה ברמת האות; כרטיסי קטלוג של מיקרופילם; ועמודי חותמת ספרייה שצולמו לצד כתבי היד. בקורפוס הנוכחי מדובר בכרבע מהעמודים, כמעט כולם קטעי טקסט זעירים. המסקנה המעשית: קטע קטן מאוד יכול להימצא בחיפוש מקטעים, שמחפש בכל עמוד מתועתק, ולא להימצא כלל בחיפוש ברמת האות — עוד סיבה לכך ששתי השיטות משלימות זו את זו.

כמה עדי נוסח של יצירה אחת

יצירה שורדת בכתבי יד רבים, ואף עותק אחד שלה אינו מוצא את כל האחרים. אפשר לתת לחיפוש ברמת האות יותר מעותק אחד של הטקסט שאתם מחפשים — כל אחד נבדק בנפרד, והתוצאות מתמזגות לרשימה אחת. לחצו על עדים לצד פקדי רמת האות כדי לפתוח את הרשימה.

יש שלוש דרכים להוסיף עד:

  • הדבקת טקסט — עד אחד בכל פעם.
  • טען מקבצים... — בחרו קובץ אחד או יותר. כברירת מחדל כל קובץ שלם הוא עד אחד; סמנו פצל כל קובץ לפי שורות ריקות כדי לחלק כל קובץ גם לפי שורות ריקות. לאחר מכן הודעה מראה כמה עדים נוספו וכמה דולגו כי היו קצרים מדי.
  • קידום מתוך התוצאות שלכם — סמנו כתבי יד ברשימת התוצאות ולחצו חפש גם עם אלו. הטקסט נלקח מן העמודים שנמצאו בפועל, לא מרשומת כתב היד.

בחיפוש ברמת האות, אל תאחדו כמה עותקים לתיבה אחת. בחיפוש מקטעים האיחוד עובד — כך אכן משתמשים שם בכמה עותקים — אבל חיפוש ברמת האות מקצה תקציב קבוע לכל שאילתה, ולכן האיחוד פוגע בו במידה מדידה: במדידה מול 614 כתבי היד שברשימת ברכת המזון שיש להם טקסט מאונדקס, העותק היחיד הטוב ביותר מוצא 348, ושבעה-עשר עותקים שנבדקו בנפרד ומוזגו מוצאים 455 — ואילו אותם שבעה-עשר, מאוחדים לשאילתה אחת, מוצאים 296, פחות מעותק בודד.

ברשימת התוצאות מתווספת עמודת עדים המציינת כמה עותקים שונים מצביעים על כל כתב יד, עם חלונית מידע המונה אותם בשמם, ושני מיונים חדשים: לפי ציון משולב ולפי מספר העדים.

הרחבה אוטומטית חוזרת על החיפוש כשהתוצאות הטובות ביותר משמשות כעדים חדשים. היא מגיעה רחוק יותר, אבל גם מוסיפה חומר לסריקה בראש הרשימה — ולכן היא לחצן שאתם לוחצים ולא משהו שהחיפוש עושה מעצמו. במצב רמת האות אותו כפתור נקרא הפעל הרחבה אוטומטית ומפעיל את ההרחבה הזו; במצב מקטעים הוא שומר על שמו ועל ההתנהגות שלו, הנכונה למנוע ההוא.

חיפוש עם כמה עדים אפשר לעצור, מה שחיפוש יחיד ברמת האות עדיין לא מאפשר: העותק שנבדק כרגע מסיים, וכל מה שנמצא עד כה נשמר. אפשר להחזיק עד 25 עדים בבת אחת.

פקדי רמת האות

  • רוחב התאמה: עד כמה כתב יד רשאי להתרחק מהטקסט שלכם ועדיין להיחשב התאמה. הגדרות רחבות יותר מוצאות עדי נוסח פגומים או שונים; ההתאמות החזקות ביותר תמיד מדורגות ראשונות.
  • אורך הקטע: האם קטע משותף קצר נחשב התאמה. "גם קטעים קצרים" מכפיל בערך את כמות החומר שצריך לעבור עליו, ומוצא עדים שההגדרה הרגילה אינה מגיעה אליהם.
  • עומק החיפוש: כמה מן הקורפוס החיפוש רשאי לבחון. חיפושים עמוקים אורכים שניות ספורות יותר ומחזירים יותר כתבי יד, כולל עותקים פגומים ומעובדים שמעבר מהיר מפספס. הטקסטים הארוכים מרוויחים מזה הכי הרבה. חיפוש עמוק אינו ניתן להפסקה אחרי שהתחיל — עצירה, Escape וסגירת החלון, כולם ממתינים לסיומו.

פתיחת תוצאה

לחיצה כפולה על תוצאה פותחת את חלון צפייה בכתב יד באותו עמוד, כשהטקסט שנמצא מסומן באדום. לצדו מוצג הטקסט שלכם, והחלק שהתאים מסומן גם בו.

בחיפוש ברמת האות שני הצדדים אינם אותן אותיות — זו בדיוק משמעותה של התאמה מקורבת. מה שמסומן בכתב היד הוא מה שיש בכתב היד; מה שמסומן בטקסט שלכם הוא מה שיש בשלכם. כאשר העותק שהניב את ההתאמה לא היה הטקסט שבתיבה — כתב יד שקודם, או עד אחר — הפאנל מציג את הקטע של אותו עד במקום את הטקסט שלכם ללא סימון.

רשימת תוצאות של חיפוש חיבורים בנויה מעמודים, ולכן כמה תוצאות רצופות יכולות להיות של אותו כתב יד. לכתב היד הבא ולכתב היד הקודם עוברים לתוצאה הקרובה ביותר ששייכת לכתב יד אחר, ומדלגים על שאר עמודי הקטע שאתם קוראים. הלחצנים מופיעים רק כאשר לכתב יד כלשהו ברשימה יש יותר מתוצאה אחת.

איך חיפוש מקטעים עובד? (המנגנון)

בניגוד לחיפוש רגיל, המנוע לא מחפש את הטקסט כולו כמקשה אחת. התהליך מתבצע כך:

  1. התוכנה מחלקת את טקסט המקור שהזנתם למקטעים קטנים.
  2. כל מקטע נשלח לחיפוש בנפרד במאגר הגניזה.
  3. אם מקטע מסוים נמצא בכתב יד, הוא מקבל "ציון".
  4. בסוף התהליך, התוכנה מקשרת מחדש את התוצאות: אם כתב יד מכיל הרבה מקטעים שנמצאו, הוא יקבל ציון גבוה ויופיע בראש הרשימה.

פרמטרים חשובים (חיפוש מקטעים)

  • מקטע: מספר המילים בכל יחידת חיפוש. ערך נמוך יחזיר הרבה תוצאות לא רלוונטיות; ערך גבוה עלול להחמיץ תוצאות אמת.
  • תדירות מקס': כלי לסינון ביטויים נפוצים. אם המנוע מגלה שרצף מילים מסוים מופיע פעמים רבות בקורפוס (כמו מטבעות לשון או פסוקים), הוא יסנן אותו לנספח.
  • סינון >: אם כותרת מסוימת (למשל "סידור רב סעדיה גאון") מופיעה בתוצאות יותר מ-X פעמים, התוכנה תקבץ את כל התוצאות הללו תחת "קבוצה" אחת בנספח, כדי לא להציף את הרשימה הראשית.
  • מיין לפי מספר מדף בלבד: מבטל את הקיבוץ החכם ומציג רשימה שטוחה וממוינת של כל כתבי היד שנמצאו.
  • מדויק / וריאנטים / מקורב: מצב החיפוש (ראו מצבי חיפוש לעיל). במצב וריאנטים מופיע לידו מחוון (עוצמת וריאנטים) במקום הכפתורים בסיסי / מורחב / מרבי; הוא קובע כמה חילופי אותיות ייבדקו. מספר השינויים אינו מוצג כאן: חיפוש חיבורים משתמש בערך ×1–×3 שנקבע לרמה בסיסי בלשונית "חפש" (במקורב תמיד ×2).
  • מינ' מקטעים: כתב יד יוצג רק אם נמצאו בו לפחות מספר זה של מקטעים תואמים (ברירת מחדל 1; הפעלת מצב מעבדה קובעת 3). הערך חל בחיפוש מלא; בשני מצבי חוצה-הפסקאות חלה במקומו ההגדרה מינימום התאמות חוצות-פסקאות (כפתור גלגל השיניים).

אפשרויות מתקדמות

  • החרג כתבי יד: מאפשר להזין רשימה של כתבי יד שאתם כבר מכירים ורוצים להסתיר מהתוצאות (יופיעו תחת קטגוריית "מוחרגים").
  • סנן טקסטים: תפריט ובו שלוש דרכים להרחיק טקסטים אחרים מהתוצאות. ראו סינון טקסטים בהמשך.
  • חיפוש רקורסיבי מלא / חיפוש רקורסיבי בתוצאות: לאחר קבלת תוצאות, כפתור זה יחפש שוב במאגר, הפעם תוך שימוש בטקסטים של כתבי היד שנמצאו כבסיס לחיפוש נוסף. כל עוד לא סימנתם תוצאות הכפתור נקרא חיפוש רקורסיבי מלא; כשסימנתם תוצאות הכפתור נקרא חיפוש רקורסיבי בתוצאות ומחפש רק בהן.

סינון טקסטים

הכפתור סנן טקסטים פותח תפריט ובו שלושה פריטים. העבירו את העכבר מעל פריט כדי לראות דוגמה.

  • מקורות מצוטטים... — טקסטים שהחיבור שלכם מצטט, כמו פסוקי תנ"ך המצוטטים בתלמוד. תוצאות שתואמות רק את הציטוטים האלה מסומנות כ"מסוננים", וכך "רעש" זה לא מוצג בין התוצאות העיקריות. המספר שליד הפריט הוא מספר המקורות המצוטטים הפעילים.
  • חיבורים מצטטים... — חיבורים שמצטטים את החיבור שלכם, כמו הרי"ף המצטט את התלמוד. עמוד תוצאה שבו נמצא החיבור המצטט עובר לקבוצה "הוסרו בגלל תנאי", יחד עם הסיבה. טען מספריא... מאפשר לבחור ספר ואחר כך את הקטע שעוסק בטקסט שלכם (למשל רי"ף ברכות 1a-2b). בחרו קטע ולא את כל הספר: ספר שלם ארוך מדי, והוא מצטט הרבה יותר מהקטע שלכם. אפשר גם להדביק טקסט (הוסף טקסט מותאם) או לטעון אותו מקבצים. כל הטקסטים שתוסיפו הם תנאי אחד; בחרו בפריט שוב כדי לשנות אותם.
    טענו או הדביקו את הקטע כמות שהוא, כולל הציטוטים. עמוד יוסר רק אם יש בו רצף אחד של 40 אותיות לפחות מהחיבור המצטט שאינן גם בטקסט הראשי שלכם (רצפים קצרים יותר אינם מצטרפים זה לזה), וכך כתבי היד של החיבור שלכם עצמו אינם מוסרים רק משום שהחיבור המצטט מצטט אותו.
  • הוסף תנאי... — טקסט שחייב להופיע, למשל כדי להציג רק תוצאות שבתמונה סמוכה (לפניה או אחריה) מופיע טקסט מסוים. עמודים שהוא אינו מופיע בהם עוברים לקבוצה "הוסרו בגלל תנאי". כדי לתת כמה נוסחים של הטקסט, הפרידו ביניהם בשורה ריקה; די שאחד מהם יימצא.

בחיבורים מצטטים ובתנאים בוחרים גם היכן לחפש: באותה תמונה, בתמונה סמוכה, או באותו כתב יד. מה שהגדרתם מופיע מתחת לטקסט הראשי, ושם אפשר לערוך (✎) או להסיר (✕) כל שורה. אפשר להגדיר עד ארבעה.

חיבורים מצטטים ותנאים פועלים רק בחיפוש ברמת האות בקורפוס הגניזה. "לא נמצא" פירושו שלא נמצא בעמודים שהאינדקס של רמת האות מכסה (ראו לעיל). כשלא ניתן היה לבדוק עמוד עד הסוף — החיפוש נעצר או הגיע למגבלה, או שהעמוד לא זוהה — הוא עובר לקבוצה "לא נבדקו עד הסוף" ואינו נחשב כעומד בתנאי. חלון צפייה בכתב יד מראה, לכל תוצאה, באיזו תמונה נמצא כל טקסט. תוצאות של חיפוש עם תנאים אינן נשמרות בין הפעלות, והרחבה אוטומטית אינה זמינה כשמוגדרים תנאים.

הבנת התוצאות

התוצאות מקובצות לפי כתב יד וממוינות לפי ציון (ציון מקסימלי / ציון ממוצע). לחצו על תוצאה כדי להרחיב ולראות את מקטע המקור שלכם לצד הטקסט התואם מכתב היד, עם הדגשת מילים תואמות להשוואה נוחה.

חיפוש חוצה-פסקאות

כאשר מחפשים מקבילות לטקסט המכיל מעברי פסקה (למשל: פיוט עם בתים, או טקסט עם חלוקה לסעיפים), ניתן להפעיל חיפוש חוצה-פסקאות כדי למצוא באופן ספציפי כתבי יד ששומרים על טקסט החוצה גבולות אלה.

למה זה שימושי?

  • טקסט בתוך פסקאות לעתים קרובות מכיל ציטוטים ממקורות אחרים (משנה, תלמוד, ביטויים ידועים) או מקורות שמצטטים את החיבור שאתם מחפשים.
  • טקסט שחוצה גבולות פסקה הוא בסבירות נמוכה בהרבה ציטוט, מכיוון שציטוטים לעיתים רחוקות חוצים גבולות מבניים.
  • זה מסנן ביעילות את רוב ה"רעש" ועוזר לכם למצוא עדי נוסח אמיתיים.

כיצד להשתמש

  1. הזינו את הטקסט שלכם עם מעברי פסקה (או הגדירו מפריד מותאם אישית כמו נקודה או נקודתיים).
  2. בחרו מצב חיפוש פסקאות:
    • חיפוש מלא – כל התוצאות (ברירת מחדל)
    • חוצה-פסקאות בלבד – רק התאמות שחוצות מעברי פסקה
    • מלא + העדפת חוצה-פסקאות – כל התוצאות, כשהתאמות חוצות-פסקאות מדורגות גבוה יותר
  3. בחרו מפריד פסקאות: מעבר שורה, שורה ריקה, נקודה (.) או נקודתיים (:).
  4. תווית הסטטוס מציגה כמה גבולות זוהו וכמה מקטעים יחצו אותם.
  5. תוצאות שחוצות גבולות פסקה מסומנות באינדיקטור 🔗 בעמודת הציון.

הגדרות מתקדמות (⚙)

לחצו על כפתור גלגל השיניים (מופיע במצבים שאינם "מלא") כדי להגדיר:

  • תוספת חוצה-פסקאות: מכפיל ציון להתאמות חוצות-גבול (1.0–3.0).
  • מינימום התאמות חוצות-פסקאות: סינון תוצאות עם פחות התאמות חוצות-גבול.
  • מינימום מילים בין מפרידים: התעלמות ממפרידים קרובים מדי.

עיון לפי מספר מדף

לשונית זו מאפשרת קריאה רציפה ונוחה של כתב יד שלם, עם סנכרון לתמונות המקור.

  • טעינה: הזינו מספר מערכת, מספר מדף או מזהה FL. החיפוש גמיש ומתעלם מרווחים או סימני פיסוק (למשל TS NS 13 15 ימצא את T-S NS 13.15). השלמה אוטומטית זמינה למספרי מדף.
  • דפדוף בעמודים: השתמשו בחיצים < > כדי לדפדף בין העמודים בתוך כתב היד הנוכחי.
  • דפדוף בין כתבי יד: השתמשו בחיצים ▶ ◀ בפינה העליונה כדי לעבור לכתב היד הבא או הקודם במאגר (לפי סדר הקבצים).
  • תמונות: בצד ימין (או שמאל, תלוי בשפה) מוצג צפיין תמונות. ניתן לסובב, להגדיל, ולבחור מקור תמונה (הספרייה הלאומית או ספריית קמברידג'/אוקספורד במקרים נתמכים). השתמשו ב-🖼️ כדי להציג/להסתיר את פאנל התמונות.
  • הכל: כפתור המציג את כל עמודי כתב היד ברצף אחד ארוך לגלילה נוחה ולשמירה כקובץ טקסט.
  • חיפוש בטקסט: הקלידו בשדה החיפוש כדי להדגיש טקסט תואם בזמן אמת בתוך כתב היד הנוכחי.
  • מקבילות: שולח את טקסט העמוד הנוכחי ללשונית חיפוש חיבורים לאיתור מקבילות בכל הקורפוס.
  • עיין בכתיב: פותח את כתב היד בקטלוג המקוון של הספרייה הלאומית.
  • מידע PGP: אם קיים מידע מפרויקט הגניזה של פרינסטון, יוצג פאנל מידע עם תעתוקים, תיאור, תגיות ותיארוך.

עיון לפי זיהוי

עיון בקטלוג המדעי לפי סיווג תחום, מחבר או כותרת יצירה.

  • היררכיית תחומים: הפאנל הימני מציג את עץ התחומים (למשל: מקרא > תורה > בראשית). לחצו על תחום כדי לראות את כל כתבי היד המסווגים תחתיו. המספרים מראים כמה כתבי יד שייכים לכל קטגוריה.
  • סינון לפי מחבר ויצירה: השתמשו בתפריטי החיפוש לסינון לפי שם מחבר או כותרת יצירה. המסננים משתלבים — בחירת תחום ומחבר מציגה רק כתבי יד התואמים לשניהם.
  • תאריך: הזינו משנה / עד שנה או לחצו על אחד מכפתורי המאות; סמנו כלול לא מתוארכים כדי להשאיר גם פריטים ללא תיארוך.
  • סינון טקסט: הקלידו מילות מפתח לחיפוש בכותרות, תיאורים ושמות תחומים. בחרו כל (כל המונחים חייבים להתאים), אחד מ- (כל מונח מתאים), או ללא (הוצאת תוצאות תואמות). הוסיפו מספר מונחים כצ׳יפים צבעוניים.
  • תעתיקים וספרייה: סנן PGP וסנן לפי תעתיק מדעי עוברים בין הכול, יש ואין; סינון לפי ספרייה מציג או מסתיר ספריות.
  • צ׳יפים של מסננים: מסננים פעילים מופיעים כצ׳יפים ניתנים להסרה מעל התוצאות.
  • חפש בתוצאות אלה / חפש מקבילות בתוצאות אלה מריצים חיפוש המוגבל לרשימה הנוכחית; ניקוי הכל מנקה את המסננים.
  • דפדוף: התוצאות מוצגות 50 בעמוד עם פקדי ניווט.
  • קישורים צולבים: תוויות תחום ומחבר בלשונית עיון לפי מספר מדף מקשרות ישירות לכאן עם המסנן המתאים.

מידע מפרויקט הגניזה של פרינסטון (PGP)

המערכת משלבת נתונים מפרויקט הגניזה של פרינסטון (Princeton Geniza Project) — מאגר מחקרי הכולל כ-36,000 מסמכים מקוטלגים עם תעתוקים, תרגומים, תיאורים ותיוג נושאי מפורט.

תג PGP בתוצאות חיפוש

כתבי יד שקיים עליהם מידע מפרויקט הגניזה של פרינסטון מסומנים בתג ירוק "PGP" בתוצאות החיפוש, כך שתוכלו לזהות במהירות כתבי יד עם תעתוקים ומידע מחקרי נוסף.

מידע PGP בלשונית עיון לפי מספר מדף

כאשר לכתב יד קיים מידע מפרויקט הגניזה של פרינסטון, מוצג פאנל מידע הכולל:

  • סוג מסמך (למשל: מכתב)
  • תגיות — לחיצה על תגית מעבירה לחיפוש כל כתבי היד באותו נושא
  • תיאור מחקרי באנגלית (עם אפשרות תרגום)
  • תאריך
  • צפה ב-PGP — קישור למסמך המקורי באתר פרינסטון

תעתוקים ותרגומים

כשקיימים תעתוקים או תרגומים של חוקרים מפרויקט הגניזה של פרינסטון, הם זמינים בבורר הגרסאות לצד התעתוק האוטומטי. המערכת מעדיפה אוטומטית תעתוק PGP (אם קיים) על פני הקריאה האוטומטית.

חיפוש לפי תגיות

בחרו מצב תגיות PGP מתפריט מצבי החיפוש כדי לעיין בכתבי יד לפי נושא. התגיות מאורגנות בקטגוריות (סוגי מסמכים, הלכה וחברה, רפואה ומחלה, מסחר ונסיעות ועוד) ומוצגות בתפריט נפתח עם תרגום לעברית.

שולחן עיון (Reading Desk)

תצוגה מקבילה המאפשרת עיון במספר כתבי יד זה לצד זה, עם תמונות מסונכרנות ובורר גרסאות לכל קטע בנפרד.

שולחן העיון שימושי לכל חוקר המעוניין לצפות בכמה מספרי מדף יחד — בין אם מדובר בקטעים המצטרפים למסמך אחד (על פי PGP או צירופים אחרים) ובין אם בכל אוסף כתבי יד שברצונכם לעיין בהם ברצף.

כיצד להשתמש

  • לחצו על כפתור הוסף לתצוגה (סמל העין) בלשונית עיון לפי מספר מדף
  • הוסיפו כתבי יד נוספים מתוצאות חיפוש או מעיון בכתבי יד אחרים
  • בסרגל שולחן העיון הקלידו מספר מדף ולחצו הוסף לשולחן, או לחצו הוסף מרשימה כדי לפתוח את הרשימות האישיות, ולחצו על פריט כדי להוסיף אותו.
  • מתפריט הצירופים של כפתור 🔗 בלשונית עיון לפי מספר מדף, פתח בשולחן העיון טוען בבת אחת את כל הקטעים המצורפים.
  • כל קטע מוצג עם תמונת המקור, בורר גרסאות (כולל תעתוקי PGP אם קיימים), ומידע מורחב
  • לסיום לחצו צא משולחן העיון

פאזל קטעים

קנבס חזותי לסידור תמונות קטעי כתבי יד זה לצד זה, לשחזור צירופים פיזיים בין קטעי גניזה.

הוספת קטעים

  • הקלידו מספר מדף בתיבת הקלט ולחצו Enter או על כפתור ההוספה
  • מרשימה אישית: לחצו על כפתור הוסף מרשימה אישית (📋), בחרו רשימה בחלון שנפתח, ואז בחרו את הקטעים להוספה
  • מצירופים ידועים: כשקיימים צירופי PGP או פרידברג לקטע מסוים, לחצו על כפתור הצירופים כדי לטעון את כל הקטעים הקשורים בבת אחת

פקדי הקנבס

  • זום: גלילה להגדלה/הקטנה; לחיצה כפולה לאיפוס התצוגה
  • סיבוב: בחרו קטע והשתמשו בפקדי הסיבוב (או בחצי המקלדת) לכוונון עדין של הזווית
  • הסרת רקע: כוונו את מחוון הסף להסרת רקע הקלף/נייר מתמונות הקטעים, לבידוד הטקסט
  • מצבי רקע: מעבר בין רקעי קנבס (אפור כהה, שחור, לבן, משבצות, שולחן אור, רשת) למציאת הניגודיות האופטימלית
  • חיתוך: חיתוך שוליים ריקים מתמונת קטע
  • היפוך: שיקוף קטע אופקית או אנכית
  • ניווט בדפים: השתמשו בפקדי עמוד קודם/הבא למעבר בין רקטו וורסו, או לניווט לדפים אחרים של אותו כתב יד

שכבות

  • הבא קדימה / העבר אחורה: כשקטעים חופפים, השתמשו בפקדים אלה לשינוי סדר השכבות כדי למקם קטעים מעל או מתחת לאחרים

בורר קטעים

השתמשו בתיבת הבחירה מעל הקנבס לבחירת קטע טעון. כפתור עיין פותח את הקטע בלשונית עיון לפי מספר מדף.

שמירה וטעינה

  • לחצו על כפתור שמירה לשמירת הסידור הנוכחי כמסמך צירוף עם כותרת והערות
  • לאחר השמירה הראשונה, שינויים נשמרים אוטומטית בכל הזזה, סיבוב או שינוי גודל
  • לחצו על כפתור פתיחה לעיון בצירופים שמורים; כל רשומה מציגה תמונה ממוזערת
  • בחרו צירוף שמור כדי לטעון אותו חזרה לקנבס

ייצוא

  • לחצו על כפתור ייצוא ליצירת תמונת PNG מורכבת של כל הקטעים כפי שסודרו על הקנבס
  • בחרו מבין מספר רמות רזולוציה: טיוטה, רגילה או רזולוציה מלאה
  • התמונה המיוצאת כוללת באנר מטא-נתונים עם רשימת מספרי המדף של כל הקטעים

רקטו / ורסו

כפתור ⇄ (הפוך את כל הקטעים) משקף את כל סידור הקנבס ומנווט כל קטע לצד ורסו (או רקטו), כדי שתוכלו לבחון את הצד ההפוך של צירוף משוחזר.

מעבדת צירופים

מעבדת הצירופים היא סביבת עבודה ייעודית לאיתור צירופים פיזיים — קטעים שהיו בעבר חלק מאותו דף או כרך, וכיום מפוזרים בין אוספים שונים. אתם מקבעים קטע אחד כעוגן, ואז מחפשים קטעים מועמדים וממיינים אותם מולו, זה לצד זה.

כיצד לפתוח את מעבדת הצירופים

  • כפתור מעבדת צירופים בפינת סרגל הכלים העליון.
  • כפתור מצא צירופים בלשונית עיון לפי מספר מדף.
  • מכל תוצאת חיפוש או עמוד עיון — פעולה הפותחת את המעבדה כשהיא מעוגנת על אותו עמוד.

החלון אינו מודאלי: הוא נשאר פתוח לצד החלון הראשי, ותוכלו לעגן אותו מחדש על קטע חדש בכל עת בלי לסגור אותו.

העוגן (פאנל ימני)

הקטע המקובע — סימן המדף שלו, מטא-דאטה תמציתית, ותמונת העמוד. השתמשו בחצי הדפדוף כדי לעבור בין תמונות העוגן, והגדילו כדי לבחון את הכתב. צירופים ידועים לעוגן (ששמרתם אתם או הקהילה) מופיעים בקטע ניתן-לקיפול.

בניית שאילתה (פאנל שמאלי)

בנו שאילתה שורה-אחר-שורה המתארת את הטקסט שאתם מצפים למצוא בקטע המצורף:

  • מצב — פרויקט השו"ת (בונה השורות המובנה המתואר כאן) או מדויק / וריאנטים / מקורב / ביטוי רגולרי (שאילתת טקסט חופשי אחת, כמו בחיפוש הראשי).
  • + הוסף שורה — הוסיפו שורת כתב יד נוספת, וקבעו כמה שורות לדלג לפניה (0 = השורה הבאה מיד).
  • + או — הוסיפו מילה חלופית שעשויה להופיע במקומה באותה שורה.
  • אפשרויות שורה (⚙) — שינויים לכל שורה: שלילה (−), כתיב מלא/חסר (%), תחיליות (#_), סופיות (_#), תווים כלליים (*), ועוגני מיקום "⊢ מתחיל שורה" / "⊣ מסיים שורה".
  • אפשרויות חיפוש — מתגים גלובליים: וריאנטים, ערבית-יהודית, ריווח גמיש ודו-כיווני.
  • מיקום — הגבילו שורה לתחילת טקסט העמוד או לסופו.
  • הצד השני של הדף (p ±1) — דרשו או כללו גם טקסט בעמוד שמנגד; צמצום משאיר רק מועמדים שגם העמוד הסמוך שלהם תואם, הרחבה מוסיפה עמודים סמוכים כמועמדים נוספים.
  • דמיון חזותי — הציגו רק קטעים הדומים חזותית, אפשר בשילוב עם שאילתת טקסט.

⚠ על אודות הדמיון החזותי: מאגר הדמיון החזותי מכסה כיום רק כמחצית מן הגניזה, והאלגוריתם אינו חד-משמעי — ולכן הוא עלול להחמיץ התאמות אמיתיות. אין להסיק שקטע שאינו מופיע בתוצאות הדמיון החזותי אינו צירוף. השתמשו בדמיון החזותי כדי להעלות מועמדים, ולעולם לא כדי לפסול קטע.

לחצו מצא מועמדים כדי להריץ את השאילתה.

מיון מועמדים

המועמדים מופיעים ככרטיסים עם תמונה ומטא-דאטה. עבור כל אחד תוכלו:

  • לסמן כן / אולי / לא למיון, ואחר כך לסנן את הרשימה לפי מצב המיון.
  • עיין — פתחו את המועמד בתצוגת העיון.
  • השווה — הציגו אותו זה לצד זה עם העוגן.
  • עגן מחדש — הפכו את המועמד לעוגן החדש והמשיכו לחפש ממנו.
  • הוסף כצירוף — תעדו צירוף מאושר בין המועמד לעוגן.
  • הוסף לפאזל — שלחו את המועמד, יחד עם העוגן, אל פאזל הקטעים להרכבה חזותית.
  • הוסף לרשימה — שמרו אותו לאחת הרשימות שלכם.

עיין בתוצאות (כפתור ◀ עיין בתוצאות בסרגל התוצאות) פותח חלון השוואה העובר על המועמדים המסוננים אחד-אחד, כל אחד מוצג זה לצד זה עם העוגן — הדרך המהירה ביותר לסקור רשימת מועמדים ארוכה. אם נבחר מועמד יחיד, החלון נפתח עליו; אחרת הוא מתחיל מן התוצאה הראשונה. זאת בנוסף לפעולת השווה שבכל כרטיס, הפותחת מועמד יחיד מול העוגן.

הערת ⚠ אי-התאמת גודל מסמנת מועמדים שמידותיהם הפיזיות שונות מאלו של העוגן, כדי שתוכלו לזהות במהירות צירופים בלתי-סבירים. השתמשו בסרגל הסינון לצמצום המועמדים לפי סימן מדף, טקסט, כותרת, חומר, מידות או מצב מיון, ועברו לתצוגת טבלה קומפקטית כשיש הרבה תוצאות. ⬇ ייצוא XLSX מייצא את המועמדים המסומנים (או את כל המוצגים, אם לא סומן אף אחד) לחוברת Excel. נקה הכל מאפס את העוגן, השאילתה, המועמדים ומצב המיון, ומנקה את מסנני הטקסט, החומר והמיון.

רשימות אישיות

לשונית רשימות אישיות מאפשרת לכם לנהל רשימות משלכם של כתבי יד ומסמכים מהספרייה המקומית, לקבץ אותן בפרויקטים, להוסיף הערות ותגיות, ולסנכרן אותן עם החשבון שלכם באתר genizahsearch.com.

רשימות ופרויקטים

  • לחצו על הוסף רשימה... (או על כפתור + מעל עץ הרשימות) כדי ליצור רשימה חדשה, ועל הוסף פרויקט... כדי ליצור תיקייה שמקבצת כמה רשימות יחד.
  • השתמשו בכפתורים ✏️ ערוך רשימה ו-🗑️ מחק רשימה מעל טבלת הפריטים כדי לשנות את שם הרשימה המוצגת או למחוק אותה (הם אינם פועלים על רשימת ברירת המחדל ועל נצפו לאחרונה); רשימה שנמחקה עוברת לסל אשפה, שממנו תוכלו לשחזר אותה או למחוק אותה לצמיתות.
  • שכפל רשימה יוצר עותק של הרשימה הנוכחית; מזג רשימות ממזג אותה לתוך רשימה אחרת שתבחרו.
  • תקן כפילויות מאתר רשימות שיש להן אותו שם (למשל עותקים שנוצרו עקב בעיית סנכרון) וממזג כל קבוצה כזו לרשימה אחת, ושואל איזו מהן לשמור כשהן שייכות לפרויקטים שונים.
  • תמיד קיימות רשימת ברירת מחדל, ששמה בהתחלה כללי, ורשימת נצפו לאחרונה. את רשימת ברירת המחדל אי אפשר למחוק; כדי לשנות את שמה, לחצו עליה לחיצה ימנית בעץ הרשימות ובחרו שנה שם רשימה. רשימת נצפו לאחרונה מתמלאת אוטומטית ככל שאתם צופים בכתבי יד; אי אפשר לשנות את שמה או למחוק אותה, והיא אינה מסתנכרנת לענן.

הוספה וניהול של פריטים

פריטים מתווספים באמצעות כפתור ☆ רשימה (הוסף לרשימה) בחיפוש, בחיפוש חיבורים ובלשונית עיון לפי מספר מדף — או בסמל ☆ שבכל שורה בתוצאות החיפוש — וכן ממועמדים במעבדת הצירופים.

  • השתמשו בתיבת סנן פריטים... ובתפריט מיון לפי (מספר מדף, כותרת או תאריך הוספה) כדי למצוא פריטים ברשימה ארוכה.
  • סמנו פריטים באמצעות בחר הכל או אחד-אחד, ואז השתמשו בהעבר לרשימה..., הוסף תגית... או הסר נבחרים על כל מה שסומן.
  • לכל שורה יש גם כפתורים משלה: 👁️ מבט מהיר פותח תצוגה מהירה של העמוד (בכתבי יד מהגניזה בלבד; אי אפשר לפתוח כך מסמך מקומי מהספרייה שלי), 📖 עיין פותח את כתב היד בלשונית עיון לפי מספר מדף, 📋 העתק מידע מעתיק את פרטיו (צמצם, מפורט או עם קישור) ללוח ההעתקה, 🧩 הוסף לפאזל שולח אותו ללוח הפאזל, ו-🗑️ הסר מרשימה מסיר אותו מהרשימה הנוכחית בלבד.

פרטי הפריט ותצוגה מקדימה

בחירת פריט מציגה את פרטי הפריט: ספרייה, מספר מדף, תמונה, כותרת, רשימות, מספר מערכת ותגיות, לצד תצוגה מקדימה של הטקסט והתמונה של העמוד. התצוגה המקדימה מיועדת לכתבי יד מהגניזה: מסמך מקומי מהספרייה שלי אינו מוצג בה. הקלידו בשדה הערה ולחצו על שמור שינויים כדי לשמור אותה; את חלונית התצוגה המקדימה אפשר לכווץ בכפתור ◀/▶ שבראשה.

ייצוא וייבוא

  • ייצוא רשימה... שומר את הרשימה המוצגת כטקסט (רגיל), JSON, אקסל (.xlsx) או וורד (.docx).
  • ייבוא רשימה... טוען רשימה בחזרה מקובץ JSON, ומדווח כמה פריטים נוספו וכמה מהם לא זוהו.

סנכרון עם החשבון שלכם

כפתור סנכרן רשימות עכשיו פעיל רק כשאתם מחוברים לחשבון שלכם באתר genizahsearch.com; לאחר ההתחברות, כל שינוי שתעשו מועלה אוטומטית.

  • לחיצה על סנכרן רשימות עכשיו מציעה הורד מהענן, העלה לענן, מזג את שתיהן (שילוב של מה שיש במחשב הזה עם מה שיש בחשבון שלכם) או דלג; כל אחת משלוש האפשרויות הראשונות מוצגת רק כשיש רשימות שהיא יכולה לפעול עליהן.
  • כשאותה הערה נערכה בשני הצדדים, מזג את שתיהן שומר את שתי הגרסאות, כשביניהן שורה מפרידה; העלאה בלבד משאירה הערה שונה בחשבון שלכם כפי שהיא.
  • אם פריט הוסר מאחת הרשימות שלכם באתר, תתבקשו לבחור עבור כל פריט כזה: להסיר גם מהמחשב הזה, להשאיר (ולהוסיף שוב לאתר) או להחליט אחר כך.
  • פריטים מהספרייה המקומית (ראו הספרייה שלי — מסמכים מקומיים) לעולם אינם מועלים, גם כשהם נמצאים ברשימה ששאר פריטיה מסתנכרנים.

לשונית קהילה

לשונית קהילה מרכזת את מה שחוקרים שיתפו: תגליות ושאלות, תיקוני תעתיק, הערות על עמודים, והצעות לצירופי קטעים — כל אחד בפאנל משלו, עם רשימה מהירה וגם חלון מלא יותר לעיון נרחב.

התחברות

טעינת מה שאחרים שיתפו דורשת חיבור לאינטרנט, אך לא חשבון; בלי חיבור, כל רשימה מהירה מציגה את מה שנטען בה בפעם הקודמת (בהערות — תחילת הטקסט של כל הערה). כדי לתרום, או כדי לראות את הפריטים שלכם, התחברו.

  • לחצו על התחבר, לצד שורת הלשוניות בראש החלון, כדי להתחבר, או על הרשמה שבכותרת לשונית קהילה עצמה כדי ליצור חשבון.
  • לאחר ההתחברות הכותרת מציגה מחובר כ שם המשתמש שלכם ואת ציון המוניטין שלכם; כשאינכם מחוברים היא מציגה לא מחובר - התחבר כדי להשתתף בקהילה.

תגליות

שתפו משהו ששמתם לב אליו בכתב יד, שאלו שאלה, הכריזו על זיהוי, או השאירו הערה כללית — וקראו מה שחוקרים אחרים שיתפו.

  • לחצו על + כדי לשתף: בחרו סוג (תגלית - מצאתי משהו מעניין, שאלה - צריך עזרה, זיהוי - זיהיתי טקסט, או הערה - תצפית כללית), מלאו כותרת ותיאור, צרפו אם תרצו מספר מדף אחד או יותר, וסמנו פרסם באופן אנונימי כדי להסתיר את שמכם.
  • סננו את הרשימה המהירה לפי סוג, או לחצו על צפה בכל התגליות... כדי לפתוח את מרכז התגליות, שמוסיף סטטיסטיקות פעילות ומסנני סוג ותקופה המקיפים גם תיקונים, הערות, צירופים וצירופי פאזל.
  • לחצו פעמיים על פריט, או בחרו הצג פרטים בתפריט הלחיצה הימנית שלו, כדי לקרוא אותו, להצביע עליו בלחיצה על הצבע בעד או הצבע נגד, ולהוסיף תגובה; בשאלה, מי שפרסם אותה (או מנהל) יכול גם ללחוץ על סמן כנענה.
  • לחצו לחיצה ימנית על תגלית שלכם כדי לבחור ערוך או מחק.

תיקונים

תיקון הוא תיקון לתעתיק שחוקר הציע בעת עיון בעמוד.

  • הלשוניות כל התיקונים והתיקונים שלי מציגות אותם, כל אחד עם סימן הסטטוס שלו: 🔵 ממתין, ✅ אושר או ❌ נדחה. לחצו פעמיים על אחד מהם כדי לפתוח את העמוד שהוא מתקן.
  • לחצו על עיין בתיקונים... כדי לפתוח טבלה של כל התיקונים, שאפשר לסנן לפי סטטוס (ממתין, אושר, נדחה) ולחפש בה, ובה הטקסט המקורי והמתוקן זה לצד זה.
  • לחצו לחיצה ימנית על תיקון ובחרו צפיה בפרטי השינוי כדי להצביע עליו ב־👍 (הצבע בעד) או ב־👎 (הצבע נגד).

הערות

הערה היא פתק שחוקר השאיר על עמוד מסוים בכתב יד בעת העיון בו, בכפתור 💬 הערה שבלשונית עיון לפי מספר מדף.

  • הלשוניות כל ההערות וההערות שלי מציגות אותן; לחצו פעמיים על אחת מהן כדי לעבור ישירות לאותו עמוד.
  • לחצו על צפה בכל ההערות שלי... כדי לדפדף בכל ההערות שלכם.

צירופים

פאנל זה מרכז שני סוגים של הצעות לצירופי קטעים: רשומות המצמידות שני קטעים זה לזה, ושחזורי צירוף חזותיים (פאזל).

  • הלשוניות כל הצירופים והצירופים שלי מציגות את רשומות הצירוף; כל אחת מצמידה שני קטעים, ואם מי שיצר אותה בחר סוג קשר, היא מציגה אותו: צירוף פיזי או אותו חיבור.
  • הלשוניות כל הפאזלים והפאזלים שלי מציגות שחזורי צירוף פאזל שפורסמו; ראו פרסום לקהילה לאופן הפרסום, ביטול הפרסום ופתיחת עותק של אחד מהם.
  • לחצו על עיין בצירופים... כדי לפתוח את חלון צירופי קטעים המלא, שבו כל ארבע הרשימות יחד במקום אחד.

פרסום לקהילה

שתפו את שחזורי הצירופים שלכם עם קהילת החוקרים ועיינו בצירופים שפורסמו על ידי חוקרים אחרים.

פרסום צירוף

  • לאחר שמירת צירוף בפאזל, לחצו על כפתור הגלובוס 🌐 (פרסם לקהילה) בסרגל הכלים
  • לאחר הפרסום, הכפתור הופך לירוק ומופיעה הודעה עם קישור השיתוף, שכבר הועתק ללוח, כדי שתוכלו לשלוח אותו לעמיתים
  • הסידור שלכם מועלה כתמונה מורכבת יחד עם מטא-נתונים (כותרת, הערות, רשימת קטעים)

ביטול פרסום

  • לחצו שוב על כפתור הגלובוס 🌐 הירוק כדי להסיר את הצירוף מהקהילה
  • מחיקת מסמך צירוף מקומי מסירה אותו אוטומטית גם מהקהילה אם היה מפורסם

עיון בצירופים שהתפרסמו

  • מרכז התגליות מציג צירופי פאזל שפורסמו לצד שאר פעילות הקהילה; בחרו צירופי פאזל במסנן סוג כדי לראות רק אותם.
  • לעיון בכל הפאזלים שפורסמו, או רק באלה שלכם, השתמשו בלשוניות כל הפאזלים והפאזלים שלי בחלונית צירופים שבלשונית קהילה, או בחלון צירופי קטעים שנפתח בלחיצה על עיין בצירופים....

פתיחת צירוף מפורסם

  • לחצו על פתח בפאזל בכל צירוף מפורסם כדי ליצור עותק מקומי בסביבת העבודה שלכם
  • נוצר עותק עצמאי שתוכלו לערוך מבלי להשפיע על הפרסום המקורי

פאנל צירופי קהילה

בעת עיון בכתב יד, מוצג פאנל עם צירופים שהתפרסמו הכוללים את הקטע הנוכחי. זה מסייע לגלות שחזורים קיימים הרלוונטיים לכתב היד שאתם חוקרים.

מצב מעבדה

כפתור "מצב מעבדה" מפעיל מנוע חיפוש ניסיוני ומתקדם יותר.

  • סריקה עמוקה: סריקה מעמיקה ויסודית יותר. איטית משמעותית, אך מומלצת לחיפוש ביטויים נדירים או כשרוצים לוודא שלא החמצתם כלום.

פרמטרים של מצב מעבדה

כאשר מצב מעבדה פעיל, מופיע פאנל הגדרות. ההגדרות הזמינות משתנות בהתאם ללשונית הפעילה.

פרמטרים ללשונית חיפוש

  • אחוז התאמה מינימלי: אחוז הטקסט המזערי מהשאילתא שחייב להופיע כדי שהתוצאה תיחשב רלוונטית.
  • מקסימום תוצאות לעיבוד: מספר המועמדים הגולמיים המרבי שיישלף מהאינדקס לפני שלב הניקוד המפורט. התוכנה שולפת ראשית מועמדים פוטנציאליים, ואז מחפשת בהם. מספר מועמדים רב יותר ימצא תוצאות טובות יותר, אבל יהיה איטי יותר.
  • מגבלת עומק: מספר המסמכים המרבי לסריקה במצב "סריקה עמוקה".

פרמטרים ללשונית חיפוש חיבורים

  • מקסימום מועמדים למקטע: מספר התוצאות המרבי שיעובדו עבור כל מקטע טקסט.
  • ציון מקטע מינימלי: הניקוד המזערי הנדרש כדי שמקטע ייחשב כ"נמצא".
  • מקסימום תוצאות סופיות: מספר התוצאות שיוצגו בעץ כדי למנוע קיפאון של הממשק (כל התוצאות עדיין נשמרות בייצוא).

ניקוד מתקדם

זמין דרך כפתור "ניקוד מתקדם...":

  • בונוס רצף מילים: ניקוד נוסף על מציאת מילים בסדר הנכון.
  • מקדם קנס כיסוי: קנס על תוצאות שאינן מכילות את כל מילות החיפוש.
  • סינון מילות עצירה: מפחית את הניקוד למילים קצרות או נפוצות מאוד כדי להפחית רעש.
  • בונוס מילה ארוכה: נותן משקל רב יותר למילים ארוכות.
  • ניקוד בסיס להתאמה ייחודית: הניקוד הבסיסי למציאת מילה ייחודית.
  • קנס מרחק: מפחית ניקוד למילים שנמצאו רחוק זו מזו.
  • קנס על מילים חוזרות: מפחית ניקוד למילים המופיעות בטקסט יותר פעמים מאשר בשאילתא.

מערכת Dicta Genizah Search מציעה ממשק HTTP/JSON ציבורי, כדי שחוקרים וכלי בינה מלאכותית יוכלו לעבוד עם הקורפוס באופן תכנותי. ישנן שתי דרכים להשתמש בו: סקיל מוכן למחקר בשיחה חופשית, וממשק ה-API הגולמי למפתחים.

שימוש מתוך קלוד וסוכני בינה מלאכותית אחרים

סקיל Cairo Genizah Research מוכן לשימוש מאפשר לכם להפעיל את מנוע החיפוש מתוך קלוד בשפה טבעית. בקשו ממנו לחפש באופן חכם ביטויים או מקבילות — עדי נוסח אפשריים לביטוי, פיוט, תשובה, מכתב או חיבור — והוא יחזיר רשימה מדורגת ובה הטקסט מתוך עמוד העיון, ייחוס לספרייה וקישורי תמונה, כך שתוכלו לעיין בתוצאות ולהציגן בלי לצאת מן השיחה. תוכלו להפנות גם מנועי בינה מלאכותית מקומיים אחרים לסקיל זה.

הסקיל זמין כאן: github.com/gershuni/GenizahSearch → skills/cairo-genizah-research.

GenizahSearch זמין גם ב-ChatGPT, וכשרת MCP (https://genizahsearch.com/mcp) לכל עוזר שתומך בחיבורי MCP. כל אפשרויות ה-AI מרוכזות בעמוד genizahsearch.com/ai.

למפתחים

אותם נתונים זמינים ישירות דרך ממשק HTTP/JSON ציבורי:

  • POST /api/search — חיפוש טקסטואלי בקורפוס.
  • GET /api/browse — טעינת תעתיק, מטא-נתונים ותמונה של כתב יד.
  • POST /api/parallels — מציאת כתבי יד מהגניזה הכוללים מקטעים תואמים לטקסט מקור ארוך.

המבנה המלא של הממשק מתועד בסכמת OpenAPI בכתובת genizahsearch.com/api/openapi.json.

הספרייה שלי — מסמכים מקומיים

לשונית הספרייה שלי מאפשרת לכם לאנדקס קובצי .docx, .pdf, .txt, .html, .xlsx ו-.csv משלכם לצד קורפוס הגניזה. המסמכים האישיים שלכם מופיעים ישירות בתוצאות החיפוש, חיפוש חיבורים ומקבילות עם תגית LOCAL וכפתור סינון תלת-מצבי.

מה מאונדקס

מסמכי Word, קובצי PDF (PDF עם שכבת טקסט בלבד — קובצי PDF סרוקים ללא OCR מדולגים), קובצי טקסט רגיל, קובצי HTML, מסמכי אקסל וקובצי CSV. האינדקס מדלג על סוגי קבצים אחרים.

אינדקס של תיקיות גדולות

אם תוסיפו תיקייה מרובת קבצים, תקבלו אזהרה שהאינדוקס עלול לקחת זמן ממושך. בכל שלב תוכלו לעצור את האינדוקס ולבחור אם לבטל את האינדוקס לקבצים שכבר נסרקו, להשאיר את התוצאות החלקיות, או להמשיך בפעולת האינדוקס.

הוספה, הסרה ובחירה של תיקיות וקבצים לחיפוש

ניתן להוסיף תיקיות לספרייה המקומית, ניתן להסיר אותן, וניתן גם לבחור באילו מן הקבצים המאונדקסים יתבצע החיפוש, על ידי לחיצה על תיבות הסימון ליד כל תיקייה או קובץ.

בנייה מחדש של האינדקס

לחיצה על "רענן" סורקת מחדש את כל התיקיות הרשומות, לא רק את התיקייה הנבחרת, ומחפשת קבצים חדשים לאינדקס. אם ברצונכם לבנות מחדש את האינדקס לחצו על "אנדקס מחדש הכל". אם נתקלתם בבעיות, תוכלו ללחוץ על "אפס את הספרייה המקומית" והאינדקס יימחק לחלוטין. בכל מצב, הקבצים המקוריים שלכם בטוחים.

פרטיות

פרטים על המסמכים המקומיים שלכם לעולם אינם מועלים לשרתי GenizahSearch. שלושה גבולות אוכפים זאת:

  • נקודת הקצה /api/search מסננת פריטים מקומיים באופן הגנתי.
  • סנכרון הרשימות לענן לעולם אינו מעלה פריטים מקומיים: פריט של מסמך משלכם נשאר במחשב הזה.
  • הגשת תיקונים דוחה מזהי מסמך מקומי עם שגיאה ברורה.

שימו לב: הטקסט המאונדקס נשמר בקובץ local_index.sqlite3 בתיקיית האינדקס המקומי, דחוס באמצעות zstd (דחיסה, לא הצפנה) — הטקסט המאוחסן אינו מוצפן. השתמשו בהצפנת דיסק ברמת מערכת ההפעלה (BitLocker / FileVault) אם נדרשת הצפנה.

בחירה מראש וסינון לאחר החיפוש

החיפוש הרגיל וחיפוש החיבורים כוללים כפתור המאפשר לכם לבחור היכן יתבצע החיפוש: גניזה, מקומי, או הכול. ניתן גם להשתמש בכפתור הסינון התלת-מצבי "סנן מקומי", שיאפשר לכם להציג רק קבצים מקומיים, רק גניזה, או כל התוצאות.

שינוי שם מחשב

שימו לב: אם תשנו את שם המחשב שלכם, מטמון ה-SQLite יתבטל והסריקה הבאה מחלצת מחדש את כל הקבצים.

תכונת הספרייה שלי נוצרה בהשראת אב-טיפוס GenizahLocal של יהודה זייבלד.

ייצוא נתונים

בכל שלב ניתן לייצא את התוצאות לשימוש חיצוני:

  • XLSX (אקסל) — חוברת מחקרית: בתוצאות חיפוש, חוברת דו-לשונית בת 4 גיליונות (תוצאות חיפוש, כתבי יד, ביבליוגרפיה, קרדיט ומידע) עם קישורים לחיצים לתמונה בכל שורה וקישורים לחיצים ל-PGP, לצפייה בספרייה ול-GenizahSearch לכל כתב יד. כאשר הייצוא כולל תוצאות מ"הספרייה שלי", מתווסף עבורן גיליון "מסמכים מקומיים"; ייצוא של תוצאות מ"הספרייה שלי" בלבד כולל רק את הגיליונות "מסמכים מקומיים" ו"קרדיט ומידע". לייצוא של חיפוש חיבורים יש גיליונות משלו: "תצוגת דו"ח", "נתונים גולמיים" ו"מידע על השאילתה", ובנוסף "כתבי יד מוחרגים" ו"מסמכים מקומיים" כשהם רלוונטיים; ייצוא שכולו תוצאות מ"הספרייה שלי" כולל את "מסמכים מקומיים" ו"מידע על השאילתה".
  • CSV: פורמט נתונים גולמי, מתאים לייבוא למסדי נתונים אחרים.
  • TXT: דוח טקסט פשוט וקריא.
  • DOCX (וורד): מסמך מעוצב של מייקרוסופט וורד.

שימו לב: הייצוא מתייחס לתוצאות שנבחרו (באמצעות תיבות הסימון). אם לא נבחר כלום, התוכנה תייצא את כל התוצאות הקיימות בטבלה.
