## [Unreleased] -- A search box in the header, and the homepage box sends words to search (web, branch `claude/header-search-box-fb09b1`)

- **Homepage box:** only a real shelfmark (`ts 20.57`, `add 3356`, the NLI catalogue form, a library-prefixed one) goes to Browse; a corpus system number still opens that manuscript; everything else -- English words, `Psalm 23`, Hebrew typed on the English layout (`dcuk`) -- goes to `/search`, which offers "Did you mean <Hebrew>?" for the last (#469). Before, all Latin text went to Browse as a shelfmark and ended on "No manuscript found" (PostHog review 2026-11-03). `web/home_query.py::home_query_target` now routes by the /search box's own recogniser (`web/search_box_input.py::search_box_input_kind`); bare numbers that are not a corpus system number are searched, not looked up. Latin text with a digit that the rules call text is first looked up in the catalogue (`MetadataManager.has_shelfmark`, a binary search of the Shelfmark search index built at server start), so `Mingana 9` and `P. Mich. Inv. 531` still open Browse. The recogniser (shared with /search) also takes a Roman numeral with a letter (`Moss. IIIa,20`), `=` and `_`, and accented catalogue names (Codex on #476): of 715,473 digit-bearing libraries.csv shelfmark strings, 1,849 are now neither recognised nor found (9,550 with the Roman-numeral fix alone), nearly all alternate catalogue names.
- **Header box:** the old "Quick search..." box (text only, unencoded URL, hidden under 768px) is replaced by a go-to box with the homepage's routing and placeholder, on every page but `/` and `/search`. From 1024px it sits in the header; below, a search button opens it across the bar (Esc or the close button folds it). On a phone the header groups keep to one line beside the button.
- Tests: `tests/test_home_query_routing.py`, `tests/render_smoke/test_header_search_render_smoke.py`, `tests/test_phone_layout_rules.py`.
