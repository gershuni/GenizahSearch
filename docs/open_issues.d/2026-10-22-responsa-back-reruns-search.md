| **Website: Back to a Responsa search runs the whole search again instead of restoring it** | `web/search_bootstrap.py::resolve_search_bootstrap`, `web/pages/search.py` (URL stamp after a search) | ⏳ Fixed, not deployed (2026-10-22, PR #436; close on deploy) | A finished Responsa search stamps `/search?q=..&mode=responsa[&variants=1...]` into the URL. Back-detection required *no* `mode` in the URL (`explicit_mode is None`), so Back from a result was treated as a fresh link: nothing was restored and the search started again. Seen in production 2026-10-22 08:43-08:47 UTC: one 45 s Responsa search (2,456 candidates, 81 results) ran three times for one visitor. Other modes stamp only `?q=` and restore. Fix written 2026-10-22: the URL also carries a random `run=` stamp kept in the saved run (`last_run['url_stamp']`); a Responsa URL is Back when stamp, query and options match, and that Back restores the saved filters too. Pinned in `tests/test_search_bootstrap.py`. Not changed: the q-only Back of the other modes still matches by query alone and does not restore filters. |
