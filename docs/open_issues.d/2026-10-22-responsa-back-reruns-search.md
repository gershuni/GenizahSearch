### P2 - Medium
| **Website: Back to a Responsa search runs the whole search again instead of restoring it** | `web/search_bootstrap.py::resolve_search_bootstrap`, `web/pages/search.py` (URL stamp after a search) | ⏳ Fixed, not deployed (2026-10-22, branch `claude/responsa-back-restore`; close on deploy) | A finished Responsa search stamps `/search?q=..&mode=responsa[&variants=1...]` into the URL. Back-detection requires *no* `mode` in the URL (`explicit_mode is None`), so Back from a result is treated as a fresh link: nothing is restored and the search starts again. Seen in production 2026-10-22 08:43-08:47 UTC: one 45 s Responsa search (2,456 candidates, 81 results) ran three times for one visitor. Other modes stamp only `?q=` and restore. Fix written 2026-10-22: a Responsa URL is Back when its query and options match the saved run (`last_run`, same snapshot as the results); pinned in `tests/test_search_bootstrap.py`. |
