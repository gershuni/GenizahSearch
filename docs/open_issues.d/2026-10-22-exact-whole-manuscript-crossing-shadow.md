### P3 - Low Priority
| **Exact/Variants/Fuzzy over whole manuscripts: a crossing from an earlier page can hide the next page's own** | `shared/search_engine.py::_cross_page_spans` (the break loop, without `page_start`) | ❌ Open (2026-10-22) | At each page break of a whole-manuscript document, `_cross_page_spans` takes the first match that crosses the break. A match that starts on an earlier page and runs over a whole page crosses the next break too, so it is taken there again, the duplicate is dropped, and the next page's own crossing of that break is lost. Example: pages `כהנים` \| `גדולים כהנים` \| `גדולים כהנים גדולים`, Exact `כהנים גדולים כהנים גדולים`, gives p1 only; p2's crossing into p3 is missing. It needs a match that spans a whole page, so a page of one or two words. PR #442 fixed this for Responsa on every route, and PR #443 fixed it for E/V/F read from a seam (`page_start`, Codex round 3 on #443). It stays on the routes that read whole manuscripts: format 1 today, and on format 2 when S > K. The fix is the same rule: at each break, count only a match that starts on the page just before it. That changes today's E/V/F rows, so it needs `scripts/verify_search_combinations.py` on the real index before it ships. |
