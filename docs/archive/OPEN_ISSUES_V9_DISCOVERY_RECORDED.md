- 📋 **Recorded (2026-08-10) — the reported Judeo-Arabic "bidi mangling" is NOT ours, and must not be fixed.** The Latin classmarks (`T- S`, `7 8G S _T`) are byte-identical in three independent layers: the document as stored, the publisher's separately harvested partition tree, and our label. `T- S` is the source's uniform hyphen convention — 679 hyphen+space occurrences in these labels, 521 between Hebrew letters (`ו- ח`), 111 between digits, **zero unspaced hyphens anywhere** — so closing the gap would treat one script's typography as an error. And no inverse exists: of 17 distinct Latin runs, 9 already read canonically and any reordering breaks them. Same ruling for `תרגום הפסוקום`: the source's own typo, in all three layers, against 39 correct siblings. Both are emitted verbatim and pinned by tests.
- 📋 **Recorded (2026-08-10) — every number in this queue is measured on the ONE-alignment bake.** `_tmp/v3_out2/discovery-v3.db`'s `discovery_evidence` has no `ref_spans_json` column (48 columns; `w_start`/`w_end` only), so WP4's every-alignment capability (`f9ffde3d`) is landed but unbaked. When it bakes, ~12.8% of rows gain extra work-side pieces — each with its own first unit for the overlap threshold to judge and its own `;` piece to render. **Nobody has a number for that.** **Session-4 correction: the true multi-alignment rate is 24.0%, not 7.0%** — `n_spans` counts PAGE-side hulls (`n_spans == len(spans_json)` on every checked row) and is a strict lower bound on alignments; 74,876 of 311,481 addressable producer rows carry more than one.
