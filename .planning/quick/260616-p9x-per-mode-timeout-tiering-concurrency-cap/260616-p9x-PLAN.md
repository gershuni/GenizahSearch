<objective>
Re-tier the public Search API so heavy search classes (variants / fuzzy / composition-parallels)
get their own timeout lane and concurrency budget instead of being forced under the 30s interactive
SLA, and stop fuzzy from silently dropping true hits to a 100-result rank cap.

Purpose: `fuzzy` mode (variants_maximum + Tantivy edit-distance) was committed (`30d1bc5a`) but is
unusable in prod — a 3-word name query measured ~195s and can never finish under
`SEARCH_API_CORE_TIMEOUT=30s`. `/api/parallels` is inherently multi-minute. The 30s cap is the right
SLA for interactive (exact/title/shelfmark) queries but the wrong one for heavy queries, which run in
a thread-pool worker (one slow query blocks ONE worker, not the event loop). Separately, fuzzy's
recall is being capped to 100 results — and the downstream consumer is an AI agent that filters noise,
so recall must not be sacrificed for precision.

Output: per-mode timeout ladder, a heavy-mode concurrency semaphore with fast-fail, a raised fuzzy
result cap, plus contract docs (SEARCH_API.md / skill contract / skill client timeout / CLAUDE.md /
CHANGELOG).
</objective>
