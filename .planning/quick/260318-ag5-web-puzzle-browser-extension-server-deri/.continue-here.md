<decisions_made>

- Chose browser extension over localhost helper / derivative cache / WASM approaches — extension is cleanest, uses user's own IP
- Server disk cache (not Supabase) for processed derivatives — 150GB available on server, Supabase free tier too small
- HMAC upload tokens for cache write security — server issues token on miss, upload requires valid token
- Single `_loadImageWithFallbacks()` as hard architectural rule — prevents regression across 4 image paths
- `WEB_PUZZLE_ENABLED` stays as feature flag permanently — emergency rollback capability
- Banner uses `document.createElement` not innerHTML — avoids Python/JS triple-quote escaping nightmare in NiceGUI
- Extension uses `Uint8Array` directly in message passing (MV3 structured clone), not `Array.from()` — performance
- Extension validates URL host (`iiif.nli.org.il` only) and message origin — security for store review
</decisions_made>

<context>
The web puzzle was previously hidden behind WEB_PUZZLE_ENABLED=false because NLI blocks datacenter IPs from fetching IIIF images. The extension solves this by fetching via the user's browser. Production is live and working — tested with CUL manuscripts, bg removal confirmed, save/load/flip all functional. The server derivative cache means once any user (extension or future desktop) processes an image, it's available to ALL users instantly. Over time the cache fills organically.

Key gotcha discovered during testing: NiceGUI's `ui.html()` renders in shadow DOM, so `document.getElementById()` from main JS can't reach elements inside it. All dynamic DOM manipulation for the banner had to use `document.createElement` via JS, not HTML strings.

The nginx fix (removing stale `/api/` → port 8000 block) was critical — all API endpoints were returning 502 on production because of this leftover from the January FastAPI removal.
</context>
