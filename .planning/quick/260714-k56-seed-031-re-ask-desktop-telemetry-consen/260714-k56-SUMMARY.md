# Phase quick-260714-k56 Plan 01: SEED-031 Re-ask Desktop Telemetry Consent Summary

Throttled, non-modal re-invitation for not-yet-opted-in desktop decliners: a WhatsNewBar-style
`TelemetryConsentBar` shown at most ~3 times, only after a 30-day cooldown and only on a
new-version launch, gated by the pure `should_reask_consent`. No new pressure, no new modal — the
too-strict "one first-run modal ever" lock is loosened without touching any Phase 112–116 anti-nag
hardening.

## What Was Built

### Task 1 — Re-ask data-model + pure gate + first-run decline recording (commit `db66a93f`)
- `desktop/telemetry.py`:
  - Four config-key constants: `TELEMETRY_LAST_ASKED_VERSION_KEY`, `TELEMETRY_LAST_ASKED_TS_KEY`,
    `TELEMETRY_ASK_COUNT_KEY`, `TELEMETRY_NEVER_ASK_KEY`; policy constants
    `REASK_COOLDOWN_DAYS = 30`, `REASK_MAX_ASKS = 3`.
  - `should_reask_consent(current_version, now=None) -> bool` — pure, never raises; evaluates in
    order: opted-in short-circuit → first-run-shown → not-never-ask → under lifetime cap →
    version differs → 30-day cooldown (absent/unparseable ts = satisfied → covers the migration case).
  - `record_consent_ask(current_version, now=None)` — +1 count, stamps version + ISO-8601 ts.
  - `set_never_ask()` — persists the hard opt-out. All three added to `__all__` along with the
    new key/policy constants. No new module globals → `_reset_for_tests` unchanged.
  - `datetime` import extended with `timedelta`.
- `desktop/consent_dialog.py`: `ConsentDialog.done()` decline branch (`if not self._accepted_telemetry`)
  now calls `telemetry.record_consent_ask(APP_VERSION)` (lazy `from version import APP_VERSION`,
  wrapped in try/except). `set_consent` remains the sole consent-state writer; accept branch, key
  write order, `keyPressEvent`, and the no-default buttons are all untouched.

### Task 2 — Non-modal TelemetryConsentBar + startup wiring + bilingual copy (commit `48183d5d`)
- `desktop/update_ui.py`: `TelemetryConsentBar(QFrame)` mirroring WhatsNewBar (40px, StyledPanel,
  `tr()` strings, hidden in `__init__`). Signals `enable_requested`, `learn_more`,
  `never_ask_requested`, `dismissed`; buttons Enable (green) / Learn more (flat link) /
  Don't-ask-again (flat) / ✕; `show_reask()` sets the invite label and shows. GUARD-01 preserved
  (no `import genizah_app`).
- `genizah_translations.py`: bilingual EN/HE keys for the invite line, `Enable`, `Learn more`,
  `Don't ask again` (`Dismiss` already keyed). Verified no HE→EN fallback.
- `genizah_app.py`: import `TelemetryConsentBar`; instantiate beside `whats_new_bar` with the four
  signal connections; call `_maybe_show_telemetry_reask()` in `on_startup_finished` right after the
  What's New block. Handlers: `on_telemetry_reask_enable` → `set_consent(True)` + hide +
  `_run_startup_telemetry_coordinator()`; `on_telemetry_reask_learn_more` → `PrivacyDialog(self,
  bilingual=True).exec()`; `on_telemetry_reask_never` → `set_never_ask()` + hide;
  `on_telemetry_reask_dismissed` → hide. The gate records the surfacing via `record_consent_ask`
  so the counter advances even on an ignored bar. Mutually exclusive with the first-run modal by
  construction (gate returns False when `FIRST_RUN_SHOWN_KEY` is absent).
- `tests/test_telemetry_reask_consent.py`: appended offscreen `TelemetryConsentBar` construct +
  four-signal test and a button-slot emission test.
