<objective>
Create the pure, side-effect-free RTL text-reconstruction helpers that the rewritten
`extract_pdf_pages` (Plan 02) will consume. These are the algorithmic contracts: baseline
line-grouping (D-02), per-line RTL classification, adaptive 1.8×-median letter-spacing
de-collapse with hysteresis (D-04) producing word-unit bbox-unions (D-05 — NO synthetic
spaces), RTL word-unit reorder adapted from Meiri `_normalize_span_dir` (D-F14 core),
reversed-bracket fix (F-C), and punctuation-spacing normalization (F-B — ASCII AND Hebrew
sof-pasuq/maqaf).

These helpers operate on a RICHER glyph record (REVIEWS HIGH-4/HIGH-5):
`{"c", "bbox", "font", "size", "span_id", "original_order"}`. The de-space hysteresis needs
font/span-boundary hints, and the reorder needs ORIGINAL rawdict reading order (+ x-jumps) —
NOT a destructive global x-sort, which would reverse RTL letters and destroy the Meiri segment
signal. Plan 02 annotates `span_id`/`original_order` while flattening spans; this plan defines
and consumes that contract.

**Round-2 M3 (intra-word letter order):** the unit reorder (Task 3) only moves whole WORD UNITS.
If rawdict emits a letter-spaced Hebrew word's glyphs in visual LTR order, building the unit's
text by `original_order` would leave the CONSONANTS reversed inside the word. So the de-space step
(Task 2) — when the line is RTL — orders the glyphs WITHIN each word unit by DESCENDING center-x
(right-to-left) before joining to text, while keeping each nikud combining mark attached to its
base consonant. The whole-unit reorder still operates at unit granularity; this M3 rule fixes the
intra-unit letter order it cannot see.

Purpose: Isolating the algorithm in a new module makes it independently unit-testable on
committed glyph-trace JSON fixtures (Codex LOW-11 — text-only `.expected.txt` cannot pin a
bbox-dependent bug) and keeps the giant `local_indexer.py` rewrite (Plan 02) thin.
Output: `shared/local_indexer_rtl.py` + unit tests + 7 committed glyph-trace fixtures.
</objective>
