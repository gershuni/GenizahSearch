## Deviations from Plan

### Key Design Discovery — Fixture Construction (Rule 2 auto-fix)

**Issue during Task 1:** Per-character `insert_text` for letter-spaced Hebrew produced separate spans for each glyph. The span_id boundary corroboration in `despace_line_to_word_units` caused mid-gap breaks for EVERY intra-word gap (since each char was in its own span), preventing de-spacing. Additionally, the LTR-damage guard's token-count check (rawdict/blocks ratio >= 0.70) fired when the de-space reduced token count from 7 to 4 (57% = below the 70% threshold), causing the guard to fall back to the broken blocks output.

**Fix applied:** Switched to whole-word insertion using reversed NFC strings (e.g., `insert_text("תמחלמ")` at x=390 for "מלחמת"). This:
1. Keeps all letters in ONE span → span_id corroboration does not fire on intra-word gaps
2. Places the first logical letter at the HIGHEST physical x (correct RTL layout) → `_order_unit_text_rtl` recovers correct Unicode order
3. Keeps rawdict/blocks token ratio = 1.0 → D-03 guard does not fall back to blocks
4. Latin anchor text added to the fixture to further stabilize the token ratio

**Note:** The fixture exercises the FULL pipeline output quality (correct Unicode word order, no single-letter tokens, nikud stripping) rather than the raw de-space algorithm in isolation. The de-space algorithm's correctness on letter-spaced glyph patterns is covered by the unit tests in Plan 01 (glyph-trace JSON fixtures).
