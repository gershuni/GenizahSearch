# Milestone v8.4.0: Dual-Mode Library Filter (Show-only / Hide)

**Status:** ✅ SHIPPED 2026-07-01 (both apps)
**Phases:** 130-131
**Total Plans:** 13 (130: 3, 131: 10 [5 base + 2 gap-closure + 3 UAT/review])

## Overview

Evolved the v8.3.0 inclusion-only library allowlist (SEED-026) into a **dual-mode** library
filter — **Show-only** (allowlist) *or* **Hide** (denylist) — persisted so each intent
survives across searches, at full **web + desktop parity** (the UI surfaces). Closes the
v8.3.0 gap where the allowlist (over a result-derived universe) could not represent a sticky
"exclude library X". Inclusion = allowlist; Hide = denylist, consistent with the existing
`domain_exclusions` / printed-filter exclusion semantics.

UI surfaces delivered: web `/search` (lead), the desktop catalog `LibraryFilterDialog`
(Browse-by-Identification), web Browse-by-Identification, and a NEW web `/parallels` library
control. The public-API dual-mode piece (DMF-11 / Phase 132) shipped separately as the
**v8.4.1** web release — see `.planning/milestones/v8.4.1-ROADMAP.md`.

## Phases

### Phase 130: Dual-Mode Filter Core — Web `/search` *(lead)*

**Goal**: The web `/search` library filter can express BOTH "show only these libraries"
(allowlist) and "hide these libraries" (denylist) — chosen via a mode toggle, persisted
(mode + set) across searches and reloads, with the existing allowlist migrated cleanly and
edge states handled predictably. Defines the shared (mode + set) state shape and dialog UX
that Phase 131 mirrors on every other surface.
**Depends on**: Phase 129 (v8.3.0 SEED-026 inclusion-only allowlist)
**Requirements**: DMF-01, DMF-02, DMF-03, DMF-04, DMF-05, DMF-06, DMF-10

- **Three phases, theme-grouped (condensed roadmap):** Phase 130 (lead — shared mode+set shape) → Phase 131 (three parity surfaces) → Phase 132 (public API, shipped as v8.4.1). One-phase-per-requirement explicitly rejected per the project's condensed-roadmap preference.

- **Migration (DMF-05):** existing v8.3.0 `search_library_filter` allowlist loads as **Show-only with the existing set** — no error, no re-entry.
- **Edge-state sentinels (DMF-06):** empty Show-only = "show all" (no collision with all-unchecked); fully-populated Hide handled predictably. Persist shape `{'mode','codes'}` via `safe_storage`.
- **DMF-10 `'LOCAL'` guard is a cross-cutting invariant, not a phase:** sanitize against `'LOCAL'` on every new web filter path (tripped the v8.3.0 release CI — did not regress).
