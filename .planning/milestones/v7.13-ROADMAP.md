## Goal

Surface PGP coverage at the result-set level on `/search` and upgrade downloaded xlsx artifacts into citation-grade dossiers so a downloaded file stands alone as a scholarly source.

Two independent, parallel-shippable phases:

1. **Phase 93** adds a post-search 3-state PGP filter toggle to the `/search` results toolbar (mirrors the existing `printed_filter` pattern). Web `/search` only — parallels and desktop are explicitly out of scope (desktop already exposes the PGP signal as a sortable column).
2. **Phase 94** restructures search-results xlsx exports into a 3-sheet workbook (`Genizah Results` + new `Manuscripts` dossier sub-sheet + new `Bibliography` sub-sheet) on BOTH web AND desktop, and adds 3 additive per-item flags to the (web-only) JSON export. English-only metadata; no transcription text; envelope `schema_version` stays 1.

## Phase Details

### Phase 93: PGP Filter on `/search`

**Goal**: Users can narrow a completed search result list down to results with PGP info (or hide them) using a single toolbar toggle, with the active filter visible as a chip in the results header. "PGP info" matches the UI signal — the green "PGP" badge at `web/pages/search_results.py:397-400` fires whenever a `sys_id` is in `search_state.transcription_sys_ids`, which can be a metadata-only PGP record, not necessarily a transcription source.
**Depends on**: Nothing — independent of Phase 94; ships in parallel
**Requirements**: PGP-FILTER-01, PGP-FILTER-02, PGP-FILTER-03, PGP-FILTER-04, PGP-FILTER-05
**Source CONTEXT**: `.planning/phases/93-filtering-by-pgp/93-CONTEXT.md` (LOCKED 2026-05-15; renamed from `999.2-filtering-by-pgp` by /gsd-review-backlog on 2026-05-19)
**Success Criteria** (what must be TRUE):
  1. After running a search that returns at least one PGP-tagged hit, the user sees a new 3-state filter button in the results toolbar (immediately after the existing `Filter Printed` button) labelled `All` / `Has PGP` / `No PGP`, cycling on click.
  2. When the user picks `Has PGP`, only results whose `sys_id` is in `search_state.transcription_sys_ids` remain visible; when the user picks `No PGP`, those results are hidden; in both cases an active-filter chip (`Only PGP` / `Hiding PGP`) appears in the results header row next to existing exclusion chips, and single-click on the chip reverts to `All`.
  3. The filter button stays hidden until the current result set contains at least one PGP-tagged hit (no clutter on searches with zero PGP coverage), and the filter stacks correctly with the existing printed filter, domain exclusions, manuscript exclusions, and refinement chain — applied AFTER `printed_filter` in the render cascade with no re-query.
  4. The user's choice persists across browser sessions via `persist_value('search_pgp_filter', ...)` routed through the `web/safe_storage.py` chokepoint, and is restored at search-page bootstrap.
  5. Zero raw `app.storage.user.{get,pop,[key]=}` accesses introduced under `web/` (Phase 87 invariant; `tests/test_no_raw_storage_access.py` stays green).
**Plans**: ~1 plan (matches backlog estimate; single-feature post-search filter mirroring the existing printed_filter end-to-end at `web/pages/search.py:1402-1434`)
**UI hint**: yes

### Phase 94: Research-Grade Export Metadata

**Goal**: Users on BOTH web AND desktop can download a search-results xlsx that stands alone as a citation source — main sheet gains per-row flags (`Has PGP`, `Is Printed`, `Domains`, optional `IIIF Manifest`), a new `Manuscripts` sub-sheet provides a one-row-per-`sys_id` scholarly dossier (PGP fields, NLI description, FJMS catalog summary, library viewer + GenizahSearch deep links), and a new `Bibliography` sub-sheet provides one row per FJMS bib entry joinable by `System ID`. On web only, the JSON envelope gains 3 additive per-item flags (`has_pgp`, `is_printed`, `domains`) with `schema_version` unchanged. Web and desktop reuse a new `shared/export_dossier.py` module containing 4 lookup helpers (PGP / NLI / Catalog / Bibliography) so the xlsx structure is identical across both apps.
**Depends on**: Nothing — independent of Phase 93; ships in parallel
**Requirements**: EXPORT-META-01, EXPORT-META-02, EXPORT-META-03, EXPORT-META-04, EXPORT-META-05, EXPORT-META-06, EXPORT-META-07, EXPORT-META-08, EXPORT-META-09
**Source CONTEXT**: `.planning/phases/94-adding-pgp-to-downloaded-data/94-CONTEXT.md` (LOCKED 2026-05-15, **BROADENED 2026-05-17** — prior `94-01-PLAN.SUPERSEDED.md` (originally `999.3-01-PLAN.md`) SUPERSEDED; main sheet now only gets boolean flags, full PGP fields moved to new `Manuscripts` sub-sheet, new `Bibliography` sub-sheet added; renamed from `999.3-adding-pgp-to-downloaded-data` by /gsd-review-backlog on 2026-05-19)
**Success Criteria** (what must be TRUE):
  1. When the user clicks "Export to Excel" from a search result set on EITHER the web app OR the desktop app, the downloaded workbook opens to a `Genizah Results` sheet (existing layout) with three new columns appended after `Full Text`: `Has PGP` ("Yes"/empty), `Is Printed` ("Yes"/empty), and `Domains` (pipe-delimited list); multi-folio hits for the same manuscript repeat these per-row.
  2. On BOTH apps, the workbook contains a second `Manuscripts` sub-sheet with one row per unique `sys_id` (first-occurrence order, deduped) carrying the full PGP dossier (URL, description, type, date with fallback chain, languages, tags), NLI description, FJMS catalog summary (3-5 planner-chosen fields with documented rationale), library viewer URL, and a GenizahSearch deep link (`https://genizahsearch.com/browse?sys_id={sys_id}`).
  3. On BOTH apps, the workbook contains a third `Bibliography` sub-sheet with one row per FJMS bib entry, joinable to `Manuscripts` via `System ID`, grouped by `System ID` then natural FJMS order with no row cap; sheet order is `Genizah Results` → `Manuscripts` → `Bibliography` with the first sheet default-active on open.
  4. When the WEB user downloads the same result set as JSON, each per-item dict gains 3 additive keys: `has_pgp` (bool), `is_printed` (bool), `domains` (list); envelope `schema_version` stays `1`; no `pgp` subobject and no dossier in JSON (research scripts wanting dossier data download the xlsx or call `/api/browse`). Desktop has no JSON export so this criterion does not apply there.
  5. All metadata appears in English on both apps (PGP canonical; NLI/FJMS English variant when available; Hebrew text emitted only as graceful fallback when English absent); no transcription text appears in any export surface; no `translation_service.py` calls in the export path.
  6. On the web app, `printed_ids` flows through `web/export_state.set_search_export(...)` alongside the existing `transcription_sys_ids` so the export pipeline can compute `Is Printed` for every row; zero raw `app.storage.user` accesses introduced under `web/` (Phase 87 invariant preserved). On desktop, the equivalent set is `self._printed_sys_ids` already available directly in the export call site; no state plumbing required.
  7. Web `export_search_results_excel` and desktop `genizah_app.py:export_results('xlsx')` both consume the SAME 4 lookup helpers from a new `shared/export_dossier.py` module (PGP / NLI / Catalog / Bibliography projection helpers). The xlsx workbook structure (column order, sheet order, formatting conventions like pipe-delimited lists and `"Yes"`/empty booleans) is identical across both apps. Desktop CSV / TXT / DOCX exports are NOT modified.
**Plans**: ~4 plans (PRIOR `999.3-01-PLAN.md` IS SUPERSEDED by the 2026-05-17 scope expansion AND the 2026-05-19 desktop-parity expansion; must be re-planned from scratch). Suggested wave shape: (1) Shared dossier module — write `shared/export_dossier.py` with 4 lookup helpers (PGP / NLI / Catalog / Bibliography), unit tests, `_split_pgp_languages` bug fix for comma-separated TEXT projection; (2) Web state plumbing — `printed_ids` through `set_search_export`, 3 additive JSON keys via `_serialize_item`, parallels JSON envelope D-10 untouched; (3) Web xlsx restructure — wire `shared/export_dossier.py` into `web/export_service.py:export_search_results_excel`, emit 3-sheet workbook; (4) Desktop xlsx parity — wire same helpers into `genizah_app.py:export_results('xlsx')` (around lines 13254 / 17986), produce identical 3-sheet workbook from desktop `_pgp_transcription_sys_ids` / `_printed_sys_ids` / `_result_domains` (verify desktop has the third). Human smoke verification on real xlsx (web AND desktop) + JSON (web only) downloads, REQUIREMENTS.md traceability close, milestone close docs.
**UI hint**: yes (export buttons exist on both apps; this phase changes the artifact, not the trigger UI)
