# Requirements: v8.4.0 Dual-Mode Library Filter — ✅ SHIPPED 2026-07-01

> Milestone goal: Library filtering can express BOTH "show only these libraries" and
> "hide these libraries" intents, persisted so each survives across searches, at full
> web + desktop parity — closing the v8.3.0 gap where the inclusion-only allowlist (over a
> result-derived universe) could not represent a sticky "exclude library X".

**Outcome:** 12 requirements (the UI dual-mode set) — 11 Complete, 1 Partial (DMF-13,
behaviorally safe). Shipped both apps 2026-07-01 (web deployed; desktop installer published
to GitHub Release `v8.4.0`). **DMF-11 (public API dual-mode) shipped separately as v8.4.1**
(web) — see `v8.4.1-REQUIREMENTS.md`.

## v8.4.0 Requirements

### Dual-Mode Filter — Web Search (lead)

- [x] **DMF-01**: On web `/search`, the user can choose between two filter modes in the library filter dialog — **"Show only selected"** (allowlist) and **"Hide selected"** (denylist). — Complete (Phase 130)
- [x] **DMF-02**: In **Hide** mode, libraries that surface in a later search but are NOT in the hidden set are shown by default (the "hide RNL" intent persists across searches); in **Show-only** mode, only the selected libraries are shown. — Complete (Phase 130)
- [x] **DMF-03**: The chosen mode AND the selected set persist across searches and reloads via the `web/safe_storage.py` chokepoint (Phase 87 invariant). — Complete (Phase 130; `{'mode','codes'}` dict shape)
- [x] **DMF-04**: The `/search` library-filter button (and any chip/label) clearly communicates the active mode and count and a neutral state when no filter is active. — Complete (Phase 130; 3-state button)
- [x] **DMF-05**: Existing v8.3.0 persisted allowlist values (`search_library_filter`) are migrated cleanly into the new (mode + set) model without error (interpretation: Show-only with the existing set). — Complete (Phase 130; migration test)
- [x] **DMF-06**: Sensible edge-state handling — empty selection in Show-only = "show all" (no collision with the all-unchecked sentinel); a fully-populated Hide set handled predictably. — Complete (Phase 130)

### Desktop Parity

- [x] **DMF-07**: The desktop catalog `LibraryFilterDialog` (Browse-by-Identification) offers the same Show-only / Hide modes, persisted, at parity with web — plus dynamic per-library counts + type-to-find + sort. — Complete (Phase 131; base + gap-closure 131-06/07)

### Browse-by-Identification (web catalog)

- [x] **DMF-08**: The web Browse-by-Identification catalog filter offers the same Show-only / Hide modes over the full canonical library list, composing with SEED-023 PGP/Editions filters without regression. — Complete (Phase 131)
- [x] **DMF-12**: The web Browse-by-Identification catalog library filter gains the `/search` dialog affordances — client-side text-search, per-library count on the shortlist, sort by count / A–Z. — Complete (Phase 131; user feedback 2026-06-30)

### Parallels Library Control

- [x] **DMF-09**: The web `/parallels` page gains a library-filter control (same dual-mode model) that scopes results via the existing `restrict_sys_ids` path, persisted for the page — closing the v8.3.0 deferred gap. — Complete (Phase 131)

### Public API

- **DMF-11**: Moved to **v8.4.1** (web) — `POST /api/search` + `/api/parallels` `library_filter_mode` (include/exclude). See `v8.4.1-REQUIREMENTS.md`.

### Invariants (guard, not new capability)

- [x] **DMF-10**: `'LOCAL'` (My Library) never appears as a web library-filter option in ANY mode or surface — `tests/test_web_library_options_no_local.py` + `tests/test_phase_97_invariants.py` stay green. — Complete (Phases 130, 131 cross-cutting)
- [~] **DMF-13**: Libraries with ZERO manuscripts never appear in the library-filter universe on ANY surface — via the shared `library_codes_with_manuscripts()` (`shared/browse_map_utils.py`, fail-open). — **Partial**: fully wired + verified on web `/search` (Phase 130); the shared helper is reused on catalog / `/parallels` / desktop (Phase 131) but full per-surface zero-count-exclusion verification was not independently confirmed on every surface. Behaviorally safe (fail-open surfaces the library rather than hiding a real one). Carried forward.
