# Milestone v8.4.1: Public API Dual-Mode (`/api/search` + `/api/parallels`)

**Status:** ✅ SHIPPED 2026-07-01 (web)
**Phases:** 132
**Total Plans:** 3

## Overview

The web point-release that carries the **public API** half of the dual-mode library filter
(DMF-11) — the API counterpart to the v8.4.0 UI dual-mode work. Programmatic callers can now
express "hide these libraries" as well as "only these": the public `POST /api/search` and
`POST /api/parallels` accept an optional library-filter `mode` (`include` / `exclude`)
alongside `filters.library`, backward-compatibly. `exclude` resolves to the complement
(sys_ids whose `library_code` is NOT in the given set) intersected into `restrict_sys_ids`,
mirroring the UI semantics.

Web-only (the desktop app doesn't consume the public API; desktop stays at 8.4.0). Deployed
on top of the v8.4.0 codebase (`version.py` stayed 8.4.0 — a web point-release increment; no
separate git tag / GitHub Release, per the project's web-only release convention). Briefly
tracked in-flight under a "v8.4.1" STATE milestone while the v8.4.0 desktop installer upload
was blocked; built + reviewed + deployed + live-verified the same day.

**Key Decisions:**

- **`library_filter_mode` default=None (not `'include'`)** — `model_dump(exclude_none=True)` drops it, so an omitted caller's request echo stays byte-for-byte unchanged (Codex plan-review R1 HIGH: `default='include'` would have injected the field into every caller's echo, breaking exact-echo tests). `_intersect_library_filter` normalizes `None → 'include'` internally.
- **`resolve_library_complement_sys_ids` is a separate module-level helper** in `shared/fjms_service.py` (single-pass `not in excl_set`), mirroring the naming convention and independently testable; the mode is read AFTER the `if not libs` short-circuit so `exclude` + empty set is a clean no-op.
- **Invalid mode → 400 automatically** via Pydantic `Literal['include','exclude']` + `extra='forbid'` (fail-closed, consistent with existing filter validation) — no bespoke validator.
- **Complement resolution runs off the event loop** via `run_in_executor`, intersected into the existing `restrict_sys_ids` path on both endpoints.
- **Skill parity:** the `cairo-genizah-research` skill clients (`search.py` / `parallels.py`) gained first-class `--library` / `--library-mode {include,exclude}` flags merged into `filters` (`setdefault`, so explicit `--filters-json` wins); omitting `--library-mode` is byte-for-byte the current include behavior.

**Review gates cleared:** plan-Codex R1 (caught + fixed the `default='include'` backward-compat
HIGH before any code was written), plan-checker PASS, verify 4/4 + live prod smoke,
