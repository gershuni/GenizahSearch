# Milestone v6.0.0: Local Data Architecture

**Status:** SHIPPED 2026-02-22
**Phases:** 35-40 (6 phases)
**Total Plans:** 21 plans (8 core + 8 bug-fix/cleanup + 5 performance)
**Requirements:** 14/14 satisfied (audit passed 2026-02-20)

## Overview

Migrated all PGP reference data from Supabase to a local SQLite sidecar (`pgp.db`, 147MB) and added FJMS catalog descriptions as a scholarly resource, making browsing fully offline-capable and eliminating cloud dependency for read-only data. Additionally stabilized the app (crash fixes, pagination, analytics) and optimized performance (parallel NLI fetch, async domain enrichment, variant cache unification).

## Milestone Summary

**Key Decisions:**
- New pgp.db sidecar (not extending existing sidecars) -- distinct domain boundary
- Tags stored as TEXT JSON, queried with json_each() -- start simple
- Supabase PGP tables kept (legacy desktop users) -- cutover deferred
- Hardcoded Supabase URL/anon key defaults matching codebase pattern
- REVERTED Phase 37 v1; v2 re-planned with enriched FIST.db export
- PAGE_SIZE=50 for pagination (WebSocket comfort zone)
- PostHog maskAllInputs + identified_only for privacy
- Module-level crossref cache shared across users (read-only data)

**Issues Resolved:**
- All desktop Qt lifecycle crashes fixed with sip.isdeleted() guards
- 200-result cap replaced with proper pagination (50 per page)
- ~5s domain filter dialog lag eliminated via cached hierarchy
- Browse page NLI metadata load time halved via parallel fetch
- Variant cache unified (no duplicate computation between Tantivy and Regex phases)

- Phase 37-05 gap closure (free description source attribution + desktop RTL) never executed

- NLI relationship UIs (PartOf, See, BifolioWith) -- service methods exist, UI deferred
