## Overview

Refactored GenizahSearch's web layer off the desktop-inherited single-user mental model so per-user state, auth, and caches cannot leak across concurrent sessions sharing one Python process. The cross-user xlsx export filename leak fixed in v7.11.1 was one instance of a class of bugs surfaced across 4 rounds of Codex review spanning `AppState` singleton mirrors, `UserListsManager` instance caching, process-wide `get_user_client()` cache, and raw `app.storage.user` access at 30+ bootstrap sites. v7.12 replaces that pattern with intentional multitenant primitives.

**Hard constraint (Codex finding):** No mid-flight `auth.set_session()` calls. Codex verified at `gotrue_client.py:713` that `set_session()` is networked (calls `get_user(access_token)` when JWT valid, `_refresh_access_token(refresh_token)` when expired), not local state mutation. All auth code in this milestone respects this finding.

**Scope:** Web-only (desktop is genuinely single-user; unaffected). Two backlog phases (Search results by folio + Line numbering) shipped alongside in the same window and touch both apps; they are included in this archive because they shipped in lockstep with v7.12.
