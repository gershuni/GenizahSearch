## Confirmed design decisions (from UAT, 2026-06-18)

- **Model:** `rows_state` is a list of LINES. Each line:
  `{'words': [ {'term': str, 'mods': dict, 'gap_to_next_word': int}, ... ],
    'line_start': bool, 'line_end': bool, 'gap_to_next_line': int}`.
  Default initial state: one line, one empty word, no mods.
- **Per-word modifiers** (in `word['mods']`): `prefix`, `suffix`, `plene`,
  `wildcard_prefix`, `wildcard_suffix`, `negation`.
- **Line-level** (NOT per word): `line_start` (⊢), `line_end` (⊣), `gap_to_next_line`.
  (User decision: "Per-word, line-anchors per-line".)

## Symbol table (under-box indicators + tooltips, all via tr())

| Modifier | Symbol | Query form | Tooltip (EN) |
|---|---|---|---|
| prefix | `#_` | `#word` | "May carry a prefix" |
| suffix | `_#` | `word#` | "May carry a suffix" |
| plene | `%` | `%word` | "Plene / defective spelling variants" |
| wildcard_prefix | `*_` | `*word` | "Wildcard before" |
| wildcard_suffix | `_*` | `word*` | "Wildcard after" |
| negation | `−` | `-word` | "Must NOT appear" |
| line_start (line-level) | `⊢` | `\|word` | "Line starts here" |
| line_end (line-level) | `⊣` | `word\|` | "Line ends here" |

## Compose mapping (REUSE compose() — do NOT change shared/joins_lab.py)

The engine (`genizah_core.py`) distinguishes:
- `[N]` (no pipe) = WORD-level proximity gap within a line (`extract_per_pair_gaps`).
- `[|N]` (with pipe) = LINE gap between lines.
- `|` prefix/suffix on a token = line-start / line-end anchor.

`compose()` already: splits `BuilderRow.term` on spaces, prepends `|` to the first
token if `line_start`, appends `|` to the last token if `line_end`, and joins rows
with `[|gap_to_next]`. The `[N]` and `[|N]` tokens contain no spaces, so they survive
split/join. THEREFORE: `build_side_query` builds ONE `BuilderRow` per LINE whose
`term` is the line's words hoisted and joined with `[N]` word-gaps:

  per word: `hoisted_i = _apply_modifiers_to_term(word_i.term, word_i.mods)`
  line term: `hoisted_1` + (` [g1] ` if g1>0 else ` `) + `hoisted_2` + ...
  BuilderRow(term=line_term, line_start=line.line_start, line_end=line.line_end,
             gap_to_next=line.gap_to_next_line)

Then `compose(SideQuery(rows=...))` produces the final query string unchanged.
Worked example (single line, two words, gap 2, line not anchored):
  words [{term:'שלום', mods:{prefix:True}, gap:2}, {term:'עליכם', mods:{}}]
  -> BuilderRow(term='#שלום [2] עליכם', line_start=False, line_end=False)
  -> compose single-line short-circuit returns '#שלום [2] עליכם'.
Worked example (two lines, line1 line_start, line gap 1):
  -> rows=[BuilderRow('שלום', line_start=True, gap_to_next=1), BuilderRow('עליכם')]
  -> compose -> '|שלום [|1] עליכם'.

## Handle contract consumed by web/pages/joins_lab.py (MUST preserve)

`create_joins_builder(allow_page_position=bool)` returns a dict with keys:
`container`, `build_side_query`, `get_mode`, `get_text_position`, `get_summary`,
`is_empty`. joins_lab.py uses `['container']` (mount + show/hide), `build_side_query()`
(-> SideQuery), `get_mode()`, `get_text_position()` (anchor side only), `get_summary()`
(collapsed bar). Keep ALL of these. The page-level Text Position 5-way select and the
Exact/Variants/Fuzzy mode selector stay as-is (top of builder) — this plan changes the
ROW AREA (lines/words) only. line-start/line-end here are the per-LINE ⊢/⊣ anchors
(BuilderRow flags), SEPARATE from the page Text Position select.

## Guardrails (hard-won this phase — do NOT regress)

   — it is the Quasar option OBJECT (a dict). Use `.value` via `on_value_change` (+
   coerce). (Caused the Text Position + Combine-mode crashes.)

   WR-05). Update value-state on change; only re-render on STRUCTURAL changes (add/

6. Run the real render/construct test — headless parser tests do NOT catch NiceGUI
   render-construction bugs (3 such crashes this phase).

   word. line_start/line_end are NO LONGER in `mods` (now line-level) — drop them from
   the per-word modifier set.
