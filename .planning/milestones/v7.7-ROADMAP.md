# v7.7 Volume-Aware Browse — Milestone Archive

**Shipped:** 2026-04-01
**Version:** 7.7.0
**Phases:** 58–61 (4 phases, 8 plans, 13 commits)

## Problem

Browse page showed wrong images for 3,193 multi-IE manuscripts (1.5%). Images always loaded from primary IE's IIIF manifest (`-1` suffix), but text could come from any IE. When a user searched and found text from IE X, clicking browse opened IE X's text but with IE 1's images — a mismatch.

## Solution

Made the entire search→browse→paging pipeline IE-aware:

### Phase 58 — IE Volume Data Infrastructure
- Extended `scripts/build_primary_ie_map.py` to extract ALL 907 fields → `ie_volume_map.json`
- Restructured `dedupe_browse_map()` to group pages by IE instead of deduping across IEs
- browse_map pages now carry `ie_id` field for per-IE addressing

### Phase 59 — Volume-Aware Web Browse
- Volume selector dropdown for multi-IE manuscripts (shows "כרך X (N עמודים)")
- Per-IE paging: prev/next stays within active IE's page range
- Volume-correct IIIF suffix for NLI image loading
- Search→browse propagates IE from search result header
- External source auto-default when NLI is down (Manchester/Cambridge/JTS)

### Phase 60 — Desktop Volume-Aware Browse
- Desktop volume selector combobox matching web design
- Per-IE paging and image loading in desktop Browse tab
- Volume-filtered images_ext slicing for external providers
- Search result → Browse tab propagates correct IE

### Phase 61 — Volume Session, Community & Validation
- Session persistence for active volume (web + desktop)
- URL includes `volume_ie` for shareable browse links
- Corrections and comments include IE context in payload
- Browse enrichment calls `enrich_metadata()` for external image discovery
- Volume-correct offsets for Manchester (canvas offset) and Oxford (folio offset)
