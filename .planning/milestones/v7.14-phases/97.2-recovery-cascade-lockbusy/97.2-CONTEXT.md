### D-01 — Architectural refactor scope: targeted fixes only

- Delete the redundant `tantivy.Index(...)` reopen at `shared/local_indexer.py:1147` (R97.2-A).
- Delete the redundant `tantivy.Index(...)` reopen at `genizah_core.py:6890` (R97.2-A).
- The SearchEngine recovery path (`genizah_core.py:6860-6901`) constructs a temporary `LocalIndexer` to drive `rebuild_main_index_atomic`. That temporary indexer holds a persistent writer (Codex called this "suspect"). Fix: **explicitly close the temporary indexer's writer + index handles before** `self.local_index = ...` opens the live searcher. Add a `LocalIndexer.close()` method (or reuse `_close_internal_writer_index()`) and call it in a `try/finally` around the rebuild.
- **NO** centralized `try_open_or_rebuild(...)` helper in this phase. Both call sites keep their own rebuild logic; duplication is documented as deferred for a future refactor phase.

**Rationale:** smaller scope, faster ship on a recovery hotfix, lower risk. Refactor deferred earns its own phase if it gains priority.

### D-02 — Bug list: all 8 bugs land

Roadmap's 5 (R97.2-A through E) are extended with 3 new requirements derived from Codex's critique:

- **R97.2-F (Bug 6 — schema-marker absence triggers rebuild)** — In BOTH `shared/local_indexer.py:1108` AND `genizah_core.py:6858`, change the mismatch detection from `(actual_marker is not None and actual_marker != expected_marker)` to `(actual_marker != expected_marker)` so that `actual_marker is None` (Phase 95 install without `.schema_version` file) ALSO triggers rebuild. This is the literal root cause of THIS user's cascade and any future Phase 95 → Phase 97 upgrade.

- **R97.2-G (Bug C2 — close `_del_writer` before reopen in `discard_run`)** — At `shared/local_indexer.py:2954-2959`, after the `_del_writer.commit()` succeeds (or after the except handler logs the failure), explicitly null and gc the local: `_del_writer = None; del _del_writer; gc.collect()`. Without this, step 5's reopen at `:3012` hits LockBusy against its own still-live writer. This was the literal LockBusy in the user's trace.

- **R97.2-H (Bug C3 — short-circuit SQLite delete on Tantivy delete failure)** — Same site `discard_run` step 2 currently logs the Tantivy failure and proceeds to SQLite deletion (step 3). Fix: convert the bare `except Exception: logger.exception(...)` to record the failure into a local flag; if Tantivy delete failed, skip SQLite deletion entirely and raise a `LocalIndexerError("discard_run aborted: Tantivy delete failed")` up to the UI. Prevents orphaned-docs state where SQLite rows are gone but Tantivy docs remain searchable.

Existing 5 requirements (R97.2-A through E) stand as written in ROADMAP.md.

### D-04 — Reset My Library: button placement + two-step typed confirm

- **Placement:** A new `_btn_reset = QPushButton(tr("Reset My Library"))` (with HE translation `אפס ספריה שלי`) in the existing main button row. Added at the right end, separated from `_btn_cancel` by a stretch. Styled with a destructive accent (red foreground via QSS) so it's visually distinct.

- **Active-scan guard:** Before opening the confirm dialog, check (a) the indexing worker thread is not running, AND (b) `start_recovery_probe()` returns an empty list (no `scan_runs.status='running'` rows). If either condition fails: disable the button + set tooltip `tr("Stop or resolve the active scan first")` / HE `עצור או פתור את הסריקה הפעילה תחילה`. Re-enable when both clear.

- **Confirmation flow:** Click opens a custom `QDialog` (not a stock QMessageBox — we need a QLineEdit). Layout: bilingual warning header (counts: `X files indexed, ~Y MB on disk`), explanation paragraph, a `QLineEdit` placeholder `Type RESET / הקלד אפס to enable`, and two buttons: Cancel (default), and Reset (destructive, initially `setEnabled(False)`). The Reset button enables ONLY when the QLineEdit `.text().strip().upper()` equals `RESET` OR equals `אפס`. Both literal strings accepted to honor RTL UX. Enter key on the enabled Reset button triggers it.

- **Post-confirm:** Show a non-modal "Resetting…" QProgressDialog while the teardown helper runs (it takes 100s–10s of ms on huge libraries due to rmtree). On success, show a brief status bar message `Library reset complete` / `איפוס ספריה הושלם`. On failure, show a QMessageBox with the raised error + suggest restarting the app.

### D-05 — Reset scope + reinitialize-with-migrations

`LocalIndexer.reset_my_library()` (new) executes in this order, with full transactional rollback semantics — on any step's failure, restore what we can and raise:

1. **Close all live handles** — call `close_searcher_cb` (engine's `close_local_searcher` + `local_lab_searcher`) + `self._close_internal_writer_index()` + close + null `self._conn` (SQLite). Codex requirement #1–3.
2. **Atomic rename-aside** — rename `LOCAL_INDEX_DIR` → `LOCAL_INDEX_DIR.reset-quarantine-<timestamp>` and `LOCAL_LAB_INDEX_DIR` → `LOCAL_LAB_INDEX_DIR.reset-quarantine-<timestamp>`. Rename is atomic on the same volume; minimizes the window of inconsistency.
3. **Recreate empty directories** — `os.makedirs(LOCAL_INDEX_DIR)` + `os.makedirs(LOCAL_LAB_INDEX_DIR)`.
4. **Schedule quarantine cleanup** — INSERT into `pending_dir_cleanup` for the two `.reset-quarantine-*` paths (next normal startup garbage-collects them). Skipped if step 4 fails since the SQLite file was just renamed aside — instead, rely on best-effort `shutil.rmtree(..., ignore_errors=True)` at the end as a fallback.
5. **Reinitialize** — call `LocalIndexer.__init__` again on `self` (or have the caller construct a fresh LocalIndexer and swap it into SearchEngine). The reinit path's `_run_migrations(self._thread_local._conn)` ladder runs against the fresh SQLite, taking it 0 → user_version=2. Codex requirement #5.
6. **Reload searcher** — call `reload_local_indexes()` to populate empty searcher state.

**What is preserved:** `pgp.db`, `fjms_enrichment.db`, `nli_crossref.db`, `libraries.csv`, `Genizah_Index/` main index — none of these are touched by Reset. Reset is LOCAL-only.

### D-06 — Stale-lockfile defensive cleanup: deferred

Codex recommended a Windows-only, LockBusy-triggered stale-lockfile cleanup helper. **Not in 97.2.** Rationale: the Bug A fix (delete redundant `tantivy.Index(...)` reopen) eliminates the actual lock-leak vector in the user's cascade. Adding the helper now would be defense-in-depth against an unknown future leak; better added if/when a new leak is observed.

If a future cascade surfaces, the helper sketch from Codex's critique (try `os.rename` then `os.remove`, abort on WinError 32, NEVER POSIX-unlink-under-lock) is the reference design.

### D-07 — `_ensure_writer()` fail-loud + 5 mandatory RED tests

- New helper `LocalIndexer._ensure_writer(self) -> tantivy.IndexWriter`:
  - If `self._writer is not None`: return it.
  - If `self._writer is None`: attempt `self._writer = self._index.writer(heap_size=15_000_000)`. On success, return it.
  - On schema-marker mismatch detected mid-call (defensive — `_read_schema_marker` doesn't match `_compute_schema_marker`): raise `LocalIndexerError("LOCAL index schema marker mismatch — Reset My Library required")`.
  - On `LockBusy` (after the existing 3-attempt retry already exhausted upstream during `__init__`): raise `LocalIndexerError("Could not acquire writer lock — restart the app or use Reset My Library")`.
  - **NO silent retry past the existing `__init__` retry loop.** `_ensure_writer` is meant for steady-state guard, not initial acquisition.

- New exception type `LocalIndexerError(RuntimeError)` in `shared/local_indexer.py`. Callers (`_delete_file`, `discard_run`, `keep_run`, `_close_internal_writer_index`, `remove_folder`) catch `LocalIndexerError`, log via `logger.exception`, and propagate to the UI via the existing `error_signal` pattern (matches Phase 96 96-09 closeEvent guard). UI catches and shows a QMessageBox with a "Reset My Library" CTA button.

- **5 RED tests, all mandatory gates, all land RED before their fix:**
  1. `tests/test_phase_97_2_schema_marker_absence.py` — Phase 95 fixture: `meta.json` exists but no `.schema_version` file. Assert `LocalIndexer.__init__` detects mismatch + triggers atomic rebuild + writer acquires successfully. (Bug 6 / R97.2-F)
  2. `tests/test_phase_97_2_writer_handle_leak.py` — Call `rebuild_main_index_atomic` on a non-empty index. Then attempt `_index.writer(heap_size=15_000_000)`. Assert no LockBusy. (Bug A / R97.2-A + Bug B / R97.2-B)
  3. `tests/test_phase_97_2_discard_writer_lifecycle.py` — Two cases: (a) Phase 95 schema fixture → assert fallback to per-uid deletion succeeds without `Field 'scan_run_id' is not defined`. (b) Phase 97 schema with simulated commit failure → assert `_del_writer` is closed (`is None`) before step 5 reopen and step 5 acquires successfully. (Bug C / R97.2-C + Bug C2 / R97.2-G)
  4. `tests/test_phase_97_2_sqlite_vs_tantivy_consistency.py` — Monkeypatch `_del_writer.delete_documents` to raise. Call `discard_run`. Assert `LocalIndexerError` raised, SQLite `local_pages` / `local_files` / `processed_files` rows for that scan_run still present, scan_runs status NOT flipped to 'discarded'. (Bug C3 / R97.2-H)
  5. `tests/test_phase_97_2_reset_my_library_full_cycle.py` — Set up a populated LOCAL index + open `local_searcher`. Call `reset_my_library()`. Assert: (a) LOCAL + LAB dirs are empty (or absent before reinit); (b) reinit succeeds; (c) SQLite is at user_version=2; (d) a fresh `start_scan` round-trips a file end-to-end. (R97.2-E)

Each RED test lands as its own commit in the task sequence BEFORE its fix(es). The test must fail before the fix lands and pass after. The plan-checker should reject 97.2-01 if any test does not appear before its corresponding fix in the task sequence.

## Specific Ideas

- **Trigger event:** 2026-05-26 cascade. User stopped a scan of a 100K-file Dropbox folder mid-run, restarted the app, clicked "Remove folder". Console emitted the full trace captured in `97.2-CODEX-BRIEF.md`. The trace's first warning (`Schema error: 'An index exists but the schema does not match.'`) is THIS user's specific symptom of Bug 6 (missing `.schema_version` marker on the Phase 95 install).
- **Codex critique reordered the bug count** from 5 to 8. The user adopted the expanded list (D-02). Bug 6 specifically is the root cause for the user's actual cascade — not the lock-busy storm that was the visible symptom.
- **Two-step typed confirm specifically chosen** over a single OK/Cancel dialog because Reset is irreversibly destructive (text cache + Tantivy index + SQLite all gone — only the user's source files remain). The friction of typing `RESET` or `אפס` matches the gravity. Pattern borrowed from GitHub repo-delete UX.
- **Quarantine-then-rmtree** chosen over direct rmtree to minimize the inconsistency window between "old data gone" and "fresh empty dir ready". On a 50K-file LOCAL index the rmtree can take 5–30 seconds; the atomic rename is sub-millisecond.
- **`_ensure_writer` is fail-loud by design** (Codex's emphasis). The existing pattern of "log + continue + reopen on next call" silently masked the Phase 97 cascade for the first iteration — we hit the second round of warnings in the trace because nothing surfaced the first failure. D-07 makes the first failure loud + actionable (Reset CTA).
- **The 5 RED tests are intentionally exhaustive** — Codex specifically recommended each one. The plan-checker will reject 97.2-01 if any test does not appear before its fix in the task sequence.
