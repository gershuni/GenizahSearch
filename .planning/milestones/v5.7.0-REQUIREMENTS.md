# Requirements: GenizahSearch v5.7.0

**Defined:** 2026-02-09
**Core Value:** Users can search the Genizah corpus using Responsa Project-style syntax and a tabular query builder, in both web and desktop apps

## v5.7.0 Requirements

Requirements for Responsa Search milestone. Each maps to roadmap phases.

### Core Engine

- [x] **CORE-01**: `parse_responsa_query()` parses Responsa syntax (`*` wildcards, `#` prefixes, `(/)` OR, inline alternatives) into structured `ResponsaComponent` list
- [x] **CORE-02**: `expand_grammatical_prefixes(word)` expands Hebrew grammatical prefixes (single + compound: ו,ה,ב,כ,ל,מ,ש,וה,וב,...) producing ~25 forms per word
- [x] **CORE-03**: `expand_judeo_arabic(word)` expands definite article (אל-) — simplified to 8 forms (no sun letter assimilation per user directive)
- [x] **CORE-04**: `build_tantivy_query()` supports Responsa components as Tantivy OR groups with boosting (exact terms boosted ^5)
- [x] **CORE-05**: `build_regex_pattern()` supports wildcards (`\S*`), alternations, and flexible spacing (`\s*` per char on original terms only)
- [x] **CORE-06**: Bidirectional gap via regex alternation `(forward)|(backward)` when checkbox enabled
- [x] **CORE-07**: Combinatorial explosion guard: MAX_EXPANDED_TERMS=500, 6-step cascade (variants->basic->off->JA off->plene off->suffixes off->prefixes off->error)
- [x] **CORE-08**: When Responsa mode ON, prefix shortcuts (`#`, `?`, `/`, `$`, `~`, `=`) are disabled -- query goes to Responsa parser instead

### Web UI

- [x] **WEB-01**: Responsa as dropdown mode with sub-options (evolved from checkbox row per 15-03 design)
- [x] **WEB-02**: Bidirectional Gap checkbox in Advanced Options section
- [x] **WEB-03**: Responsa mode in dropdown; sub-options show/hide based on mode selection
- [x] **WEB-04**: Tabular query builder as dialog with 2-4 component columns
- [x] **WEB-05**: Tabular generates Responsa syntax text and inserts into search field (one-way sync)
- [x] **WEB-06**: URL persistence: `?mode=responsa&variants=1&ja=1&flex_spaces=1&bidirectional=1` + query text
- [x] **WEB-07**: Responsa sub-options hidden when PGP Tags mode is active

### Desktop UI

- [x] **DESK-01**: Responsa as combo mode option with sub-options (evolved from checkbox row per 15-04 design)
- [x] **DESK-02**: Bidirectional Gap checkbox in sub-options
- [x] **DESK-03**: Responsa mode in combo; sub-options show/hide based on mode selection
- [x] **DESK-04**: "Query Builder" button opens QDialog with 2-4 component columns
- [x] **DESK-05**: QDialog generates Responsa syntax text and inserts into search field (one-way sync)
- [x] **DESK-06**: `SearchThread` extended with optional `responsa_options` parameter (backward-compatible)
- [x] **DESK-07**: Responsa sub-options hidden when PGP Tags mode is active
- [x] **DESK-08**: Checkbox defaults on startup (no persistence between sessions)

### Cross-App

- [x] **XAPP-01**: Both web and desktop apps produce identical search results for the same Responsa query (31 parity tests, all 16 checkbox combos)
- [x] **XAPP-02**: All Responsa logic lives in genizah_core.py (shared) -- no search logic in UI code

## Future Requirements

Deferred to v5.8.0 or later. Tracked but not in current roadmap.

### Option III Features

- **OPT3-01**: Per-component search mode (exact/variants/wildcard per column)
- **OPT3-02**: Scope search (sentence/paragraph/document)
- **OPT3-03**: Per-component negation (NOT clause)
- **OPT3-04**: Bidirectional sync between tabular and text field

### Advanced Spacing

- **SPACE-01**: `\s*` per char applied to variant/JA expansions (currently only originals)
- **SPACE-02**: Dual-track search with content_nospaces Tantivy field
- **SPACE-03**: N-gram character-level index for space-agnostic search

### Persistence & Polish

- **PERSIST-01**: Desktop QSettings persistence for Responsa checkbox states
- **PERSIST-02**: Saved Responsa queries (serialized SearchPlan)
- **PERSIST-03**: Query history with Responsa metadata

### Deferred from v5.6.0

- **SRCH-01**: PGP transcriptions indexed in Tantivy (Phase 13, reverted)
- **SRCH-02**: User corrections indexed in Tantivy
- **SRCH-03**: Search filter toggle (all/transcriptions only/exclude)
- **EXPAND-01**: NLI joins import (~424K PartOf relationships)

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Transcription search in Tantivy | Deferred from v5.6.0, needs server-side index architecture |
| PGP people/places integration | Separate milestone |
| Map-based geographic browse | Separate milestone |
| Two-way tabular<->text sync | Complexity too high for MVP, one-way sufficient |
| `##` double-hash syntax | Checkbox approach preferred (doc 5 recommendation) |
| Query preview line | User explicitly excluded ("no need for expanded query preview every time") |
