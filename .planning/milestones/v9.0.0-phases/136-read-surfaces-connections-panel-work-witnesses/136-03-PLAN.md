<objective>
Compute every piece of evidence the owner needs for a wave-1 decision, put ALL of those decisions in
front of them in ONE sitting, and record the answers — including the owner-supplied ground truth the
novelty funnel will later be graded against.

Purpose: two things force this shape. First, these decisions are open BY DESIGN and three of them
become named constants inside the rebuilt asset and both surfaces, so guessing would propagate an
unratified number everywhere. Second, this project's waves are hard barriers — a checkpoint anywhere in
wave 1 blocks all of wave 2 — so two separate wave-1 checkpoints would cost two owner round-trips for
one wave of latency. Consolidating them costs one.
Output: an evidence script, two briefs, one ratified decision record, and an owner-labelled evaluation
set.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live asset → owner-facing brief | Real work titles and ids cross into documents that will be read and quoted |

| owner label → measurement ground truth | The only non-circular source of truth for the novelty axis's error rate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-136-03-01 | Information disclosure | A restricted-corpus name reaching a brief through a work title or id prefix | mitigate | Masking scan on both briefs and both artifacts as acceptance criteria; M-source codename only |
| T-136-03-02 | Spoofing | A zero-row query presented as a finding ("nothing is affected") | mitigate | Script exits nonzero on an unexpected zero-row result |
| T-136-03-03 | Spoofing | The pipeline grading itself against labels it invented, on cases chosen because it fails on them | mitigate | Drafts are marked `PROPOSAL` and are not labels; the owner supplies verdicts at a blocking checkpoint; `label_provenance` is required per entry and enforced downstream in plan 136-04 |
| T-136-03-04 | Repudiation | A threshold later changed with no trace of what it was decided on | mitigate | The record pins question, number, verbatim answer and date; constants cite the record by filename |
| T-136-03-05 | Tampering | A provisional value hardening into a frozen constant unnoticed | mitigate | `PROVISIONAL` marker plus its revisit condition; the record states whether the 300-case review was authorized |
| T-136-03-06 | Tampering | A label file edited after the owner supplied it | mitigate | Content hash recorded in the decision record and re-checked by plan 136-04 before grading |
