<objective>
Derive the two visibility axes as pure, testable rules and emit the public projection as a closed
graph — then prove the masking scan would actually catch a leak.

Purpose: "origin of the displayed assertion" is not representable in the shipped schema as written.
The schema REQUIRES `discovery_claim.source_corpus` to equal the work's identity source, and
`discovery_evidence` carries only a family code — so `works.source_corpus` IS exactly the proxy the
requirement says is insufficient. Measured: the restricted-corpus id prefix maps to **656
restricted-identity works AND 235 open ones**, so a corpus-keyed rule mislabels in both directions.
VIS-01 stays in this trimmed rebuild deliberately: exclusion must be STRUCTURAL, "never merely hidden
by a UI filter or a query predicate", so any publicly-reachable surface has to read a public asset —
and the axes can only be derived at build time, before the raw provenance ids are discarded.
Output: a derivation module, a projection script, and a leak control.
</objective>

  <action>
    Write `scripts/project_discovery_public.py <private_db> <public_db_out>` on the verifier's CLI
    shape: positional paths, violation accumulation, exit 0/1, no raising for an expected data problem.

    The projection emits a NEW database containing only rows where `shared.discovery_visibility.is_public`
    holds on the stored axes, and then closes the graph:

    - **FK closure** — every referenced work, witness unit, unit member and evidence row referenced by a
      surviving claim exists in the output; every row in the output references only rows that exist.
    - **No unreachable works** — a work with no surviving claim is dropped, not left orphaned.
    - **Auxiliary tables projected too** — `discovery_routing_audit`, `band_precision`, `meta`, the
      identification grain and the manuscript display table each get their own projection rule, stated
      explicitly. A table with no rule is a build error, so a table added later cannot be silently
      shipped whole.
    - **Counts and aggregates recomputed, not copied** — any stored count, total or aggregate in the
      output must be recomputed over the projected rows. A copied total is a leak: it tells a reader how
      many rows were removed.
    - **Identifications recomputed from surviving PUBLIC claims** — `discovery_identification` rows are
      re-derived over the claims that survive the projection, never copied from the private build. A
      copied row carries a bucket, a reason, a page count and a coverage figure computed with private
      claims in the denominator, which is a private contribution surviving inside a shared aggregate
      even though no private row is present. Recompute `display_work_id` too: the representative of a
      canonical group may itself be private, and the public artifact must pick a public representative
      or drop the identification.
    - **Sort behaviour preserved** — the same ordering keys and indexes exist in the output, so the
      public surface's ordering is identical in shape to the private one.

    Emit a reconciliation report next to the artifact: per table, private row count, public row count,
    and the delta; plus `reconcile_launch_scope`'s two counts and their symmetric difference. This
    report is the VIS-02 input a later phase needs and the evidence plan 136-13 puts in front of the
    owner.

    Run the masking gate over the emitted artifact as the projection's own final gate and fail the
    projection if it does not exit 0. **A database needs BOTH scans, not just `--scan-asset`.** The
    scanner's own module docstring says why: a SQLite file must be scanned **cell by cell** —
    `sqlite_master.sql` for schema, DDL and column NAMES, then every row of every table, every column,
    TEXT and BLOB — because a raw byte-blob scan can miss a leak that straddles SQLite's page or
    overflow structure. The required invocation per database is:

        python scripts/check_atlas_masking.py --strict --scan-repo \
            --scan-asset <db> --scan-sqlite <db>

    Never write the output file to a location inside `web/static/`.

    Also write `meta.audience = 'public'` into the projected artifact. That single field is what lets
    the runtime loader refuse to serve a private database to a public route (plan 136-20); the
    projection is the only place that can honestly assert it.
  </action>
