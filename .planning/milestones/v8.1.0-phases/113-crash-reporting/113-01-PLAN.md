<objective>
Add the NEUTRAL, LOCK-FREE priority/direct crash-send transport helper to `shared/posthog_server.py`
(D-06 + D-05) and stand up the Wave 0 test scaffolds that every downstream Phase 113 task verifies against.

Purpose: The crash event must NOT race the FIFO daemon-drain queue (D-06 / CRASH-06). A direct,
deadline-bounded POST is the only delivery path that survives a saturated/stale queue at process
exit. CRUCIALLY (REVIEWS HIGH-1 / D-05) the direct sender must be LOCK-FREE end-to-end: the prior
plan resolved the key/url via `_resolve_api_key()`/`_resolve_capture_url()`, which both take
`_capture_config_lock` (`shared/posthog_server.py:147,:154`) — so the "lock-free" crash path was
actually acquiring a lock that a failing thread could already hold. The fix is to add plain
snapshot globals written by the existing `set_capture_api_key()`/`set_capture_host()` setters and
have `send_crash_event_direct()` read ONLY those globals. This plan also creates the four crash
test files + crash-local reset fixture so plans 02 and 03 have automated verify targets
(Nyquist Dimension 8).

Output: lock-free snapshot globals + `send_crash_event_direct()` in `shared/posthog_server.py`;
four new test files with the direct-send + lock-free assertions live (rest stubbed);
`tests/conftest.py` crash-LOCAL reset fixture (non-global).
</objective>
