<objective>
Add indexing-duration telemetry (D-01 / D-02 — PERF-01's "indexing" clause): time the
`LocalIndexerWorker` (bulk re-extraction) and the `LabRebuildWorker` (LOCAL LAB side-index rebuild)
with a monotonic clock, and emit one lightweight `desktop_indexing_complete` event per completed run
from the UI-thread completion slots. The event carries an `operation_kind` literal constant
(`incremental_add` / `reindex_all` / `lab_rebuild`; `initial_scan` is reserved but not populated this
phase — REVIEWS finding 10), `duration_ms`, and a coarse `doc_count_bucket` — never folder paths,
filenames, or raw doc counts. This is a SEPARATE, lighter event from the per-search session summary
(D-01 — one long background op vs many short searches), so it is emitted immediately via
`track_performance()` (indexing runs are rare — once per folder scan, not 50×/day).

The Codex review surfaced two correctness gaps folded in here: (finding 6) the `_last_operation_kind`
race — a queued follow-up worker could overwrite tab-level operation state before the prior event
emits — fixed by stashing `operation_kind`/`elapsed_ms` from the just-finished worker into locals
BEFORE `self._worker = None`, and by propagating `operation_kind` through the `_queued_action` lambda;
and (finding 7) the literal-constant discipline is now actually enforced because plan 01 extended
`tests/test_no_dynamic_telemetry_strings.py` to scan `desktop/my_library_tab.py` and recognize
`track_performance`.

Purpose: PERF-01 (indexing durations measured) + PERF-02 (doc count as bucket only). All emission
routes through `desktop/telemetry.py` — `my_library_tab.py` calls `telemetry.track_performance()`,
never `enqueue_event`, so the AST guards stay green.
Output: `desktop/my_library_tab.py` with timed indexing producers + race-free operation_kind.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| indexer worker → UI slot | worker carries only `elapsed_ms` (float) + a doc count int; never the file list / paths / filenames. |
| UI slot → PostHog | `track_performance(INDEXING_COMPLETE, ...)` is the only crossing; goes through the chokepoint scrubber + allowlist. |
| just-finished run state → emit | operation_kind/elapsed_ms are stashed from the finished worker into locals before the worker is cleared and before the queued-action re-entry, so the emitted value belongs to the run that actually finished. |
