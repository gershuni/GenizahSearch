<objective>
Wire the shared `PdfImageController` (Plan 01) into the desktop Browse panel (`genizah_app.py::_open_local_browse_page`) so opening a LOCAL **PDF** result reveals the (currently always-hidden-for-LOCAL) image pane and shows the rendered page, with prev/next PAGE navigation keeping the image in sync with the text (PDFIMG-04). Non-PDF LOCAL results stay text-only with the pane hidden and no render attempt (PDFIMG-05).

`_open_local_browse_page` is the single point-of-truth: `_on_local_browse_nav` and the page navigation already re-enter it, so wiring the render here covers prev/next PAGE automatically (D-06). The image feeds the **existing** `self.browse_viewer` (`ManuscriptViewerWidget`) via `display_image(QImage)` (Phase 99 D-02 — no new pane). The controller is the one already owned by `GenizahGUI` (`self._pdf_image_controller`, Plan 01).

**Scope + cancellation (REVIEWS HIGH-1/HIGH-2):** Browse uses the fixed scope key `"browse"` (one Browse panel exists). Every `request`/`cancel` passes `"browse"` so Browse's render state is isolated from any open ResultDialog's per-dialog scope on the shared controller. The non-PDF / no-filepath branch CANCELS the `"browse"` scope (instead of just hiding the pane) so a stale in-flight PDF render from a previously-browsed PDF cannot land in the pane after the user browses to a `.docx`/`.csv` (REVIEWS HIGH-2). Browse keeps plain `cancel` (NOT `discard_scope`) because `"browse"` is a PERMANENT scope — one fixed key for the lifetime of the app — so its single timer-dict pair never accumulates (REVIEWS-R2-3 is a ResultDialog-only concern, handled in Plan 02).

**LOCAL-PDF → Genizah transition (REVIEWS-R2-4):** Plan 03 originally cancelled `"browse"` only for non-PDF LOCAL files. Moving from a LOCAL PDF to a **Genizah** (non-LOCAL) manuscript was caught by the sid/page guards (no stale DISPLAY) but the controller still RETAINED the `"browse"` callbacks until the in-flight render terminated. Codex round 2 (LOW) asked to release them promptly. Fix: add a single guarded `controller.cancel("browse", silent=True)` in `_start_browse_enrichment(self, sid, is_part=False)` — the centralized funnel ALL Genizah-browse manuscript loads pass through (4 call sites: the shelfmark/sys browse handler, `_browse_load_part`, and the volume/nav paths; genizah_app.py:7352). It is NOT on the LOCAL path (`_open_local_browse_page` does not call it), runs at manuscript-load time (not a per-page hot path), and already resets stale browse state — so the cancel is on a clean semantic anchor and minimal-risk. **Chosen option:** the explicit cancel at the clean `_start_browse_enrichment` anchor (the planning brief's preferred option) over documenting an accepted residual, because a single clean funnel exists.

**Defensive guard (REVIEWS MEDIUM-5):** the `on_image`/`on_placeholder` callbacks capture and recheck BOTH `current_browse_sid` AND `current_browse_p` (sys_id + page). The controller's per-scope token already discards a stale page of the same document, but the sid+page recheck is defense-in-depth mirroring the existing `_on_volume_manifest_loaded` guard (genizah_app.py ~10241-10249), now extended to also compare the page.

Purpose: the second researcher-facing surface. All token/debounce/watchdog/gate/placeholder logic lives in the controller — this plan flips the unconditional `_set_browse_image_pane_visible(False)` to gate on the `is_pdf` already computed in this method, requests a render for PDFs, cancels the scope for non-PDF, and releases the browse scope on LOCAL-PDF→Genizah transitions.

Output: edits to `genizah_app.py` only.

**Serial-integration note (REVIEWS LOW-9):** This plan and Plan 100-01 both edit `genizah_app.py` (a ~25K-line file). This plan is Wave 2 / `depends_on: ["100-01"]` so it is applied AFTER 100-01's worker-ownership edits land. 100-01 edits module imports, `GenizahGUI.__init__`, and `closeEvent`; this plan edits `_open_local_browse_page` AND `_start_browse_enrichment` — all disjoint methods from 100-01's. Both plans use SEMANTIC anchors (method names + unique code strings), NOT raw line numbers, to survive line drift.
