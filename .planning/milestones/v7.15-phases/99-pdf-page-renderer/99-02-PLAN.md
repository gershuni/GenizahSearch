Public enqueue API (called from the UI thread by the Phase 100 controller):
```python
def enqueue(self, token: int, sys_id: str, page_num: int, filepath: str) -> bool:
    # REVIEW item 4 (Codex): defined behavior after stop — drop + log; never silently
    # queue work that can never emit a result against a stopping/dead thread.
    if self._stopping:
        logger.debug("PdfRenderWorker.enqueue after stop — dropping token=%s sys_id=%s",
                     token, sys_id)
        return False
    self._queue.put((token, sys_id, page_num, filepath))
    return True
```
The token is passed IN (the counter lives in the Phase 100 controller per RESEARCH Open Question 1);
the worker only echoes it. Do NOT create a monotonic counter here. The queue is intentionally
UNBOUNDED for Phase 99 — "latest-wins" (D-03) protects the DISPLAYED result via token echo, not the
render backlog; a bounded/coalescing enqueue is a Phase 100 controller concern (note it in the
module docstring; do NOT build it here) — REVIEW item 4 (Codex MEDIUM).

`_handle_request(self, item)` — MANDATORY extraction (REVIEW item 1, Codex HIGH). The per-request
render+emit body lives in its own method so unit tests can drive it SYNCHRONOUSLY without spinning
the thread or tripping the thread assertion. It contains NO thread assertion (that lives in `run()`)
and NEVER raises:
```python
def _handle_request(self, item) -> None:
    token, sys_id, page_num, filepath = item
    try:
        img = render_via_lru(self._lru, filepath, page_num)   # Plan 01 core
        self.render_succeeded.emit(token, sys_id, page_num, img)
    except PdfRenderError as e:
        # Plan 01's classifier already logged once (the _log_and_raise helper); just emit.
        self.render_failed.emit(token, sys_id, page_num, e.reason, e.detail)
    except Exception as exc:  # noqa: BLE001 — no-crash contract; thread must survive
        logger.exception("PdfRenderWorker: unexpected render error token=%s sys_id=%s",
                         token, sys_id)
        self.render_failed.emit(token, sys_id, page_num, PdfRenderFailure.RENDER_ERROR, str(exc))
```
The try/except is the PDFIMG-06 no-crash envelope (mirror LocalIndexerWorker.run): `_handle_request`
NEVER raises, so the run-loop that calls it can never die. `render_via_lru` raises only
`PdfRenderError` for classified failures; the bare `except` maps anything unexpected to RENDER_ERROR.

`run(self)` — the long-lived loop (net-new; no one-shot analog). Single-owner discipline: ALL fitz
access (the LRU + render) happens on THIS thread. The thread assertion AND the `close_all()` teardown
both live here — NOT in `stop()`, which runs on the caller thread (REVIEW item 2, Codex HIGH):
```python
def run(self) -> None:
    self._assert_worker_thread()        # single-owner guard — render thread only
    try:
        while True:
            item = self._queue.get()    # blocks until work or the _STOP sentinel
            if item is _STOP:
                break
            self._handle_request(item)
    finally:
        self._lru.close_all()           # D-06: all docs closed ON the render thread
```
Shutdown ordering note: the loop breaks only at the `_STOP` sentinel. Items already in the queue
AHEAD of `_STOP` are drained FIFO first; only items enqueued AFTER `stop()` are dropped (by the
`enqueue` guard). This is the intended behavior — tests must NOT rely on prequeue-then-stop dropping
mid-queue work (REVIEW item 4, Codex MEDIUM).

Clean shutdown — COOPERATIVE ONLY, NO `terminate()`, NO caller-thread LRU access (REVIEW item 2,
Codex HIGH — `terminate()` on a thread mid-`fitz` C call is unsafe and contradicts D-05's "do not
force-kill the C call", and `close_all()` from the caller thread violates single-owner):
```python
def stop(self, timeout_ms: int = 5000) -> None:
    self._stopping = True
    self._queue.put(_STOP)              # unblock the blocking get()
    if not self.wait(timeout_ms):
        # A wedged C call cannot be safely killed (D-05). Log and let the thread drain:
        # it will hit _STOP and close the LRU in run()'s finally once the in-flight
        # render returns; process exit reaps it if still wedged. UI never blocked (off-thread).
        logger.warning("PdfRenderWorker did not stop within %dms; leaving it to drain "
                       "(wedged C call cannot be force-killed per D-05)", timeout_ms)
    # Deliberately NO self._lru.close_all() here — that would touch fitz off the render
    # thread (single-owner violation). run()'s finally owns LRU teardown.
```

Single-owner guard (RESEARCH Pitfall 3 / Open Question 2): `def _assert_worker_thread(self)` does
`assert QThread.currentThread() is self, "fitz/LRU touched off the render thread"`. Call it ONCE at
the top of `run()` — NOT in `_handle_request`, `enqueue`, or `stop` (which run on the caller thread).
Keeping the assertion out of `_handle_request` is exactly what lets synchronous unit tests call
`_handle_request` directly (REVIEW item 1, Codex HIGH).

Add a module-level docstring note: the ~8s QTimer watchdog + TIMEOUT reason are Phase 100 UI-
controller scope (D-05/D-07); this worker never emits TIMEOUT and never force-kills the C call.

|-----------|----------|-----------|-------------|-----------------|
| T-99-04 | Tampering / DoS | concurrent fitz access from a future caller touching the LRU off-thread (PyMuPDF "not thread-safe" caveat → may crash Python) | mitigate | Single-owner discipline: all fitz/LRU access is inside `run()` on the render thread; `_assert_worker_thread()` (`assert QThread.currentThread() is self`) fails loudly if a future contributor calls the render branch off-thread (RESEARCH Pitfall 3 / Open Question 2). |
| T-99-05 | Denial of Service | one wedged/exception-raising render killing the worker thread, hanging all future navigation | mitigate | Per-request try/except envelope (both `PdfRenderError` and bare `except Exception`) emits `render_failed` and the loop continues — the thread never dies (mirror LocalIndexerWorker.run).
