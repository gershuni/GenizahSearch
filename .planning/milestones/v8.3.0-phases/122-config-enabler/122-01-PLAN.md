## STRIDE Threat Register

This phase is a pure in-process Python class relocation: `Config` moves from `genizah_core.py`
to `shared/config.py` behind a same-object re-export facade, one module-level import is
retargeted, and a static AST test is added. There is **no network I/O, no user input, no
deserialization of untrusted data, no cryptography, no authentication/authorization surface,
and no new external package** (the change is stdlib-only — `os`, `sys`, lazy `ctypes.wintypes`).

The only load-time side effect — `os.makedirs(INDEX_DIR, exist_ok=True)` — already runs today
on `import genizah_core`; it is preserved byte-for-byte and merely runs on `import shared.config`
instead. No new filesystem write path, no path derived from user input.

Therefore the STRIDE register is intentionally **empty — no new attack surface**. (Package
Legitimacy Gate is N/A: zero package-manager installs in this phase.)
