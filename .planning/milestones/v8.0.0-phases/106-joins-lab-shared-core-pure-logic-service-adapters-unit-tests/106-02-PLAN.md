## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-106-04 | Denial of Service (unbounded memory on huge result sets) | `dedup_candidates` / `apply_cross_side` iterating raw result lists | accept | dedup is O(n) single pass and collapses to one Candidate per (sys_id,page), so it strictly REDUCES memory; cross-side AND filters (reduces), OR adds at most 2 neighbor synth dicts per B-set page. The result-set ceiling is owned upstream by the engine (`execute_search` returns the engine's already-capped list — the project caps render at 200 in the UI layer per MEMORY). No new unbounded allocation introduced here; the OR neighbor synthesis is bounded by `len(b_set) * 2`. The VS list is bounded to 80 by the caller (sketch `_VsLoadWorker.LIMIT = 80`). |
| T-106-05 | Tampering / robustness | `apply_cross_side` calling executor methods that may raise/return None | mitigate | Every executor call (`execute_search`, `get_browse_page`, `get_meta_for_id`, `get_library_for_id`) is wrapped try/except returning `[]`/`None`/`""` (PATTERNS error convention) so a service hiccup degrades to fewer candidates rather than an exception; `total_pages` missing → `None` → no upper clamp (still safe, lower clamp drops `<1`). Verified by FakeSearchExecutor returning None for unknown browse keys. |
| T-106-06 | Tampering / correctness | merge annotation on frozen Candidate | mitigate | Frozen dataclasses forbid attribute mutation; merge uses `dataclasses.replace(...)` exclusively, so provenance annotation cannot silently corrupt a shared Candidate instance. Enforced by acceptance criterion `grep 'dataclasses.replace'` + TestMerge::test_overlap_annotated. |
