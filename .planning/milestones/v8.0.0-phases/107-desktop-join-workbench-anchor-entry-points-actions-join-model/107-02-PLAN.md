    GENERATION-TOKEN PATTERN (must-fix #7 - applies to ALL workers in this plan). `cancel()` /
    `quit()` do NOT interrupt a worker's already-running blocking `run()` body, so a fast re-anchor
    can let a stale worker emit AFTER the new anchor was set and repaint the wrong fragment. Defend
    with a monotonically-increasing generation token:
    - The window holds `self._gen = 0`. Every operation that starts a new anchor cycle
      (set_anchor) increments it: `self._gen += 1; gen = self._gen`.
    - Each worker is constructed with the current `gen` and STORES it (`self._gen = gen` in the
      worker ctor). The worker emits its token alongside its payload, e.g.
      `done = pyqtSignal(int, dict)` / `done = pyqtSignal(int, str)` / `done = pyqtSignal(int, list)`,
      emitting `self.done.emit(self._gen, payload)`.
    - Every slot first checks `if gen != self._gen: return` (drop stale results) before touching any
      widget. (For the image loader, which has no native token, capture the gen in the slot closure:
      connect via `lambda qi, g=gen: self._on_img(g, qi)` and drop if `g != self._gen`.)
    Apply this token to _AnchorLoadWorker, _PageTextWorker, the ImageLoaderThread slot, ThumbBatchWorker
    (Task 2), and _KnownJoinsLoadWorker (Task 2/3).
