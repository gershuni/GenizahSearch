<objective>
Wire the shared `PdfImageController` (Plan 01) into `desktop/result_dialog.py` so a LOCAL **PDF** hit shows its rendered page image in the (currently hidden-for-LOCAL) external pane, in sync with prev/next result navigation and within-document page navigation (PDFIMG-03). Non-PDF LOCAL hits keep the pane hidden with no render attempt (PDFIMG-05).

ResultDialog does NOT create its own worker — it borrows the app's shared worker + controller via its existing `self._app` reference (D-07). The image is fed to the **existing** `self.ms_viewer` (`ManuscriptViewerWidget`) via `display_image(QImage)` — no new pane, zoom/pan/rotate come free (Phase 99 D-02).

**De-duplication (REVIEWS HIGH-3 — verified against the actual call chain):** `load_result_by_index()` (result_dialog.py:1993) calls `self.load_page(target=p)` at line 2175. `load_page()` (line 2255) dispatches LOCAL hits to `self.load_local_page(...)` at line 2262-2263 (`if _is_local(self.current_sys_id): return self.load_local_page(...)`). So on initial open AND on prev/next result, the LOCAL path ALWAYS flows through `load_local_page`. Therefore the render trigger fires from **`load_local_page` only** (the single source of truth for "the shown LOCAL page changed"), guaranteeing exactly ONE request per LOCAL PDF page shown. `load_result_by_index` does NOT request — it only **cancels** the dialog scope when the newly-shown result is NOT a LOCAL PDF (non-LOCAL, or LOCAL non-PDF), so moving off a PDF invalidates the in-flight token and hides the pane.

**Per-dialog scope + cancellation (REVIEWS HIGH-1/HIGH-2):** the dialog uses a stable scope key `self._pdf_scope = id(self)` set in `__init__`. Every `request`/`cancel` passes this scope so the dialog's render state is isolated from Browse's (a ResultDialog is modal — opened via `.exec()` — but Browse may have a render in flight when the dialog opens; per-scope state prevents either surface from stranding the other). The dialog cancels its scope on non-PDF/non-LOCAL navigation AND in `closeEvent` (so a late `render_succeeded` cannot write into the closed dialog's `ms_viewer`).

Purpose: This is one of the two researcher-facing surfaces. The controller already owns all token/debounce/watchdog/gate/placeholder logic — this plan only computes the render trigger / cancel points and connects two callbacks (image, placeholder).

Output: edits to `desktop/result_dialog.py` only.

    """Phase 100 (PDFIMG-03/05): if the current hit is a LOCAL PDF, reveal the
    external pane and request a render of the current page. Called from
    load_local_page's SUCCESS path only (single source of truth for the shown
    LOCAL page — REVIEWS HIGH-3 de-dup). Does NOT cancel; non-PDF/non-LOCAL
    cancellation is handled by load_result_by_index + closeEvent."""
    controller = self._pdf_controller()
    fp = getattr(self, '_rd_local_filepath', None)

        return  # non-LOCAL or non-PDF LOCAL: nothing to render (cancel handled elsewhere)
    sys_id = self.current_sys_id

        self._pdf_scope,
        sys_id,
        page_num,
        fp,

    )
