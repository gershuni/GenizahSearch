<objective>
Build the shared UI controller Phase 99 deliberately left out, and wire the single app-level render worker into `GenizahGUI`.

This plan creates `PdfImageController` — the thin coordinator both ResultDialog (Plan 02) and Browse (Plan 03) consume. It owns: ONE global monotonic token counter (D-07b), latest-wins discard of stale `render_succeeded`/`render_failed` (D-03), the ~150ms debounce before enqueue (D-04), the ~8s `QTimer` watchdog that synthesizes a `TIMEOUT` placeholder (D-05), the extension gate (`.pdf` only — D-08/PDFIMG-05), and the per-`PdfRenderFailure`-reason → localized placeholder text map (D-02/D-03).

**Architecture decision (REVIEWS HIGH-1 — replaces the prior single-slot design): PER-SURFACE SCOPED STATE on ONE controller (Option A).**
The first version of this plan held ONE `_awaiting_token`, ONE `_pending`, ONE debounce timer and ONE watchdog shared by BOTH surfaces. Codex's cross-AI review correctly disputed the internal checker's "only one surface navigated at a time" assumption: a `ResultDialog` is opened modally OVER the Browse panel, and Browse can have a render in flight when the dialog opens. With shared state, the dialog's `request()` would supersede Browse's `_awaiting_token`, stranding Browse on "Loading…" forever (or letting a result write into the wrong viewer).

The fix keeps ONE controller object, ONE shared worker, and ONE global token counter — but partitions the *request state* by a `scope` string passed into every call. `request(scope, ...)` and `cancel(scope, ...)`; per-scope `_awaiting_token[scope]`, `_pending[scope]`, per-scope `QTimer` debounce + watchdog. ONE global monotonic counter makes tokens globally unique so a worker result routes to whichever scope's `_awaiting_token` equals the echoed token (no scope match → discard silently).

**This is fully consistent with D-05 "one code path":** "one code path" means ONE controller class with ONE method body parameterized by `scope` — NOT one global request slot. Both surfaces still execute the identical debounce/token/watchdog/gate/placeholder logic; they differ only in which per-scope dict entry and timers they touch. Scope keys: `"browse"` for the Browse panel (one Browse panel exists), and a per-dialog key (`id(self)` of the ResultDialog) for ResultDialog. `ResultDialog` is opened modally via `.exec()` (genizah_app.py:11671/13268/13340) so only one is interactively navigated at a time, but using `id(self)` as the scope key makes the controller robust to any future non-modal/multi-dialog use and guarantees a closed dialog's scope is torn down by `cancel(scope)`.

It also adds `cancel(scope, silent=True)` (REVIEWS HIGH-2) so a surface that navigates off a PDF (to a `.docx`/`.txt`/Genizah result, or closes the dialog) invalidates its in-flight token and a late `render_succeeded` cannot write a stale image into its viewer. Every terminal state — success, failure, watchdog timeout, AND cancel — clears that scope's `_pending` + `_awaiting_token` and stops its watchdog (REVIEWS MEDIUM-4), so a closed ResultDialog's callbacks (which close over the dialog + viewer) are released immediately.

It also instantiates ONE shared `PdfRenderWorker(maxsize=4)` on `GenizahGUI`, starts it, and stops it cooperatively in `closeEvent` (D-07/D-07a).

Purpose: Plans 02 and 03 are pure wiring on top of this controller — they call `controller.request(scope, ...)` per navigation, `controller.cancel(scope)` when leaving a PDF/closing, and connect one viewer per surface. Concentrating token/debounce/watchdog/gate/placeholder logic in one tested unit keeps both surfaces on a single code path (D-05) while isolating their request state.

Output: `desktop/pdf_image_controller.py` (new), worker ownership + shutdown in `genizah_app.py`, and `tests/test_pdf_image_controller.py` (new) covering all behaviors named in the planning context AND the five Codex-named risk tests.

def _debounce_timer(self, scope) -> QTimer:
    t = self._debounce_timers.get(scope)
    if t is None:
        t = QTimer(self); t.setSingleShot(True)
        t.timeout.connect(lambda s=scope: self._fire_pending(s))

Public entry point (NOTE the new leading `scope` parameter):
```python
def request(self, scope, sys_id, page_num, filepath, on_image, on_placeholder):
    """Debounced render request for a given surface SCOPE. Returns the token for
    this request, or None if gated out (non-PDF / no filepath).
    on_image(QImage) is called on success with the scope's latest token;
    on_placeholder(str) shows a localized placeholder. Per-scope state means a
    request in another scope never supersedes this one's awaited token."""
    if not self.is_pdf(filepath):
        return None
    token = self._next_token()
    self._awaiting_token[scope] = token
    self._pending[scope] = (token, sys_id, int(page_num), str(filepath), on_image, on_placeholder)
    # D-01: show Loading immediately, before debounce/enqueue
    on_placeholder(self._loading_text())
    self._debounce_timer(scope).start(self._debounce_ms)   # restart persistent per-scope timer
    return token
```

Cancellation API (REVIEWS HIGH-2):
```python
def cancel(self, scope, silent: bool = True):
    """Invalidate any in-flight render for SCOPE. Clears pending + awaited token,
    stops the scope's debounce + watchdog. silent=True shows no placeholder
    (used when navigating off a PDF / closing a dialog). A late worker result
    for the cleared token then finds no matching scope and is discarded."""
    self._pending.pop(scope, None)
    self._awaiting_token.pop(scope, None)
    t = self._debounce_timers.get(scope)
    if t is not None:
        t.stop()
    w = self._watchdog_timers.get(scope)
    if w is not None:
        w.stop()
    # silent=True: deliberately show nothing. (No placeholder branch needed today;
    # keep the param so callers can request a cleared/blank state in future.)
```

| cross-surface (Browse ⇄ ResultDialog) | two surfaces share one worker; a result for one surface must never be routed to the other's viewer |
