## Where (transcription surfaces)

Multi-select. Question: "Which transcription views should display line numbers?"

| Option | Description | Selected |
|--------|-------------|----------|
| Browse page (main viewer) | The main two-pane manuscript viewer at /browse — primary place users read transcriptions | ✓ |
| Search results (inline accordion) | The expanded text shown under each search hit on /search — short preview snippets |  |
| Parallels / Composition results | Text blocks shown on /parallels and composition search views |  |
| PGP transcription dialog / version views | Wherever a PGP edition or alternate version is displayed inside browse | ✓ |

**User's choice:** Browse page (main viewer), PGP transcription dialog / version views, and "Also Quick View. Perhaps we should do it on desktop app too (browse+ResultDialog)".

**Notes:** User expanded scope beyond the offered options to include (a) Quick View on search results and (b) the desktop app (Browse tab + ResultDialog). Search-results inline accordion was deliberately left out. Parallels likewise. These exclusions captured as deferred ideas.

## Visual presentation

| Option | Description | Selected |
|--------|-------------|----------|
| Fixed gutter on the right (RTL-aware) | Small grey numbers in a dedicated column on the leading edge. Doesn't interfere with copy-paste of the text itself. (Recommended) | ✓ |
| Inline prefix at start of each line | e.g. '1  בשם...' — simpler but numbers get included when users copy text |  |
| Hover-only / row marker | Number appears only on hover or selection — least intrusive |  |

**User's choice:** Fixed gutter on the right (RTL-aware).
**Notes:** Selection-safe copy is a hard requirement — line numbers must not appear in the clipboard when users copy transcription text.

---

## Visibility default & toggle

| Option | Description | Selected |
|--------|-------------|----------|
| Always on by default, with a toggle to hide | Discoverable for new users; researchers can hide if they want a clean view. (Recommended) | ✓ |
| Off by default, opt-in via toggle | Keeps current visual density; users who need numbers turn them on |  |
| Always on, no toggle | Simplest implementation; matches conventions like printed scholarly editions |  |

**User's choice:** Always on by default, with a toggle to hide.

## Click interaction

| Option | Description | Selected |
|--------|-------------|----------|
| No interaction — display only | Smallest scope; numbers are purely visual reference. (Recommended) | ✓ |
| Click to anchor / deep-link to that line | Generates a shareable URL like /browse?sys_id=X&line=3 |  |
| Click inserts L<N>: into the search box | Bridges the existing Responsa L3:word syntax |  |

**User's choice:** No interaction — display only.
**Notes:** Both deferred alternatives captured for future backlog items.

## Numbering scheme

| Option | Description | Selected |
|--------|-------------|----------|
| Each logical newline (split on \n) | Numbers match the L<N>: search syntax (genizah_core.py:4976 already counts this way). (Recommended) | ✓ |
| Each visual rendered row | Wrapped text increments the counter — mirrors what user sees but shifts with window width |  |
| Skip blank lines in counting | Cleaner look but breaks L<N>: alignment |  |

**User's choice:** Each logical newline (split on \n).
**Notes:** Locks numbering to match the existing Responsa-syntax `line_constraints` semantics in `genizah_core.py:4976-4994` and the parser at `genizah_core.py:7679-7691`.

## Toggle UI placement & persistence

| Option | Description | Selected |
|--------|-------------|----------|
| Small toggle in the transcription header, persisted per-user (localStorage / safe_storage) | Sits next to version selector / highlight toggle in browse and dialogs. (Recommended) | ✓ |
| Global Settings panel toggle | One place for all views; persisted in user settings |  |
| Per-view toggle, not persisted | Simplest but annoying for power users |  |

**User's choice:** Small toggle in the transcription header, persisted per-user (localStorage / safe_storage).
**Notes:** Persistence goes through `web/safe_storage.py` per Phase 87 chokepoint discipline. Desktop persists via its existing settings mechanism.

## Reset behavior across pages/folios

| Option | Description | Selected |
|--------|-------------|----------|
| Restart at 1 for each page/folio displayed | Browse already shows one page at a time. L<N>: search also operates on the displayed page. (Recommended) | ✓ |
| Continuous across the whole manuscript | Requires tracking cumulative offsets — more complex, only useful for cross-folio citation |  |

**User's choice:** Restart at 1 for each page/folio displayed.
