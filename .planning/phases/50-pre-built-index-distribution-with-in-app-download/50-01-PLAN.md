**1. `auto_suggest_title(fragments: List[PuzzleFragment]) -> str`**
Generate title from unique fragment shelfmarks joined by ' + '. If no shelfmarks, return 'Untitled Join'.
```python
def auto_suggest_title(fragments):
    seen = []
    for f in fragments:
        if f.shelfmark and f.shelfmark not in seen:
            seen.append(f.shelfmark)
    return ' + '.join(seen) if seen else 'Untitled Join'
```

**2. `compose_puzzle_export(fragments: List[PuzzleFragment], image_service: PuzzleImageService, export_size: int = 3000, margin: int = 20) -> Optional[Image.Image]`**
Compose full-resolution RGBA PNG:
- For each fragment: call `image_service.resolve_fragment_image(fl_id, size=export_size, threshold=bg_removal_threshold, processed=True)`
- Open as PIL RGBA image
- Apply transforms in order: scale, flip_h (FLIP_LEFT_RIGHT), flip_v (FLIP_TOP_BOTTOM), rotation (Image.rotate with expand=True, resample=BICUBIC, fillcolor=(0,0,0,0))
- Track each fragment's canvas position (x, y) from the PuzzleFragment. These are in 800px canvas coordinate space.
- Compute scale_ratio = fragment's actual loaded image width / 800 to map canvas coords to export coords. Since we load at export_size, and the canvas loaded at 800px, the ratio is `export_image_width_before_transforms / (800 * fragment.scale)` -- but simpler: just compute everything relative to export images.

  Actually, the coordinate mapping is: canvas stores (x, y) in Fabric.js pixel coords where images were loaded at 800px width. For export, images are loaded at `export_size` px width. The scale factor between canvas-space and export-space for each fragment is `(export_img_original_width / canvas_img_width_at_800)`. But since both are fetched from IIIF at a given width, and fragment.scale is applied on top, the simplest approach:

  - Load export image at `export_size` width (pre-scale, pre-transform)
  - The canvas image was `800` width, so `coord_scale = export_img.width / 800.0`
  - Apply `fragment.scale` to export image: `new_w = export_img.width * fragment.scale`, `new_h = export_img.height * fragment.scale`
  - Apply flips and rotation
  - Fragment center in export space: `cx = fragment.x * coord_scale`, `cy = fragment.y * coord_scale`
  - Place fragment so its center is at (cx, cy)

- After computing all placed fragments, find bounding box (min_x, min_y, max_x, max_y) across all fragment corners
- Create RGBA canvas of size (max_x - min_x + 2*margin, max_y - min_y + 2*margin), filled transparent
- Paste each transformed fragment at (frag_left - min_x + margin, frag_top - min_y + margin) using alpha mask
- Auto-crop with `canvas.getbbox()` and add `margin` px on each side
- Return the PIL Image

**3. `generate_thumbnail(fragments: List[PuzzleFragment], image_service: PuzzleImageService, thumb_size: int = 150) -> str`**

**Important implementation detail for rotation pivot:** Fabric.js stores `left` and `top` as the object's origin point (top-left corner by default, but with rotation the object's bounding box origin). For the export, use fragment.x and fragment.y as the center of the fragment in canvas space. The Fabric.js `getState()` function in puzzle.py stores `obj.left` and `obj.top` which are the origin coords. With Fabric.js default originX/originY='center' (set in the addFragment JS), these ARE the center coordinates. So fragment.x, fragment.y = center in 800px canvas space.
