**Sidecar file strategy (Claude's discretion):** Use a SEPARATE sidecar file (`nli_data/nli_crossref.db`) rather than adding to fjms_enrichment.db because:
- Different data provenance (NLI crossref vs FIST scholarly data)
- Independent update cycles (NLI data updates independently from FIST)
- Avoids coupling two unrelated data sources

**Table 1: `nli_images`** (from nli_crossreference.csv)
- Store ALL 25 columns from the CSV. Column names: LibraryNameEng, LibraryAbbrev, LibraryCity, LibraryNameHeb, CollectionName, Shelfmark, InventoryId, OBBox, OBVolume, OBFolio, NLI_AlmaId, CatalogAbbrev, CatalogEntry, FGPImageNumberId, FGPNumber, ImageName, ImageSourceName, PartOf, See, BifolioWith, NumFolio, NumBifolio, Material, Size, IsNotGenizah
- All columns as TEXT (matches CSV source types)
- Read with `csv.DictReader`, encoding `utf-8-sig` (BOM-prefixed CSV)
- Batched inserts of 10,000 rows using executemany
- **Indexes:** NLI_AlmaId (primary join key to libraries.csv system_number), FGPImageNumberId (image URL construction in Phase 30), Shelfmark (lookup by shelfmark)

**Table 2: `cambridge_manifests`** (from cambridge_genizah.json)
- Columns: label TEXT NOT NULL, manifest_url TEXT NOT NULL, normalized_shelfmark TEXT
- Read `cambridge_genizah.json` -> `data['manifests']` -> each item has `label` and `@id` (manifest URL)
- For `normalized_shelfmark`: convert CUDL label to normalized form:
  1. Strip "MS-" prefix
  2. Split by "-"
  3. Strip leading zeros from numeric segments (e.g., "00006" -> "6")
  4. Rejoin: use "." between consecutive numeric parts, space otherwise
  5. Apply `normalize_shelfmark()` from genizah_core.py (import it)
- **Indexes:** normalized_shelfmark (join to libraries.csv), label (lookup by CUDL ID)

**Table 3: `meta`** (version tracking)
- Same pattern as FJMS: key TEXT PRIMARY KEY, value TEXT NOT NULL
- Store version "1.0.0", created timestamp, source files

**Script structure:**
1. `import_nli_images(target_cursor)` - reads CSV, creates table, inserts all rows, creates indexes
2. `import_cambridge_manifests(target_cursor)` - reads JSON, creates table, inserts rows with normalization, creates indexes
3. `create_meta(target_cursor)` - version tracking
4. `main()` - orchestrator (create dir, delete existing db, WAL mode, call functions, VACUUM)
- Use `tqdm` for progress bars (already a project dependency)
- Import `normalize_shelfmark` from `genizah_core` for Cambridge label normalization

**Add `nli_data/` to `.gitignore`** (same pattern as fist_data/).
