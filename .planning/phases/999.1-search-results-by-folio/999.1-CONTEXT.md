# Phase 999.1: Search results by folio - Context

**Gathered:** 2026-05-15
**Status:** Ready for planning (backlog — promote with /gsd-review-backlog when ready)

<domain>
## Phase Boundary

Web search-result parity with desktop: show the page/image number on each
search result card so users see *which folio* a hit came from without
having to open Quick View.

In scope:
- `web/pages/search_results.py` result-card rendering.
- Web only. Desktop already has this (`genizah_app.py:16111` populates the
  "Img" column at `genizah_app.py:5591`).

Out of scope (see Deferred Ideas):
- Replacing the image number with a true folio label (e.g. "1r" / "2v").
- Grouping or collapsing multiple hits per manuscript.
- Sorting within a manuscript by folio order.
- Folio-based pagination / "next matching folio" navigation.
- Adding the folio indicator to parallels / composition result lists.

</domain>

<decisions>
## Implementation Decisions

### Data source
- **D-01:** Display the page/image number for each result, sourced from the existing `result['display']['img']` field. This is the same field the desktop "Img" column reads at `genizah_app.py:16111` and the same field Quick View already uses internally at `web/pages/search_results.py:883` and `:1107`. No new extraction, no new search-engine plumbing.

### Visual format
- **D-02:** Render the value as **just the number, no prefix**. Keep it compact. If `display.get('img')` is empty/falsy, render nothing (no badge, no separator).

### Position on the card
- **D-03:** Place the number **right after the shelfmark on the title line**, inline with the existing shelfmark label at `web/pages/search_results.py:468`. Use a subtle separator between shelfmark and number (e.g. middle dot `·` or thin space — Claude's discretion).
- **D-04:** Do NOT place it in the badge row (next to library / PGP / domain) — user explicitly chose the title line over the badge row.

### Interaction
- **D-05:** Display only. No click handler, no link, no tooltip change. Browse button on the card already deep-links to the correct page via the existing `_card_browse_url` builder at `web/pages/search_results.py:580-584`, so users have a path to the folio if they want it.

### Claude's Discretion
- Exact separator character between shelfmark and number (`·`, `—`, parens, or a thin space).
- Font weight / color of the number — should NOT compete visually with the shelfmark, which is the primary label (currently `font-bold` + `var(--primary-700)` at `:468`).
- Whether to also surface the number in any neighboring views (catalog dialog, etc.) — out of scope unless trivial.

</decisions>

<specifics>
## Specific Ideas

User framed this explicitly as "very simple: show the folio number in search results (it is in desktop but not in web)" — strict parity scope. Resist temptation to also add folio labels, grouping, or sorting in this phase; those are deferred items.

</specifics>

<deferred>
## Deferred Ideas

- **True folio labels (recto/verso, e.g. "1r", "2v")** — would replace the raw image number with the scholarly citation form. Requires resolving page index → folio label per library (CUL, CUDL, NLI, Oxford each handle this differently). Captured as a future backlog item.
- **Group results by manuscript, list folios inside the card** — collapse multiple hits from the same shelfmark into one card. Visual restructuring; its own phase.
- **Sort matching folios within a manuscript in folio order** — currently relevance-ranked; ordering inside a shelfmark group would need a sub-sort. Tied to the grouping idea above.
- **Folio-based pagination / "next matching folio" navigation** — step through matches within a single manuscript.
- **Add folio indicator to parallels / composition result lists** — separate render sites with their own layouts; out of scope.

</deferred>
