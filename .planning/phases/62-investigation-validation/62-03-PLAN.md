    Create `scripts/ec2_fs_test.py` per D-08/D-15 from CONTEXT.md.

    **Purpose:** Create a representative directory structure on the target EC2 instance with dummy files and measure performance. This script is meant to be copied to EC2 via scp and run there -- it has no local dependencies beyond Python stdlib.

    **Function `create_test_structure(base_dir, num_files, file_size_kb=100)`:**
    - Create 2-level hex hash directory structure: `{base_dir}/{xx}/{yy}/{hexname}.jpg`
    - The hash is computed from a sequential counter: `hex_str = format(i, '06x')`, dir1 = hex_str[0:2], dir2 = hex_str[2:4]
    - This gives up to 256 * 256 = 65,536 directories, each containing up to ~5 files at 300K scale (well under ext4 optimal of 100-500 per dir)
    - Write each file with `os.urandom(file_size_kb * 1024)` content (simulates JPEG-like random data)
    - Use tqdm if available, fallback to print-every-1000 if tqdm not installed (EC2 may not have it)
    - Report: directories created, files created, total size, time elapsed

    **Function `run_benchmarks(base_dir, num_files)`:**
    Run and time the following operations:
    1. `ls` single directory: `os.listdir(base_dir + '/00/00/')` -- measure time
    2. `stat` single file: `os.stat(base_dir + '/00/00/000001.jpg')` -- measure time
    3. `find` count all files: walk entire tree with `os.walk()`, count .jpg files -- measure time
    4. `du` total size: sum all file sizes via os.walk -- measure time
    5. Random access: stat 1000 random files from different directories -- measure avg time per stat
    6. Sequential read: read 100 random files fully -- measure avg read time and throughput

    Also collect system info:
    - `os.statvfs(base_dir)` for filesystem stats (total inodes, free inodes, block size)
    - `/etc/fstab` or `mount` output for filesystem type (parse if available)
    - Disk info: try to read from `/sys/block/` or run `lsblk` via subprocess

    **Function `report(results)`:**
    Print formatted results table and write JSON to `{base_dir}/_benchmark_results.json`:
    ```json
    {
      "num_files": 50000,
      "file_size_kb": 100,
      "total_size_mb": 4882,
      "filesystem": "ext4",
      "total_inodes": N,
      "free_inodes": N,
      "inode_usage_pct": N,
      "benchmarks": {
        "ls_single_dir_ms": N,
        "stat_single_file_ms": N,
        "find_all_files_sec": N,
        "du_total_sec": N,
        "random_stat_avg_ms": N,
        "sequential_read_avg_ms": N,
        "read_throughput_mbps": N
      },
      "directory_structure": {
        "levels": 2,
        "max_files_per_dir": N,
        "total_directories": N
      },
      "projected_at_300k": {
        "estimated_find_sec": N,
        "estimated_inode_usage_pct": N,
        "feasible": true
      }
    }
    ```

    **Function `cleanup(base_dir)`:** Remove all test files and directories. Called with `--cleanup` flag.

    **CLI (argparse):**
    - `--base-dir` (default: `/tmp/cache_test`)
    - `--num-files` (default: 50000)
    - `--file-size-kb` (default: 100 -- approximate average JPEG size)
    - `--cleanup` (remove test files after benchmarking)
    - `--benchmark-only` (skip file creation, just run benchmarks on existing structure)
    - `--json-output FILE` (write results to JSON file)

    **Important:** Script must work with Python 3.8+ stdlib only (no pip packages required). EC2 may have minimal Python install. tqdm is a nice-to-have, not required.

    **Projected scaling:** After measuring at 50K files, extrapolate to 300K:
    - find/du time scales roughly linearly with file count
    - stat/ls time should be constant (O(1) with htree indexing)
    - Inode usage: (300K files + 65K dirs) / total_inodes
