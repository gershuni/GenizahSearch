**1. `on_search_select_all_toggled` (~line 25944):**
Add `if self.results_table.isRowHidden(i): continue` inside the loop, BEFORE accessing `self.results_table.item(i, self.COL_CHECKBOX)`. This ensures Select All only checks visible rows.

```python
def on_search_select_all_toggled(self, checked):
    state = Qt.CheckState.Checked if checked else Qt.CheckState.Unchecked
    self.results_table.blockSignals(True)
    for i in range(self.results_table.rowCount()):
        if self.results_table.isRowHidden(i):
            continue
        item = self.results_table.item(i, self.COL_CHECKBOX)
        if item:
            item.setCheckState(state)
    self.results_table.blockSignals(False)
    self._update_search_export_label()
```

The web export API reads `state.last_results` (global singleton). The cleanest fix is to update `state.last_results` whenever post-search filters change what the user sees. This avoids changing the export API endpoints.

**In `_apply_manuscript_exclusions` (~line 3220):**
After the filter pipeline completes (inside the `try` block, after the downstream filter calls but before `finally`), sync the global export state:

```python
# Inside _apply_manuscript_exclusions, after the downstream filter pipeline runs
# but before finally restores search_state.results:
from web.state import state as app_state
app_state.last_results = filtered  # sync export state with visible results
```

Wait -- this isn't quite right. The downstream filters (word search exclusions, domain exclusions, printed filter, measurement filter) may further reduce `filtered`. The correct place to sync is in `render_results` where `displayed_results` is already set.

**Better approach: Update `state.last_results` in `render_results` (~line 4470).**
Find the line `search_state.displayed_results = results` and add right after it:

```python
search_state.displayed_results = results  # existing line
state.last_results = results  # keep export in sync with displayed results
```

This ensures that `state.last_results` always reflects whatever the user sees, regardless of which filter in the chain was the last to run. The `state` import already exists at the top of search.py (verify with `from web.state import state`).

**Important:** `state` is the global AppState singleton. Since NiceGUI is single-process and each page render is per-user, the last user to render results will set `state.last_results`. This is the EXISTING behavior (line 4045/4096 already sets it at search completion). The per-user `search_state.displayed_results` is the proper per-user field. But since the export API already uses the global `state.last_results`, we maintain that pattern. This is safe because export is triggered by the same user who just rendered.

**Also verify:** The no-exclusion path (lines 3226-3237) passes through to existing filters which all call `render_results`, so `state.last_results` will be updated there too. No special handling needed for the no-exclusion case.
