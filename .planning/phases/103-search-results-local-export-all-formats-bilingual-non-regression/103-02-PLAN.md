<objective>
Adapt the desktop xlsx builder so a mixed (Genizah + LOCAL) result set gains a dedicated
**"Local Documents"** sheet, LOCAL rows are excluded from the Genizah sub-sheets, and a
LOCAL-only export produces a usable workbook — while a Genizah-only export stays byte-identical
to today (cross-parity invariant green).

Two edits in `genizah_app.py`:
1. **`_build_search_results_xlsx_bytes` (lines 2531-2839)** — add a `local_filepath_map=None`
   kwarg (defaults to `{}` so existing test call sites are unaffected), partition LOCAL rows,
   conditionally create the "Local Documents" sheet at position 4 (D-04) **only when ≥1 LOCAL
   row exists** (D-06), flip the two `skip_local=False → True` args on Manuscripts/Bibliography
   (D-07), write the LOCAL rows via the Wave 1 `build_local_document_row` + `build_rich_snippet_cell`
   (D-03), and set the active sheet to Local Documents for LOCAL-only exports (D-05).
2. **`export_results` xlsx branch (line ~19807)** — prime the filepath cache for the export set
   and pass `local_filepath_map=dict(self._local_filepath_cache)`.

Purpose: deliver LEXP-03 (Local Documents sheet), LEXP-04 (sub-sheet exclusion),
LEXP-05 (LOCAL-only usable), LEXP-07 (bilingual sheet, via Wave 1 primitives).
Output: modified `genizah_app.py` + new xlsx export tests.
