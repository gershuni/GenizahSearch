<objective>
Adapt the three single-table desktop export formats so LOCAL rows carry local-meaningful
values instead of empty Genizah cells, and redesign the DOCX export into a per-result
"research handout" block layout (for both Genizah and LOCAL) using the Wave 1 shared writer.

Edits in `genizah_app.py::export_results`:
1. **Shared pre-check** — compute `_has_local_in_export` once at the top of the method.
2. **CSV branch (lines ~19857-19872)** — when LOCAL rows are present, remap LOCAL row columns
   (Shelfmark=filename, Library=parent folder, Source="LOCAL", Snippet=matched text) and append
   two columns, **Filepath** and **Page**, that appear **only when LOCAL rows are present** (D-08).
   Every LOCAL-originated cell is run through `sanitize_text_for_excel` (formula-injection guard,
   T-103-07). A Genizah-only CSV stays the unchanged 7-column table (LEXP-08).
3. **TXT branch (lines ~19925-19938)** — emit a LOCAL block (D-09) for LOCAL rows; the Genizah
   branch stays byte-identical to the current TXT output (LEXP-08 strict content non-regression).

   block layout via `shared.docx_export.write_docx_result_block` (D-10/D-11). Applies to both
   Genizah and LOCAL (D-12 intentional Genizah enrichment).

Purpose: deliver LEXP-01 (local fields on Search-results export), LEXP-06 (single LOCAL-aware
table for CSV/TXT/DOCX), LEXP-07 (bilingual labels on the appended/inline fields).
Output: modified `genizah_app.py` + new CSV/TXT/DOCX tests.
