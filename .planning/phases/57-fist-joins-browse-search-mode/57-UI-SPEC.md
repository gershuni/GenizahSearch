## Component Inventory

### 1. Visual Similarity Dialog (web: `ui.dialog`, desktop: `QDialog`)

**Trigger:** "Visual Similarity" chip button in browse enrichment toolbar.

**Layout:**
```
+------------------------------------------------------+
| [icon: compare] Visual Similarity -- T-S 12.123  [X] |  <- orange gradient header
+------------------------------------------------------+
| Sort: [Rank v]  Filter: [Library v] [Domain v]       |  <- filter row
+------------------------------------------------------+
| #1  T-S 8J.15.2  | Bible > Torah  | CUL  [Browse] [Puzzle] |
| #2  T-S 10J.5.1  | Piyyut         | CUL  [Browse] [Puzzle] |
| #3  ENA 3150.1   | --             | JTS  [Browse] [Puzzle] |
| ...                                                   |
| #20 (default cap, scrollable)                         |
+------------------------------------------------------+
```

**Columns (web ui.table / desktop QTableWidget):**

| Column | Width | Content |
|--------|-------|---------|
| Rank | 48px | `#N` in orange badge |
| Shelfmark | flex | Clickable shelfmark text (navigates to browse) |
| Domain | 120px | Domain classification from FJMS, or "--" if none |
| Library | 80px | Library code badge |
| Actions | 120px | "Browse" icon button + "Puzzle" icon button |

**Accessibility for icon-only action buttons:** The "Browse" and "Puzzle" icon buttons in the Actions column render without visible text labels. Each button MUST carry an accessible label: on web, set both `title` attribute and `aria-label` ("Browse manuscript" / "Add to puzzle"); on desktop, call `setToolTip("Browse manuscript")` / `setToolTip("Add to puzzle")` on each QPushButton. Hebrew equivalents: "עיין בכתב יד" / "הוסף לפאזל".

**Interactions:**
- Click shelfmark -> navigate to that manuscript's browse page (closes dialog)
- "Browse" button -> same navigation
- "Puzzle" button -> add fragment to puzzle canvas
- Sort dropdown: Rank (default), Library, Domain
- Filter by library: multi-select dropdown of libraries present in suggestions
- Filter by domain: multi-select dropdown of domains present in suggestions
- Scrollable body, max-height 90vh, 20 rows shown by default

**States:**
- Loading: spinner centered in dialog body while fetching suggestions
- Empty: "No visual similarity suggestions available for this manuscript" with info icon
- Error: "Could not load visual similarity data. Try again later." with retry button
- Loaded: table with rank-ordered rows

### 2. Browse Toolbar Chip (web)

```
[Bibliography (3)] [Catalog] [Measurements] [Visual Similarity (20)]
```

**Style:** `border: 1.5px solid #ef6c00; border-radius: 12px; min-height: 22px; color: #ef6c00; font-weight: 400;`
**Props:** `flat dense size=sm no-caps`
**Classes:** `text-xs px-2 py-0`
**Count:** Show suggestion count in parentheses, e.g., "Visual Similarity (20)"
**Visibility:** Only shown when manuscript has visual suggestions (check via service method)
**Icon:** `compare` (Material Icons)

### 3. Desktop Browse Toolbar Button

**Pattern:** Matches existing emoji-icon buttons in desktop browse toolbar.
**Label:** `Visual Similarity` / `דמיון חזותי`
**Icon:** Use text prefix or emoji consistent with existing desktop pattern.
**Enabled:** Only when manuscript has visual suggestions.

### 4. "Search in Visual Suggestions" Action

**Entry points (all platforms):**
- Browse page: action button/menu item near the Visual Similarity chip
- Search results: context menu or action button per result row
- ResultDialog (desktop): action button in toolbar
- Lists page: action on selected list items

**Trigger UI (web):** `ui.dialog` with:
```
+-----------------------------------------------+
| Search in Visual Suggestions            [X]   |
+-----------------------------------------------+
| Selected manuscripts:                          |
|   [chip] T-S 12.123  [x]                      |
|   [chip] T-S 8J.15.2 [x]                      |
+-----------------------------------------------+
| Combination: (o) Union  ( ) Intersection       |
+-----------------------------------------------+
| [Browse suggestions]  [Search within]          |
+-----------------------------------------------+
```

**Interactions:**
- "Browse suggestions" -> opens a result-set view of the visual suggestion pool (no text query)
- "Search within" -> enters refine mode with restrict_sys_ids set to the suggestion pool, user types text query
- Union/Intersection toggle: radio buttons, default Union
- Each selected manuscript shown as removable chip
- Minimum 1 manuscript must be selected

### 5. Search Results Join Partner Enrichment

**NOT in this phase.** Per CONTEXT.md decisions, the search integration is via "Search in Visual Suggestions" action (D-10, D-12), not automatic enrichment of search results. The ROADMAP success criterion #3 about "expandable join partners section" is superseded by the CONTEXT.md decisions (D-10 through D-12) which describe a cross-cutting action pattern instead.

### 6. Settings: Full DB Download Option

**Location:** Settings page, under a "Data" or "Advanced" section.
**UI:** Toggle switch with label "Download full visual similarity database for offline use" / Hebrew equivalent.
**States:** Off (default), Downloading (progress bar), Downloaded (green checkmark + file size), Error (red text + retry).
**Desktop:** Settings dialog, same toggle pattern.

## Interaction Contracts

### Dialog Data Fetch

- Web: `await run.io_bound(service.get_visual_suggestions, sys_id)` -- async, does not block UI
- Desktop: QThread worker or lazy fetch on first dialog open (matches measurements pattern)
- Show spinner during fetch, then populate table

### Navigation from Dialog

- Clicking a shelfmark or "Browse" button navigates to that manuscript's browse page
- Web: `ui.navigate.to(f'/browse?sys_id={target_sys_id}')`, dialog closes
- Desktop: calls `on_browse(target_shelfmark)` callback (same as JoinsDialog pattern), dialog closes

### On-Demand Fetch + Cache (Desktop)

- First access for a manuscript triggers HTTP fetch from server API
- Response cached to local disk (SQLite or JSON, Claude's discretion)
- Subsequent access reads from local cache
- Cache has no TTL for this phase (data is static FIST export)

### "Search in Visual Suggestions" Flow

1. User triggers action from any entry point
2. Service gathers union/intersection of suggestion partner sys_ids
3. **Browse mode:** Display partner sys_ids as a result set (reuse search results UI with a "Visual Similarity Results" header)
4. **Search mode:** Set `restrict_sys_ids` to partner sys_ids, enter refine mode (reuses Phase 55 mechanism)
5. Breadcrumb shows "Visual suggestions for T-S 12.123" as the restriction label

### Sort and Filter in Dialog

- Sort by rank (default, ascending), library (alpha), domain (alpha)
- Filter by library: multi-select, shows only libraries present in current suggestions
- Filter by domain: multi-select, shows only domains present in current suggestions
- Filters apply client-side (data already fetched, max 20 rows)

## Dark Mode Compliance

All new UI elements must use CSS custom properties from `common.css`:
- Dialog body background: `var(--bg-card)`
- Dialog body text: `var(--text-primary)`
- Table borders: `var(--border-light)`
- Muted/secondary text: `var(--text-muted)`
- Empty state icon/text: `var(--text-muted)`

The orange gradient header is colorful enough to work in both light and dark modes without inversion.

Desktop dark mode: follow existing desktop theme detection pattern (if any). The orange accent works on both light and dark backgrounds.

---

## RTL Compliance

- Dialog layout direction follows `get_language()` -- RTL for Hebrew, LTR for English
- Shelfmark text is always LTR (manuscript identifiers are Latin characters)
- Action buttons stay on the trailing edge (right in LTR, left in RTL)
- Close button stays in top-trailing corner
- Sort/filter row follows document direction
