## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| QLineEdit query input → `compose()` → `execute_search()` | Scholar-entered query strings cross into the engine (validated by the Tantivy tokenizer / Responsa parser, not by us). |
| `sys_ids` list → SQLite `manuscript_measurements` IN-query | Internal sys_ids (from search results) cross into a parameterized SQLite read. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-108-01 | Tampering (SQL injection) | `get_measurements_batch` IN-query | mitigate | Parameterized `?` placeholders only (the IN list is built from `'?'*len(batch)`, values bound as the parameter tuple) — same pattern as `get_domains_for_sys_ids`; no string interpolation of values. |
| T-108-02 | Information disclosure | measurement read | accept | Desktop single-user, local read-only SQLite sidecar; no PII; no network boundary. |

**Honest assessment (per phase guidance):** No high-severity threats. V5 Input Validation is the only
partially-applicable ASVS category; the engine tokenizer/Tantivy validate query strings and the
SQLite read is parameterized. Standard controls only.
