# Phase 108 — UI Design Contract

> Visual and interaction contract for the Phase 108 desktop Join Workbench right pane:
> line-by-line query builders, candidate grid/table, self-match readout, source selector,
> and CompareDialog. Generated by gsd-ui-researcher; verified by gsd-ui-checker.
>
> **Platform note:** This is a PyQt6 desktop surface, not a web surface. "Design system"
> means the existing app's PyQt idiom — existing dialogs, widget conventions, and the
> `TabularQueryBuilderDialog` visual language. No shadcn, no Tailwind.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (PyQt6 native widget styling) |
| Preset | not applicable |
| Component library | PyQt6 (QFrame, QLabel, QTextBrowser, QTableWidget, QSplitter, QScrollArea) |
| Icon library | Unicode emoji inline (📖 🧩 📋 🔗 ⚓ ⤢ ★ ⊙ ✎) — no external icon library |
| Font | System default (app-wide; no explicit family override) |

**Visual language anchor:** `TabularQueryBuilderDialog` (`genizah_app.py:1543`) — borrow its
scope-radio row, modifier checkbox row, and Preview field look. The new builder widget is a
**separate class** (D-03); do not modify the existing dialog.

## Spacing Scale

All values are multiples of 4, matching the existing PyQt app convention:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | `setSpacing(4)` / `setContentsMargins(4,4,4,4)` inside cards and compact rows |
| sm | 8px | `setSpacing(8)` in main layouts; button row internal gaps |
| md | 16px | `setContentsMargins(16,...)` for pane-level inset; section padding |
| lg | 24px | Inter-section vertical spacing (builder → refine bar → candidate area) |
| xl | 32px | Not used at component level; reserved for dialog-level breathing room |

Exceptions:
- Card thumbnail fixed at 220×130 px (content-driven, not a spacing token).
- Card fixed width 232 px (grid column width — matches the sketch invariant).
- Compare pane image minimum height 360 px (content-driven).
- Touch/click targets for Y/?/N + action buttons: minimum 28×28 px (compact card row), 34×28 px for prev/next nav buttons.
- Other-side builder indent: 18 px left margin (visual subordination under the anchor builder).

## Surface Inventory

### 1. QueryBuilder widget (JoinQueryBuilder)

**Reuse class for both anchor-side and other-side builders.** Separate from
`TabularQueryBuilderDialog` (D-03).

**Layout (outer `QVBoxLayout`, `spacing=2`, `contentsMargins=0`):**

```
[rows_box VBoxLayout]          ← stacked row widgets
  [Row 1]
  [Row 2]
  …
[controls HBoxLayout]
  [+ Add Line button]  [variants checkbox]  [stretch]
```

**Each row is a `QHBoxLayout(spacing=2, contentsMargins=0)` containing:**

```
[ends line ⊣ checkbox] [term QLineEdit, stretch=1] [⊢ starts line checkbox] [↓ N ln QSpinBox] [× QPushButton, fixedWidth=24]
```

RTL/LTR contract (D-06):
- The `term` `QLineEdit` (Hebrew word input) has `setLayoutDirection(Qt.LayoutDirection.RightToLeft)` — Hebrew text entry flows right-to-left.
- The surrounding row chrome (`ends line ⊣`, `⊢ starts line`, gap spinbox, `×` remove button) is LTR (natural widget order in an `QHBoxLayout` without `RightToLeft` override).
- Hebrew line START is the right edge: "⊢ starts line" checkbox sits to the RIGHT of the input field; "ends line ⊣" sits to the LEFT. This matches what the sketch established in iteration E.
- The full builder `QWidget` does NOT set `setLayoutDirection(RightToLeft)` — only the input fields inside it do.

**Checkbox labels and tooltips (tr()-wrapped):**
- "ends line ⊣" — tooltip: tr("The LAST word must be at the END of the line (left edge in Hebrew) — a torn line ending")
- "⊢ starts line" — tooltip: tr("The FIRST word must be at the START of the line (right edge in Hebrew) — a torn line beginning")

**Gap spinbox:**
- Range 0–40; prefix "↓ "; suffix " ln"; tooltip: tr("Lines to skip before the next line (0 = the very next line)")
- Visible only when the row is NOT the last row (`_sync()` hides it on the final row).

**Controls row:**
- "+ Add Line" button — tr("+ Add Line")
- "variants" checkbox — tr("variants"); tooltip: tr("Expand spelling variants (responsa variant expansion)")

**Read-only Preview field (borrowed from `TabularQueryBuilderDialog` modifier row):**

Below the controls row, a `QHBoxLayout` containing:
```
[QLabel "Preview:"]  [QLineEdit, stretch=1, readOnly=True, setStyleSheet("color: #94a3b8;")]
```
Updates on every keystroke and checkbox change via `_update_preview()` calling `compose()`.

**Modifier row (carried from `TabularQueryBuilderDialog`):**

A single `QHBoxLayout` with checkboxes for: Start/End of line (already per-row above, so OMIT these from the modifier row), Negation, Defective, Wildcards, Prefixes, Suffixes, Bidirectional, Flex Spacing, Judeo-Arabic, Variants (global — already in controls row, so OMIT duplicate). Remaining modifiers in the row: Negation, Defective, Wildcards, Prefixes, Suffixes, Bidirectional, Flex Spacing, Judeo-Arabic. These map to `responsa_options` keys passed to `compose()`.

**First-row placeholder text:**
- Anchor-side builder: tr("word(s) on this line…") (first row hint); subsequent rows: tr("word(s) on this line…")
- Other-side builder: first row placeholder: tr("word(s) required on the OTHER side…")

**Empty state:** if all term fields are blank, `is_empty()` returns True; the Search button is disabled with tooltip tr("Enter at least one word to search").

### 6. Status bar, view toggle, and pagination row

**`QHBoxLayout`:**

```
[status QLabel, stretch=1]  [view toggle QPushButton]  [< prev QPushButton, fixedWidth=34]  [page label QLabel]  [next > QPushButton, fixedWidth=34]
```

- Status label: font-size 11px, color `#94a3b8` (muted); updates with self-match readout + filtered count + triage counts.

**Self-match readout (D-15) — placement decision (Claude's Discretion):**
The self-match signal lives INLINE in the status label, prefixed before the count:
- When anchor matched: `"⚓ anchor matches this query ✓  ·  N/M shown  [Y x  ? y  N z]"`
- When anchor did NOT match: `"⚓ anchor does NOT match this query ✗  ·  N/M shown  [Y x  ? y  N z]"`
- When no query run yet or VS-only: status shows: `"Build a line-by-line query, then Search."` (initial) or search/progress updates.

Rationale: inline placement avoids a separate UI widget, stays always visible without competing with the candidate area, and matches the sketch's established pattern. The anchor-self-match ✓/✗ is a diagnostic signal, not a primary action — it belongs in the status band.

- View toggle button: text alternates `tr("Table view")` / `tr("Grid view")`; tooltip: tr("Toggle thumbnail grid / text table")
- Pagination: `< ` / `>` buttons; label shows `"N/M"` (current page / total pages) in grid mode; `"N rows"` in table mode.

### 9. CompareDialog

**`QDialog` (modeless child of JoinWorkbenchDialog), resize(1320, 870).**

```
[top bar: < prev btn] [position label, stretch] [next > btn]  [Y btn] [? btn] [N btn]
[action row: 📖 Browse] [🧩 Puzzle] [📋 Add to List] [🔗 Add as Join] [⚓ Re-anchor] [stretch]
[body HBoxLayout]
  [left pane]    [right pane]
```

**Position label format:** `"candidate N/M   {anchor shelfmark}  vs  {candidate shelfmark}   [{triage}]"`

**Each pane (`_pane()` returning a VBoxLayout):**
```
[shelfmark QLabel, bold 13px]
[meta QLabel, wordWrap, 11px, color META_COLOR]    ← library · img · title · "◧ W×H · material" · "VS N.NN"
[image QLabel, minHeight=360, AlignCenter, bg #e2e8f0]
[QTextBrowser, stretch=1]                           ← apply_line_numbered_text, RTL, highlighted
```

Pane sizing: equal stretch (no fixed ratio — QHBoxLayout default). Dialog total 1320×870 → each pane approximately 640 wide. Image target size: 620×460 px (passed as `target=(620, 460)` to `_load_image()`).

Anchor pane (left): populated from `wb.anchor` (the pinned fragment); does NOT reload when navigating candidates — stays static.

Candidate pane (right): loads the candidate's image via `_load_image(pane["img"], r_sid(res), width=1400, target=(620, 460))` and text via `apply_line_numbered_text`.

**"Open to the matched page" (D-18):**
When a candidate was pulled in via the other-side builder (i.e. `res["_via_other_side"]` is True), the compare dialog opens to the NEIGHBORING page (p±1) that matched query B, not the candidate's own page. The `page_of(res)` accessor already resolves this from `res["display"]["img"]` which the `_CrossSideWorker` sets when building neighbor result dicts. No special-case branch needed — `_fill()` uses `res["display"]["img"]` as the page index. Label the candidate pane meta line with `"  ·  other side matched"` when `_via_other_side` is set.

**Triage inside CompareDialog:**
- Y / ? / N buttons in top bar call `wb.mark(r_sid(candidate), val)` — persists to `wb.triage` and restyles the originating card.
- The position label refreshes to show the current triage state.

**Re-anchor inside CompareDialog:**
- Calls `wb.set_anchor(current_candidate)` and closes the dialog (`self.accept()`).

**Add as Join inside CompareDialog (D-17):**
- Calls `wb.act_join(current_candidate)` → opens `JoinsDialog` pre-filled with anchor=fragment A, candidate=fragment B via the Phase 107 public action API (D-20: no `_vs_*` private calls).

**Prev/Next navigation:**
- Steps through `wb.filtered` (the current filtered list, including triage filter state).
- Wraps to bounds (clamps, no wrap-around).

## Interaction Contracts

### Focus order and keyboard navigation

1. On dialog open: focus → anchor-side builder first row `term` QLineEdit.
2. Inside a QueryBuilder: Tab moves L→R across `[end checkbox] [term] [start checkbox] [gap spinbox] [× button]`, then to next row.
3. Enter / Return in any `term` field triggers `do_search()` (same as "Search" button).
4. Keyboard shortcut: no new global shortcuts defined (follows existing app conventions).
5. CompareDialog: ← / → arrow keys (or < prev / next > buttons) step through candidates.

### Search trigger events

- "Search" button click: `do_search()`
- Enter in any builder `term` QLineEdit: `do_search()`
- Toggling other-side AND/OR combo: does NOT auto-re-search (user must click Search again)
- Toggling "include anchor itself": does NOT auto-re-search

### Filter trigger events

- Text filter, material combo, has-dimensions checkbox, triage combo, size-filter spinboxes: all trigger `apply_filters()` immediately on change (`textChanged`, `currentIndexChanged`, `stateChanged`)
- `apply_filters()` operates on the already-fetched `self.results` list — no re-search

### Triage persistence scope (D-10)

- Keyed by `sys_id` (canonical per-candidate key surviving re-runs; stable across filter changes).
- Lives in `self.triage = {}` on `JoinWorkbenchDialog`.
- Cleared on re-anchor (`set_anchor()` resets `self.triage = {}`).
- NOT persisted to disk (a confirmed join is persisted as a real join via Act_join → JoinsDialog).

### Image loading concurrency

- Max 5 concurrent `ImageLoaderThread` instances (`MAX_CONCURRENT_IMG = 5`).
- Grid page: `ThumbResolver` resolves NLI thumbnail URLs for all 20 cards simultaneously (bulk QThread), then images are enqueued into the bounded 5-slot pool.
- `_cancel_images()` called on: page change, view toggle, dialog close.
- Card image on load failure: `label.setText("(no image)")`.

### Search execution (D-21 — batched enrichment)

- Search results from `SearchThread` arrive in `_on_results()` — raw list.
- Dedup to one-per-image before any enrichment (key: `uid` or `sys_id|img`).
- All per-candidate enrichment (material, dimensions via `shared/fjms_service`, thumbnail URL via `meta_mgr.get_thumbnail`, snippet via `snippet_html/snippet_plain`, cross-side membership) is batched in workers, not per-candidate serial.
- Cross-side worker (`_CrossSideWorker`) runs after the main text results arrive; fires progress signals; result delivered to `_on_cross_done()`.

### RTL/LTR split (D-06) — detailed contract

| Element | Direction | Rationale |
|---------|-----------|-----------|
