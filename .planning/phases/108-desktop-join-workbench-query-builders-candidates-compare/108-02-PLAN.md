#   "%שלום" -> plene_defective; "שלום*" -> wildcard='suffix'; "*נדר" -> wildcard='prefix' (:5719-5725)

#
# ⚠ HOIST RULE (RR-13 — parser _parse_* :6113-6163, code-verified). The parser strips a LEADING '-'
#   (negation, :6117-6119), then leading '%'/'#' (:6125-6130), then a TRAILING '#' (:6135-6137) from the
#   WHOLE token, THEN checks for the OR group "(...)" and `after == '*'` for a group wildcard-suffix
#   (:6140-6163). So GROUP-LEVEL hoisted forms parse correctly:
#     "#(שלום/שלומות)" -> words=['שלום','שלומות'] + grammatical_prefixes=True
#     "%(a/b)" -> plene_defective; "-(עץ/אילן)" -> negated on the group; "(a/b)#" -> grammatical_suffixes;
#     "(a/b)*" -> wildcard='suffix' on the group.
#   It does NOT strip a leading '*' before the OR check, so "*(a/b)" is NOT a group wildcard-prefix.
#   Per-alternative mods INSIDE the group ("(#a/%b)") are RAW words from inner.split('/') — LITERAL '#'/'%'.
#   THEREFORE build_side_query HOISTS the row mods OUTSIDE the group; it does NOT decorate per box and join.
#

#   decorate order at :6014-6027) — borrow its SINGLE-token decoration order, but NOTE it emits the per-box
#   form f"({'/'.join(words_with_mods)})" for a multi-alternative component (:6032-6033), which has the SAME
#   parser limitation. You are NOT copying that multi-box form — you HOIST instead (RR-13).
