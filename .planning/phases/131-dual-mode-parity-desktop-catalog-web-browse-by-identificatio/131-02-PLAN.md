<objective>
Add a backward-compatible `library_mode` parameter to the shared
`shared/fjms_service.py::get_browse_results` so BOTH the desktop catalog worker (Plan 03) and the
web Browse-by-Identification page (Plan 04) can express the Phase 130 dual-mode (Show-only / Hide)
intent server-side, with `total` and pagination computed over the full filtered set. ALSO add a new
bounded `get_browse_library_facets(...)` method that returns true full-set per-library counts
(`{library_code: count}`) via DISTINCT-manuscript counting honoring the active non-library filters,
so the catalog dialog (Plan 04) shows real DMF-12 shortlist counts — not page-local A2 counts
(Codex R1 MED #7, tightened by R2 N5). The AlmaId -> library mapping is supplied by the caller as a
CALLABLE (`sys_id_to_library: Callable[[sys_id], str | None]`) — matching the bound method
`state.meta_mgr.get_library_for_id` that Plan 04 passes (Codex R3 F3).

Purpose: catalog and desktop are pre-query/server-side surfaces (unlike web `/search`, which is a
post-fetch client filter). The Hide-mode semantics for these surfaces belong inside the single
shared browse query, where the existing library filter already lives as an `EXISTS` constraint
over the `_browse_filter_library` temp table. Flipping `EXISTS` -> `NOT EXISTS` is the minimal,
total-correct way to support Hide. The facet method belongs in the same shared service because
counts must honor the same domain/author/work/pgp/editions conditions the browse query uses, and
must count DISTINCT manuscripts (one row per AlmaId) exactly like the live browse COUNT. This
isolates BOTH shared changes (Wave 1) so the two Wave-2 surface plans (03 desktop / 04 web catalog)
never collide on `shared/fjms_service.py`.
Output: one new SQL-shape + facet contract test (test-first, exercising a callable mapper) + one new
`library_mode` param + one SQL branch in `get_browse_results` + one new `get_browse_library_facets`
method.
</objective>
