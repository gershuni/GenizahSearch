<objective>
Close the single Phase 131 UAT gap: the desktop catalog `LibraryFilterDialog` shows per-library manuscript COUNTS (e.g. `CUL (1,234)`), and those counts are DYNAMIC — they honor the catalog's other active filters (PGP Only / Scholarly-Editions / domain / date / text), at parity with web `/catalog` Browse-by-Identification.

The shared engine ALREADY supports this. `shared/fjms_service.py::get_browse_library_facets(...)` (verified present at lines 2417-2507) reuses `_build_browse_conditions`, counts `DISTINCT AlmaId` under the active non-library filters, intentionally excludes the library filter itself, takes a CALLABLE `sys_id_to_library` (full-corpus resolver), and skips `'LOCAL'`. NO new SQL and NO shared-method change is needed. The web reference implementation is `web/pages/catalog_browse.py::_fetch_library_facets_blocking` (line 335). Only the DESKTOP surface is unwired:
  1. `LibraryFilterDialog` (desktop/dialogs_filter.py:1677) renders rows as `get_library_display(code)` only — no count, no `facets` param.
  2. The desktop catalog path (genizah_app.py:10434 `_open_catalog_library_dialog`) never calls `get_browse_library_facets`.

This is desktop-only. Web `/catalog` already satisfies DMF-12; do NOT touch web. DMF-07 parity gap + DMF-12 (desktop facet counts).

Purpose: Bring the desktop catalog library filter to count + dynamic parity with web, per UAT user feedback (2026-06-30).
Output: `facets` param + count rendering in `LibraryFilterDialog`; off-UI-thread facet wiring in `genizah_app._open_catalog_library_dialog`; extended `tests/test_libfilter_desktop.py`.
