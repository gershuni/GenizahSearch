<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> NiceGUI server (catalog page) | The dialog's checked-codes list returns from client JS (`catLibFilterGetChecked`) and the persisted `catalog_library_filter` value can be crafted/stale. Untrusted input crosses here. |
| per-user state -> safe_storage | The `{'mode','codes'}` value is written/read through `web/safe_storage.py`; multitenant leakage is the boundary the Phase 87 chokepoint guards. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-131-04-01 | Tampering | crafted/stale `catalog_library_filter` value or JS-returned checked list | mitigate | Apply handler runs `sanitize_library_codes()` (drops non-str, unknown, and `'LOCAL'`); restore runs `sanitize_library_codes()` on both list and dict branches; the dialog build keeps the inline `c != 'LOCAL'` guard (V5 input validation). |
| T-131-04-02 | Spoofing/Info disclosure | cross-user state leak | mitigate | All reads/writes route through `safe_user_get`/`safe_user_set` (the `web/safe_storage.py` chokepoint, Phase 87); `tests/test_no_raw_storage_access.py` allowlist stays `[]` (V3 session). |
| T-131-04-03 | Tampering | `'LOCAL'` injected as a web library option | mitigate | Dialog universe is `library_codes_with_manuscripts()` minus `'LOCAL'` with an inline literal guard; `tests/test_web_library_options_no_local.py` AST scan enforces the literal in every function touching `LIBRARY_CODES`. |
| T-131-04-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs (RESEARCH § Package Legitimacy Audit: none). |

**V5 input validation:** every library-code input (crafted storage, JS-returned checked list) passes
`sanitize_library_codes()` and the inline `c != 'LOCAL'` guard before being persisted or used as a filter.
**V3 session:** catalog persistence routes ONLY through `web/safe_storage.py` (`safe_user_get`/`safe_user_set`);
no raw `app.storage.user`; allowlist stays `[]`. No new network endpoint, auth path, or schema change.
</threat_model>
