<threat_model>
## Trust Boundaries

Desktop is a single-user local app. There is NO multitenant boundary, NO web persistence, and NO
network endpoint introduced. `_catalog_library_mode` is an in-process Python attribute; library codes
are chosen from a fixed, constructed list (`library_codes_with_manuscripts()` minus `'LOCAL'`).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-131-03-01 | Tampering | library codes -> get_browse_results | mitigate | Codes originate from the constructed `library_codes_with_manuscripts()` list (LOCAL excluded by the inline `c != 'LOCAL'` guard); `library_mode` is mapped to a fixed SQL keyword in Plan 02 (no injection). |
| T-131-03-02 | Information disclosure | Hide-mode catalog view | accept | Same public catalog corpus the user already browses; Hide narrows/complements an existing view, discloses nothing new. |
| T-131-03-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs (RESEARCH § Package Legitimacy Audit: none). |

**V5 input validation:** the dialog constructs `_all_codes` with the inline `c != 'LOCAL'` guard;
no untrusted text becomes a filter. **V3 session:** N/A — desktop uses an in-memory attribute, NOT
`web/safe_storage.py` (the web chokepoint applies only to the web surface plans). This plan introduces
no new web persistence and no new network/auth surface beyond Phase 130's analysis.
</threat_model>
