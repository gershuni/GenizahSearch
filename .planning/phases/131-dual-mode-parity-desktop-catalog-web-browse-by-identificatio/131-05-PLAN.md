Add a NEW library-filter control to the web `/parallels` page using the Phase 130 dual-mode
(mode + set) model, closing the v8.3.0 deferred gap logged in `docs/OPEN_ISSUES.md` (2026-06-29).
The control gets a Show-only / Hide toggle (D-03), D-04 mode-flip reset, text-search, a
count-shortlist + expand-all-A–Z dialog, a 3-state button using the REAL Phase-130 pluralized keys,
the `library_codes_with_manuscripts()` universe (DMF-13), and persistence under a new
`parallels_library_filter` safe_storage key as a `{'mode','codes'}` dict (with legacy-list migration).

The Show-only Apply normalization (all-selected -> `[]`) uses a LOCAL helper defined in parallels.py
(`_parallels_apply_selection`) — it does NOT call search.py's nested `_library_apply_selection`,
which is a closure scoped inside the `/search` page function and is NOT importable/in-scope here
(Codex R2 N2: referencing it would NameError on Show-only Apply).

Scoping uses a **HYBRID** (A3 revised per Codex R1 HIGH #5; tightened by Codex R3 F4): Show-only
resolves the selected-library sys_ids PRE-query and intersects them into the existing
`restrict_sys_ids` path. CRITICAL (Codex R3 F4): the Show-only library resolution MUST NOT be gated
behind `_has_active_filters()` — that gate is `False` when ONLY a library filter is set, so a
library-only Show-only would silently never scope. Resolve and intersect WHENEVER a Show-only library
set is active, and do it BEFORE the existing per-manuscript exclusion subtraction (parallels.py
2219-2221) so library-only AND advanced+library cases both compose. Hide stays a POST-FETCH filter
over the result rows (the full-corpus complement cannot be computed from `restrict_sys_ids` alone —
Pitfall 4). The Hide post-fetch filter runs BEFORE export/storage writes so exports are scoped
(Codex R1 MED #6).

Purpose: closes DMF-09. Output: dual-mode parallels library filter at model parity with web `/search`.
