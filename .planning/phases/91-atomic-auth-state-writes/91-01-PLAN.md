Passing `show_error` directly as `show_error_fn` to `_oauth_complete_login` is SAFE — the entire UI-recovery transition (spinner/status hide; error/home show; posthog event) fires atomically within the existing closure. No additional closure wrapping needed.

**However, observed double-posthog risk:** `_oauth_complete_login` ALSO calls `posthog_capture('login_failed', {'reason': 'session_storage_unavailable'|'auth_state_storage_unavailable', 'method': 'google_oauth'})` BEFORE calling `show_error_fn`. Since `show_error_fn === show_error` and `show_error` itself emits `posthog_capture('login_failed', ...)`, the resulting trace will have TWO `login_failed` events per partial-write failure — one with `reason='session_storage_unavailable'` (rich) and one with `reason='Session storage unavailable. Please try again.'` (truncated message text). This is acceptable for Phase 91 (the rich reason is the operational signal; the truncated message-text event is a duplicate but not harmful), and matches the existing behavior pattern of show_error firing posthog for ALL OAuth error paths. Documented as a known minor instrumentation quirk; PostHog dashboard can filter on the rich `session_storage_unavailable` / `auth_state_storage_unavailable` reason tags.

**Future-contributor guidance:** If a future refactor adds spinner/status restoration logic to a NEW UI element on the OAuth callback page, that element MUST be added to `show_error`'s body. The `_oauth_complete_login` helper is intentionally UI-agnostic — it only knows about `status_label` (which it mutates on happy-path) and `show_error_fn` (which it invokes on failure). All other UI state recovery lives inside `show_error`.

@classmethod
def set_auth(cls, user: Dict, profile: Dict = None) -> bool:
    """Set authentication after successful login. Returns False if any
    write fails (prune race) -- caller MUST handle by surfacing an error
    and rolling back any pre-existing partial state.

    Phase 91 D-04 (REVISED per Revision MUST-2 / Codex HIGH catch in
    91-REVIEWS.md): multi-write atomicity is best-effort under NiceGUI
    storage semantics (no compare-and-swap). On partial-write failure we
    roll back ALL successful writes SYMMETRICALLY across the 3 auth keys
    so callers never observe a half-state AND so stale auth_profile from
    a prior session cannot survive (GlobalAuthState.get_role()/is_admin()/
    is_editor() read profile independently of user — leaving stale
    auth_profile would be a security/correctness leak per Codex's HIGH).

    Semantic shift for profile=None:
        Previously: `if profile:` skipped the profile branch entirely,
                    leaving any stale auth_profile from a prior session.
        Now:        `profile is None` triggers a best-effort pop of the
                    PROFILE_KEY so a new login with no profile cannot
                    inherit a stale role.
    """
    if not safe_user_set(cls.USER_KEY, user):
        return False
    if profile is not None:
        if not safe_user_set(cls.PROFILE_KEY, profile):
            # SYMMETRIC rollback: pop BOTH the user write AND any stale
            # profile to ensure no half-state and no role leak.
            safe_user_pop(cls.USER_KEY, None)
            safe_user_pop(cls.PROFILE_KEY, None)
            return False
    else:
        # profile is None: clear any stale auth_profile from a prior
        # session (best-effort -- safe_user_pop returns the default on
        # any failure including no-such-key, so this is idempotent).
        safe_user_pop(cls.PROFILE_KEY, None)
    # Identify user in PostHog for session tracking
    cls._posthog_identify(user, profile)
    return True

**Notes on the test shape:**

1. **No `@pytest.mark.asyncio` markers (Revision MUST-1).** Tests use plain `def test_*(...)` with `asyncio.run(_oauth_complete_login(...))`. This avoids introducing pytest-asyncio as a new dependency. asyncio.run() creates a new event loop, runs the coroutine to completion, closes the loop — perfect for one-shot async-helper tests.

2. **`_RoutingStorage` dict subclass.** New helper class for T-D and T-E. Allows configuring which key writes raise AssertionError. Reads behave as normal dict semantics. Tests verify storage state via `'key' in storage` (dict membership) and `storage.get('key')` (dict access).

3. **`_build_pruned_storage()` helper.** Factored out of T-A/T-C duplication. Returns a MagicMock that raises AssertionError on every access (read, write, pop). Each test calls it fresh; no shared state.

4. **The Late import pattern** (`from web.main import _oauth_complete_login` AFTER monkeypatch) ensures the helper resolves `web.safe_storage.app` against the monkeypatched binding on first access.

5. **T-D's verification uses `'key' in storage` rather than `storage['key']`** because dict subclass `_RoutingStorage` makes membership-tests cheap and unambiguous about state.
