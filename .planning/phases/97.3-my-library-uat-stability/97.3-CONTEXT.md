<decisions>
## Implementation Decisions

### Worker Architecture (R97.3-A)

- **D-01:** **Reuse `FolderWalkWorker`** at `desktop/my_library_tab.py:594` — extend signal signature from `(filepath, mtime_ns, size)` 3-tuple to `(filepath, canonical, mtime_ns, size)` 4-tuple. Push `_canonical_filepath()` off the UI thread INTO the worker. This is Codex's revised Option B (he initially recommended a separate `FolderTreeBuildWorker` but revised after reading the actual `FolderWalkWorker` code — see `97.3-CODEX-CRITIQUE.md`). Rationale: the existing worker is already cancellable, batched, signal-only, and guarded by the AST test `tests/test_folder_walk_worker.py::test_no_widget_mutation`. Option A (canonicalize in UI slot with `processEvents`) does not meet the 100ms responsiveness goal for 100K files at ~1ms/`Path.resolve` on Windows.

- **D-02:** **Worker pre-filters by `_SUPPORTED_EXTENSIONS`** imported from `shared.local_indexer` (single source of truth — also closes R97.3-N). Unsupported files (`.ds_store`, `.git/*`, anything outside `{.docx, .pdf, .txt, .html, .xlsx, .csv}`) are dropped BEFORE stat/canonical/emit, so they pay zero `Path.resolve()` tax. The `desktop/my_library_tab.py:227` literal `SUPPORTED = {'.pdf', '.docx', '.txt'}` set is deleted; the new UI slot reads the extension set from the worker's filtered output (no UI-side extension knowledge needed).

- **D-03:** **Token/generation guard for stale batches** — `_UnifiedFileTreeWidget` maintains a monotonic `_tree_token: int` incremented on every `populate_for_folder` call. The worker captures the token at construction; each `batch_emitted` carries the token; the UI slot compares before applying. If user cancels mid-walk or selects another folder, queued in-flight batches are silently dropped. This is the Codex-flagged pitfall ("queued batches can arrive after Cancel or after selecting another folder").

### Tree UX (R97.3-A)

- **D-04:** **Never `expandAll()`** — the populated tree starts collapsed to root regardless of size. User expands subtrees manually. (This OVERRIDES the SPEC.md's earlier "bounded expandAll(≤500)" — Codex caught the SPEC-discuss drift; SPEC.md was updated to match this decision.)

- **D-05:** **Cancel mid-populate clears the tree entirely** — `_cancel_existing_tree_worker()` calls `_worker.cancel()`, then `self.clear()` + resets `_displayed_paths` + `_leaf_by_path`. No "partial results" view, no resume. Empty state restored. (Rationale: simpler than partial-results state machine; matches user's "workable narrow" preference.)

### Discovery Phase UX (R97.3-E)

- **D-06:** **Indeterminate Qt busy progress bar** via `QProgressBar.setRange(0, 0)` during the enumeration phase of `LocalIndexerWorker`. Once enumeration finishes and indexing begins, `setRange(0, 100)` restores determinate mode and the existing `progress_updated(int, int, str)` signal resumes driving real percent.

- **D-07:** **Status text reused via existing `GenizahGUI.statusBar()`** — `self._parent_window.statusBar().showMessage("Discovering files… / מאתר קבצים…", 0)` (`0` = until next `showMessage` clears it). Status text is cleared when indexing begins. No new label widget. RTL handling is automatic in Qt's QStatusBar for the Hebrew portion.

### Skip → No Auto-Rescan (R97.3-D)

- **D-08:** **Auto-fading status bar message ~5 seconds** when Skip is clicked on the recovery modal — `statusBar().showMessage("Recovery skipped. Use Refresh to rescan. / ההתאוששות דולגה. לחץ Refresh לסריקה מחדש.", 5000)`. The 5000ms timer is Qt-managed; no manual cleanup needed.

- **D-09:** **One-shot `_skip_startup_rescan_once: bool` instance flag** — set to `True` in `_show_recovery_modal` when the Skip button is clicked; read AND cleared by `_auto_rescan_on_startup` on its first invocation. If `True` at entry, the function returns early after showing the D-08 status message. Subsequent manual Refresh in the same session works normally. The Resume and Restart paths do NOT set this flag (both intentionally trigger a fresh scan).

### Reset Guard Simplification (R97.3-B)

- **D-10:** **Drop the `start_recovery_probe()` check from `_update_reset_button_state`** entirely. Guard collapses to:
  ```python
  worker_running = self._worker is not None and self._worker.isRunning()
  if worker_running:
      self._btn_reset.setEnabled(False)
      # ... "Stop the active scan first" tooltip
  else:
      self._btn_reset.setEnabled(True)
      # ... reassuring tooltip
  ```
  `LocalIndexer.reset_my_library()`'s own 7-step protocol (path-safety pre-check + handle-close + retry-rename + LAB-rollback + fail-loud + deferred-GC) is the load-bearing safety; the UI guard does not duplicate it. The Phase 97.2 tests `test_reset_my_library_full_cycle` and `test_reset_my_library_lab_rename_failure_rolls_back_local` already cover the internal-safety side.

### MuPDF Suppression (R97.3-C)

- **D-11:** **`fitz.TOOLS.mupdf_display_warnings(False)` at `shared/local_indexer.py` module import** (immediately after `import fitz`, wrapped in `try/except AttributeError` for forward-compat with future PyMuPDF versions). Process-wide stderr is NOT redirected — that would hide unrelated failures (Codex's pushback against my "could also capture stderr to a debug log" suggestion). Constructor-level placement was considered and rejected as it'd re-call the API per `LocalIndexer` instance for no benefit.

### `prior_status` Preload (Codex-surfaced new risk)

- **D-12:** **`prior_status` cached in memory on the `MyLibraryTab` instance** — populated once at `__init__` (or first folder-selection if startup latency is a concern). The click path NEVER issues a fresh `local_files` DB query. Cache is invalidated (cleared) at the end of every `_on_worker_finished` / `_on_worker_error` so the next click picks up newly-scanned status. Codex flagged this as a new R97.3-A risk: even with the walk off-thread, a 100K-row `local_files` DB lookup on each click would still miss the 100ms target. SPEC.md acceptance was updated to require ≥100K prior_status rows in the test fixture.

### Test Pitfalls (Codex-flagged, must land as explicit tests)

- **D-13:** Test pitfall #1 — **stale batch token guard** (D-03): a unit test that constructs a `FolderWalkWorker`, queues a batch, increments the UI token, applies the batch, asserts NO tree mutation occurred.
- **D-14:** Test pitfall #2 — **unsupported files are NOT canonicalized**: a unit test with a fixture folder of `.ds_store` + `.git/objects/*` + supported files, monkeypatches `_canonical_filepath` to count calls, asserts call count == number of supported files (not total files).
- **D-15:** Test pitfall #3 — **non-following directory traversal**: an explicit behavioral test creating a Windows junction (or `os.symlink` on test platforms that support it) pointing OUT of the test tree, asserts the worker does NOT emit any files from the junction target. Codex flagged that `tests/test_folder_walk_worker.py` currently does NOT pin this (it only asserts batch sizing + no widget mutation).

- Exact line where `mupdf_display_warnings(False)` is called (anywhere in `shared/local_indexer.py` top-of-module after `import fitz` is fine).
- Internal helper method names (e.g., `_cancel_existing_tree_worker`, `_on_tree_batch`, `_invalidate_prior_status_cache`).
- Whether to land the SPEC.md acceptance test (≥100K prior_status rows) using a `pytest.fixture` that bulk-inserts via `local_files.executemany` or a pre-built SQLite fixture file.
- Wave/plan grouping during plan-phase (recommended: one wave per requirement is overkill — group A+E+N as the "tree refactor" wave since they all touch `_populate_node`).

<specifics>
## Specific Ideas

- Codex's Option B framing (extend `FolderWalkWorker` signal to 4-tuple) is the locked direction for D-01. The 4-tuple is `(filepath, canonical, mtime_ns, size)` — not 5-tuple, not a dataclass; keep the wire format minimal.
- The D-08 status message text is verbatim: `"Recovery skipped. Use Refresh to rescan. / ההתאוששות דולגה. לחץ Refresh לסריקה מחדש."` — use this exact wording (single string, ` / ` separator).
- The D-07 status text is verbatim: `"Discovering files… / מאתר קבצים…"` (with the ellipsis character `…`, not three dots).
- Worker pre-filter happens BEFORE `stat()` per D-02 — meaning the worker checks extension first, then stats only supported entries. Saves both `os.stat` syscalls and `_canonical_filepath` calls on unsupported files.
- The D-12 `prior_status` cache is per-`MyLibraryTab` instance (not module-level). Cleared on worker finish so a fresh scan refreshes it.
- The new acceptance criterion (e) "tree starts collapsed to root" maps to a Qt test that calls `topLevelItem(0).isExpanded()` and asserts `False`.

</specifics>

<deferred>
## Deferred Ideas

These came up during discussion or Codex review but belong in other phases:

- **N1 — `prescan_count_all()` synchronous on UI thread** during manual Refresh on large registered libraries. Separate code path from Bug A; not in user's UAT repro. Defer to v7.15+.
- **N2 — `_show_recovery_modal` only handles `running_runs[0]` with no `ORDER BY`.** Multiple orphan rows are silently lost. Add `ORDER BY started_at DESC` to `start_recovery_probe` and loop over all rows. Edge case (multiple stale running rows are rare). Defer to v7.15+.
- **Resume button real behavior.** Currently `_show_recovery_modal::Resume` just marks the run completed; real resume is deferred per Phase 97 R-01 comment. Either implement real resume or relabel the button to avoid misleading UX. Defer to v7.15+.
- **Aggregate enumeration progress bar.** Show file-count growing during discovery ("Discovering 1,432 files…"). Considered as an Area 3 option but rejected for scope. Requires worker to emit periodic count signals. Defer to v7.15+.
- **MuPDF warnings discoverable for diagnostics.** Codex considered redirecting MuPDF warnings to a debug log; rejected for scope. If needed later, use `fitz.TOOLS.mupdf_warnings()` to capture per-document and log at DEBUG level. Defer to v7.15+.
