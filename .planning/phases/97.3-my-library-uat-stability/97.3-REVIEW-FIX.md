### WR-01: Cancel button can be disabled while a newer tree-worker is still running

**Files modified:** `desktop/my_library_tab.py`
**Commit:** 8d2d9cc9
**Applied fix:** Rewrote `_on_tree_population_ended` to short-circuit on BOTH the
scan worker (`self._worker`) AND the current tree worker
(`self._unified_tree._tree_worker`). Previously the method checked only the scan
worker, so a stale `finished_signal` from a superseded tree-worker (created during
rapid Folder A → Folder B switching) would grey out the Cancel button even though a
newer tree-worker was still walking the filesystem. The fix computes
`tree_still_running` (guarded with `getattr` + `hasattr(...,"isRunning")` for
partial-construction safety) and only disables Cancel when neither worker is
running. This is a genuine race-condition fix against the "Cancel always reflects
whether SOMETHING is cancellable" invariant (R97.3-A acceptance) — applied exactly
as the review recommended.

Verification: Tier 1 (re-read confirms fix present, surrounding code intact) +
Tier 2 (`ast.parse` syntax check passed). The desktop my_library_tab test suite was
run to confirm no regression.

### WR-02: Tree pre-filter includes `.html`/`.xlsx`/`.csv` — extensions with no extraction path

**Files modified:** `desktop/my_library_tab.py`
**Commit:** 4712f2c0
**Applied fix:** Documentation clarification (NOT a code reversion). The reviewer
flagged WR-02 as ambiguous and offered Fix option (a) — narrowing the worker filter
back to `{'.pdf','.docx','.txt'}`. That option is WRONG here: CLAUDE.md's Phase 97.3
"Recently Changed" entry documents R97.3-N, which DELIBERATELY deleted the old
3-extension literal and unified the opt-out tree on the broader
`_SUPPORTED_EXTENSIONS` (`.docx/.pdf/.txt/.html/.xlsx/.csv`). Narrowing the filter
would revert R97.3-N.

The legitimate residual concern is purely a signposting gap (users could misread
`.html`/`.xlsx`/`.csv` rows that currently have no extraction path as "the tree is
broken"). The lightest-touch resolution that addresses this without reverting
R97.3-N is a clarifying comment at the `FolderWalkWorker` extension pre-filter site,
explaining that `_SUPPORTED_EXTENSIONS` is the intentional R97.3-N opt-out surface,
that it is deliberately broader than the indexer's extraction set, that some rows
may show an empty/unsupported Status until extraction lands, and that the filter
must NOT be narrowed back to the old literal. This makes the design intent
self-documenting for the next maintainer who hits the same question the reviewer did.

Verification: Tier 1 (re-read confirms comment present, code intact) + Tier 2
(`ast.parse` syntax check passed).
