## Area 1: Tree Worker Reuse Strategy (R97.3-A)

### Q1: How to bridge FolderWalkWorker's flat batch signal to tree needs?

| Option | Description | Selected |
|--------|-------------|----------|
| Reuse FolderWalkWorker as-is; UI slot canonicalizes + builds hierarchy | Zero new classes. UI slot does Path.resolve via processEvents chunks. | |
| Extend signal to (filepath, canonical, mtime, size) — canonicalize in worker | Pushes canonicalize off UI thread; changes signal arity (no consumers yet). | ✓ (via Codex) |
| Write FolderTreeBuildWorker emitting tree-shaped records | Max decoupling but duplicates os.walk. | |

**User's choice:** "Ask Codex" — delegated to Codex for technical sub-decision.

**Codex critique:** Selected **extend signal to 4-tuple** (revised from his initial Option C recommendation after reading the actual `FolderWalkWorker` code). Rationale: the existing worker is already cancellable, batched, signal-only, and the AST guard `test_folder_walk_worker.py::test_no_widget_mutation` only enforces "no QWidget mutation" — it doesn't pin tuple arity. Option A leaves `_canonical_filepath()` on the UI thread, which does not meet the 100ms goal for 100K files at ~1ms/resolve on Windows. Option C duplicates a walker without enough payoff.

### Q2: Filter location — worker or UI slot?

| Option | Description | Selected |
|--------|-------------|----------|
| Worker pre-filters by `_SUPPORTED_EXTENSIONS` (also closes R97.3-N) | Single source of truth; unsupported files pay zero Path.resolve tax. | ✓ (via Codex) |
| Worker emits all; UI slot filters | Format-agnostic worker; bigger batches, pointless work. | |
| Worker emits all; UI shows full tree (unsupported greyed out) | Users see everything; scope creep — not in SPEC. | |

**User's choice:** "Ask Codex" — delegated.

**Codex critique:** Selected **worker pre-filter**. Rationale: closes R97.3-N at the same time and keeps signal traffic proportional to visible/indexable leaves. The current UI-side literal at `desktop/my_library_tab.py:227` is exactly how the drift happened.

### Codex-surfaced SPEC corrections

1. **`tests/test_folder_walk_worker.py` does NOT pin `follow_symlinks=False`** — only batch sizing + no widget mutation. SPEC.md's claim that this is already covered was wrong. Added explicit test requirement to SPEC.md acceptance (R97.3-A criterion d).
2. **SPEC.md still mentioned "bounded `expandAll(≤500)"** but the locked Area 2 decision says NEVER. Updated SPEC.md target + acceptance (R97.3-A criterion e).
3. **NEW RISK: `populate_for_folder` loads `prior_status` synchronously** — if 100K rows exist in `local_files`, the click path still misses 100ms even with the walk off-thread. Updated SPEC.md acceptance to require ≥100K prior_status rows in the test fixture; captured implementation strategy in D-12.

### Codex-flagged pitfalls (folded into D-13, D-14, D-15)

- **Stale batches after Cancel / folder-switch** must be dropped via token guard (D-03 + D-13 test).
- **Unsupported files must NOT be canonicalized** (D-14 test).
- **Non-following directory traversal** needs an explicit test (D-15).

## Area 2: Tree Responsiveness Policy (R97.3-A)

### Q1: `expandAll()` policy?

| Option | Description | Selected |
|--------|-------------|----------|

### Q2: Cancel mid-populate behavior?

| Option | Description | Selected |
|--------|-------------|----------|
