## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical Functionality] Windows junction pruning beyond `followlinks=False`**

- **Found during:** Task 2 (GREEN FolderWalkWorker — `test_junction_not_followed` failed even with `os.walk(followlinks=False)`)
- **Issue:** The plan's literal text "Clicking a folder containing a Windows junction does NOT recurse into the junction target (followlinks=False in worker)" describes a property that CANNOT be satisfied by `followlinks=False` alone on Windows. Python's `os.path.islink()` returns False for junctions (`FILE_ATTRIBUTE_REPARSE_POINT`), so `os.walk` does not consider them symlinks and descends into them regardless of `followlinks=False`. Empirically verified with `mklink /J` on Win11. This would have left the elevation-of-privilege threat (T-97.3-07 in the plan's threat model) UNMITIGATED if shipped as-written.
- **Fix:** Added an explicit `_is_reparse_point(path)` helper using `os.stat(path, follow_symlinks=False).st_file_attributes & 0x400` (FILE_ATTRIBUTE_REPARSE_POINT) and prune `dirs[:]` in place inside the `os.walk` loop. POSIX symlinks ARE caught by `followlinks=False` as documented.
- **Files modified:** desktop/my_library_tab.py FolderWalkWorker.run (added _is_reparse_point + dirs[:] pruning)
- **Verification:** `test_junction_not_followed` PASSES on Windows with a real `mklink /J` junction; the AST fallback (for CI without admin/dev-mode) still verifies `followlinks=False` + `onerror=...` keyword presence so the test never silently skips.
- **Committed in:** `c50bca29` (Task 2 commit)

**2. [Rule 2 - Missing Critical Functionality] _wait_for_tree_worker helper redesign**

- **Found during:** Task 4 (GREEN _UnifiedFileTreeWidget — `test_tree_starts_collapsed_after_populate` initially timed out)
- **Issue:** The plan's test sketch used `QSignalSpy(worker.finished_signal).wait(...)`. On a tiny fixture folder, the worker frequently finishes BEFORE the spy is attached, and QSignalSpy cannot capture past emissions. The test would intermittently fail in CI even though production behaviour was correct.
- **Fix:** Replaced the QSignalSpy approach with a polling loop that waits for `tree._tree_worker` to be set to `None` (which `_release_finished_worker` does AFTER the UI-thread `finished_signal` slot drains). This is a reliable observable sentinel for "worker has fully exited AND UI has processed the result".
- **Files modified:** tests/test_unified_tree_async_populate.py (`_wait_for_tree_worker` helper)
- **Verification:** All 7 unified-tree tests now PASS consistently; the helper handles both the "worker still running" case (returns True when it eventually exits) AND the "worker already finished before helper called" case (returns True immediately).
- **Committed in:** `a796ae40` (Task 4 commit) — initial; `75365e25` (Task 6 commit) — final form
