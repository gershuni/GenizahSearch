## Decisions Made

- **Test 4 fixture strategy:** in-test PDF construction via `fitz.open() + xref_stream injection` rather than a checked-in binary fixture. Pros: deterministic, version-controlled in test source, no risk of stale binary; cons: depends on PyMuPDF's content-stream parser behavior being stable (which it has been since at least 1.20).
- **`capfd` instead of `capsys`:** confirmed empirically that PyMuPDF emits its `MuPDF error:` / `MuPDF warning:` lines via C-level `fprintf(stderr, ...)`. Python's `sys.stderr = io.StringIO()` does NOT intercept these. `capfd` performs OS-level fd 2 duplication and catches them. SPEC R97.3-C acceptance is meaningful only when fd-level capture is used.
- **Suppression placement (top-of-module, not constructor):** matches D-11 literal text. A constructor-level placement would re-call the API per `LocalIndexer` instance; module-level is correct because the suppression is a process-wide PyMuPDF setting.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical Functionality] Added `fitz.TOOLS.mupdf_display_errors(False)` alongside plan's named `mupdf_display_warnings(False)`**

- **Found during:** Task 3 (MuPDF stderr suppression)
- **Issue:** The plan instructed to call ONLY `fitz.TOOLS.mupdf_display_warnings(False)` at module import. Empirical verification using PyMuPDF 1.27.2.3 showed this API silences `MuPDF warning:` lines but does NOT silence `MuPDF error:` lines. The user's UAT noise was 624× `MuPDF error: ... unknown keyword: 'TF'` (errors, not warnings). SPEC R97.3-C verbatim acceptance ("extract_pdf_pages on a malformed-PDF fixture produces zero `MuPDF error:` lines on stderr") would have FAILED if only the plan's named API was called.
- **Fix:** Added a second adjacent `try/except Exception` block calling `fitz.TOOLS.mupdf_display_errors(False)`. Each suppression call has independent fallback to `logger.debug` so a future API change to either one does not crash module import.
- **Files modified:** `shared/local_indexer.py` (3 extra lines + comment block)
- **Verification:** `tests/test_mupdf_warnings_suppressed.py::test_extract_pdf_pages_emits_no_mupdf_error_to_stderr` (uses `capfd`) now PASSES on a deterministic malformed-Tf fixture. With only the plan's named API, the test FAILS with the captured MuPDF error string.
- **Committed in:** `40015b61` (Task 3 commit)

The fix is documented inline in the source as a "Deviation from PLAN literal text (Rule 2)" comment block, citing the SPEC acceptance and the both-APIs-needed rationale.
