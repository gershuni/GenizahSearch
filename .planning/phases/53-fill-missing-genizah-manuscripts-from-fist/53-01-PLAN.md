2. Queries fist_data/FIST.db for gap records with AlmaId deduplication:
   ```sql
   SELECT ia.AlmaId, i.Shelfmark, i.CollectionId, c.LibraryId
   FROM dbo_Inventory i
   JOIN dbo_InventoryAlma ia ON ia.InventoryId = i.InventoryId
   JOIN CODE_Collection c ON i.CollectionId = c.CollectionId
   WHERE i.RecordStatus = 0
   AND ia.AlmaId IS NOT NULL AND ia.AlmaId != ''
   ```
   Then GROUP BY AlmaId — emit exactly one row per distinct AlmaId.

3. **Deduplication rules** for AlmaIds with multiple inventory rows:
   - If all rows have the same LibraryId: pick the shortest non-empty shelfmark
   - If rows span multiple LibraryIds (3 known cases): use a hardcoded override table mapping those AlmaIds to the preferred library/shelfmark. Log all cross-library collisions for review.
   - For AlmaIds with multiple shelfmark variants from the same library: collapse into pipe-separated `call_numbers` column (matching existing libraries.csv convention)

4. Maps LibraryId to library_code using a dict keyed by explicit LibraryId (NOT by name string). Build from the live distinct gap set. Key mappings:
   - 233→CUL, 79→JTS, 229→RNL, 242→Manchester, 235→Oxford, 238→BL
   - 177→Mosseri, 169→AIU, 248→Westminster, 147→HAS, 90→Katz, 130→Senckenberg
   - 510→JCBerlin, 515→Warsaw, 236→Birmingham, 292→Leeds, 408→IOM
   - New codes only for LibraryIds actually present in the gap set (verify before adding)
   - Assert that every distinct gap LibraryId maps cleanly before writing output. Fail loudly on unmapped IDs.

5. For titles, queries **fist_data/fjms_enrichment.db** (correct schema):
   ```sql
   SELECT AlmaId, GenizahTitleOrgTitle
   FROM catalog
   WHERE GenizahTitleOrgTitle IS NOT NULL AND GenizahTitleOrgTitle != ''
   AND AlmaId IN (gap_alma_ids)
   ```
   **Title dedup rule**: For AlmaIds with multiple distinct non-empty GenizahTitleOrgTitle values (828 cases), populate the title ONLY when there is exactly one distinct value. For ambiguous cases, leave title empty and log them to a separate `fist_gap_ambiguous_titles.txt` for human review.

6. Generates CSV rows to a standalone **fist_gap_rows.csv** first (NOT directly into libraries.csv):
   - Column 0: AlmaId as-is from FIST
   - Column 1: empty
   - Column 2: Shelfmark(s) — single or pipe-separated if multiple variants for same AlmaId
   - Column 3: library_code from mapping
   - Columns 4-6: empty
   - Column 7: title from FJMS catalog (when unambiguous) or empty
   - Use Python csv.writer to handle comma-containing shelfmarks properly

7. Skips: AlmaId already in libraries.csv, Shelfmark contains "Undefined Shelfmark", LibraryId has no mapping.

8. After generating fist_gap_rows.csv, validates it:
   - Every row has exactly 8 columns
   - No duplicate AlmaIds within the file
   - All library_codes are valid (present in LIBRARY_CODES after Task 2)
   - No "Undefined Shelfmark" values
   Then appends validated rows to libraries.csv.

9. Also emits a manifest file `fist_gap_manifest.txt` with one AlmaId per line, for downstream test validation.

10. Supports --dry-run flag (prints stats without writing any files). Supports --validate-only (reads existing fist_gap_rows.csv and validates without regenerating).

11. Prints summary: total gap records, dedup stats (how many AlmaIds had multiple inventory rows), records appended, skipped by reason, library distribution, ambiguous titles count.
