  <how-to-verify>
**Setup:**

1. Start the web app:
   ```
   python -m web.main
   ```
   The app should start on port 8080 (or 8081). Watch the terminal output for the actual URL.

2. Open the URL in a browser (likely http://localhost:8080).

**Spot-check 1: /search JSON download (EXPORT-01, EXPORT-04, locator round-trip)**

1. Navigate to the `/search` page.
2. Run a query — for Hebrew RTL coverage use `אגדה` (mode: text). Wait for results to render.
3. Confirm the toolbar shows three icon-only buttons in this order: Word (icon: description), Excel (icon: table_view), JSON (icon: data_object). Hover the JSON button and confirm tooltip says "Export JSON" (or its Hebrew equivalent if the language is set to Hebrew).
4. Click the JSON button. The browser should trigger a file download named `genizah-search-2026-04-27T<HHMMSS>.json` (UTC timestamp).
5. Open the downloaded file in a UTF-8-aware text editor (VS Code, Notepad++, etc.):
   - **Valid JSON?** Confirm no parse errors when opened in a JSON-aware viewer.
   - **Hebrew renders natively?** Look for `אגדה` or any Hebrew text in the response — it must appear as native characters, NOT `אגדה`.
   - **Envelope shape?** Confirm top-level keys: `schema_version`, `source: "search"`, `query: "אגדה"`, `mode: "text"`, `gap`, `filters`, `count`, `total`, `warnings: []`, `generated_at`, `results: [...]`.
   - **Locator on every item?** Pick one item from `results[]`. Confirm it has BOTH `uid` (string, may be empty) AND `locator: {sys_id, volume_ie, p_num}` (dict).
   - **Score rounded?** Confirm scores are 4 decimals max (e.g., `0.8731`, not `0.8731129`).
   - **No `full_text` field on items?** Confirm items have `excerpt` instead (max ~500 chars).
6. **EXPORT-04 collision check:** Click the JSON button a second time within ~5 seconds. Confirm the browser saves a file with a DIFFERENT name (the timestamps should differ by at least 1 second).

**Spot-check 2: /parallels JSON download (EXPORT-02, D-11, D-13)**

1. Navigate to the `/parallels` page.
2. Confirm the JSON button is initially DISABLED (greyed out).
3. Paste in a multi-sentence Hebrew or English source text (anything ≥3 chunks; e.g., the first three lines of a Mishnah passage).
4. Run the composition search. Wait for results.
5. Confirm the JSON button is now ENABLED.
6. Click it. Download the file `genizah-parallels-{ts}.json`.
7. Open the file:
   - **`source: "parallels"`** at the top
   - **`source_text` echoed** (the text you typed)
   - **`results` AND `filtered` are SEPARATE top-level arrays** (D-11)
   - **One result per manuscript** with a `matches: [...]` array (D-13). If your source has 3 chunks all matching the same manuscript, the matches array on that manuscript should have 3 entries (assuming Plan 02 Path A landed and the search engine produced three chunk hits).
   - Each match has keys `chunk_index` (0-based int), `source_chunk_text`, `manuscript_snippet`, `score`.

**Spot-check 3: Existing handlers unchanged (regression baseline)**
