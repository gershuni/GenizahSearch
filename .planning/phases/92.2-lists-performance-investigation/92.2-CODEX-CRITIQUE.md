## Codex Output (verbatim)

### 1. Memo Location
**ISSUE** — `nicegui.context.client` is not request-scoped. NiceGUI creates one `Client` for the page, keeps it in `Client.instances`, then reuses it across WebSocket events, async continuations, and `ui.timer` callbacks until disconnect/delete. So this reopens a per-tab long-lived cache, not an intra-request memo.

Fix: use task/render-scoped memo instead, e.g. a `WeakKeyDictionary` keyed by `asyncio.current_task()` plus `(_session_uuid, access_token)`, or an explicit `/lists` render-scope context manager. If you still use `context.client`, clear on auth mutation and client delete.

### 2. Key Composition
**CONFIRM** — `(_session_uuid, access_token)` is enough. The Supabase client auth state only depends on the bearer access token; refresh token is not applied to PostgREST/functions/storage. Skip memo entirely if `_session_uuid` is absent.

### 3. B1 Scope
**ISSUE** — `_render_list_item` is private to `project_tree.py`, but the proposed refactor misses two real fetch sources: `get_lists_by_project()` re-fetches `.data`, and `web/pages/lists.py` selected-list header calls `state.lists_mgr.data` then `get_list_display_color()` on fresh manager instances.

Fix: add `data=None` to `get_lists_by_project()` and `get_list_display_color()`, pass the one `data` object through `project_tree.py`, and capture `lists_mgr = state.lists_mgr` once inside `render_list_content()`.

### 4. B2 Batched Count Query
**ISSUE** — RLS is fine, but the no-migration query shape is fragile. `list_items` RLS correctly limits rows through `user_lists`, but `select('list_id').in_(...)` transfers every item row and can silently undercount if Supabase/PostgREST row caps apply.

Fix: prefer an RPC/security-invoker SQL function returning `{list_id,count}`. If you keep Python aggregation, explicitly document the row cap assumption and page/range until exhausted.

### 5. `get_list_display_color` Signature
**CONFIRM** — safe if `data` is optional. Actual Python callers are only `project_tree.py` and `web/pages/lists.py`; the `discoveries.py` lines are `_get_list_item_count`, not color. Do not make `data` required.

### 6. NLI Cache Retry Timing
**ISSUE** — retry-only misses in-process write contention. `_persist_positive_cache_snapshot()` can call `_save_nli_persistent_cache()` concurrently.

Fix: add a module-level `threading.Lock` around temp-write + replace, retry `os.replace` on `PermissionError` / WinError 5 with `100ms / 250ms / 500ms`, warn once on final failure, clean temp, do not raise.

### 7. Structural Missing Piece
**ISSUE** — the query formula in the brief is wrong. Project-contained lists call `_render_list_item(... show_color=False)`, so they do not trigger `get_list_display_color()`. Current cost is closer to `4 + L + 2S`, where `S` is standalone/system rendered with color, not always `5 + 3L`.

Instrumentation still matters. Plan 92.2-02 should be sketched, not locked, until 92.2-01 confirms query count, client-build count, and wall-clock distribution.

**Overall verdict:** ship with these 5 adjustments.
