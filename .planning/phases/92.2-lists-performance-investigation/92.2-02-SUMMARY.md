# Phase 92.2 Plan 02: Lists Performance Fix Summary

Task-scoped WeakKeyDictionary memo + batched RPC + threaded data/counts closes the ~36s /lists warm-render regression introduced by Phase 92.1's reader migration.

## What Was Built

### D-MEMO-01..04 (Task 1): Task-scoped get_user_client() memo

`web/supabase_client.py` — `_user_client_memo: WeakKeyDictionary` keyed by `asyncio.current_task()` with inner dict keyed by `(get_persisted_session_uuid(), access_token)`. Deduplicates the ~30 `create_client()` builds per `/lists` render to 1. Phase 90 D-12 "no cross-request caching" invariant preserved by construction: task end = GC = entry gone. `asyncio.to_thread` / `run.io_bound` callers bypass memo correctly (current_task() is None in thread pool). 9 behavioral tests.

### D-FANOUT-01 (Task 2): data=None threading

`web/user_lists.py` — `get_list_display_color()` and `get_lists_by_project()` accept `data: Optional[Dict] = None` with fallback to `_get_cached_data()`. When caller threads data, no second Supabase fetch occurs. Already shipped by Plan 92.2-01 Task 2b; Task 2 confirmed + added 6 behavioral tests.

### D-FANOUT-02 (Task 3+5): Batched RPC

`migrations/add_list_item_counts_rpc.sql` — zero-arg `get_list_item_counts_for_user()` RPC with `SECURITY INVOKER`, `STABLE`, `SET search_path = public`, `REVOKE ALL FROM PUBLIC, anon`, `GRANT EXECUTE TO authenticated, service_role`, `CREATE INDEX IF NOT EXISTS idx_list_items_list_id`, soft-delete filter, rollback comment (Reviews MUST-FIX 2).

`web/supabase_client.py:get_list_item_counts()` — Python helper calling the zero-arg RPC via `get_user_client()`. RE-RAISES on non-JWT errors so caller's `counts=None` fallback path is reachable (Reviews MUST-FIX 1). 6 behavioral tests.

### D-FANOUT-01 extension (Task 6): Thread data+counts through all render paths

`web/components/project_tree.py`:
- `_resolve_list_item_count()` helper at module level: `counts=None` → legacy `_get_list_item_count()` fallback; `counts={}` → return 0 WITHOUT fallback (Reviews MUST-FIX 1)
- `create_project_tree()`, `_render_project_group()`, `_render_list_item()` all accept `data=` and `counts=` kwargs

`web/pages/lists.py`:
- `_COUNTS_UNSET` sentinel distinguishes "caller didn't pass counts" from "counts intentionally None"
- `_load_list_item_counts()` helper returns None on RPC failure (never {})
- `render_lists_sidebar()` — pre-merged version preserves Plan 92.2-01 instrumentation + adds counts threading + `_select_from_sidebar` closure threading the triple to `select_list`
- `select_list()`, `render_list_content()`, `refresh_ui()`, `async_refresh_ui()` all accept+thread `lists_mgr`+`data`+`counts` (Reviews Codex-HIGH 1)
- `render_list_content` captures `lists_mgr` once, uses threaded `data` for color lookup, uses `counts` for `expected_count` display
- `async_refresh_ui` consumes `refresh_data()` return Dict and threads it forward (Reviews Codex-HIGH 2 — avoids double-fetch)

`web/user_lists.py`:
- `refresh_data() -> Dict` (was void) — returns fetched data dict from all 3 branches (Reviews Codex-HIGH 2)

3 behavioral tests for `_resolve_list_item_count`.

### D-NLI-01 (Task 7): NLI cache os.replace lock+retry

`web/api.py`:
- Module-level `_nli_persist_lock = threading.Lock()` — acquired BEFORE temp-file write
- `_save_nli_persistent_cache()` retry loop: 100/250/500ms on `os.replace` failure
- Returns `bool` (True on success, False on exhaustion); callers ignore return
- WARNING logged exactly once on final failure; temp file cleaned up

3 behavioral tests: retry-succeed, all-fail-warns-once, concurrent serialization (barrier BEFORE lock per Reviews Codex-LOW-1).

### D-DOC-01 (Task 8): SUPABASE_GUIDE.md wording fix

Removed `discoveries` from the partial-auth tables list. Added explanatory note: `discoveries` has `TO public USING (is_hidden=false)` SELECT policy only (no `TO authenticated` branch per `scripts/fix_rls_policies.sql:60-95`), so anon and authenticated clients return identical rows and `get_client()` reads are correct.
