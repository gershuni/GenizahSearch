**Problem:** Language is stored only in a Python global variable `_current_lang` in translations.py. On `ui.navigate.reload()`, this resets to hardcoded `'he'`. Language choice is lost.

**Fix in web/main.py:**

1. In `toggle_lang()` (around line 1645-1649), persist the new language to `app.storage.user` BEFORE calling reload:
```python
def toggle_lang():
    current = get_language()
    new_lang = 'en' if current == 'he' else 'he'
    try:
        app.storage.user['ui_language'] = new_lang
    except Exception:
        pass
    set_language(new_lang)
    ui.navigate.reload()
```

# Restore persisted language preference
try:

    pass

**Important:** NiceGUI's `app.storage.user` is per-browser-tab persistent storage. It survives `ui.navigate.reload()` calls. Using `'ui_language'` as the key to avoid collisions with other storage keys.

  <name>Task 2: Distinguish language-switch from cross-page navigation in reading desk restore</name>
  <files>web/pages/browse.py</files>
  <action>
**Problem:** The initialization block at lines 3648-3667 calls `_restore_reading_desk_state()` whenever `initial_sys_id` is present OR absent. It doesn't distinguish between:
- Language switch: `ui.navigate.reload()` preserves same URL params, user expects same reading desk
- Cross-page navigation: `ui.navigate.to('/browse?sys_id=X')` has NEW sys_id, user expects that manuscript

**Fix the initialization block** (around lines 3648-3667):

Replace the `elif initial_sys_id:` block with logic that checks whether the initial_sys_id is one of the persisted reading desk entries:

```python
elif initial_sys_id:
    # Determine if this is a language-switch reload (same manuscripts)
    # or cross-page navigation (different manuscript)
    saved_rd = None
    try:
        saved_rd = app.storage.user.get('reading_desk_state')
    except Exception:
        pass

    if saved_rd and saved_rd.get('entries'):
        # Check if initial_sys_id matches one of the persisted desk entries
        persisted_sids = {e.get('sys_id', '') for e in saved_rd['entries']}
        if initial_sys_id in persisted_sids:
            # Language-switch case: sys_id is one of the desk's manuscripts
            # Restore the full reading desk
            if not _restore_reading_desk_state():
                load_page(p_num=initial_page)
        else:
            # Cross-page navigation: user wants a DIFFERENT manuscript
            # Clear stale reading desk state and load the requested manuscript
            try:
                app.storage.user.pop('reading_desk_state', None)
            except Exception:
                pass
            load_page(p_num=initial_page)
    else:
        # No saved reading desk state, normal page load
        load_page(p_num=initial_page)
```

Also update the `else:` block (no initial_sys_id, around line 3655-3667) to handle the same distinction. If there's no sys_id in the URL but reading desk state exists, this could be a language-switch from a reading desk that was entered without a URL sys_id (e.g., via "Add to View" from the toolbar). Keep the existing restoration logic here:

```python
else:
    # No sys_id in URL -- try to restore reading desk (language-switch case)
    if _restore_reading_desk_state():
        pass  # Reading desk restored successfully
    else:
        # Try to restore previous position
        saved_position = app.storage.user.get('browse_position')
        if saved_position and saved_position.get('sys_id'):
            state.sys_id = saved_position['sys_id']
            state.shelfmark_query = saved_position.get('shelfmark', '')
            load_page(p_num=saved_position.get('p_num', 1))
        else:
            update_content()
```

**Key insight:** The `else` branch (no sys_id) is unchanged because if someone navigates to /browse without a sys_id and reading desk state exists, it IS a legitimate restore scenario (language switch from a desk that was entered standalone).

**Also add debug logging** to `_restore_reading_desk_state()` to help diagnose future issues:

- On success: `print(f"[ReadingDesk] Restored {len(frag_info)} entries")`
- The existing error logging is fine.
