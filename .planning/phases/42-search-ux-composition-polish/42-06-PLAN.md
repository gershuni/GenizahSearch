Wrap the `execute_search` call + `results_signal.emit` in a try/except that catches InterruptedError. On InterruptedError, emit whatever partial results exist. Since execute_search returns results at the end, we need to handle partial results differently:

In `SearchThread.run()`, change to:
```python
def run(self):
    try:
        def cb(curr, total):
            if self.cancel_flag:
                raise InterruptedError("Search cancelled by user")
            self.progress_signal.emit(curr, total)
        results = self.searcher.execute_search(
            self.query, self.mode, self.gap,
            progress_callback=cb,
            exclude_words=self.exclude_words,
            responsa_options=self.responsa_options
        )
        self.results_signal.emit(results)
    except InterruptedError:
        # Emit empty list -- partial results not available from execute_search
        self.results_signal.emit([])
    except Exception as e:
        self.error_signal.emit(str(e))
```

Note: `execute_search` collects results in a local list and returns them at the end. When InterruptedError is raised inside the progress_callback (which is called inside the for loop in execute_search), the exception propagates up and the local `results` list is lost. This is acceptable because the user gets a responsive cancel. For true partial results, execute_search would need to be refactored to accept a results accumulator, which is out of scope.
