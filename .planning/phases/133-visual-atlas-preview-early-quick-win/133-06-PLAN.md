## Headless-browser DOM capture (Codex HIGH-4)
- The masking risk is that catalogue strings render only in the CLIENT DOM (tooltips/focus rows/search results), which an ASGI GET / `curl` never sees. Add a `--browser-dom <base-url>` mode to `scripts/capture_atlas_html.py` using Playwright (dev/ops tool — install ad hoc via `pip install playwright && python -m playwright install chromium`; do NOT add to requirements.txt/requirements-lock.txt/requirements-atlas-bake.txt): navigate to `<base-url>/atlas` in EN and again in HE, wait for renderer readiness (a documented readiness signal — e.g. the canvas populated / a window flag the renderer sets), programmatically exercise the interactions that create catalogue DOM (type into the search box, focus/click a region, hover a star to trigger a tooltip), then dump `document.documentElement.outerHTML` per language to the capture dir.
- The GUARANTEED execution of the browser-DOM capture is the LIVE production smoke (Task 4, against `https://genizahsearch.com`), where a real browser + real server exist and the beta is behind the flag (so a caught leak is contained by flipping the flag OFF). Pre-deploy (Task 1) runs it BEST-EFFORT against a locally-served instance if one is available, but the hard pre-deploy leak gate remains the recursive `--scan-asset atlas_data/` (every embedded string) + `--scan-repo` (from 133-01).
