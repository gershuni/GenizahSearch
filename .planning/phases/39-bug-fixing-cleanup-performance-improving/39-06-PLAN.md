  <name>Task 1: Fix bottom pagination scroll-to-top RuntimeError</name>
  <files>web/pages/search.py</files>
  <action>
In web/pages/search.py, find the `on_page_change_bottom` function (around line 2264-2268).

Current code:
```python
def on_page_change_bottom(e):
    search_state.current_page = e.value - 1
    render_results(results, page=search_state.current_page)
    # Scroll to top of results
    ui.run_javascript('window.scrollTo(0, 0)')
```

The bug: `render_results()` calls `results_container.clear()` which destroys the bottom pagination's parent slot. After that, `ui.run_javascript()` fails because its NiceGUI context (the parent element) has been deleted.

Fix: Move the `ui.run_javascript('window.scrollTo(0, 0)')` call BEFORE `render_results()`. The JavaScript is sent to the client immediately and queued for execution, so it will run even though the Python-side parent element gets destroyed afterward.

New code:
```python
def on_page_change_bottom(e):
    search_state.current_page = e.value - 1
    # Scroll to top BEFORE render_results destroys this element's parent slot
    ui.run_javascript('window.scrollTo(0, 0)')
    render_results(results, page=search_state.current_page)
```

Note: The top pagination (`on_page_change_top`) does NOT have this issue because it does not call scrollTo -- leave it unchanged.
  </action>

Run `python -c "import web.pages.search"` to verify no syntax errors (this may fail if NiceGUI isn't in context, that's OK -- the import check is a bonus).
  </verify>

<task type="auto">
  <name>Task 2: Fix VRD mouse wheel zoom-instead-of-scroll</name>
  <files>genizah_app.py</files>
  <action>
In genizah_app.py, find the `ZoomableScrollArea.wheelEvent` method (around line 1477-1482).

Current code:
```python
def wheelEvent(self, event):
    self._auto_fit_enabled = False
    delta = event.angleDelta().y()
    factor = 1.1 if delta > 0 else 0.9
    self._apply_zoom(factor)
    event.accept()
```

The bug: ALL wheel events are intercepted for zoom. The parent QScrollArea never receives wheel events, so users cannot scroll.

Fix: Add a Ctrl modifier check. Plain mouse wheel = scroll (propagate to parent), Ctrl+mouse wheel = zoom (keep current behavior).

New code:
```python
def wheelEvent(self, event):
    if event.modifiers() & Qt.KeyboardModifier.ControlModifier:
        # Ctrl+wheel: zoom
        self._auto_fit_enabled = False
        delta = event.angleDelta().y()
        factor = 1.1 if delta > 0 else 0.9
        self._apply_zoom(factor)
        event.accept()
    else:
        # Plain wheel: propagate to parent for normal scrolling
        event.ignore()
```

Verify that `Qt` is already imported from PyQt6.QtCore at the top of the file (it should be -- this is a PyQt6 desktop app with extensive Qt usage). If for some reason `Qt` is not imported, add it to the existing PyQt6.QtCore import line.

<task type="auto">
  <name>Task 3: Fix E2E tests crashing on missing selenium</name>
  <files>tests/e2e/test_browse_flow.py, tests/e2e/test_search_flow.py, tests/e2e/test_performance.py</files>
  <action>
The bug: All 3 E2E test files have bare module-level `from selenium...` imports that cause `ModuleNotFoundError` before conftest.py's `pytest_collection_modifyitems` skip hook can run. Pytest imports test modules at collection time (step 2), but the skip hook runs at step 3 -- too late.

Fix: Add `pytest.importorskip("selenium")` at the top of each file, BEFORE any selenium imports. `pytest.importorskip` raises `pytest.skip` during collection, which is handled gracefully.

**test_browse_flow.py** -- change the imports section from:
```python
import os
import pytest

from selenium.webdriver.common.by import By
```
to:
```python
import os
import pytest

pytest.importorskip("selenium", reason="selenium not installed -- skipping E2E tests")
from selenium.webdriver.common.by import By
```

**test_search_flow.py** -- change the imports section from:
