<objective>
Eliminate the ~5-second domain filter dialog lag by adding in-memory caching to FjmsService.get_domain_hierarchy() and optimizing the underlying SQL query.

Purpose: The domain filter dialog currently re-queries the database on every open, running a GROUP BY with COUNT DISTINCT on 390K rows (~5 seconds). The hierarchy data is static (doesn't change at runtime), so caching it after the first computation eliminates the lag entirely. This is the single highest-impact web performance fix identified in research.

Output: shared/fjms_service.py with hierarchy caching, tests/test_fjms_service.py with cache behavior test.
</objective>

```python
def get_domain_hierarchy(self) -> dict:
    """
    Get domain hierarchy with counts, grouped by parent domain.
    Results are cached in memory after first computation (hierarchy is static).
    Thread-safe via double-checked locking.
    """
    # Fast path: return cached result
    if self._hierarchy_cache is not None:
        return self._hierarchy_cache

    if self._conn is None:
        return {}

    # Slow path: compute and cache
    with self._hierarchy_lock:
        # Double-check after acquiring lock
        if self._hierarchy_cache is not None:
            return self._hierarchy_cache

        try:
            # Optimized query: COUNT(*) instead of COUNT(DISTINCT AlmaId)
            # No duplicate (AlmaId, Domain, ParentDomain) tuples exist in the data
            cursor = self._conn.execute(
                "SELECT Domain, DomainHeb, ParentDomain, ParentDomainHeb, "
                "COUNT(*) as count "
                "FROM domains GROUP BY Domain, ParentDomain ORDER BY count DESC"
            )
            rows = cursor.fetchall()

            # ... existing hierarchy building logic (lines 574-665) UNCHANGED ...
            # Build hierarchy: map parent -> {parent_domain_heb, count, children[]}
            hierarchy = {}
            parent_counts = {}

            # [Keep ALL existing logic from lines 577 to 665 exactly as-is]

            result = dict(sorted(hierarchy.items(), key=lambda x: parent_counts.get(x[0], 0), reverse=True))

            # Cache the result
            self._hierarchy_cache = result
            return result
        except Exception as e:
            logger.error(f"FjmsService.get_domain_hierarchy error: {e}")
            return {}
```

The ONLY changes to the existing logic are:

2. `threading.Lock()` around the computation (slow path)
3. Double-check inside the lock
4. `COUNT(*)` instead of `COUNT(DISTINCT AlmaId)` in the SQL query
5. `self._hierarchy_cache = result` before returning
6. Store result in local var `result` before caching and returning
