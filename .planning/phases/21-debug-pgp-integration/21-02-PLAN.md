**Create the SQL migration file** at `migrations/add_sections_column.sql`:

```sql
-- Add structured sections column to document_sources
-- Stores per-canvas section data parsed from pgp-text HTML files
-- Format: [{"canvas_url": "...", "canvas_num": 1, "label": null, "text": "..."}]
ALTER TABLE document_sources ADD COLUMN IF NOT EXISTS sections JSONB;

-- Also add language and direction metadata
ALTER TABLE document_sources ADD COLUMN IF NOT EXISTS source_language TEXT;
ALTER TABLE document_sources ADD COLUMN IF NOT EXISTS source_direction TEXT;
```

**Create the import script** at `scripts/import_pgp_sections.py`:

The script should:

1. **Clone or update pgp-text repo** to a local path (e.g., `pgp_data/pgp-text/`). Use `git clone --depth 1` for efficiency (~68MB). If directory exists, do `git pull` instead.

2. **Scan for HTML files** matching pattern `PGPID{pgpid}_s{source_id}_{scholar}_{type}.html`. Extract pgpid from filename. Use glob: `pgp_data/pgp-text/*/*/PGPID*.html`

3. **Parse each HTML file** using `parse_html_sections()` from `shared.document_service` (implemented in Plan 01). This returns structured sections with canvas_url, canvas_num, label, text, plus language and direction.

4. **Match to document_sources records** by pgpid. For each HTML file:
   - Extract pgpid from filename
   - The import does NOT need to match by source_id or scholar -- we update ALL edition sources for the pgpid with the same sections data (since all editions for a document share the same physical page structure).
   - Alternatively, if the filename contains `s{N}`, try to match to a specific source. But the simple approach is: group by pgpid, and for each source record of that pgpid, set the sections.

5. **Build update records** with: pgpid, sections (JSONB), source_language, source_direction.

6. **Upsert in batches** (batch size 500, same as import_pgp_full.py). Update only the new columns -- do NOT overwrite existing content, source_scholar, etc. Use `.update()` with `.eq('pgpid', pgpid)` rather than upsert to avoid touching other columns.

   Actually, since multiple sources can exist per pgpid, and sections are per-source (each source may have different structure), the better approach:
   - For each HTML file, extract pgpid and source scholar from filename
   - Match to specific document_sources record by pgpid + approximate scholar match
   - If no exact match, update ALL Digital Edition sources for that pgpid

7. **Dry-run mode** (default): Report statistics without writing to database. Same pattern as import_pgp_full.py.

8. **Verification report**: Write to `pgp_data/sections_import_report.txt` with:
   - HTML files found
   - Successfully parsed
   - Matched to document_sources records
   - Unmatched files
   - Update count

Script structure (follow import_pgp_full.py patterns):
```python
#!/usr/bin/env python3
"""
PGP Sections Import Script

Parses structured HTML files from the pgp-text GitHub repository and
populates the sections JSONB column in document_sources.

Usage:
  python scripts/import_pgp_sections.py --dry-run   # Validate (default)
  python scripts/import_pgp_sections.py --execute    # Import data

Prerequisites:
  1. Run migrations/add_sections_column.sql in Supabase SQL Editor
  2. Set SUPABASE_SERVICE_KEY environment variable
  3. Internet access to clone pgp-text repo (first run only)
"""
```

Use `argparse` for CLI, `tqdm` for progress, `dotenv` for env loading. Import `parse_html_sections` from `shared.document_service`.

Key implementation details:
- The pgp-text repo bucket structure: `{bucket}/PGPID{pgpid}/PGPID{pgpid}_s{source_id}_{scholar}_{type}.html`
- Buckets are: 00000, 01000, 02000, ..., 41000
- Each PGPID may have multiple HTML files (one per source)
- The `_type` suffix distinguishes editions vs translations (e.g., `_transcription.html`, `_translation.html`)
- Focus on edition HTML files for sections data

Run: `python scripts/import_pgp_sections.py --dry-run` to verify it works (clones repo, parses files, reports statistics).
