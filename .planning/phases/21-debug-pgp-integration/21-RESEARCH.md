## Summary

Phase 21 has two complementary goals: (1) import structured HTML section data from the pgp-text GitHub repository into the database, enabling reliable canvas-based recto/verso mapping for ~7,300 PGP documents, and (2) fix the regex fallback in `parse_transcription_sections()` to handle the ~712 missed marker variants for documents not covered by pgp-text HTML.

The pgp-text repository (`princetongenizalab/pgp-text`) contains automated backups of PGP transcription content as HTML files. Each HTML file uses `<div data-canvas="...">` elements to structurally map transcription sections to specific IIIF manuscript page images. This eliminates the need for regex-based guessing for the majority of sources. The HTML structure is clean and consistent (generated by Django templates), with well-defined patterns for canvas URLs, section labels (`<h3>` elements), and text content (`<ol><li>` or `<p>` elements).

The import pipeline involves: (a) cloning the pgp-text repo (~68MB, shallow clone), (b) scanning ~7,300 PGPID directories for HTML files, (c) parsing each HTML file into structured section data using Python's stdlib `html.parser`, (d) storing the parsed sections as JSONB in a new column on `document_sources`, and (e) updating the display pipeline to prefer structured sections over regex parsing when available.

**Primary recommendation:** Add a `sections` JSONB column to `document_sources`, build an import script that parses pgp-text HTML files using `html.parser.HTMLParser`, fix the regex fallback, and update `get_section_for_page()` to use structured sections when available with regex fallback.

```

  main branch, ~68MB, last updated 2025-10-13

  +-- 00000/           # Bucket for PGPIDs 0-999

  |   |   +-- PGPID444_s3_gil_transcription.txt
  |   +-- 445/

  |   +-- 1000/
  |   |   +-- PGPID1000_s166_weiss_transcription.html
  |   |   +-- PGPID1000_s166_weiss_transcription.txt
  |   |   +-- PGPID1000_s757_goitein_transcription.html
  |   |   +-- PGPID1000_s757_goitein_transcription.txt

```

**Filename convention:** `PGPID{pgpid}_s{source_id}_{author_slug}_{type}.{ext}`
- `pgpid`: PGP document ID (integer)
- `source_id`: PGP's internal numeric source ID (NOT available in our CSV exports)
- `author_slug`: Slugified author last name(s), hyphenated (e.g., `goitein`, `umrethwala-elbaum`)
- `type`: `transcription` or `translation`
- `ext`: `html` or `txt`

**Bucket rule:** PGPID is in bucket `floor(pgpid/1000)*1000`, padded to 5 digits. E.g., PGPID 3750 is in bucket `03000`, directory `3750`.

### HTML Structure (HIGH confidence -- verified against 6 real files)

```html
<html>
  <head><title>Transcription of {type}: {shelfmark}</title></head>
  <body style="max-width: 860px; margin: auto">
    <h1>Transcription of {type}: {shelfmark}</h1>
    <p>{citation HTML}</p>

    <section dir="rtl" lang="jrb">          <!-- or lang="he", lang="ar", dir="ltr" for translations -->

      <div data-canvas="https://cudl.lib.cam.ac.uk/iiif/{ms-id}/canvas/1">
        <h3>recto</h3>                      <!-- OPTIONAL: first section may omit h3 -->
        <ol>
          <li>line 1 of recto</li>
          <li>line 2 of recto</li>
        </ol>
        <h3>recto - right margin</h3>       <!-- OPTIONAL: sub-section within same canvas -->
        <ol>
          <li>margin line 1</li>
        </ol>
      </div>

      <div data-canvas="https://cudl.lib.cam.ac.uk/iiif/{ms-id}/canvas/2">
        <h3>Verso.</h3>                     <!-- Various label formats -->
        <ol>
          <li>line 1 of verso</li>
        </ol>
        <h3>verso - bottom margin - address</h3>
        <ol>                                <!-- OR <p> elements for short sections -->
          <li>address line 1</li>
        </ol>
      </div>

    </section>
  </body>
</html>
```

### Critical Structural Observations

1. **h3 is INSIDE data-canvas div, not before it.** The previous research/plan incorrectly stated h3 appears before the div. Verified across all 6 inspected files: h3 elements are children of the data-canvas div.

2. **Multiple h3+ol pairs per canvas div.** A single canvas div can contain multiple sub-sections (e.g., "recto" + "recto - right margin"). These are sub-sections of the same physical page.

3. **First canvas may omit h3.** PGPID 3750 and PGPID 444 have no h3 in the first canvas div -- the content starts directly with `<ol>`.

4. **Text can be in `<ol><li>` or `<p>` elements.** Most content uses ordered lists, but short sections (like addresses) may use `<p>` tags instead (seen in PGPID 4036 verso address).

5. **Canvas URL formats vary:**
   - CUDL: `https://cudl.lib.cam.ac.uk/iiif/{ms-id}/canvas/{N}` -- numeric canvas ID
   - Figgy (Princeton): `https://figgy.princeton.edu/concern/.../manifest/canvas/{UUID}` -- UUID canvas ID
   - The regex for extracting canvas_num must handle BOTH formats (or fall back to positional order).

6. **Language/direction on section element:**
   - Transcriptions: `<section dir="rtl" lang="jrb">` (Judeo-Arabic), `lang="he"` (Hebrew), `lang="ar"` (Arabic)
   - Translations: `<section lang="en" dir="ltr">` (English)

7. **HTML entities present.** Content may contain `&gt;`, `&amp;`, `&hellip;`, `&nbsp;` which need decoding.

8. **`<li>` may contain `<p>` wrapper.** Some files wrap line content in `<li><p>text</p></li>` (seen in PGPID 7003).

### Source ID Mapping Strategy

The `s{N}` in pgp-text filenames is the PGP database's internal footnote source ID, which is NOT present in our exported CSV data. Matching approach:

1. **Primary: Match by PGPID.** All HTML files for the same PGPID share the same physical manuscript structure. Extract sections from ANY edition HTML file for that PGPID and apply to ALL edition sources for that PGPID.

2. **Secondary: Match by scholar + type.** The filename contains `{author_slug}_{type}`. For multi-source documents, try matching the filename's author slug against `source_scholar` in `document_sources` to assign source-specific sections. The `_transcription` vs `_translation` suffix maps to `doc_relation` containing "Edition" vs "Translation".

3. **Fallback: Apply uniformly.** Since section structure (recto/verso/margin layout) is a property of the physical manuscript, not the scholarly edition, applying the same sections to all editions of the same PGPID is correct in all cases.

## The Regex Bug (unchanged from previous research)

### Current Regex (line 199 of document_service.py)

```python
section_pattern = re.compile(
    r'^(Recto|Verso)(?:\s*[-,]\s*[^\n]+)?[:\s]*\n',
    re.MULTILINE | re.IGNORECASE
)
```

### What It MISSES

| Pattern | Example | Count | Why Missed |
|---------|---------|-------|------------|
| Trailing period | `Verso.\n` | 268 | Period not in `[:\s]` char class |
| Period + more | `Verso. Address.\n` | 68 | Period breaks the pattern |
| Recto period | `Recto.\n` | 7 | Same as Verso |
| Parenthetical | `Verso (address)\n` | 12 | Parens not matched by `[-,]` |
| Space-separated | `Recto Margin\n` | 12 | Space not matched |
| Other parens | `Verso (upside down)\n` | 7 | Same paren issue |
| **Total missed** | | **712** | |

### The Fix

```python
section_pattern = re.compile(
    r'^(Recto|Verso)\b[^\n]{0,60}\n',
    re.MULTILINE | re.IGNORECASE
)
```

- `\b` word boundary prevents matching "Rectory" etc.
- `[^\n]{0,60}` matches any modifier characters (periods, parens, spaces)
- 60-char limit prevents matching content lines starting with "Recto"/"Verso"

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| HTML parsing | Custom string splitting/regex | `html.parser.HTMLParser` | Handles entities, nesting, attribute extraction correctly |
| Section marker detection | Multiple specific patterns | Single `\b[^\n]{0,60}\n` regex | Handles all variants uniformly |
| Git clone management | Custom download logic | `subprocess.run(['git', 'clone', ...])` | Standard, handles auth, progress |
| JSONB storage | Custom serialization | Supabase JSONB column type | Native PostgreSQL, queryable |

**Key insight:** The HTML is generated by Django templates and is extremely clean/consistent. A simple HTMLParser subclass is sufficient -- no need for BeautifulSoup, lxml, or other heavy parsers.

## Common Pitfalls

### Pitfall 1: h3 Placement Assumption
**What goes wrong:** Assuming `<h3>` appears BEFORE `<div data-canvas="...">` rather than inside it.
**Why it happens:** Looking at the HTML from a browser's rendered view rather than the raw source.
**How to avoid:** The parser must handle h3 as a child element of the data-canvas div, not a sibling before it.
**Verified:** ALL 6 inspected HTML files have h3 INSIDE the data-canvas div.

### Pitfall 2: Figgy Canvas URL Format
**What goes wrong:** Canvas number extraction regex `r'/(\d+)/?$'` fails on Princeton Figgy URLs which use UUIDs instead of integers.
**Why it happens:** Only testing with CUDL-style URLs.
**How to avoid:** Use positional ordering (1st canvas div = canvas_num 1, 2nd = canvas_num 2) as the primary canvas_num assignment. Only use URL-extracted numbers as a secondary signal.
**Warning signs:** canvas_num is None for any parsed section.

### Pitfall 3: Multiple Sub-Sections Per Canvas
**What goes wrong:** Parser creates separate top-level sections for "recto" and "recto - right margin" when they should both map to the same canvas/page.
**Why it happens:** Treating each h3 as a new canvas boundary.
**How to avoid:** Sub-sections within the same data-canvas div should be merged or grouped under the same canvas_num. The canvas boundary is the `<div data-canvas>` element, not the `<h3>` element.
**Recommendation:** Store sub-sections as part of the same canvas entry. Each canvas entry can have multiple labeled text blocks.

### Pitfall 4: Over-matching Section Markers in Regex Fallback
**What goes wrong:** A too-broad regex matches content lines starting with "Recto" or "Verso".
**How to avoid:** The 60-char limit on the regex prevents matching long content lines. The `\b` word boundary prevents matching "Rectory" etc.

### Pitfall 5: Source ID Mapping
**What goes wrong:** Trying to match pgp-text filenames to document_sources by numeric source_id (the `s{N}` in filename), which is not available in our data.
**How to avoid:** Match by PGPID only. All editions for the same document share the same physical page structure.

### Pitfall 6: Text Extraction Missing p-wrapped Content
**What goes wrong:** Parser only extracts text from `<li>` elements, missing content in `<p>` elements (addresses, short sections) or `<li><p>` nested wrappers.
**Why it happens:** Incomplete handling of text containers.
**How to avoid:** Extract text from both `<li>` and `<p>` elements within data-canvas divs. Handle the `<li><p>text</p></li>` nesting (strip the inner `<p>` wrapper).

### Pitfall 7: Document-Level vs Source-Level Sections
**What goes wrong:** Trying to add sections to the `documents` table instead of `document_sources`.
**Why it happens:** The `documents.transcription` field is document-level, but sections are per-source.
**How to avoid:** Sections belong on `document_sources` because different editions of the same document could theoretically have different section structures (though in practice they share the same physical structure). The `get_section_for_page()` consumers already work at the source level.

### HTML Parser Implementation Pattern

```python
from html.parser import HTMLParser
from html import unescape
import re

class PGPHTMLParser(HTMLParser):
    """Parse PGP HTML into structured per-canvas sections."""

    def __init__(self):
        super().__init__()
        self.sections = []          # Final list of canvas sections
        self.language = None
        self.direction = None

        self._in_canvas_div = False
        self._current_canvas_url = None
        self._current_canvas_num = None
        self._current_subsections = []  # [{label, lines}]
        self._current_label = None
        self._current_lines = []

        self._in_h3 = False
        self._h3_text = ''
        self._in_li = False
        self._in_p = False
        self._in_p_inside_canvas = False
        self._li_text = ''
        self._p_text = ''
        self._canvas_count = 0

    def handle_starttag(self, tag, attrs):
        attrs_dict = dict(attrs)

        if tag == 'section':
            self.language = attrs_dict.get('lang')
            self.direction = attrs_dict.get('dir')

        elif tag == 'div' and 'data-canvas' in attrs_dict:
            self._canvas_count += 1
            self._in_canvas_div = True
            self._current_canvas_url = attrs_dict['data-canvas']
            # Try to extract numeric canvas ID from URL
            m = re.search(r'/canvas/(\d+)/?$', self._current_canvas_url)
            self._current_canvas_num = int(m.group(1)) if m else self._canvas_count
            self._current_subsections = []
            self._current_label = None
            self._current_lines = []

        elif tag == 'h3' and self._in_canvas_div:
            self._in_h3 = True
            self._h3_text = ''

        elif tag == 'li' and self._in_canvas_div:
            self._in_li = True
            self._li_text = ''

        elif tag == 'p' and self._in_canvas_div and not self._in_li:
            # Standalone <p> in canvas div (not <li><p>)
            self._in_p_inside_canvas = True
            self._p_text = ''

    def handle_data(self, data):
        if self._in_h3:
            self._h3_text += data
        elif self._in_li:
            self._li_text += data
        elif self._in_p_inside_canvas:
            self._p_text += data

    def handle_endtag(self, tag):
        if tag == 'h3' and self._in_h3:
            self._in_h3 = False
            # Save any accumulated lines under the previous label
            if self._current_lines:
                self._current_subsections.append({
                    'label': self._current_label,
                    'lines': self._current_lines[:]
                })
                self._current_lines = []
            self._current_label = unescape(self._h3_text.strip())

        elif tag == 'li' and self._in_li:
            self._in_li = False
            self._current_lines.append(unescape(self._li_text.strip()))

        elif tag == 'p' and self._in_p_inside_canvas:
            self._in_p_inside_canvas = False
            text = unescape(self._p_text.strip())
            if text and text != '...':
                self._current_lines.append(text)

        elif tag == 'div' and self._in_canvas_div:
            # Finalize any remaining lines
            if self._current_lines:
                self._current_subsections.append({
                    'label': self._current_label,
                    'lines': self._current_lines[:]
                })

            # Build merged text from all sub-sections
            all_text_parts = []
            for sub in self._current_subsections:
                if sub['label'] and len(self._current_subsections) > 1:
                    all_text_parts.append(f"[{sub['label']}]")
                all_text_parts.extend(sub['lines'])

            self.sections.append({
                'canvas_url': self._current_canvas_url,
                'canvas_num': self._current_canvas_num,
                'label': self._current_subsections[0]['label'] if self._current_subsections else None,
                'text': '\n'.join(all_text_parts),
                'subsections': self._current_subsections if len(self._current_subsections) > 1 else None,
            })

            self._in_canvas_div = False
            self._current_canvas_url = None
            self._current_canvas_num = None
            self._current_subsections = []
            self._current_label = None
            self._current_lines = []

    def handle_entityref(self, name):
        self.handle_data(unescape(f'&{name};'))

    def handle_charref(self, name):
        self.handle_data(unescape(f'&#{name};'))


def parse_html_sections(html_content: str) -> dict:
    """Parse PGP HTML into structured per-canvas sections."""
    if not html_content:
        return {'sections': [], 'language': None, 'direction': None}

    parser = PGPHTMLParser()
    parser.feed(html_content)

    return {
        'sections': parser.sections,
        'language': parser.language,
        'direction': parser.direction,
    }
```

### Import Script Pattern

```python
#!/usr/bin/env python3
"""Import structured sections from pgp-text HTML files."""

import os
import subprocess
import glob
import re
from pathlib import Path

def clone_or_update_pgp_text(target_dir: str):
    """Clone pgp-text repo (shallow) or update if exists."""
    if os.path.exists(target_dir):
        subprocess.run(['git', '-C', target_dir, 'pull'], check=True)
    else:
        subprocess.run([
            'git', 'clone', '--depth', '1',
            'https://github.com/princetongenizalab/pgp-text.git',
            target_dir
        ], check=True)

def scan_html_files(repo_dir: str) -> dict:
    """Scan for HTML files, returns {pgpid: [file_paths]}."""
    pattern = os.path.join(repo_dir, '*', '*', 'PGPID*_transcription.html')
    files = glob.glob(pattern)

    pgpid_files = {}
    filename_re = re.compile(r'PGPID(\d+)_s(\d+)_(.+)_(transcription|translation)\.html')

    for filepath in files:
        basename = os.path.basename(filepath)
        m = filename_re.match(basename)
        if m:
            pgpid = int(m.group(1))
            pgpid_files.setdefault(pgpid, []).append(filepath)

    return pgpid_files
```

## Open Questions

1. **Canvas URL to image mapping: Is it needed now?**
   - What we know: data-canvas URLs contain IIIF canvas references. Our browse page already loads images from IIIF manifests independently.
   - What's unclear: Should we use the canvas URL to align section text with specific images, or just use canvas_num as page_num?
   - Recommendation: For now, canvas_num == page_num is sufficient. Canvas URLs are stored in JSONB for future use (e.g., direct image-text alignment without manifest loading). Don't over-engineer the display pipeline.

2. **Should translations also get structured sections?**
   - What we know: Translation HTML files have the same data-canvas structure as transcriptions. Translations are displayed alongside transcriptions.
   - What's unclear: Whether to import `_translation.html` sections too or just `_transcription.html`.
   - Recommendation: Import both. Same parser works for both. The `doc_relation` column in `document_sources` distinguishes them.

3. **How to handle PGPIDs not in pgp-text but with sources in our DB?**
   - What we know: ~7,090 unique PGPIDs in our sources data, ~7,300 in pgp-text. Most overlap, some don't.
   - What's unclear: Exact overlap percentage.
   - Recommendation: Import what's available, regex fallback handles the rest. The import script should report unmatched PGPIDs.

4. **Should `p_num` > 2 use structured sections?**
   - What we know: Multi-fragment documents may have pages 3, 4+. Current code returns full transcription for page_num > 2.
   - What's unclear: How pgp-text handles multi-fragment documents -- do they have 3+ canvas divs?
