## Round 4 (uncommitted, genizah_app.py only)

### Desktop translation fixes
1. **Search table title translation**: Initial display now uses `_resolve_display_title(sid, title, compact=True)` instead of raw title (line ~19413)
2. **Oxford pre-computed translations**: Both ResultDialog and Browse pre-populate `_field_translation_cache` with batch Oxford translations from `libraries_translations.db` before rendering, so Oxford fields show "Translated/Original" toggle immediately instead of on-demand "Translate" badge
3. **Language-aware `_resolve_display_title`**: Non-compact mode now respects `show_translations` + `CURRENT_LANG`. English UI + ON → English only. Hebrew UI + ON → Hebrew only. OFF → both (`he | en`)
4. **Language-aware `_trans_or_badge` / `_trans_or_badge_b`**: Both functions now check UI language direction. English UI skips English text (no badge). Hebrew UI skips Hebrew text. Fixes: English Title not offered for translation in English UI, Hebrew notes offered for translation in English UI
5. **Bidirectional on-demand translation**: `_start_field_translation` direction no longer hardcoded to `en2he`. Hebrew text in English UI → `he2en`. No early-return guard — if badge was shown, click always works
6. **Consolidated notes**: Notes merged into single translatable block (`rd_notes`/`br_notes`) with one badge instead of per-paragraph badges. `_get_field_original_text` and `_rd_auto_translate_all` updated for new key
7. **Inline "Translating..." indicator**: Sentinel `'__translating__'` in cache → ⏳ Translating... shown inline in HTML (visible inside ResultDialog). Clears on success (shows toggle) or failure (reverts to Translate badge + statusbar error)
