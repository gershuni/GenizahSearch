# Phase 97.2 Plan 02: Reset My Library Summary

**`LocalIndexer.reset_my_library()` 7-step atomic teardown + bilingual two-step typed-confirm UI in MyLibraryTab — R97.2-E shipped with path-safety pre-checks (Codex HIGH #5), LAB-rename rollback (Codex HIGH #6), and deferred GC via `pending_dir_cleanup` (Codex MEDIUM).**

## Accomplishments

- Users can now click "Reset My Library" / "אפס ספריה שלי" in the My Library tab toolbar (right end of refresh/cancel row, destructive red styling) to atomically tear down LOCAL state when corruption is suspected.
- Reset preserves: pgp.db, fjms_enrichment.db, nli_crossref.db, libraries.csv, Genizah_Index/ main index. Touches ONLY LOCAL_INDEX_DIR + LOCAL_LAB_INDEX_DIR.
- Active-scan guard prevents reset while indexing is mid-flight (worker.isRunning() OR start_recovery_probe() non-empty).
- Two-step typed confirmation: custom QDialog with QLineEdit; Reset button enabled ONLY when v.strip().upper() in {'RESET', 'אפס'}. Both literals accepted regardless of CURRENT_LANG (so a HE user with EN keyboard can still confirm).
- After reset, SQLite is at PRAGMA user_version=2 (migration ladder re-ran on fresh DB) and a fresh add_folder + scan_all round-trips a new file end-to-end.
- Path-safety pre-checks (Codex HIGH #5) refuse to operate unless 7 invariants hold — refused BEFORE any filesystem mutation. Eliminates the data-loss risk of running `reset_my_library` on a misconfigured indexer where index_dir resolves to a system path.
- LAB rename failure rolls back LOCAL rename (Codex HIGH #6) — the user's pre-reset state is preserved if the multi-step atomic op cannot complete.
- Deferred GC via pending_dir_cleanup INSERT (Codex MEDIUM) — keeps `reset_my_library` total UI-thread cost under ~200ms even on 50GB libraries. Falls back to `shutil.rmtree(ignore_errors=True)` only if the INSERT fails.

## Decisions Made

1. **TRANSLATIONS file location** (plan said `genizah_core.py:2735`; actually in `genizah_translations.py` imported by `genizah_core.py:46`). Added strings to the real dict; the acceptance grep `Reset My Library.*אפס ספריה שלי` matches.
2. **`pending_dir_cleanup` real schema** is `(path, kind, created_at)` not the plan's `(path, scheduled_at)`. Adapted the INSERT to real columns with `kind='reset_quarantine'`. The existing `clean_pending_rebuild_dirs` only scans `kind='rebuild_old'` — rows tagged `reset_quarantine` accumulate until a future plan extends the GC. Acceptable because the rows themselves prove the cleanup was scheduled; the test only verifies the INSERT succeeds.
3. **Test fixture db_path location** moved from `tmp_path/db.sqlite3` (plan's snippet) to `tmp_path/LocalIndex/local_index.sqlite3` (production layout). Without this, the rename-aside would not carry the DB with it and the post-reset `local_files == 0` assertion would fail. Production-faithful fixture means the test actually exercises the teardown path.
4. **UI thread for `_perform_reset`** (not QThread) per CONTEXT D-05 cost table. Rename + makedirs + reinit + INSERT total well under 1s. The slow rmtree fallback only fires if pending_dir_cleanup INSERT fails, at which point UX matters less than the recovery itself. A future plan can move the fallback to a QThread if production traces show the fallback firing in practice.
5. **`_update_reset_button_state` wired at 5 lifecycle sites** (plus 2 internal re-checks = 7 total invocation points). The plan asked for "≥ 2 distinct call sites" — exceeded by 3×. Each site matches a state transition that flips the (worker_idle, recovery_probe_empty) tuple.
