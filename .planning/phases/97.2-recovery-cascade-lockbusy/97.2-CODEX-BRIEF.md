## My proposed 5 bugs and fixes

### Bug A — Redundant `tantivy.Index(...)` reopen after `rebuild_main_index_atomic` already reopened
- `shared/local_indexer.py:1147` and `genizah_core.py:6890`
- The rebuild's step 6 calls `_reopen_internal_writer_index()` which opens both `self._index` AND `self._writer` (`writer` holds the writer lock on the new live index_dir).
- The caller then **rebinds `self._index`** with a fresh `tantivy.Index(...)` — but `self._writer` from step 6 is still alive and still holds the writer lock.
- Result: line 1164's `self._writer = self._index.writer(...)` tries to acquire another writer on the same dir → LockBusy.
- **My proposed fix**: remove lines 1147 (and 6890). The rebuild already set up both handles; the retry loop just confirms.

### Bug B — `.tantivy-writer.lock` may be carried into the live index_dir by os.rename
- `shared/local_indexer.py:2747` (`del fresh_writer; del fresh_index`) then `:2784` (`self._retry_windows_rename(rebuild_dir, self._index_dir)`).
- On Windows, `del` only decrements the Python refcount. The underlying Rust IndexWriter is dropped synchronously when refcount hits 0 — BUT only after Python GC runs. If there's any latent reference (e.g. inside a traceback object or a generator frame), the lock file stays.
- Even after the writer drops, Windows can hold the file handle briefly via the OS's deferred-close behavior; the lockfile may still be present + locked when os.rename runs.
- **My proposed fix candidates**: (1) `gc.collect()` + small `time.sleep(0.1)` after del; (2) explicit `os.remove(os.path.join(rebuild_dir, '.tantivy-writer.lock'))` with retry before rename; (3) wrap fresh_writer in a context manager pattern via a helper.

### Bug C — `discard_run` calls `delete_documents("scan_run_id", run_id)` unconditionally
- `shared/local_indexer.py:2956`
- When the on-disk index still has Phase 95 schema (because the startup atomic rebuild failed via Bug A), the `scan_run_id` field doesn't exist → `ValueError: Field 'scan_run_id' is not defined in the schema`.
- **My proposed fix**: detect schema version. If `scan_run_id` field is absent, fall back to per-uid deletion: select `uid` values from SQLite `local_pages` matching this run_id, then `_del_writer.delete_documents("unique_id", uid)` per row.

### Bug D — Missing `self._writer is None` guards
- `_delete_file` and other code paths call `self._writer.delete_documents(...)` and `self._writer.commit()` without checking.
- After a failed `discard_run` (steps 2 + 5 both failed in the trace), `self._writer = None` (from step 1 rollback null) and the next operation crashes with NoneType.
- **My proposed fix**: helper `_ensure_writer()` that lazy-opens writer if None; called at the top of every method that touches the writer.

### Bug E — "Reset My Library" referenced in 2 error messages but never implemented
- Error messages at `local_indexer.py:1152` and `:2766` tell the user to use "Reset My Library in Advanced settings" — feature doesn't exist.
- **My proposed fix**: implement `LocalIndexer.reset_my_library()` (close all handles + rmtree index_dir + lab_index_dir + sqlite + recreate) + add a button in `desktop/my_library_tab.py` Advanced section with bilingual EN+HE confirm dialog.
