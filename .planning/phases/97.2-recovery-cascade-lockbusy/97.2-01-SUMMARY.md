## Accomplishments

- Phase 95 installs upgrading to Phase 97 now trigger an atomic rebuild on `LocalIndexer.__init__` instead of crashing with `Schema error → LockBusy ×3 → 'Field scan_run_id is not defined' → 'NoneType has no delete_documents'` (the 2026-05-26 cascade).
- `rebuild_main_index_atomic` no longer leaks a writer-lock handle into the post-rebuild call site (`del fresh_writer/fresh_index` replaced with explicit null + `gc.collect()`).
- `discard_run` is schema-aware: detects Phase 95 (no scan_run_id field) via try/except ValueError probe and falls back to per-uid `unique_id` delete loop.
- `discard_run` step 5 reopen no longer races against step 2's still-held writer lock (null + `gc.collect()` in the new `finally` block).
- Tantivy delete failures NO LONGER leave orphaned docs: `LocalIndexerError` raised BEFORE the SQLite transaction; SQLite rows + `scan_runs.status` preserved for a Reset My Library / app-restart recovery.
- New `LocalIndexerError` exception class and `_ensure_writer()` fail-loud helper give UI code a stable contract for surfacing the Reset My Library CTA.

## Decisions Made

1. **Probe-based fallback chosen over schema introspection** (R97.2-C). The plan's PATTERNS.md draft preferred `index.schema.field_names()` to detect Phase 95 schema. Verification showed tantivy-py 0.25.1's `tantivy.Schema` exposes only `_internal_from_pythonized` — no `field_names()`/`get_field_names()`. PATTERNS.md's explicit fallback authorization ("wrap delete_documents in try/except ValueError as e: if 'scan_run_id' in str(e): ...") was taken. Tests were updated to simulate the ValueError signal via `_DelWriterShim` instead of `_SchemaShim.field_names()`.
2. **LocalIndexerError as its own foundation commit** (4250c731). Per the plan's Task 10 Option A: cleanest git history when multiple downstream commits raise/catch it.
3. **`_ensure_writer` is fail-loud only** (R97.2-D). No lazy reopen of `self._index`; honors REVIEWS Codex HIGH #4 / CONTEXT D-07 "fail-loud by design". __init__'s 3-attempt retry loop remains the ONLY silent-retry path.
4. **4 call sites wired, not 5** (R97.2-D). Plan called the wiring "5 None-guards" but enumerated 4 distinct call sites in PATTERNS.md §H (the 5th was `keep_run` which already has an explicit `if self._writer is not None:` guard — left as-is per planner discretion). Net effect on writer-acquisition coverage is identical to the 5-site spec.
