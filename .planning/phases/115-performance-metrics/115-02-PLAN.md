<objective>
Build the Phase 115 performance accumulator + flush machinery entirely inside the
`desktop/telemetry.py` chokepoint (D-09), with the privacy + robustness fixes from the Codex review
folded in. This adds the new public ingest API (`accumulate_performance`), the internal
aggregation/flush (`_flush_perf_summary` + `_percentile`), the two public flush entry-points the GUI
calls (`flush_perf_if_due`, `flush_perf_unconditionally`), the new opt-out hook
(`_clear_perf_accumulator`, wired into `set_consent(False)` + `_reset_for_tests`), the input
normalizers (`_normalize_mode` / `_normalize_corpus` / `_normalize_operation_kind` /
`_normalize_flush_reason`), validated env-knob readers (`_perf_env_int` / `_perf_env_float`), the new
`DesktopEvent.INDEXING_COMPLETE` registry member (PRIV-06), the three new `_ALLOWED_PROPS` keys
(`perf_summary`, `operation_kind`, `doc_count_bucket`), the three module-level accumulator globals,
the `session_id` threading onto the summary event, and the `_reset_for_tests()` extension. This plan
makes the plan-01 unit tests that exercise the accumulator/flush/consent-gate/scrubber/opt-out-clear/
mode-normalize/env-clamp turn GREEN.

Purpose: resolve the SC#1↔SC#3 tension (per-search ingest accumulates, never emits; only the flush
emits one summary) so heavy users get ~tens of events/day, not hundreds — while CLOSING the three
HIGH privacy/correctness gaps Codex found (opt-out must clear the unsent buffer; free-string mode must
not become an unscrubbed nested key; env knobs must not silently disable telemetry). All emission stays
in the chokepoint so the AST guards keep passing.
Output: an extended `desktop/telemetry.py` with the accumulator + flush API + the REVIEWS fixes.
</objective>
