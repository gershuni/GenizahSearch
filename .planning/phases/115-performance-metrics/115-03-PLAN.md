## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker thread → UI thread | `perf_signal(float, int)` crosses thread boundary; only numbers cross — no query text, no result objects. |
| UI slot → accumulator → PostHog | The slot calls `accumulate_performance` (ingest); emission happens only at flush via the chokepoint. |
| run context capture | mode/corpus/session_id are captured at thread start (fresh) and bound into the connection, so signal-time attribution cannot drift onto a stale run object. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-115-PRIV-4 | Information Disclosure | perf_signal payload | mitigate | `perf_signal` carries only `(elapsed_ms: float, result_count: int)` — structurally incapable of carrying query text/shelfmarks/paths. The result objects (`results`) are NEVER passed; only `len(...)`. |
| T-115-PRIV-5 | Information Disclosure | mode/corpus on accumulate | mitigate | `mode`/`corpus_scope` are read from the Phase-114 per-run state object (producer-side enum literals) AT THREAD START and bound into the connection, never from `currentText()`/`tabText()`/a window title (D-04). `accumulate_performance` additionally normalizes them to a fixed allowed set (plan 02). `test_no_dynamic_telemetry_strings` enforces no UI accessor at the call site. |
| T-115-PRIV-6 | Information Disclosure | cancelled-run partial data | mitigate | `perf_signal` emits ONLY on the success path (after `results_signal.emit(results)`, before any `except`), so a cancelled run contributes no skewed duration and no partial result count (D-08). |
| T-115-INTEG-1 | Tampering (data integrity) | stale-run mis-attribution (REVIEWS finding 2) | mitigate | The slot no longer reads the shared `_current_*_run` at signal time. mode/corpus/session_id are captured at thread start (when the run object is fresh) and travel with the signal via a default-arg closure / partial, so a composition perf signal is recorded under the composition mode even when a prior, never-cleared `_current_search_run` is still set. Composition result_count also uses the live `len(main)+len(filtered)` formula (finding 5), so the recorded counts/buckets match the UI. |
| T-115-SC | Tampering | npm/pip/cargo installs | accept | No package installs (RESEARCH §Package Legitimacy Audit: N/A — zero new deps). |
