<objective>
Add the web `/search` library multi-select filter (LIBFILTER-01): a compact "Filter by library" dropdown-with-checklist placed beside the existing PGP/Printed filter buttons; filtering applied over the FULL `search_state.results` set BEFORE the `PAGE_SIZE` (50) render slice / pagination; facet-style per-library counts computed from the pre-filter full set with 0-match libraries hidden (D-02); active selections as removable chips (D-03); EN/HE labels via `get_library_display` (D-01); state persisted as a list under `search_library_filter` through the `safe_storage` chokepoint (Phase 87 invariant). Independent of Plan A — this post-filters the result list and does not call `get_browse_results`.

CRITICAL — the filter must be folded into the SHARED post-search cascade, not just `_apply_printed_filter_and_render`. `/search` reaches its post-search filters through a cascade with ROUTING PREDICATES (not a single helper). The existing printed/PGP filter is gated by predicates like `(search_state.printed_filter != 'all' and search_state.printed_ids) or search_state.pgp_filter != 'all'` (lines 3418, 3446, and analogues in the word-search / domain / immediate / enrichment / history rerender paths). When the library filter is the ONLY active filter, every such predicate is false and control falls through to a bare `render_results(...)` / measurement-only branch that never applies the library filter — so the filter would silently do nothing in the common library-only case. The fix: (a) apply `_apply_library_filter` inside the filtering steps of ALL post-search render paths, and (b) widen every such routing predicate with `or bool(search_state.library_filter)` so library-only routes through a filtering path.

Purpose: The web search half of the feature — narrows the full result set, not the visible page.
Output: Modified `web/pages/search.py`; new `tests/test_libfilter_web_search.py`.
</objective>
