# Phase 999.3: Adding PGP to downloaded data - Context

**Gathered:** 2026-05-15
**Status:** Ready for planning (backlog — promote with /gsd-review-backlog when ready)

<domain>
## Phase Boundary

Extend the Excel search-results export to include PGP metadata columns so
researchers can sort / filter / cite PGP data directly from the
downloaded spreadsheet. JSON export already includes PGP; Word, list, and
parallels exports are not touched in this phase.

In scope:
- `web/export_service.py:286 export_search_results_excel` — add PGP columns.
- Reuse the existing `_build_pgp_subset` field set from
  `shared/search_serializer.py:473-485` as the canonical PGP source.

Out of scope (see Deferred Ideas):
- Word search-results export.
- List exports.
- Parallels exports.
- PGP transcription text in any export (intentionally excluded for size).
- Translating PGP descriptions to Hebrew for the export.

</domain>

<decisions>
## Implementation Decisions

### What gets exported
- **D-01:** Add the following columns to the Excel search-results export:
  | Column | Source field | Notes |
  |---|---|---|
  | PGP URL | `pgp_url` | Direct link to the PGP record on princeton.edu |
  | PGP Description | `description` | Free-text scholarly description |
  | PGP Type | `document_type` | e.g. "Letter", "Legal document", "Bible" |
  | PGP Date | `inferred_date_display` | Display-formatted date, falls back to `doc_date_standard` then `doc_date_original` if `inferred_date_display` is empty |
  | PGP Languages | `languages_primary` + `languages_secondary` | Combined: primaries first, then secondaries |
  | PGP Tags | `tags` | List |
- **D-02:** **Do NOT include PGP transcription text** (`page_section_text`) in the Excel export. Reason: row-cell size + 32K Excel cell limit + readability. Stays available in JSON export.

### Column placement
- **D-03:** Append the new columns at the end, **after the existing `Full Text` column**. Final column order:
  ```
  Shelfmark | Library | Title | System ID | Score | Snippet | Full Text |
  PGP URL | PGP Description | PGP Type | PGP Date | PGP Languages | PGP Tags
  ```
  Existing column indices and `set_excel_column_widths` mapping at `web/export_service.py:303-308` are preserved as-is; only new columns are added.

### Language
- **D-04:** **Always emit PGP data in English.** PGP is the canonical English-language scholarly source for these manuscripts (per user). The export pipeline does NOT call `get_language()`, does NOT touch `pgp_translations`, does NOT pass through `shared/translation_service.py`. The export is a citation-quality artifact and stays in the source language.

### Multi-value field formatting
- **D-05:** List-valued fields (`PGP Languages`, `PGP Tags`) are joined with **pipe-space-pipe NO — pipe character only**: `'Bible|Letter|Legal'`. No surrounding spaces. Rationale per user: round-trip safe, parses cleanly in research scripts, less ambiguous than commas (which can appear inside individual values).

### Missing data
- **D-06:** Manuscripts without PGP data get **empty cells** in every PGP column. Do not write `"N/A"`, `"—"`, or any placeholder. This matches the existing export convention (e.g. empty `Library` cells when `library_code` is unknown).

### Per-row repetition
- **D-07:** When a manuscript has multiple folio-hits in the result list, **PGP fields repeat on every row** for that manuscript. Each row stays self-contained for sorting / filtering. Matches the existing per-folio row shape — do not collapse rows.

### Data source
- **D-08:** Use the same PGP lookup the JSON exporter uses: per-`sys_id` resolution via the document service (PGP enrichment). The cleanest reuse is to call the same logic that populates `_build_pgp_subset(pgp)` at `shared/search_serializer.py:473-485` and read its returned dict. Planner decides whether to factor out a shared helper or duplicate the lookup inline; either is acceptable.
- **D-09:** Manuscripts NOT in `search_state.transcription_sys_ids` short-circuit: do not call the PGP lookup, just emit empty cells. (Performance: avoids ~all-results × PGP-fetch cost.)

### Out-of-scope confirmations
- **D-10:** Word search-results export, list exports, parallels exports: **NO PGP columns added in this phase.** Each is its own follow-up if desired.
- **D-11:** JSON search-results export: **already includes PGP via `_build_pgp_subset`.** No changes needed.

### Claude's Discretion
- Exact column widths for the new columns in `set_excel_column_widths` (PGP URL needs ~40, Description ~50, Type ~15, Date ~15, Languages ~20, Tags ~30 — but planner can tune).
- Whether to extract a shared `pgp_fields_for_export(sys_id, meta_mgr) -> dict` helper or inline the lookup in `export_search_results_excel`. Either is fine.
- Whether to escape pipe characters that legitimately appear inside a tag/language value. Default: leave as-is (extremely unlikely in PGP data).
- Whether to wrap the PGP URL as an Excel hyperlink (clickable) or leave it as plain text. Default: plain text is simpler and copy-safe; planner may upgrade to hyperlink if cheap.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `_build_pgp_subset` at `shared/search_serializer.py:473` — the exact field projection we want. Reuse rather than reimplement.
- `transcription_sys_ids` — already in scope on the search export payload, enables the D-09 short-circuit.
- `set_excel_column_widths`, `sanitize_text_for_excel`, `get_cell_alignment` from `shared_export_utils` — handle the rendering plumbing; new columns plug in without new helpers.

### Established Patterns
- Excel exports use `ws.append(row)` per result with subsequent per-cell alignment setting. New PGP cells follow the same pattern — likely all `ltr_align` since PGP data is English.
- JSON export uses `serialize_search_payload(results, meta_mgr=..., ...)` to attach PGP and other enrichments. Excel export currently does NOT take `meta_mgr` — but it gets `results` that have `display.id` (sys_id). The PGP lookup needs a `meta_mgr` handle; planner decides whether to pass it through or fetch from `get_export_service(meta_mgr=...)` which already holds one.

### Integration Points
- One function to modify: `export_search_results_excel`. No new modules, no schema migration, no new endpoints.
- One field-projection function to reuse: `_build_pgp_subset`.
- Existing PGP enrichment pipeline already populates the underlying data — no new data fetching unless we move from lazy to eager.

</code_context>

<specifics>
## Specific Ideas

- User was explicit that **PGP is English** — overriding any default assumption that downloads should be locale-aware. Honor this literally; do not add language fallback logic, do not call translation services, do not look at user language. The export is canonical English.
- The user wants `pipe|delimited` for lists, not commas. Comma was a tempting default; do not regress to it.
- Empty cells (not "N/A") for missing data. Keeps the spreadsheet sortable and filterable in Excel without dummy values polluting the data.

</specifics>

<deferred>
## Deferred Ideas

- **Word export PGP columns** — extend `export_search_results_word` at `web/export_service.py:357` with the same fields. Different layout primitives (paragraphs not table rows), so its own design pass.
- **List export PGP columns** — `export_list_excel` at `web/export_service.py:413`. Likely the same column set, just on a different data shape.
- **Parallels export PGP columns** — `export_parallels_excel` / `export_parallels_word` at `:477` / `:563`. Parallels results have a different per-row shape (source text + matches), so the PGP columns may need re-thinking.
- **PGP transcription text in exports** — `page_section_text` field. Intentionally excluded from this phase due to Excel cell-size limits and readability concerns. Could be added as an optional column with a checkbox toggle on the download dialog.
- **PGP source / scholar attribution columns** — beyond the basic record, PGP has per-source author/year metadata (Goitein, V0.8, etc.) that researchers may want as separate columns.
- **Hebrew translations of PGP descriptions in export** — explicitly rejected by user this phase, but pgp.db DOES have `pgp_translations` (34,954 EN→HE descriptions per memory). A future phase could add an opt-in "translated" export mode if researchers request it.
- **Excel hyperlink rendering for PGP URL** — currently plain text; turning the URL into a clickable hyperlink is a small upgrade.

</deferred>
