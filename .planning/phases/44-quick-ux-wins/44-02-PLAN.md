**Step 2: Update get_library_display()** to accept a `lang` parameter:

```python
def get_library_display(code: str, short: bool = True, lang: str = None) -> str:
    """Return library name for display.

    Args:
        code: Library code (e.g., 'CUL', 'JTS')
        short: If True, return code; if False, return full name
        lang: Language code ('he', 'en', or None for auto-detect from CURRENT_LANG)

    Returns:
        Display string for the library
    """
    if not code:
        return ''
    if short:
        return code
    effective_lang = lang if lang else CURRENT_LANG
    if effective_lang == 'he':
        return LIBRARY_CODES_HE.get(code, LIBRARY_CODES.get(code, code))
    return LIBRARY_CODES.get(code, code)
```

This is backward-compatible: existing desktop callers pass no `lang` and get CURRENT_LANG-based behavior. Web callers will pass `lang=get_language()` explicitly.

**IMPORTANT:** The desktop app sets CURRENT_LANG at module load time. When the user toggles language in the desktop app, CURRENT_LANG is updated. So all desktop callers automatically get the right language without any changes. Only the web callers need updating because the web app has its own separate language state.
