    **In genizah_core.py build_regex_pattern:**

       to:
       ```python

       ```

    3. Do NOT apply mark-tolerance to:
       - Regex mode (line ~5088) -- user provides their own pattern
       - Flex spacing patterns (already custom regex, line ~5041-5044)
       - Wildcard patterns (_build_wildcard_regex results, lines ~5016-5027)
       - Inline alternation patterns (_expand_inline_alternation, line ~5012)

       The flex spacing and wildcard patterns generate their own regex; making them mark-tolerant would require modifying those generators which is out of scope (and those patterns involve character-level matching where interleaved marks would confuse semantics).

    **In web/pages/search.py highlight_full_text** (line ~2888):

    4. At the top of the `highlight_full_text` function, add mark-tolerance to the pattern before applying it:
       ```python
       def highlight_full_text(text, pattern):
           if not text:
               return ""
           escaped = html.escape(text)
           if pattern:
               try:
                   # Make pattern mark-tolerant so highlighting works through combining marks
                   from genizah_core import make_mark_tolerant_pattern
                   tolerant_pattern = make_mark_tolerant_pattern(pattern) if pattern else pattern
                   highlighted = re.sub(
                       f'({tolerant_pattern})',
                       r'<span class="highlight-match">\1</span>',
                       escaped,
                       flags=re.IGNORECASE
                   )
                   return highlighted
               except re.error:
                   return escaped
           return escaped
       ```

       IMPORTANT: The `pattern` passed to `highlight_full_text` is `regex.pattern` which is already a compiled regex pattern string. Wrapping it with `make_mark_tolerant_pattern` won't work correctly because it's a full pattern with groups and alternations, not a single escaped term.

       Instead, the approach should be: the highlight_pattern stored in search results is ALREADY mark-tolerant because it was generated by `build_regex_pattern` which now uses `make_mark_tolerant_pattern`. So the web highlight function inherits mark-tolerance automatically through the pattern string. No changes needed to `highlight_full_text`.

       HOWEVER: For lab_search results, the `highlight_pattern` is built separately (line ~1093 in lab_search):
       ```python
       highlight_regex_str = "|".join(re.escape(w) for w in found_words) if found_words else ""
       ```
       This needs mark-tolerance too. Change to:
       ```python
       highlight_regex_str = "|".join(make_mark_tolerant_pattern(re.escape(w)) for w in found_words) if found_words else ""
       ```

    5. Similarly, in the desktop `_apply_source_highlights` (genizah_app.py line ~3476), the pattern_str comes from the search results which is already the compiled pattern string from build_regex_pattern. Since build_regex_pattern now generates mark-tolerant patterns, the desktop viewer inherits this automatically. No desktop code changes needed.
