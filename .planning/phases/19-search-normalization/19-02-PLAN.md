       ```python

       ```
       to:
       ```python

       ```

    3. Do NOT apply mark-tolerance to:
       - Regex mode (line ~5088) -- user provides their own pattern
       - Flex spacing patterns (already custom regex, line ~5041-5044)
       - Wildcard patterns (_build_wildcard_regex results, lines ~5016-5027)
       - Inline alternation patterns (_expand_inline_alternation, line ~5012)

       The flex spacing and wildcard patterns generate their own regex; making them mark-tolerant would require modifying those generators which is out of scope (and those patterns involve character-level matching where interleaved marks would confuse semantics).

    **In genizah_core.py lab_search highlight builder** (line ~1093):

    4. The lab_search highlight_regex_str is built separately from build_regex_pattern. Change:
       ```python
       highlight_regex_str = "|".join(re.escape(w) for w in found_words) if found_words else ""
       ```

       to:
       ```python
       highlight_regex_str = "|".join(make_mark_tolerant_pattern(re.escape(w)) for w in found_words) if found_words else ""
       ```

Since `build_regex_pattern` now generates mark-tolerant patterns, both web and desktop highlighting inherit mark-tolerance automatically through the pattern string. No changes needed in web/pages/search.py or genizah_app.py.

    **Summary of actual changes (all in genizah_core.py):**
    - build_regex_pattern non-Responsa path: wrap re.escape with make_mark_tolerant_pattern
    - build_regex_pattern Responsa path: wrap re.escape with make_mark_tolerant_pattern
