<objective>
Wire OpenAPI spec exposure and Swagger UI by:

1. Adding a `path_prefix` keyword parameter to `init_search_api` in `web/search_api.py`. Default `path_prefix='/api'` preserves backward compatibility with existing tests (they register on bare apps and hit `/api/search`). When `path_prefix=''`, routes become `/search`, `/browse`, `/parallels` — correct for sub-app mounting.

2. Adding `description=` kwargs to all Pydantic `Field()` definitions across the 5 request models (`FiltersModel`, `ResponsaOptions`, `SearchRequest`, `BrowseRequest`, `ParallelsRequest`) so Swagger UI shows meaningful descriptions, not just types and constraints.

3. Building a `search_helper_app` FastAPI sub-app in `web/main.py` with `docs_url='/docs'`, `openapi_url='/openapi.json'`, calling `init_search_api(app_override=search_helper_app, path_prefix='')`, and mounting it on the NiceGUI singleton via `app.mount('/api', search_helper_app)`. Result: `/api/docs` (Swagger UI), `/api/openapi.json` (spec), `/api/search`, `/api/browse`, `/api/parallels` all served through the sub-app.

Per RESEARCH §1 (Pattern 1) and Pitfall 1: the route paths on the sub-app become `/search`, `/browse`, `/parallels` (no `/api/` prefix — the mount provides that prefix). Tests that call `init_search_api(app_override=bare_app)` need to keep hitting `/api/search`, so `path_prefix='/api'` is the default.

NiceGUI ships `app.docs_url=None, app.openapi_url=None` — naïve turning-on-defaults does not work. Sub-mount is the ONLY viable approach per RESEARCH verified evidence.

Purpose: Expose interactive OpenAPI surface at `/api/docs` + `/api/openapi.json` scoped to exactly the 3 search-helper endpoints, with zero regression on existing routes or tests.
Output: Modified `web/search_api.py` (path_prefix + Field descriptions) + modified `web/main.py` (sub-app wiring).
