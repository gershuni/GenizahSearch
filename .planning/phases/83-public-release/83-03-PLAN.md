<objective>
Wire OpenAPI spec exposure and Swagger UI in a way that produces a USEFUL spec — not a hollow one. Codex review concern #2 (HIGH): the existing handlers in `web/search_api.py` accept raw `Request` and instantiate Pydantic models manually inside the body; FastAPI cannot infer requestBody / query / response schemas from raw `Request` handlers, so adding `Field(description=...)` alone produces an OpenAPI spec where `/search` has no documented body and Swagger UI renders three buttonless endpoints.

**Solution chosen — typed-wrapper pattern that preserves envelope behavior (NOT a refactor of the existing handler bodies):**

Per Codex's "typed wrapper functions" suggestion: keep the existing `request: Request` handler bodies intact (they own the envelope/error-routing logic locked by Phases 78–81A) but ALSO register thin typed-signature wrapper routes on the sub-app via `openapi_extra=` declarations OR via a FastAPI factory that registers routes with explicit Pydantic-typed signatures whose body delegates to the existing handler. We pick **Option B (explicit `openapi_extra` on each route)** because it is the lowest-risk option — it changes only the OpenAPI spec metadata, NOT the handler signatures, NOT the request parsing path, NOT the envelope/error machinery. The handler bodies stay byte-identical to today's; only the routing decorators gain `openapi_extra={"requestBody": {...}, "responses": {...}}` arguments built from the existing Pydantic models via `model_json_schema()`.

This approach:
- Preserves Concern #2 (no global FastAPI exception handlers; envelope rewriting stays inside the handler body) — the existing rationale at search_api.py:444-448 holds.
- Produces the same OpenAPI spec a typed-signature handler would produce, derived from the existing Pydantic models.
- Means existing tests pass byte-identically because handler signatures and bodies are unchanged.

    **Helper to build at module scope (above init_search_api), once:**

    ```python
    def _openapi_request_body(model_cls) -> dict:
        """Build an OpenAPI requestBody object from a Pydantic model.

        Codex HIGH concern #2: handlers parse Pydantic manually inside the body to
        keep error-envelope routing local (search_api.py:444-448 rationale). FastAPI
        therefore cannot infer the request body shape from the handler signature.
        We declare it explicitly via openapi_extra so /api/docs renders parameters.
        """
        schema = model_cls.model_json_schema(ref_template="#/components/schemas/{model}")
        return {
            "required": True,
            "content": {
                "application/json": {"schema": schema},
            },
        }


    def _openapi_query_parameters(model_cls) -> list:
        """Build OpenAPI 'parameters' (in: query) list from a Pydantic model.

        Used for /browse which takes query params, not a body.
        """
        schema = model_cls.model_json_schema(ref_template="#/components/schemas/{model}")
        props = schema.get("properties", {})
        required = set(schema.get("required", []))
        params = []
        for name, prop_schema in props.items():
            params.append({
                "name": name,
                "in": "query",
                "required": name in required,
                "description": prop_schema.get("description", ""),
                "schema": {k: v for k, v in prop_schema.items() if k != "description"},
            })
        return params


    _ENVELOPE_SUCCESS_SCHEMA = {
        "type": "object",
        "properties": {
            "schema_version": {"type": "string", "example": "1.0"},
            "request": {"type": "object", "description": "Echo of validated request input."},
        },
        "required": ["schema_version", "request"],
        "additionalProperties": True,
    }
    _ENVELOPE_ERROR_SCHEMA = {
        "type": "object",
        "properties": {
            "error": {
                "type": "object",
                "properties": {
                    "code": {"type": "string", "description": "ERROR_CODES key (see shared/api_errors.py)."},
                    "message": {"type": "string", "description": "Human-readable, sanitized."},
                },
                "required": ["code", "message"],
            },
        },
        "required": ["error"],
    }


    def _openapi_responses_for(success_summary: str) -> dict:
        return {
            "200": {
                "description": success_summary,
                "content": {"application/json": {"schema": _ENVELOPE_SUCCESS_SCHEMA}},
            },
            "400": {
                "description": "Validation error (e.g. invalid_request, query_required, invalid_combination, unresolvable_filter_value).",

            },
            "429": {
                "description": "Rate limit exceeded (rate_limited).",
                "content": {"application/json": {"schema": _ENVELOPE_ERROR_SCHEMA}},
            },
            "503": {
                "description": "Mode-gate disabled or upstream service unavailable.",
                "content": {"application/json": {"schema": _ENVELOPE_ERROR_SCHEMA}},
            },
        }
    ```
