  <name>Task 1: Add folio-labeled page navigation to desktop browse tab</name>
  <files>genizah_app.py</files>
  <action>
Enhance the desktop browse tab to display folio labels and provide folio-aware navigation. Two areas need modification:

**A. Browse tab page combo (combo_browse_page, ~line 8072):**

Currently the combo_browse_page is populated with generic page numbers ("Page 1", "Page 2", etc.). Modify the population logic to use folio labels from the crossref service when available:

1. In the browse page loading flow (around `browse_load_page` or the enrichment path where combo_browse_page items are set), after the manuscript is identified by sys_id:
   - Import get_nli_crossref_service from shared.nli_crossref_service (with try/except for graceful degradation)
   - Call `get_folio_images(sys_id)` to get the folio sequence with labels
   - If folio data is available, populate combo_browse_page with folio labels instead of generic page numbers: `"1r"`, `"1v"`, `"2r"`, etc.
   - Store the folio images list as `self._browse_folio_images` for later use
   - If crossref service is unavailable, keep existing generic page numbering

2. Add a folio count label near the page combo: `"of N pages"` showing total image count from get_image_sources().

3. When `on_browse_page_combo_changed` fires with a folio-labeled combo, map the selected index back to the correct image page for navigation. The folio sequence from get_folio_images is ordered by ImageName (same order as FL IDs returned by the existing image pipeline), so combo index maps directly to image index.

**B. MSViewer source combo enhancements (~line 1528, load_images ~line 1627):**

The existing MSViewer.combo_source already handles NLI/Cambridge/Oxford switching. Enhance it:

1. In `load_images()` method, after the combo_source is populated, add source availability context:
   - Call `get_image_sources(sys_id)` (via the lazy `_get_crossref_service()` already available in genizah_core.py) during enrichment
   - Store the result in `current_meta['image_source_info']` during `enrich_metadata()`

2. Add a clickable "View in KTIV" button next to the existing "External Website" button (btn_external). This button:
   - Is visible when NLI FGP images are available (image_source_info['nli_fgp'] == True)
   - On click, opens `https://web.nli.org.il/sites/NLIS/he/ManuScript/Pages/Item.aspx?ItemID={sys_id}` in the default browser
   - Label: "KTIV" or "NLI Viewer"

3. Ensure the existing btn_external (which already opens Cambridge/Oxford viewers) and the new KTIV button are both visible when their respective sources exist, providing the same "clickable source indicator" pattern as the web app.

4. In `load_images()`, when building the combo_source items, add folio label context: instead of just `"NLI (4)"`, show `"NLI (4 pages)"` or similar.

**C. Folio label in image viewer:**

In MSViewer.set_page(), add a label showing the current folio notation. After setting `self.current_idx`, look up the folio label from the active image list (images carry the 'label' key from enrich_metadata, which is the ImageName). Parse that label with `parse_folio_label()` (imported from shared.nli_crossref_service) and display it. Options:
- Update the attribution label area to show `"Folio 1r"` alongside attribution
- Or add a small QLabel above/below the image that shows the folio

Per user decision: "Navigation bar positioned above the image viewer, near the shelfmark/title area" -- the folio label and navigation should be in the existing nav_bar area (line 8086), not inside MSViewer itself. The folio combo replaces/supplements the existing page combo.
