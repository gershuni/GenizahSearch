  **1. Add Cambridge IIIF image proxy endpoint to web/api.py:**

  Cambridge IIIF images need a server-side proxy (like NLI and Oxford) because some CUDL IIIF endpoints may have CORS restrictions or require consistent caching.

  Add a new endpoint `/api/cambridge_image/{sys_id}` that:
  - Accepts `sys_id` and `page` (0-indexed) query params
  - Looks up the manuscript in `state.meta_mgr.nli_cache[sys_id]` for `images_ext`
  - If `images_ext` has a canvas at the given `page` index, fetches the image using the IIIF Image API URL pattern: `{canvas_url}/full/max/0/default.jpg`
  - Returns the image bytes with proper Content-Type and Cache-Control headers
  - Uses a cache similar to `_oxford_image_cache` with same TTL
  - Falls back to 404 if no Cambridge images available or page out of range

  Implementation pattern — follow the existing `oxford_image` endpoint at line ~257 of web/api.py. Same cache structure, same timeout, same error handling.
