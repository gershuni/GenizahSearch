The async `create_and_add` handler in `add_to_list_dialog.py` calls `await lists_mgr.create_list(...)` which (in `web/user_lists.py:218-244`) calls the SYNCHRONOUS `sb_create_list(...)` directly inside the async function body — no `run.io_bound()`, no thread offload. So the error is NOT a thread-context loss.

**Reviews C2 (2026-05-17) — actual gating mechanism corrected:** `app.storage.user` is NOT gated by the NiceGUI client slot stack. It is gated by `nicegui.storage.request_contextvar` (verified at `venv/Lib/site-packages/nicegui/storage.py:109-113`). When that contextvar is `None` at access time, the storage layer raises `RuntimeError("app.storage.user can only be used within a UI context")`. The slot-stack helpers (`Client.__enter__` at `venv/Lib/site-packages/nicegui/client.py:140`, `Slot.get_stack()`, `context.client.run_async(...)`) operate on a DIFFERENT axis — they manage which UI client owns rendered elements; they do NOT bind `request_contextvar`. So Hypothesis-D and its `with _dialog_owner_client:` rebind cannot fix the storage error: even inside the dialog's client context, if `request_contextvar.get() is None`, storage still raises. The fix must operate on `request_contextvar` binding (or re-read live storage at click time once contextvar is valid again).

**The error string "can only be used within a UI context"** is raised by NiceGUI (`venv/Lib/site-packages/nicegui/storage.py:109-113`) when `nicegui.storage.request_contextvar.get()` returns `None` at the moment `app.storage.user` is accessed. This is NOT a slot-stack issue and NOT a prune-race AssertionError. The contextvar is bound per-request by NiceGUI middleware and propagates through `asyncio` task spawns via the standard `contextvars` module — but if an event handler fires from a context where the contextvar was never bound (or was bound to a different request that has since completed), access raises and the exception propagates to the second `except Exception` branch (line 58-60). It's not noise; it's a real request-context bind failure.

**Hypothesis D (REFRAMED per Reviews C2) — Event listener captures NO request at registration:**
NiceGUI registers event listeners by capturing the current request via `request_contextvar` at the time the `on_click=...` kwarg is bound to the `ui.button(...)` (or similar) — see `venv/Lib/site-packages/nicegui/element.py:390-398`.
