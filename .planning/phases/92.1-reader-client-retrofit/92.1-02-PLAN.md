**Hypothesis C — Project lookup branch fires `_get_cached_data()` which calls `get_user_lists` AGAIN (re-entrancy through the same migrated reader):**

**Hypothesis D (REFRAMED per Reviews C2) — Event listener captures NO request at registration:**
NiceGUI registers event listeners by capturing the current request via `request_contextvar` at the time the `on_click=...` kwarg is bound to the `ui.button(...)` (or similar) — see `venv/Lib/site-packages/nicegui/element.py:390-398`. This is the most likely root cause given the failure surface (dialog buttons inside a search-results card).

| T-92.1-02-02 | Spoofing | Captured Context used to execute a handler against a DIFFERENT user's request | mitigate | The `copy_context()` call happens INSIDE the request that opens the dialog. No mechanism exists for User A's Context to reach User B's dialog handler — they have distinct closures in distinct event-loop tasks. The fix re-binds request_contextvar at click time to the SAME request that opened the dialog; live storage reads (auth_user, auth_session) reflect the current state of THAT user's session at click time.
