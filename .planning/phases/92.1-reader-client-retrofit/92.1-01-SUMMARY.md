## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Anonymous-fallback test path needed pre-configured chain on anon_sentinel**
- **Found during:** Task 2 (regression-test installation) — discovered when reasoning through the negative-control test before running it
- **Issue:** The plan's `_install_common_stubs` skeleton configured the chained `.table(...).select(...).eq(...).order(...).execute()` return value on `fake_client` only. But the negative control (anon fallback) routes through `get_client_mock.return_value = anon_sentinel`, not through `fake_client`. Without the same chain configuration on `anon_sentinel`, the reader would crash at the first `.execute()` call before the assertion could fire — making the negative control vacuously pass for the wrong reason (or worse, fail with an unrelated MagicMock TypeError).
- **Fix:** Replicated the four chain-return-value lines for `anon_sentinel` (4 lines added in `_install_common_stubs`). The negative control now exercises a real reader call that successfully returns and then asserts both that `_apply_user_auth_to_client` was NOT called AND that `get_client_mock.called is True`.
- **Files modified:** `tests/test_supabase_client_reader_rls.py`
- **Verification:** `test_reader_falls_back_to_anonymous_when_no_auth_session` PASSES with the stronger assertion firing on a real reader execution path.
- **Committed in:** `857999fc` (atomic Task 2+3 commit)
