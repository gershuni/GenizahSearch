## Phase Boundary

<decisions>
## Implementation Decisions

### EXPUX-01 — Open File / Open Folder on the "export complete" dialog
- **D-01:** Replace the bare `QMessageBox.information(self, tr("Saved"), tr("Saved to {}").format(path))` at **every** export-complete site with a small dialog (a `QMessageBox` carrying custom buttons, or a tiny reusable helper `_show_export_saved_dialog(path)`) offering **Open File**, **Open Folder**, and **Close**.
- **D-02:** "Open File" → `os.startfile(path)` (Windows-native; the saved export is xlsx/csv/txt/docx). "Open Folder" → reveal-in-Explorer with the file selected, **reusing `desktop/file_actions.reveal_local_file(path)`** (it already does the correct separate-argv `["explorer", "/select,", path]` form that survives spaces). Do NOT route "Open File" through `open_local_file` — that gate is for My-Library extensions; an export file should open regardless.
- **D-03:** Apply to ALL `tr("Saved to {}")` sites in `export_results` (xlsx/csv/txt/docx) **and** `export_comp_report` (xlsx/csv/txt/docx) — 8 sites. The standalone "Manuscript saved to:" site (`:10951`) is out of scope (different surface) unless trivially shared.
- Failures (missing file / launch error) degrade gracefully: log + no crash.

### EXPUX-02 — LOCAL-only xlsx must not warn "Domain enrichment pending"
- **D-04:** Root cause: the pre-export gate at `genizah_app.py:~19978` warns when `(not self._result_domain_map) and _has_sys_ids`, but `_has_sys_ids` counts LOCAL synthetic 97-prefix ids too. Fix: change the guard to count only **Genizah** ids — `any(id and display.source != 'LOCAL' ...)`. A LOCAL-only export then skips the warning entirely (domains are a Genizah-only concept). Mixed/Genizah exports still warn as before.

### EXPUX-03 — LOCAL-only exports omit the MiDRASH credit
- **D-05:** `_get_credit_header()` gains a `local_only: bool = False` parameter. When `local_only`, it returns only the "Generated by Genizah Search Pro" line + separator — **omitting** the "Data Source: MiDRASH Automatic Transcriptions…" and "Dataset available at: https://doi.org/10.5281/zenodo.17734473" lines (and the Hebrew `REPORT_CREDIT_TXT` equivalent). The MiDRASH attribution is meaningless for purely local documents.
- **D-06:** `export_results` computes `_local_only = _has_local_in_export and all(display.source=='LOCAL')` over the export set, and passes `local_only=_local_only` to `_get_credit_header()` for the CSV/TXT/DOCX branches. For **xlsx**, the "Credits and Info" sheet credit lines (`shared/export_dossier.credits_lines` / `build_credits_info_sheet`) must likewise omit the MiDRASH attribution when LOCAL-only — thread a `local_only` flag through `_build_search_results_xlsx_bytes` → `build_credits_info_sheet`.
- **D-07:** `export_comp_report` is Genizah-only today (composition has no LOCAL path) → `local_only` is always False there; no behavior change. Pass `local_only=False` explicitly for clarity.

### EXPUX-04 — Full-text capped context in DOCX + TXT
- **D-08:** DOCX and TXT (`export_results`, both Genizah and LOCAL) show the **full matched page/chunk text**, capped at **~2000 chars** (`_EXPORT_CONTEXT_CAP = 2000`), with matched terms still bold/`*`-highlighted — replacing the current ±60-char `raw_file_hl` one-line snippet. XLSX and CSV are UNCHANGED (they keep the compact snippet — wide cells/flat table).
- **D-09:** New module-level, Qt-free helper (in `shared/docx_export.py` or a shared export util, reusable by both the DOCX block writer and the TXT builder):
  `build_expanded_context(full_text, raw_file_hl, cap=2000) -> str`
  - Recover the matched term(s) from `raw_file_hl` (substring(s) between `*` markers).
  - Locate the first match in `full_text`; build a window of ≤cap chars (prefer centering on the first match, or from text start if the match is early); re-insert `*` markers around all in-window occurrences of the matched term(s).
  - **Fallback (no regression):** if `full_text` is empty/None or the matched term can't be located, return the existing `raw_file_hl` snippet unchanged.
- **D-10:** `write_docx_result_block` takes the expanded text for its body paragraph (keeps the existing `_add_highlighted_runs` `*`-split rendering). The TXT block builder uses the same expanded text. Newlines preserved where the format allows (TXT keeps them; DOCX flows).
- **D-11:** Genizah full text comes from the existing `full_text_fetcher` (`searcher.get_full_text_by_id`) already wired for xlsx; LOCAL full text from the result dict's `full_text` (page text). The cap protects against multi-thousand-word PDF pages.

### Non-regression
- **D-12:** `tests/test_export_xlsx_cross_parity.py` must stay green unmodified (xlsx structure untouched by these changes — only the Credits sheet credit *lines* change, and only for LOCAL-only sets, which the Genizah-only-fixture invariant never exercises). EXPUX-04 touches DOCX/TXT only.

### Claude's Discretion
- Exact dialog button labels/order and bilingual strings (EN/HE) for Open File / Open Folder / Close.
- Whether `build_expanded_context` lives in `shared/docx_export.py` vs a new `shared/export_text.py`.
- Window-centering heuristic and the precise cap value (≈2000) — keep it a named constant.

</decisions>

## Existing Code Insights

### Reusable Assets
- `desktop/file_actions.reveal_local_file` — correct Explorer `/select,` reveal (handles spaces); reuse for Open Folder.
- `_has_local_in_export` + `_export_filepath` + `_prime_local_filepath_cache` — LOCAL partition + filepath map already built in `export_results` (Phase 103).

### Established Patterns
- Export helpers are module-level, Qt-free, offline-testable (mirror `test_desktop_xlsx_multi_sheet.py` / Phase 103 helper tests). `build_expanded_context` follows suit.
- LOCAL discrimination = `display['source']=='LOCAL'` primary, 97-prefix secondary (Phase 103 D-14).

### Integration Points
- A shared "Saved" dialog helper called from 8 sites (both export methods).
- `_get_credit_header(local_only)` + xlsx Credits `local_only` thread.
- `build_expanded_context` consumed by the DOCX block writer and the TXT branch in `export_results`.

<specifics>
## Specific Ideas
- User framing: the export-complete toast should let them jump straight to the file or its folder ("Open File and Open Folder buttons").
- LOCAL exports should not nag about Genizah metadata/domains or cite MiDRASH — those are irrelevant to a user's own local documents.
- DOCX/TXT are the "reading" formats — a one-line snippet is too little; show the full matched passage (capped).

</specifics>

- Composition-report LOCAL handling — deferred (Phase 104 / EXP-F3).
