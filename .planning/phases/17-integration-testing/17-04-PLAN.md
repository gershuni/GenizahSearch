**Fix A — Sofit conversion in _build_wildcard_regex() (lines ~4861-4878):**

For suffix wildcards (wildcard == 'suffix'), the trailing letter of each regex_term may be a sofit (final-form) letter. When a sofit letter appears at the end of a stem followed by `\S*`, it will never match text where the stem continues with more letters (because Hebrew uses normal form mid-word, sofit only at word end).

For each term in regex_terms for suffix wildcard:
1. Check if the last character is in _SOFIT_TO_NORMAL
2. If yes, replace the trailing sofit with a character class matching BOTH forms. Example: שלום -> שלו[םמ] (matches both standalone שלום and continuation שלומ-)
3. Then append `\S*` as before

Implementation for suffix wildcard section (~line 4861):
```python
if wildcard == 'suffix':
    regex_terms = component.get('regex_terms', [])
    if regex_terms:
        sorted_terms = sorted(set(regex_terms), key=len, reverse=True)
        escaped = []
        for t in sorted_terms:
            if t and t[-1] in _SOFIT_TO_NORMAL:
                # Replace trailing sofit with char class matching both forms
                normal = _SOFIT_TO_NORMAL[t[-1]]
                sofit = t[-1]
                base = re.escape(t[:-1])
                escaped.append(f'{base}[{sofit}{normal}]' + r'\S*')
            else:
                escaped.append(re.escape(t) + r'\S*')
        return f"({'|'.join(escaped)})"
    return ''
```

For prefix wildcards (wildcard == 'prefix', ~line 4871), the sofit letter would be at the END of the term, which is also the end of the matched word — sofit is correct there. However, if the FIRST character of a prefix wildcard term is a sofit (rare but possible), no conversion is needed since `\S*` precedes it. So prefix wildcards need no change.

```python
except Exception as e:

```

**Replace with:**
```python
except ValueError as e:
    # Explosion guard or other validation error — show to user
    error_msg = str(e)
    print(f"Search Validation Error: {error_msg}")
    return {'error': error_msg}
except Exception as e:
    print(f"Search Error: {e}")
    import traceback
    traceback.print_exc()
    return []
```

Then, after the `run_core_search` call (~line 1696), handle the error dict:
```python
results = await run.io_bound(run_core_search)

# Handle validation errors from explosion guard
if isinstance(results, dict) and 'error' in results:
    error_msg = results['error']
    ui.notify(error_msg, type='warning', timeout=8000, close_button=True)
    search_state.is_running = False
    search_state.is_cancelled = False
    search_state.progress = 0
    results_count.text = f"0 {tr('Results')}"
    render_results([])
    return
```

This way:
- ValueError (explosion guard, validation) shows user-facing notification
- Other exceptions (network, unexpected) still log to console and return empty
- The user sees WHY they got 0 results and can simplify their query

**Important:** The run_core_search function runs in run.io_bound (a thread), so it cannot directly call ui.notify. That's why we return a sentinel dict and handle the notification in the main async context.
