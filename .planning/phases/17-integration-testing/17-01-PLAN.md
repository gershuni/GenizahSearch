Create `tests/test_responsa_parity.py` with a `TestCrossAppParity` class that verifies XAPP-01.

**Critical insight from codebase analysis:** Both apps construct `responsa_options` identically:
- Web (search.py:1659-1668): `{'responsa_mode': True, 'variants': cb.value, 'ja': cb.value, 'flex_spacing': cb.value, 'bidirectional': cb.value, 'variant_mode': 'variants' if variants_cb.value else 'exact'}`
- Desktop (genizah_app.py:13405-13414): `{'responsa_mode': True, 'variants': cb.isChecked(), 'ja': cb.isChecked(), 'flex_spacing': cb.isChecked(), 'bidirectional': cb.isChecked(), 'variant_mode': 'variants' if variants_cb.isChecked() else 'exact'}`

Since both call the same `SearchEngine.execute_search()`, parity is architecturally guaranteed IF the dicts are identical. Tests verify:

1. **Dict structure parity** (parametrized over all 16 boolean combinations of the 4 checkboxes: variants, ja, flex_spacing, bidirectional):
   - Both apps produce dicts with identical keys: `responsa_mode`, `variants`, `ja`, `flex_spacing`, `bidirectional`, `variant_mode`
   - `variant_mode` is `'variants'` when `variants=True`, else `'exact'` -- verify this logic holds

2. **Pipeline determinism** -- using `_make_search_engine()` from test_responsa_integration.py pattern:
   - Same query + same `responsa_options` dict -> same Tantivy query string
   - Same query + same `responsa_options` dict -> same regex pattern string
   - Test with: `#shalom`, `#shalom olam*`, `#(shalom/shalmot) %olam`, `#shalom [3] olam`

3. **Execute search determinism** -- with mocked index returning fixed hits:
   - Same query + same options -> same result count
   - Same query + same options -> same result UIDs (compare as sets, NOT ordered lists -- per research Pitfall 3)

4. **Mode detection parity**:
   - Web uses `mode_select.value == 'responsa'` (string comparison)
   - Desktop uses `self.mode_combo.currentIndex() == self.MODE_RESPONSA` (integer)
   - Test that both produce `responsa_options` with `responsa_mode: True` for Responsa selection and `None` for non-Responsa selections

5. **Explosion guard warning parity**: Both apps read `results[0].get('responsa_warning')` -- test that warning propagates through execute_search (this builds on the existing test in test_responsa_integration.py but with a more complete mock that returns actual results).

Reuse the `_make_search_engine()` helper pattern from `tests/test_responsa_integration.py`. Import from genizah_core: `SearchEngine, parse_responsa_query, ResponsaComponent, extract_per_pair_gaps`. Use `unittest.mock.MagicMock, patch`.

Target: ~8-12 tests.
