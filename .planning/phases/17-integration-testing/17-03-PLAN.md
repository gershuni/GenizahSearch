Fix the keyboard shortcut handler so that R+Space (and all other prefix shortcuts) correctly trigger on_mode_change() after programmatically setting mode_select.value.

**Root cause:** In NiceGUI, setting mode_select.value programmatically does NOT fire the 'update:model-value' event, so the on_mode_change() handler (line ~573) never runs. The dropdown UI works because user interaction fires the Vue/Quasar event natively.

**Fix location:** on_query_input_change function, around line 350. After the line `mode_select.value = target_mode`, add an explicit call to `on_mode_change()`.

The on_mode_change function is defined at line ~573 and handles:
- variant_slider_row visibility
- query_column / tag_column visibility toggle
- responsa_sub_row visibility (line ~594)
- storage persistence

**Important:** on_mode_change() is defined AFTER on_query_input_change in the source. Both are closures inside the same search_page() function, so on_mode_change is accessible from on_query_input_change because Python closures capture variables by reference, not by value, and the function object will exist by the time the shortcut handler actually runs (it's an event callback, not called at definition time). However, verify this works — if there's a NameError, the alternative is to inline the visibility calls:

<task type="auto">
  <name>Task 2: Cap large result sets to prevent WebSocket crash</name>
  <files>web/pages/search.py</files>
  <action>
Fix the WebSocket overload caused by storing unbounded results in app.storage.user and making unbounded batch Supabase lookups. This also resolves the toolbar disappearing issue (Gap 4), which is a symptom of connection instability.

**Fix 1 — Cap app.storage.user results (line ~1719):**
Change:
```python
app.storage.user['search_results'] = results
```
To:
```python
# Cap stored results to prevent WebSocket overload (18K+ results = 50-100MB JSON)
capped = results[:200]
# Strip full_text from stored results (only needed for display, not persistence)
storage_results = []
for r in capped:
    sr = dict(r)
    sr.pop('full_text', None)
    display = sr.get('display')
    if display and isinstance(display, dict):
        d = dict(display)
        d.pop('full_text', None)
        sr['display'] = d
    storage_results.append(sr)
app.storage.user['search_results'] = storage_results
```

**Fix 2 — Cap batch transcription lookup (lines ~1698-1706):**
Change the result_sys_ids to only use the first 200 results (the ones that will actually be rendered):
```python
# Only look up transcriptions for displayed results (first 200)
displayed_results = results[:200]
result_sys_ids = [
    r.get('display', {}).get('id')
    for r in displayed_results
    if r.get('display', {}).get('id')
]
```

**Fix 3 — Cap apply_filters render call (line ~868):**
Change `render_results(filtered)` to `render_results(filtered[:200])`.
Update the count text to indicate capping if filtered > 200:

render_results(filtered[:200])
shown = min(len(filtered), 200)
