## SC#5 / CRASH-06 reconciliation (REVIEWS HIGH-4 — chosen option documented)
**Chosen: option (a) — direct-send supersedes the hook-time FIFO flush.** The crash event is delivered by the
lock-free `send_crash_event_direct` inside `_emit_crash_direct` (Plan 02), so the crash event is already on the
wire before the hook returns — there is no need (and it would be unsafe) to call `_flush_before_exit` from the
crash hook, because `_flush_before_exit` takes `_capture_config_lock` via `_resolve_api_key` (posthog_server.py:288),
violating D-05's lock-free invariant for the crash path. The clean-exit `atexit` flush (~1.5s, registered once
inside `install_exception_hooks`) covers any QUEUED non-crash events on a normal shutdown. This satisfies CRASH-06
("the crash event is prioritized over a full queue") via the direct send, and SC#5 ("bounded synchronous flush
delivers the crash event before exit + atexit for clean exits") via direct-send + clean-exit atexit.
