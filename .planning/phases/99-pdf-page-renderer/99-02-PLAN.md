`run(self)` — the long-lived loop (net-new; no one-shot analog). Single-owner discipline: ALL fitz
access (the LRU + render) happens here on this thread.
```python
def run(self) -> None:
    while True:
        item = self._queue.get()
        if item is _STOP or self._stopping:
            break
        token, sys_id, page_num, filepath = item
        try:
            img = render_via_lru(self._lru, filepath, page_num)   # Plan 01 core
            self.render_succeeded.emit(token, sys_id, page_num, img)
        except PdfRenderError as e:
            logger.warning("render_failed token=%s sys_id=%s page=%s reason=%s detail=%s",
                           token, sys_id, page_num, e.reason.value, e.detail)
            self.render_failed.emit(token, sys_id, page_num, e.reason, e.detail)
        except Exception as exc:  # noqa: BLE001 — no-crash contract; thread must survive
            logger.exception("PdfRenderWorker: unexpected render error")
            self.render_failed.emit(token, sys_id, page_num,
                                    PdfRenderFailure.RENDER_ERROR, str(exc))
    self._lru.close_all()   # D-06: all docs closed when the thread exits
```
The per-request try/except is the PDFIMG-06 no-crash envelope (mirror LocalIndexerWorker.run): one
bad render emits render_failed and the loop continues serving the next request — the thread never
dies. `render_via_lru` raises only `PdfRenderError` for classified failures; the bare `except`
catches anything unexpected and maps to RENDER_ERROR.

Clean shutdown (mirror viewers.py:1078-1102 conventions; long-lived variant per 99-PATTERNS Analog 4):
```python
def stop(self, timeout_ms: int = 2000) -> None:
    self._stopping = True
    self._queue.put(_STOP)              # unblock the blocking get()
    if not self.wait(timeout_ms):
        logger.warning("PdfRenderWorker did not stop in %dms; terminating", timeout_ms)
        self.terminate()
        self.wait()
    self._lru.close_all()               # belt-and-suspenders: also close if run() didn't reach it
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI thread → render worker thread | Render requests cross from the Qt UI thread into the single dedicated render thread via a thread-safe `queue.Queue`. The worker is the SOLE owner of all `fitz` access + the DocLRU (D-09 single-owner discipline). No other thread touches fitz concurrently. |
| user filesystem → renderer | (Inherited from Plan 01) local user-owned PDF files; no network/auth. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-99-04 | Tampering / DoS | concurrent fitz access from a future caller touching the LRU off-thread (PyMuPDF "not thread-safe" caveat → may crash Python) | mitigate | Single-owner discipline: all fitz/LRU access is inside `run()` on the render thread; `_assert_worker_thread()` (`assert QThread.currentThread() is self`) fails loudly if a future contributor calls the render branch off-thread (RESEARCH Pitfall 3 / Open Question 2). |
| T-99-05 | Denial of Service | one wedged/exception-raising render killing the worker thread, hanging all future navigation | mitigate | Per-request try/except envelope (both `PdfRenderError` and bare `except Exception`) emits `render_failed` and the loop continues — the thread never dies (mirror LocalIndexerWorker.run). Verified by `test_worker_survives_bad_render_and_serves_next`. The ~8s soft watchdog for a wedged C call is Phase 100 (D-05); the worker itself never blocks the UI thread (work is off-thread by construction). |
| T-99-06 | Denial of Service | zombie thread / unclosed fitz handles on shutdown | mitigate | `stop()` sets stop flag + pushes `_STOP` sentinel + `wait(timeout)` then `terminate()` last-resort; `DocLRU.close_all()` closes every open handle on thread exit AND in `stop()` (D-06: all docs closed on shutdown). |

No HIGH threats. Desktop-only, no network/auth surface.
