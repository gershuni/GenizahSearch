<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user filesystem → renderer | The renderer opens a local PDF file the user themselves selected/indexed via My Library. No network, no auth, no remote/untrusted input. The only "untrusted" data is a possibly-malformed PDF the user already has on disk. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-99-01 | Denial of Service | `render_page` / `fitz.open` on a malformed or malicious PDF (crash, exception, resource spike) | mitigate | `_open_doc_classified` + `render_page` classify every failure into `PdfRenderFailure` and raise a typed `PdfRenderError` (logged) instead of crashing; bounds validated pre-render (D-04a); DocLRU bounds open handles at maxsize=4 (D-06) so a flood of distinct PDFs cannot exhaust handles unbounded. No recursion. (Covered by test_corrupt_reason, test_encrypted_reason, test_page_out_of_range, test_failures_logged.) |
| T-99-02 | Tampering / Information Disclosure | user filepath handling (`os.path.exists`, `.pdf` suffix check, `fitz.open`) | accept | Local desktop reading a user-owned path; no privilege boundary crossed, no path travels to a network/other user. Suffix + existence checks are correctness guards, not a security perimeter. Rationale: single-user local app, filepath originates from the user's own My Library index. |
| T-99-03 | Denial of Service | unbounded memory from caching rendered images | mitigate | D-06 hard constraint: NO page/pixmap caching and NO on-disk image cache — only bounded open `fitz.Document` handles (LRU size 4). (Covered by test_no_disk_cache, test_doc_lru_evict_and_close.) |

No HIGH threats. No web/auth/network surface applies (desktop-only, local files).
