  <behavior>
    - get_filter_sys_ids(domain=None, author=None, work=None, date_from=None, date_to=None, include_undated=False, material_include=None, material_exclude=None) returns set of matching sys_id strings
    - With no filters: returns None (meaning "no restriction" — callers treat None as "all manuscripts")
    - domain="Halakha" returns only sys_ids classified under Halakha domain (or its parent)
    - author=person_id returns sys_ids where catalog Author FK or title Author FK matches (same logic as get_browse_results)
    - work=title_id returns sys_ids where GenizahTitleId matches
    - date_from=1100, date_to=1200 returns sys_ids with CopyDate in range
    - material_include=["Printed"] returns only sys_ids with matching FragmentMaterial values in catalog_fields
    - material_exclude=["Printed"] returns sys_ids that do NOT have FragmentMaterial=Printed
    - Combining filters uses intersection (AND logic — same as browse)
    - Returns set (not list) for O(1) membership testing
    - Returns empty set (not None) when filters are active but match nothing
  </behavior>
  <action>
    Add `get_filter_sys_ids()` method to FjmsService. Reuse the same dynamic SQL WHERE clause pattern from `get_browse_results()` but:
    1. Return only DISTINCT AlmaId values as a set (no pagination, no metadata enrichment)
    2. Add `material_include` and `material_exclude` parameters that query catalog_fields WHERE FieldCategory='FragmentMaterial' AND FieldValue IN (...) / NOT IN (...)
    3. Return None when ALL filter params are None/empty (caller optimization — None means "don't filter")
    4. Return set() when filters are active but nothing matches

    The method should be efficient for large result sets (up to ~200K sys_ids). Use a single SQL query with JOINs rather than multiple queries.

    For material filters, join against catalog_fields:
    - material_include: `c.AlmaId IN (SELECT AlmaId FROM catalog_fields WHERE FieldCategory='FragmentMaterial' AND FieldValue IN (...))`
    - material_exclude: `c.AlmaId NOT IN (SELECT AlmaId FROM catalog_fields WHERE FieldCategory='FragmentMaterial' AND FieldValue='Printed')`

    Note: The catalog table has ~685K rows but AlmaId is indexed. The method should complete in <1s for typical filter combos.
