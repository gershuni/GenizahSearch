    Add the filter UI components to web/pages/search.py:

    **1. State additions to SearchUIState.__init__():**
    Add filter state fields:
    ```python
    self.filter_domain: str = None      # Selected domain filter
    self.filter_author: str = None      # Selected author (person_id)
    self.filter_author_name: str = ''   # Author display name
    self.filter_work: str = None        # Selected work (title_id)
    self.filter_work_name: str = ''     # Work display name
    self.filter_date_from: int = None   # Date range start
    self.filter_date_to: int = None     # Date range end
    self.filter_material_exclude: list = []  # Material types to exclude (e.g., ['Printed'])
    self.filter_manuscript_count: int = None  # Count of manuscripts matching current filters
    self.restrict_sys_ids: set = None   # Computed from filters, passed to search engine
    self.word_search_excluded_ids: set = set()  # Per-manuscript exclusions for word search mode
    ```

    **2. Restore filters from storage (after SearchUIState creation, ~line 78):**
    Restore each filter field from `app.storage.user` using `_persist` pattern keys like `'search_filter_domain'`, `'search_filter_author'`, etc. Also restore `word_search_excluded_ids` from storage.

    **3. Collapsible Advanced Filters panel:**
    Add BELOW the search bar row (after the mode/gap/variant controls, before results). Use `ui.expansion` with text "Advanced Filters" (translatable). Collapsed by default UNLESS filters are active (auto-expand when any filter is set, e.g., after arriving from browse page).

    Inside the panel, create a responsive layout with:
    - **Domain filter:** Use `ui.select` with options populated from `fjms.get_domain_hierarchy()`. Flatten hierarchy into a grouped select: parent domains as option-group headers, child domains as options. Show manuscript count per domain.
    - **Author filter:** `ui.select` with search/filter capability (NiceGUI `with_input`). Options from `fjms.get_browse_authors(domain=search_state.filter_domain)`. Cross-filtered by domain.
    - **Work filter:** `ui.select` with search/filter capability. Options from `fjms.get_browse_works(domain=search_state.filter_domain, author=search_state.filter_author)`. Cross-filtered by domain and author.
    - **Date range:** Two `ui.number` inputs (From year, To year) for CopyDate range.
    - **Material exclude:** Prominent "Exclude Printed" checkbox (most common use case per user decision). This is separate from the existing 3-state printed_filter toggle (which is a post-search filter). The pre-search material filter restricts the Tantivy search scope entirely.

    Each filter change should:
    - Update the corresponding `search_state.filter_*` field
    - Persist via `_persist()`
    - Cross-filter dependent selects (author filtered by domain, work filtered by domain+author)
    - Recompute `search_state.filter_manuscript_count` by calling `fjms.get_filter_sys_ids()` and getting `len()` (run in background to avoid blocking UI)
    - Update the chip bar

    **IMPORTANT:** Changing a filter does NOT auto-run the search (per user decision: "removing a filter chip requires manual re-search"). User must click Search to apply.

    **4. Chip bar:**
    Add a row of removable chips ABOVE the results area (below the filter panel). Each active filter shows as a chip: `[Halakha ×]`, `[Rambam ×]`, `[1100-1200 ×]`, `[Exclude Printed ×]`.

    Also show total manuscript count: `"3,241 manuscripts"` (or translated equivalent).

    Clicking × on a chip clears that filter, updates storage, cross-filters dependent selects, and recomputes count. The chip bar should be visible even when the filter panel is collapsed.

    **5. Word search per-result exclusion:**
    In the `render_results()` function, for each result row in word search mode (not composition), add a small "×" button or icon button that:
    - Adds the result's sys_id to `search_state.word_search_excluded_ids`
    - Persists via `_persist('word_search_excluded_ids', list(search_state.word_search_excluded_ids))`
    - Re-renders results with the excluded item moved to a collapsible "Excluded Results" section (matching the composition mode pattern)

    The excluded section should match the existing pattern from composition/parallels: collapsible `ui.expansion`, collapsed by default, showing count.

    **6. Search history integration:**

    ```python
        'author': search_state.filter_author,

        'date_from': search_state.filter_date_from,
        'date_to': search_state.filter_date_to,
        'material_exclude': search_state.filter_material_exclude,
    }
    ```
    When recalling a search from history, restore these filter fields. In the history dropdown, show a filter icon (e.g., 'filter_list' material icon) on entries that had active filters.

  <name>Task 2: Integrate pre-search filtering with execute_search call</name>
  <files>web/pages/search.py</files>
  <action>
    Wire the filter state to the actual search execution:

    **1. Compute restrict_sys_ids before search:**
    In the `execute_search()` async function (~line 2247), BEFORE `run_core_search()`, compute the filter set:
    ```python
    # Compute pre-search filter set from active filters
    restrict_sys_ids = None
    if any([search_state.filter_domain, search_state.filter_author, search_state.filter_work,
            search_state.filter_date_from, search_state.filter_date_to,
            search_state.filter_material_exclude]):
        fjms = get_fjms_service(thread_safe=True)
        if fjms.is_available():
            restrict_sys_ids = await run.io_bound(lambda: fjms.get_filter_sys_ids(
                domain=search_state.filter_domain,
                author=search_state.filter_author,
                work=search_state.filter_work,
                date_from=search_state.filter_date_from,
                date_to=search_state.filter_date_to,
                material_exclude=search_state.filter_material_exclude or None,
            ))
            search_state.restrict_sys_ids = restrict_sys_ids
            # If filters are active but match nothing, show message and return
            if restrict_sys_ids is not None and len(restrict_sys_ids) == 0:
                ui.notify(tr("No manuscripts match the current filters."), type='warning')
                search_state.is_running = False
                return
    ```

    **2. Pass restrict_sys_ids to execute_search:**
    In `run_core_search()` (~line 2339), pass the computed set:
    ```python
    return state.searcher.execute_search(
        clean_query,
        mode=mode,
        gap=int(gap_input.value),
        progress_callback=progress_cb,
        exclude_words=not_words,
        responsa_options=responsa_options,
        restrict_sys_ids=restrict_sys_ids  # NEW
    )
    ```
    Also for lab_search, if it has been extended to support restrict_sys_ids, pass it. Otherwise skip (lab mode is a secondary path).

    **3. Apply word search exclusions to results:**
    After results return from `run_core_search()`, filter out any results whose sys_id is in `search_state.word_search_excluded_ids`. Move excluded results to a separate list for the excluded section, matching the existing pattern used for domain_excluded_results.

    **4. Update search summary:**
    If filters were active, include filter info in the search summary line (e.g., "42 results in 2.3s (filtered: Halakha, 3,241 manuscripts)").

    **5. Capture restrict_sys_ids in state snapshot for search history:**
    Do NOT store the full set (could be 200K+ items). Instead store a flag `had_filters: True` and the filter params in the state snapshot.
