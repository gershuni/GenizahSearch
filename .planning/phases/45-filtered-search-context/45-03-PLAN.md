  <files>genizah_app.py</files>
  <action>
    **1. Create PreSearchFilterDialog class** (add near DomainFilterDialog, ~line 4877):

    A QDialog with tabbed or scrollable layout containing:
    - **Domain filter:** QComboBox or QTreeWidget with domain hierarchy from `fjms.get_domain_hierarchy()`. Show parent/child structure with manuscript counts. Support search/filter.
    - **Author filter:** QComboBox with editable search text. Populated from `fjms.get_browse_authors(domain=selected_domain)`. Cross-filtered by domain selection.
    - **Work filter:** QComboBox with editable search text. Populated from `fjms.get_browse_works(domain=selected_domain, author=selected_author)`. Cross-filtered by domain and author.
    - **Date range:** Two QSpinBox inputs (From year, To year) with range 0-2000 and special value for "any".
    - **Material:** Prominent "Exclude Printed" QCheckBox. Additional QListWidget or multi-select for other material types (paper, parchment, etc.) with include/exclude capability.
    - **Manuscript count label:** Shows "X manuscripts match" updated as filters change.
    - **OK/Cancel/Clear buttons:** OK applies filters, Cancel reverts, Clear All resets all filters.

    The dialog should accept current filter state as input and return updated filter state. Use a similar pattern to DomainFilterDialog.

    When any filter changes inside the dialog, recompute the count by calling `fjms.get_filter_sys_ids()` in a background thread (using QThread or simple threading to avoid blocking the dialog UI).

    **2. Add Filters toolbar button to search tab:**
    In `create_search_tab()` (~line 6094), add a "Filters" QPushButton in the toolbar area (near the domain filter button). Clicking opens `PreSearchFilterDialog`. After dialog closes with OK:
    - Store filter state on `self` (e.g., `self.pre_search_filters = {...}`)
    - Compute `self.pre_search_restrict_sys_ids = fjms.get_filter_sys_ids(...)`
    - Update chip bar display
    - Persist filter state via `_schedule_session_save()`

    **3. Add chip bar widget below search bar:**
    Create a horizontal QHBoxLayout below the search bar / above results that shows:
    - One QLabel "chip" per active filter: "[Halakha ×]", "[Rambam ×]", etc. Use QPushButton with flat style and close icon for each chip.
    - Clicking × on a chip clears that filter, recomputes restrict_sys_ids, and updates the display.
    - A manuscript count label: "3,241 manuscripts" (or Hebrew equivalent based on CURRENT_LANG).
    - The chip bar is always visible (not inside the dialog).

    **4. Add per-result word search exclusion:**
    In the search results table (regular word search, not composition), add a context menu item or small button per row: "Exclude this manuscript". Clicking adds the result's sys_id to `self.word_excluded_sys_ids: set` and re-filters the displayed results. Excluded results shown in a collapsible section below main results (matching the composition excluded section pattern).

    Also add an "Import exclusions" feature: "Import from composition" copies `self.excluded_sys_ids` (composition exclusions) to `self.word_excluded_sys_ids`, and vice versa. Add this as a button or menu option near the exclusion controls.

    **5. Session persistence for filters:**
    In `_save_session()` / `_restore_session()`, include:
    - `pre_search_filters` dict (domain, author, work, date_from, date_to, material_exclude)
    - `word_excluded_sys_ids` set
    - Do NOT persist `restrict_sys_ids` (it's computed from filters)

    **6. Parallels tab chip bar:**
    Add the same chip bar to the composition/parallels tab area. The filter dialog and state should be shared (or at least synchronized) between search tab and parallels tab — same pre-search filters apply to both.
