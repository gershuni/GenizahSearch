### Button placement in create_result_card()

In the `create_result_card()` function (around line 2174), add the catalog button in the metadata section of each card. The best location is after the domain indicator badges (around line 2240) and before the shelfmark label, OR as part of the actions column. Per the research recommendation: "For search results, use visible-when-data-exists pattern instead of always-visible-disabled. Reserve the always-visible-disabled pattern for browse page only."

**Chosen location:** Add a small button after the domain badges, on the same row as the metadata badges. This keeps the card compact.

After the domain indicator section (around line 2240), before the shelfmark label:

```python
# Catalog Records indicator
sys_id = display.get('id')
if sys_id and search_state.catalog_record_counts:
    cat_count = search_state.catalog_record_counts.get(sys_id, 0)
    if cat_count > 0:
        def make_catalog_handler(sid=sys_id, sm=shelfmark, count=cat_count):
            async def handler():
                # Lazy-load full records only when clicked
                from shared.fjms_service import get_fjms_service
                fjms = get_fjms_service(thread_safe=True)
                records = await run.io_bound(fjms.get_catalog_records, sid)
                if records:
                    from web.components.catalog_dialog import create_catalog_records_dialog
                    dlg = create_catalog_records_dialog(records, sid, shelfmark=sm)
                    dlg.open()
            return handler

        ui.button(
            f'{tr("Catalog Records")} ({cat_count})',
            icon='description',
            on_click=make_catalog_handler(),
        ).props('outline dense size=sm no-caps').classes('text-xs').style(
            'color: #6c3483; border-color: #d5b8e8;'
        )
```

**Key design decisions:**
1. **Visible only when data exists** — on search cards, do NOT show disabled (0) buttons (too noisy with 200 results). Only show button when `cat_count > 0`.
2. **Lazy-load records** — Do NOT pre-fetch all catalog records for all results. Only fetch full records when the user actually clicks the button. The button shows the count (from the batch query) and clicking triggers an `io_bound` fetch of the full records.
3. **Closure for click handler** — Use `make_catalog_handler()` factory to capture `sys_id` and `shelfmark` correctly in the loop.
4. **Purple styling** — consistent with FJMS catalog purple branding (`color: #6c3483; border-color: #d5b8e8;`).
5. **Placement** — after domain badges in the metadata row, keeping the card compact.

**Important: WebSocket safety** — The dialog is created and opened inside an async handler, which is fine for NiceGUI. The `run.io_bound` ensures SQLite calls happen off the event loop.
