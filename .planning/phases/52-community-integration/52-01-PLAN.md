The module does NOT import web/supabase_client.py directly — instead, each function accepts a `client` parameter (a Supabase Client object) so it works with both web's `get_user_client()` and desktop's `self._get_client()`.

    **Constants:**
    - `STORAGE_BUCKET = 'puzzle-images'`
    - `THUMBNAIL_SIZE = 300`  (px, for feed display)
    - `EXPORT_SIZE = 3000` (px, for full-res published image)

    **Functions:**

    1. `publish_join(client, user_id: str, doc: PuzzleDocument, image_service) -> str`:
       - Generate composite PNG via `compose_puzzle_export(doc.fragments, image_service, export_size=EXPORT_SIZE)`
       - Generate 300px thumbnail from the composite (composite.copy(); thumb.thumbnail((300, 300)); save as PNG)
       - Upload PNG to `{user_id}/{doc.id}.png` with content-type image/png, upsert=true
       - Upload thumbnail to `{user_id}/{doc.id}_thumb.png` with content-type image/png, upsert=true
       - Extract unique shelfmarks: `list(dict.fromkeys(f.shelfmark for f in doc.fragments if f.shelfmark))`
       - Upsert into `published_joins` table: id, user_id, local_doc_id=doc.id, title, notes, join_type, fragments_json=json.loads(doc.to_json()), shelfmarks, image_path, thumbnail_path, is_published=True
       - Delete existing `published_join_fragments` rows for this join_id, then insert new rows: (join_id, sys_id, shelfmark) for each fragment
       - Return the join_id (which equals doc.id)
       - NOTE: Re-publishing (updating) uses the same upsert logic — no separate update function needed.

    2. `unpublish_join(client, user_id: str, join_id: str)`:
       - Update `published_joins` set is_published=False where id=join_id
       - Remove storage files: `{user_id}/{join_id}.png` and `{user_id}/{join_id}_thumb.png`

    3. `list_published_joins(client, limit: int = 50, offset: int = 0) -> List[Dict]`:
       - Query `published_joins` where is_published=True, order by created_at desc, limit/offset
       - For each row, get thumbnail public URL via `client.storage.from_(STORAGE_BUCKET).get_public_url(thumbnail_path)`
       - Collect unique user_ids and call `resolve_author_profiles(client, user_ids)` to get display names
       - Return list of dicts: id, title, notes, shelfmarks, thumbnail_url, user_id, author_name, created_at

    4. `get_published_joins_for_fragment(client, sys_id: str) -> List[Dict]`:
       - Query `published_join_fragments` where sys_id=sys_id
       - IMPORTANT: Batch fetch parent rows — collect all join_ids from child query, then fetch parents with `.in_('id', join_ids).eq('is_published', True)` in a single query. Do NOT fetch parent rows one-by-one (N+1 anti-pattern).
       - Collect unique user_ids and call `resolve_author_profiles(client, user_ids)` to get display names
       - Return list of dicts: id, title, shelfmarks, thumbnail_url, user_id, author_name, created_at

    5. `get_published_join_detail(client, join_id: str) -> Optional[Dict]`:
       - Query `published_joins` by id
       - Get full-res image public URL
       - Resolve author profile for the single user_id
       - Return: id, title, notes, shelfmarks, fragments_json, image_url, thumbnail_url, user_id, author_name, created_at

    6. `fork_published_join(client, join_id: str, puzzle_service) -> Optional[str]`:
       - Get detail via get_published_join_detail
       - Create PuzzleDocument from fragments_json with new UUID, title="Fork of: {original_title}"
       - Save to local joins.db via puzzle_service.save_document(doc)
       - Return new doc.id

    7. `resolve_author_profiles(client, user_ids: List[str]) -> Dict[str, str]`:
       - Batch-fetch display names from the `profiles` table: `client.table('profiles').select('id, full_name').in_('id', user_ids).execute()`
       - Return dict mapping user_id -> full_name (or "Anonymous" if not found)
       - This follows the same pattern used by `get_feed_items` and `get_fragment_joins` in web/supabase_client.py for resolving author names
       - CONTEXT.md requires display names (e.g. "Published by Dr. Sarah Cohen"), not raw UUIDs

    **Supabase schema SQL** — append to docs/guides/SUPABASE_GUIDE.md under a new section "Published Joins (Phase 52)":
    - `published_joins` table with columns: id UUID PK, user_id UUID NOT NULL REFERENCES auth.users(id), local_doc_id TEXT, title TEXT NOT NULL DEFAULT '', notes TEXT NOT NULL DEFAULT '', join_type TEXT NOT NULL DEFAULT 'physical', fragments_json JSONB NOT NULL, shelfmarks TEXT[] NOT NULL DEFAULT '{}', image_path TEXT, thumbnail_path TEXT, is_published BOOLEAN NOT NULL DEFAULT TRUE, created_at TIMESTAMPTZ NOT NULL DEFAULT now(), updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
    - `published_join_fragments` table with: join_id UUID NOT NULL REFERENCES published_joins(id) ON DELETE CASCADE, sys_id TEXT NOT NULL, shelfmark TEXT NOT NULL
    - Indexes: idx_published_joins_user(user_id), idx_published_joins_published(is_published, created_at DESC), idx_published_joins_shelfmarks GIN(shelfmarks), idx_pjf_sys_id(sys_id)
    - RLS policies for `published_joins`: publicly readable (is_published=true), users see own joins (auth.uid()=user_id), users can insert/update/delete own
    - RLS policies for `published_join_fragments` — CRITICAL: Must include INSERT and DELETE policies tied to parent ownership, not just SELECT:
      ```sql
      -- SELECT: anyone can read fragments of published joins
      CREATE POLICY "Anyone can read published join fragments"
      ON published_join_fragments FOR SELECT
      USING (EXISTS (SELECT 1 FROM published_joins pj WHERE pj.id = join_id AND pj.is_published = true));

      -- INSERT: users can insert fragments for their own joins
      CREATE POLICY "Users can insert own join fragments"
      ON published_join_fragments FOR INSERT TO authenticated
      WITH CHECK (EXISTS (SELECT 1 FROM published_joins pj WHERE pj.id = join_id AND pj.user_id = auth.uid()));

      -- DELETE: users can delete fragments for their own joins
      CREATE POLICY "Users can delete own join fragments"
      ON published_join_fragments FOR DELETE TO authenticated
      USING (EXISTS (SELECT 1 FROM published_joins pj WHERE pj.id = join_id AND pj.user_id = auth.uid()));
      ```
      Without INSERT and DELETE policies, the publish_join() DELETE+INSERT cycle on published_join_fragments will fail at runtime with RLS enabled.
    - Storage bucket: puzzle-images (public read), authenticated users upload/delete in own folder (foldername=auth.uid())
