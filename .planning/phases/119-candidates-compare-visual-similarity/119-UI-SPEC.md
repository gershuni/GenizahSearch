# Phase 119 — UI Design Contract
## Candidates, Compare & Visual Similarity

> Visual and interaction contract for the Phase-119 frontend work.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> This phase extends `web/components/candidate_grid.py` and `web/pages/joins_lab.py`
> (Phase 117/118 spine) with: a working candidate surface (triage + table view + filters +
> pagination + large thumbnails), a full-screen Compare modal, and a VS toggle.
> The desktop Joins Lab (`desktop/join_workbench.py`) is the explicit parity north star
> for behavior; web idioms govern presentation.

## Spacing Scale

Declared values (all multiples of 4, consistent with existing `gap-*` / `p-*` usage
across `joins_lab.py`, `candidate_grid.py`, and `visual_similarity_dialog.py`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, triage badge inner padding, inline chip padding |
| sm | 8px | Button row gaps, compact element spacing, card inner padding |
| md | 16px | Default element spacing, card padding (`p-4`), pane gaps |
| lg | 24px | Section padding, Compare pane internal padding |
| xl | 32px | Layout column gaps, Compare outer margin |
| 2xl | 48px | Empty-state icon-to-text vertical gap, page-level breathing room |
| 3xl | 64px | Not used in Phase 119 |

Exceptions:
- Candidate thumbnails: 160×160px (grid cards) and 48×48px (table rows) — image
  dimensions, not spacing tokens.
- Touch targets on triage Y/?/N buttons: minimum 44px height (`min-h-11`) — accessibility
  minimum, not a spacing token.
- Sticky anchor pane: existing width 380px, top offset 64px — pre-existing Phase 117
  dimensions, unchanged.

All new Phase-119 element spacing uses ONLY the declared scale tokens (4, 8, 16, 24, 32,
48). The earlier draft's `p-3`/`gap-3` (12px) usages are replaced with `p-2`/`gap-2` (8px)
in compact contexts and `p-4`/`gap-4` (16px) in default contexts — see the Spacing
Application Map below. No 12px spacing is used.

## Typography

Reuses the application-wide type scale already declared via Tailwind utility classes.
No new type sizes are introduced in Phase 119.

| Role | Class | Size | Weight | Line Height | Source |
|------|-------|------|--------|-------------|--------|
| Body | `text-sm` | 14px | 400 (regular) | 1.5 | existing codebase convention |
| Label / metadata | `text-xs` | 14px | 400 (regular) | 1.4 | existing chip/badge/muted label pattern |
| Heading / section | `text-base font-semibold` | 16px | 600 (semibold) | 1.5 | existing candidates header pattern |
| Pane heading (Compare) | `text-lg font-semibold` | 18px | 600 (semibold) | 1.2 | mirrors VS dialog header pattern |

Weights in use: exactly **two** — **400** (regular) for body/label text and **600**
(semibold) for all headings. The Compare pane heading uses `text-lg font-semibold` (600),
NOT `font-bold` (700), to hold the contract to two weights.

Sizes in use: **3** distinct — 14px (body + label), 16px (section heading), 18px (Compare
pane heading). Label metadata uses the 14px body size at the muted color token rather than
a smaller size, keeping the size count at 3.

RTL: all transcription text and Hebrew shelfmarks render with `direction: rtl; text-align: right`.
LTR metadata (library codes, scores, dimensions) render without direction override.

## Component Inventory

### 1. Candidate Card (Grid view)

**Size:** 160×160px thumbnail, full card width (~280–300px in 2-col grid at ≥640px).

```
┌─────────────────────────────────────────────┐
│ [thumbnail 160×160, object-fit:cover]       │  ← full width, rounded-t
│ ┌────────────────────────────────────────┐  │
│ │ [lib chip] [shelfmark bold]            │  │  ← 8px padding sides
│ │ [title — RTL, 2-line clamp, muted]     │  │
│ │ [triage row: Y ✓  ?  N ✗] [👁 badge]  │  │  ← new Phase 119
│ │ [View in Browse link] [Compare button] │  │  ← Compare button new
│ └────────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

- Thumbnail: `width:160px; height:160px; object-fit:cover; border-radius:8px 8px 0 0`
  (top-rounded, full card width). Error fallback: same `_PLACEHOLDER_STYLE` at 160×160.
- Triage buttons: `Y` / `?` / `N` — three `ui.button` with `props='flat dense'`,
  each 44px min-height touch target. Active state: filled background in triage color.
  Inactive state: outlined / flat, muted text.
- 👁 badge: shown when `via_vs=True` per `badge_and_tooltip()` precedence (⚓ anchor self
  › ⇄ via_other_side › 👁 via_vs). Icon `visibility` with amber tint, tooltip from helper.
- Compare button: `ui.button('Compare', icon='compare_arrows')` flat dense — carries a
  **visible text label** (not icon-only) so it is self-describing for keyboard / screen-reader
  users; also `.tooltip(tr('Compare fragment'))`. Launches the Compare modal.
- Grid responsive: `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3` (1 col < 640px, 2 col
  640–1023px, 3 col ≥1024px) — 3 cols replaces Phase-117's max of 2 cols to match D-09's
  "large thumbnails" intent at wider viewports.
- Page size: **24 cards/page** (default; D-08). Pagination controls below the grid.

### 2. Candidate Row (Table view)

8-column shape (D-10). All columns except Checkbox and Triage are sortable.

| Col | Content | Width | Sortable |
|-----|---------|-------|----------|
| Checkbox | `ui.checkbox` (multi-select) | 40px | no |
| Shelfmark | Text + 👁 badge | flex | yes (default asc) |
| Score | Numeric relevance (float 2dp) | 64px | yes |
| Snippet | RTL Hebrew text, 80 char truncate | flex | no |
| Material | Material label (from FJMS enrichment) | 80px | yes |
| Dimensions | `W×H cm` or `—` if unavailable | 72px | yes |
| Page | Fragment page number | 48px | yes |
| Triage | Y/?/N compact buttons (icon-with-tooltip) | 80px | no |

- Default sort: **Score descending** (relevance-first).
- When VS toggle is ON: sort switches to **VS rank ascending** automatically; column header
  "Rank" replaces "Score" as the primary sort indicator.
- Row double-click: opens Compare modal (parity desktop `:3207`).
- Bulk triage bar: appears when ≥1 row selected — shows "Mark selected as: Y / ? / N"
  with count badge. Fixed at bottom of the table, `position:sticky bottom:0`.
- Enrichment loading: Material and Dimensions cells show `—` with `ui.spinner(size='xs')`
  while the batch enrichment is in-flight, then update in place.
- The compact triage buttons in the Triage column are icon-style but each carries a
  `.tooltip` ("Yes" / "Maybe" / "No") for accessibility.

### 3. Toolbar (above candidate grid/table)

```
[Candidates (N)] [Grid ● | Table] [Filters ▼] [👁 VS toggle] [← Prev page N/M Next →]
```

All in one `ui.row().classes('w-full items-center gap-2 flex-wrap')`.

- View toggle: `ui.toggle(['Grid', 'Table'])` or two `ui.button` with active state.
  Icons: `grid_view` (grid) / `table_rows` (table).
- Filters button: `ui.button('Filters', icon='filter_list')` flat. Opens filter popover/dialog.
- VS toggle: `ui.switch()` with icon label `'👁 Visual Similarity'`. Disabled when no anchor
  loaded or VS data unavailable (disabled state: muted, tooltip explains why). Loading spinner
  replaces icon while VS fetch is in-flight.
- Pagination: `‹ Prev` / `N / M` / `Next ›` — `ui.button` flat dense, current page/total
  center-aligned. "Page N of M" label. Disabled state when on first/last page.

### 4. Filter Dialog / Popover

Opened by "Filters" button (D-14). Implemented as `ui.dialog` (not inline panel) to keep
the candidate surface clean.

Filters:
1. **Material** — `ui.select(multiple=True)` of available material values from enrichment.
2. **Has dimensions** — `ui.switch('Has dimensions data')` — excludes candidates with no
   W/H enrichment.
3. **Size mismatch** — `ui.switch('Exclude size mismatch')` — excludes ratio > 1.4 (D-15).
4. **Triage state** — `ui.select(multiple=True)` with options: All / Not triaged / Yes /
   Maybe / No.
5. **Text filter (optional)** — a single `ui.input(placeholder='Filter by shelfmark...')`
   applying a case-insensitive substring match on `shelfmark + title`. Included per the
   "optional — discretion" flag in CONTEXT.md; keeps the filter dialog useful for large sets.

Dialog footer: `[Reset] [Apply]` right-aligned. Apply closes dialog and re-renders current page.
Active filter count badge on the Filters button (e.g. `Filters (2)`).

### 5. Compare Modal (D-01 / D-02 / D-03)

Full-screen `ui.dialog` (`props='maximized'`), two-pane layout.

```
┌─────────────────────────────────────────────────────────────────────┐
│ [← Back to Lab] [Shelfmark ANCHOR  ↔  Shelfmark CANDIDATE]  [✕]   │  ← header bar, primary gradient bg
├──────────────────────────────┬──────────────────────────────────────┤
│  ANCHOR                      │  CANDIDATE                           │
│  [Image viewer — zoom/pan]   │  [Image viewer — zoom/pan]           │
│  [Folio nav ← 1/N →]         │  [Folio nav ← 1/N →]                │
│  [Transcription — RTL lines] │  [Transcription — RTL lines]         │
├──────────────────────────────┴──────────────────────────────────────┤
│  [‹ Prev candidate]  Verdict: [Y Yes] [? Maybe] [N No]  [Next ›]   │  ← verdict bar, bg-tertiary
└─────────────────────────────────────────────────────────────────────┘
```

- Header background: `var(--bg-header)` (same deep-green gradient used on all modal headers
  in the app). Text white. Close button `props='flat dense round'` white icon.
- Pane separator: `border-right: 2px solid var(--border-light)`.
- Each pane: reuses the **extracted `/browse` image viewer** (Phase 117 D-10) — full
  `AnchorViewer`-style image + folio navigation. Zoom/pan is per-pane and independent.
- Transcription: RTL numbered lines, `direction:rtl; text-align:right`, `font-size:14px`,
  `line-height:1.5`, `color:var(--text-primary)`. Line numbers `color:var(--text-muted)`.
- Verdict bar (`position:sticky bottom:0`, `background:var(--bg-tertiary)`):
  - Three verdict buttons with **visible text labels**: `Yes` (green-700), `Maybe`
    (amber-700), `No` (red-700). Size: `props='size=md'` (not dense) — primary CTA
    prominence. Active state: filled background. Recording a verdict auto-advances to next
    candidate.
  - Flip-through: `‹ Prev` / `Next ›` flat buttons, `counter label` "3 / 47" center.
    Disabled at boundaries (first/last candidate in filtered order).
- Size mismatch warning in candidate pane header: amber `ui.badge` icon `warning`
  "Size mismatch" when ratio > 1.4 (from enrichment data).
- 👁 badge in candidate pane header: same `badge_and_tooltip()` rule as grid/table.
- Compare opens **from**: grid card "Compare" button, table row double-click, and a
  keyboard shortcut (Enter on focused card — Phase 121 a11y pass; not blocking 119).

### 6. VS Toggle States

All four states must have a non-blank affordance (D-06):

| State | Visual | Copy |
|-------|--------|------|
| OFF | Switch unchecked, icon muted | "Visual Similarity" (EN) / "דמיון חזותי" (HE) |
| Loading | Switch checked, amber spinner on icon | "Loading visual similarity…" tooltip |
| ON — results | Switch checked, amber icon | "Visual Similarity: N matches" |
| ON — empty intersection | Switch checked, amber icon, amber inline notice | "No candidates match both text and visual similarity. Try clearing the builder for VS-only browse." |
| ON — no VS data for anchor | Switch disabled, muted | Tooltip: "No visual similarity data for this fragment" |

## Interaction Contracts

### Triage

- Triage state is `dict[str, Literal['yes','maybe','no']]` keyed by `sys_id`, held as
  page-level Python variable — no `safe_storage` writes in Phase 119.
- Setting a triage value updates the dict, then restyles ALL card/row/Compare renderings
  for that `sys_id` immediately (single source of truth).
- Resetting on re-anchor: triage dict cleared at the same moment a new anchor loads.
- Bulk triage (table multi-select): all selected `sys_id`s updated simultaneously.

### View Toggle (Grid ↔ Table)

- Switching view preserves triage state (shared dict), VS badge state, and current page.
- The grid starts rendered; the table is lazily rendered on first switch to avoid double
  rendering cost.

### Pagination

- Filters apply **before** pagination; changing a filter resets to page 1.
- Page changes do NOT reset triage (the dict survives page changes).
- Enrichment batch covers the **full filtered set**, not just the current page — so
  Material/Dimensions columns are populated on every page even before it is viewed.

### Compare auto-advance

- Recording a verdict (Y/?/N) in Compare advances to `next` in the current filtered+sorted
  order. If already at last candidate: advance wraps to first (consistent with desktop
  parity `step(delta)` wrapping in `join_workbench.py:3741`).
- Manual `‹ Prev` / `Next ›` always available regardless of verdict.

### VS Toggle

- ON click: dispatch VS lookup off-loop (`run.io_bound`), show spinner on toggle.
- On completion: call `merge_candidates(text_candidates, vs_candidates)` (or
  `merge_candidates([], vs_candidates)` when builder is empty), re-render current page 1.
- Toggle tracks loaded anchor sid; on re-anchor with VS still ON: auto-refetch for new anchor.
- Sort switches to VS rank when toggle is ON (reverts to score sort when toggled OFF).

### Off-loop discipline

- VS lookup: `await run.io_bound(vs_service.get_suggestions, sid, 200)` — same pattern
  as `visual_similarity_dialog.py:176`.
- Enrichment batch: `await run.io_bound(fjms_svc.get_measurement_summaries_batch, sys_ids)`
  — same pattern as desktop `_EnrichWorker`.
- Thumbnail image fetches: existing per-provider proxy + Phase-98 NLI circuit breaker
  (unchanged). Breaker trips degrade thumbnails to placeholder gracefully.
- The CI guard `tests/test_joins_lab_off_loop.py` must stay green: VS lookup and enrichment
  batch must be called only inside `run.io_bound` closures.
