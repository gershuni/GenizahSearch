**Two ROUTING/STARTUP blockers this plan MUST solve (Codex F-A1 BLOCKER + F-A2 HIGH):**
- **F-A1 (BLOCKER):** NiceGUI's `user` fixture resolves the app via `get_path_to_main_file(request)` (general_fixtures.py:21-31), which defaults to a root `main.py` that does NOT exist in this repo — the `/joins-lab` route lives in `web/main.py` (VERIFIED: `@ui.page('/joins-lab')` at web/main.py:1802). Without explicit wiring, `await user.open('/joins-lab')` reaches nothing. The harness MUST point at `web/main.py` — either the `nicegui_main_file` marker / the `main_file` ini option (VERIFIED marker name: `nicegui_main_file`, resolved relative to `request.config.inipath.parent` = repo root where pyproject.toml lives), OR a LOCAL fixture with an explicit route root.
- **F-A2 (HIGH):** `user_simulation` (user_simulation.py:37-47) does `runpy.run_path(web/main.py, run_name='__main__')` THEN enters `core.app.router.lifespan_context(core.app)`, which fires `app.on_startup(initialize_engine)` (VERIFIED: web/main.py:2358-2359 registers `compact_export_storage_on_startup` + `initialize_engine`; initialize_engine builds the real MetadataManager / SearchEngine / Indexer / Tantivy at :2302-2339). If the harness drives the real lifespan unmocked, it hits real services — slow/failing in CI. The harness MUST mock startup BEFORE lifespan.

**Chosen approach (concrete — solves BOTH F-A1 and F-A2): a LOCAL user-style fixture in `tests/render_smoke/conftest.py` that does NOT use `runpy.run_path`.** Rationale: `runpy.run_path(web/main.py, run_name='__main__')` re-executes `web/main.py` from scratch (its `__main__` block's `ui.run()` early-returns under simulation — VERIFIED `ui_run.py:206 if helpers.is_user_simulation(): return` — so no server starts, good), but it RE-REGISTERS a freshly-defined `initialize_engine` as the on_startup handler, so a monkeypatch of the cached `web.main.initialize_engine` would not catch it. Instead the local fixture:
  1. `import web.main` once (the `@ui.page('/joins-lab')` decorator registers the route on `core.app` at import — no runpy re-exec needed).
  2. Monkeypatch `web.main.initialize_engine` and `web.main.compact_export_storage_on_startup` to trivial async no-ops, AND seed `web.state` (or `web.main.state`) with deterministic stub managers (meta_mgr / searcher / lab_engine / var_mgr / indexer) so the page renders without the real engine. ALSO patch the page's heavy seams (WebSearchExecutor.execute_search / get_meta_for_id / get_library_for_id, get_browse_page, get_vs_service.get_suggestions, get_fjms_service.get_measurement_summaries_batch) to return small deterministic fixtures, and AnchorViewer image resolution to a tiny inline `data:` URL.
  3. Construct `User(httpx.AsyncClient(transport=httpx.ASGITransport(core.app), base_url='http://test'))` (mirror `nicegui.testing.user_plugin.create_user` at user_plugin.py:40) INSIDE `core.app.router.lifespan_context(core.app)` — entered AFTER the patches are applied, so the no-op `initialize_engine` runs, not the real one (F-A2 solved). Use `nicegui_reset_globals()` (general.py:30) around it for isolation.
  4. The route `/joins-lab` is reachable because `web.main` was imported and the decorator registered it on `core.app` (F-A1 solved without a missing root `main.py`).
(If the executor prefers the marker path, `@pytest.mark.nicegui_main_file("web/main.py")` + an autouse fixture that patches the startup seams BEFORE the `user` fixture enters `user_simulation` is the alternative — but it must STILL apply the patches before lifespan, which is fiddly with runpy re-execution; the local fixture is the cleaner, verified path.
