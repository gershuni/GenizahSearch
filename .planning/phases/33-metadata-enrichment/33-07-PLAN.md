<objective>
Fix the Oxford manuscript enrichment short-circuit bug by removing cache-first pattern from _browse_load_part and browse_navigate, making them unconditionally start EnrichMetadataThread like browse_load does.

Purpose: Plans 33-05 and 33-06 added enrichment thread startup but used the same "cache-first" pattern that IS the bug. When basic CSV metadata is already cached (always true for Oxford), the cache-check is truthy and on_browse_enriched_loaded is called with UN-ENRICHED data. The EnrichMetadataThread never starts, so enrich_metadata() never runs, which means NLI crossref data (catalog_entry, is_not_genizah, bibliography, folio_images) is never fetched. The NLI data EXISTS (38K Oxford rows in crossref, CatalogEntry=2613.1 for sys_id 990053385780205171) but enrichment is never invoked.

Output: Oxford manuscripts display full enrichment metadata including Neubauer-Cowley catalog numbers, IsNotGenizah badges, bibliography references, and catalog cross-references.
</objective>

**Why this fixes the bug:**

The cache (nli_cache) contains basic CSV metadata (shelfmark, library, titles from libraries.csv) which is populated early. It does NOT contain enrichment data (catalog_entry, is_not_genizah, bibliography, folio_images, etc.) from NLI crossref or FJMS until after enrich_metadata runs.

When the cache-check finds basic metadata and calls on_browse_enriched_loaded with it, the enrichment never runs, so the extended metadata is never fetched. The EnrichMetadataThread must ALWAYS start -- the enrich_metadata() method itself handles caching internally and builds enriched metadata on top of the basic cached metadata.
