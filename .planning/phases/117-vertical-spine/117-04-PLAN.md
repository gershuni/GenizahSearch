## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous client -> /joins-lab page handler | No auth wall; the page must serve anonymous users and isolate per-session state |
| URL params (sys_id/shelfmark/fl_id/page/volume_ie) -> resolution/anchor load | Untrusted strings cross here into search_by_shelfmark / get_browse_page |
| builder textarea -> compose() -> execute_search | User text feeds the search engine (engine tokenizes; no shell/SQL surface) |
| per-user anchor -> safe_storage | Cross-session bleed would expose one user's anchor to another |
| NiceGUI event loop -> search engine | A multi-second search must run off the loop |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-117-01 | Denial of Service | `execute_search` on the event loop (blocks all sessions) | mitigate | Search runs only inside the `run_search_core` closure passed to `run.io_bound`; tests/test_joins_lab_off_loop.py (Plan 01) statically enforces against joins_lab.py (SC#3) |
| T-117-04 | Information Disclosure | per-session anchor bleed across anonymous sessions | mitigate | All anchor state via Plan-02 `write_anchor`/`read_anchor` (safe_user_*, cookie-keyed); no raw `app.storage.user` (Task 2 grep); two-session test in Plan 02 |
| T-117-12 | Denial of Service | repeated/rapid Run Search clicks stacking searches / stale overwrite | mitigate | `_is_running` re-entrancy guard + `_search_generation` latest-wins check (Task 3, search.py pattern) |
