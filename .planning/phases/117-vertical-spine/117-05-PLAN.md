<objective>
Build the read-only candidate grid component (CND-02) that renders a list of `shared.joins_lab.Candidate` objects as cards — thumbnail, shelfmark, library chip, title, and a "View in Browse" link. This is a NEW thin component (the existing `create_result_card` is too feature-heavy). Phase 119 EXTENDS this component with triage Y/?/N, table view, and VS badges — so it must be structured to add those without a rewrite (D-14, D-04).

**REVIEW RECONCILIATION (MEDIUM-6):** CND-02 requires a thumbnail. `Candidate` (shared/joins_lab.py:103) has no thumbnail field, so the component DERIVES one from the candidate's `sys_id`/`page` using the SAME proxy-thumbnail logic the search result cards use (`web/pages/search_results.py:645-665`): `/api/nli_image_by_sysid/{sys_id}?page={page_idx}&width=300` with the `is_synthetic_sys_id` guard. The earlier "if a thumbnail is non-trivial, render a small placeholder" escape hatch is REMOVED — the thumbnail is a first-class part of the card. A placeholder box appears ONLY in the two legitimate fallback cases: a synthetic sys_id (whose proxy returns 204, so no image exists) or an `<img>` load error. The full async metadata enrichment (CND-08) remains Phase 119 — but a static proxy thumbnail URL needs no enrichment (it's a single string built from sys_id/page).

Purpose: CND-02 candidate grid WITH thumbnail. Read-only display only in the spine — no triage, no per-card actions, no Compare (those are Phase 119, locked out).
Output: `web/components/candidate_grid.py` + `tests/test_candidate_grid.py`.
