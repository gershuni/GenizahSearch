<objective>
Wire the two highest-fidelity usage producers: `desktop_tab_activated` (every user tab switch, programmatic changes suppressed) and `desktop_search_executed` (exactly once per user run, completed or cancelled, with enum search_mode + corpus_scope + result bucket) — across BOTH the regular `SearchThread`/`LabSearchThread` path AND the composition (`CompositionThread`/`LabCompositionThread`) path. Parallels has no separate dispatch — it seeds the composition tab and runs through the composition path — so the composition wiring covers it.

Purpose: These are the core usage signals (Success Criteria 2, 3; USAGE-02/03; D-05). The hard constraints here are the value-side privacy guard (D-04: hardcoded constants, never translated UI strings) and the exactly-once search emission (D-09: per-run state objects that close every cancel path without double-counting, AND do not count app-shutdown cancellation). USAGE-03 / Success Criterion 3 / D-05 require the search event for the COMPOSITION and PARALLELS flows, not just the regular `SearchThread`→`on_search_finished` path — composition runs through a separate dispatch (`run_composition()` → `CompositionThread.scan_finished_signal` → `on_comp_scan_finished`) that never calls `on_search_finished`.

Output: `_on_tab_changed` telemetry guard; a regular per-run search state object created in `start_search` with an `_emit_search_telemetry` helper wired into `on_search_finished` and `stop_search`; a composition per-run state object created in `run_composition` with an `_emit_comp_search_telemetry` helper (shutdown-guarded) wired into `on_comp_scan_finished`; and tests extending `tests/test_telemetry_phase114.py`.
</objective>
