<objective>
Wire the two highest-fidelity usage producers: `desktop_tab_activated` (every user tab switch, programmatic changes suppressed) and `desktop_search_executed` (exactly once per user run, completed or cancelled, with enum search_mode + corpus_scope + result bucket) — across the regular `SearchThread`/`LabSearchThread` path, the PGP-Tags dispatch path (`_execute_tag_search`/`_on_tag_search_results`), AND the composition (`CompositionThread`/`LabCompositionThread`) path. Parallels has no separate dispatch — it seeds the composition tab — so the composition wiring covers it.

Purpose: These are the core usage signals (Success Criteria 2, 3; USAGE-02/03; D-05). The hard constraints here are the value-side privacy guard (D-04: hardcoded constants, never translated UI strings, never the PGP tag text), the exactly-once search emission (D-09: per-run state objects that close every cancel path without double-counting, AND do not count app-shutdown cancellation), and the producer gate (REVIEWS MEDIUM-9: nothing emits before the coordinator sets `_session_id`). USAGE-03 / Success Criterion 3 / D-05 require the search event for the COMPOSITION, PARALLELS, and PGP-TAGS flows — PGP-Tags dispatches via `_execute_tag_search()` and never reaches `start_search()`/`on_search_finished` (REVIEWS HIGH-1), and composition runs through `run_composition()` → `on_comp_scan_finished` which never calls `on_search_finished`.

Output: `_on_tab_changed` telemetry guard (restore + programmatic); a regular per-run search state object created in `start_search` with an `_emit_search_telemetry` helper (shutdown-guarded) wired into `on_search_finished` and `stop_search`; a PGP-tag per-run state object created in `_execute_tag_search` emitted in `_on_tag_search_results`; a composition per-run state object created in `run_composition` with an `_emit_comp_search_telemetry` helper (shutdown-guarded) wired into `on_comp_scan_finished`; and tests extending `tests/test_telemetry_phase114.py`.
</objective>
