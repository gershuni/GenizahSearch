  <action>
Add the following methods to FjmsService class (after the existing get_domain_hierarchy method):

1. `get_browse_authors(self, domain: str = None) -> list[dict]`:
   - Returns all unique AuthorText values from catalog table with manuscript counts
   - Each dict: {"author": str, "count": int}
   - If domain is provided, only include manuscripts that have that domain (JOIN with domains table, match Domain OR ParentDomain)
   - Filter out NULL/empty AuthorText
   - Sort by count descending
   - Cache full author list (no domain filter) in `_authors_cache` with double-checked locking (same pattern as _hierarchy_cache)

2. `get_browse_works(self, domain: str = None, author: str = None) -> list[dict]`:
   - Returns all unique Title/TitleHeb pairs from catalog with manuscript counts
   - Each dict: {"title": str, "title_heb": str, "count": int}
   - If domain is provided, filter by domain (JOIN with domains, match Domain OR ParentDomain)
   - If author is provided, filter by AuthorText = author
   - Filter out NULL/empty Title AND TitleHeb (both empty = skip)
   - Sort by count descending
   - Cache full work list (no filters) in `_works_cache` with double-checked locking

3. `get_browse_results(self, domain: str = None, author: str = None, work: str = None, offset: int = 0, limit: int = 50) -> dict`:
   - Returns paginated browse results matching all provided filters (intersection)
   - Returns dict: {"results": list[dict], "total": int}
   - Each result dict: {"sys_id": str, "title": str, "title_heb": str, "author": str, "copy_date": str, "textual_frame_heb": str, "textual_frame_eng": str, "domains": list[str], "domains_heb": list[str]}
   - Build WHERE clause dynamically from non-None filters:
     - domain: JOIN domains ON catalog.AlmaId = domains.AlmaId WHERE (domains.Domain = ? OR domains.ParentDomain = ?)
     - author: catalog.AuthorText = ?
     - work: catalog.Title = ?
   - For "domains" and "domains_heb" in results: use a subquery or post-fetch from domains table for each sys_id
   - Use GROUP BY catalog.AlmaId to deduplicate (a sys_id may appear in catalog multiple times)
   - For the result metadata, pick the first non-empty value from grouped rows (use GROUP_CONCAT or pick via subquery)
   - COUNT query first for total, then apply LIMIT/OFFSET for pagination
   - When no filters provided, return ALL manuscripts that have at least one catalog or domain entry (the "Unclassified" bucket is NOT returned in unfiltered mode -- too many results; instead return manuscripts that have catalog data)

4. `get_unclassified_count(self) -> int`:
   - Returns count of AlmaIds in catalog that have NO corresponding entry in domains table
   - Used for showing "Unclassified" bucket in UI

5. Add `_authors_cache`, `_works_cache` attributes to `__init__` (initialize to None), and corresponding `_authors_lock`, `_works_lock` (threading.Lock instances).

SQL optimization notes:
- Use `COUNT(DISTINCT catalog.AlmaId)` for counts since a sys_id may have multiple catalog records
- For get_browse_results, the JOIN between catalog and domains should be LEFT JOIN when no domain filter, INNER JOIN when domain filter is active
- The domains list per result can be fetched separately in a batch after the main query (more efficient than correlated subqueries)
- Index hint: The existing data likely has no index on catalog.AuthorText or catalog.Title. Add CREATE INDEX IF NOT EXISTS statements at the end of __init__ (same pattern used elsewhere in the service) for: idx_catalog_author (AuthorText), idx_catalog_title (Title), idx_catalog_alma (AlmaId), idx_domains_domain (Domain), idx_domains_parent (ParentDomain). Only create if self._conn is not None. Wrap in try/except to handle read-only DBs gracefully.
