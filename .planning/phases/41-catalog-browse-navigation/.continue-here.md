### Bug 1: Slot deletion error on chip remove (PARTIALLY FIXED)
- Bottom sidebar chips and top-bar text chips both trigger `remove_text_term`
- The chip element gets destroyed during `refresh_results` → `render_chips()` clear
- Added `_safe_refresh()` wrapper with try/except RuntimeError — may still not work
- ROOT CAUSE: NiceGUI q-chip 'remove' event fires from the chip's slot context.
  When render_chips() clears the container, the slot is destroyed mid-handler.
- PROPER FIX NEEDED: Use JavaScript-based event emission from chip to a stable parent,
  OR use `app.storage` pattern, OR bind chip removal to a stable element's handler.
  Consider: making the top-bar text chips use `on_click` (not q-chip 'remove') on a
  regular button styled as chip (like desktop does with QPushButton). That avoids the
  q-chip remove event slot issue entirely.

### Bug 2: FTS5 doesn't search domain names → too few results
- FTS5 index (catalog_fts) contains: Title, TitleHeb, TextualFrameHeb, TextualFrameEng,
  RunningTitle, FreeDescription, FullText, DetailedFrames
- Does NOT contain domain names (Domain, DomainHeb from `domains` table)
- "פילוסופיה" has 4,661 matches in domains table but 0 in catalog fields
- FIX: Hybrid approach — FTS5 for catalog fields UNION with domain LIKE search:
  ```sql
  c.rowid IN (
    SELECT rowid FROM catalog_fts WHERE catalog_fts MATCH ?
    UNION
    SELECT c2.rowid FROM catalog c2
    INNER JOIN domains dtf ON c2.AlmaId = dtf.AlmaId
    WHERE dtf.Domain LIKE ? OR dtf.DomainHeb LIKE ?
  )
  ```
  This keeps FTS5 speed for catalog text but also catches domain name matches.
  Domain LIKE is fast because the domains table is small (390K) and already indexed.
- Test data: FTS "פילוסופיה" = 653, LIKE domains = 4,661, LIKE catalog = 0
  Expected combined: ~5,000+ (union of FTS catalog + domain matches)
