In `shared/fjms_service.py`, rewrite the SQL in `get_join_group()` to return each unique partner AlmaId exactly once, **aggregating** all distinct scholar names and join types from all groups.

Replace the current query (lines 213-218):
```sql
SELECT AlmaId, JoinGroupId, ScholarName, Comment, JoinType
FROM joins
WHERE JoinGroupId IN (SELECT JoinGroupId FROM joins WHERE AlmaId = ?)
AND AlmaId != ?
```

With:
```sql
SELECT AlmaId,
       GROUP_CONCAT(DISTINCT JoinGroupId) as JoinGroupIds,
       GROUP_CONCAT(DISTINCT ScholarName) as ScholarNames,
       GROUP_CONCAT(DISTINCT Comment) as Comments,
       GROUP_CONCAT(DISTINCT JoinType) as JoinTypes
FROM joins
WHERE JoinGroupId IN (SELECT JoinGroupId FROM joins WHERE AlmaId = ?)
  AND AlmaId != ?
GROUP BY AlmaId
```

Then in the Python post-processing (the dict comprehension that builds the return list), parse the aggregated strings into lists:

```python
def _split_concat(val):
    """Split GROUP_CONCAT result into list of non-empty strings."""
    if not val:
        return []
    return [v.strip() for v in val.split(',') if v.strip()]
```

Change the returned dict keys from singular to plural for aggregated fields:
- `scholar_name` (str) → `scholar_names` (list of str) — all distinct scholars who identified this join
- `join_type` (str) → `join_types` (list of str) — all distinct join types across groups
- Keep `alma_id` (str), `comment` (str — join with '; ' if multiple), `join_group_id` → `join_group_ids` (list of int)
