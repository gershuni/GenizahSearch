<objective>
Give PANEL-02's "Other manuscripts matching ⟨work⟩" expansion the three things it actually needs and
does not have: the anchor side's relation and band, the weaker-band rule applied across the pair, and a
real total from a count query.

Purpose: this plan exists because a revision-1 instruction — including my own reading of it — was
wrong. `get_work_witnesses()` returns only the OTHER carrier's `claim_type` and band, with neither the
anchor's relation nor a total, so "wiring an existing field through" was never possible. PANEL-02
requires each side's own relation type when they differ, DATA-01 requires the weaker band of the pair,
and a visible real total requires a count query — a bounded page cannot supply one. All three need
service work, and pretending otherwise would have produced a panel section that silently showed the
anchor's band and a page size where a total belongs.
Output: an anchor-aware projection, a count query, and an enveloped wrapper.
</objective>

  <action>
    Write the tests first, including a fixture where the anchor's relation kind and the other carrier's
    genuinely DIFFER, and a second where the anchor's band is stronger than the other carrier's.

    Then extend the function to accept the anchor's already-loaded identity explicitly — the panel has
    all of it in hand from the page query, so passing it in is cheaper and less fragile than re-joining
    the anchor claim inside a window query that is already doing grouping work.

    **Three parameters, not two — and ALL THREE OR NONE.** `_band_rank` takes
    `(evidence_source, confidence_band)`, so ranking the anchor side requires `anchor_evidence_source`
    as well as `anchor_confidence_band` — passing the band alone cannot produce a rank and would
    silently compare against a default. Add `anchor_claim_type`, `anchor_evidence_source` and
    `anchor_confidence_band` as keyword-only parameters, each defaulting to `None` so every existing
    call site keeps working unchanged.

    Independent defaults alone are NOT sufficient, and this is the subtle part: with three independent
    optionals, "anchor arguments are supplied" is ambiguous for the six partial combinations. A partial
    call could rank against a defaulted side, or emit `relations_differ` computed from a missing
    relation — both silently wrong rather than loudly broken. **Enforce an all-or-none invariant at the
    top of the function: exactly three supplied, or exactly zero. Every other combination raises a
    ValueError naming which fields were present and which were missing.** The two valid states are then
    the only reachable ones, which is what makes "when anchor arguments are supplied" a well-defined
    condition everywhere else in this plan.

    **Resolve the filter contract explicitly — the two obvious readings contradict each other.** The
    enabled-band filter must apply to the **resolved weaker band**, which is the band the reader
    actually sees. Filtering on the other carrier's band while displaying the weaker one would show a
    screening-band row whenever the anchor happened to be the weak side — a row appearing above the
    disclosure line because of a band nobody is looking at. So: **when anchor arguments are supplied the
    filter moves to the resolved displayed band; when they are absent the existing other-carrier
    filtering is unchanged.** State that split in a docstring, because it is a genuine behaviour change
    under the new call shape and a silent one under the old.

    Add `anchor_claim_type`, `anchor_confidence_band`, `relations_differ` and the resolved
    `displayed_confidence_band` to the returned dict. Compute the weaker band with `_band_rank` rather
    than a local comparison — the lattice already exists and a second copy would drift.

    Keep the SQL/pure-helper symmetry: whatever the SQL path computes, `_project_work_witnesses` must
    compute identically, and a test should assert the two agree on the same fixture. That symmetry is
    the module's existing discipline and it is what makes this function testable without a database.

    Do not change grouping, anchor exclusion, member suppression or ordering. Band FILTERING does change
    under the new call shape, per the contract above — that is the one deliberate exception, and it is
    why the docstring has to say so.
  </action>
