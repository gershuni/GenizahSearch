    **1. The two-bucket rule.** Render the scholar-facing sentence verbatim: *"A fragment is treated as
    a probable identification when it matches the work across more than one leaf, or covers almost a
    whole page on its own. Everything else appears under 'more matches'."* — plus its Hebrew
    equivalent. Define this text ONCE as a module-level bilingual constant named
    `MAIN_POOL_SENTENCE` in `web/pages/help.py` so there is a single string to point at; plan 136-07
    will assert that `shared.discovery_main_pool.main_pool_sentence()` returns byte-identical text, so
    the rule can never be described two different ways on two surfaces. State that the second bucket
    means there was **not enough evidence for the rule**, never that the identification is probably
    wrong: it holds probable quotations, shared wording, unresolved ties, missing signals and genuinely
    indeterminate cases alike.

    **2. Known limitations, stated plainly.** A work that contains another work's text absorbs matches
    belonging to the contained work — the liturgy inside a legal code is the live example — and a small
    share of the main pool remains misattributed for that reason; express the share in words ("a small
    minority", "a low single-digit share"), never as a measured percentage. A two-page agreement is
    often the two sides of one leaf rather than two independent leaves. Composition dates can demote an
    implausible direction of borrowing but cannot settle identity.

    **3. The novelty check.** The enumerable checked-source list with each source's as-of date, and the
    explicit statement that the identification underlying a candidate is an unreviewed algorithmic
    match, so a candidate is not a confirmed find. State plainly that absence from the checked aids is
    not evidence that a match is correct. If the dated source list is not yet available on disk (plan
