<objective>
Ship the main-pool rule as one shared implementation, materialize it onto a new
identification-grain table together with the manuscript display keys, and prove the findings
query now meets its budget.

Purpose: the two visible buckets on every discovery surface are drawn by four non-compensating
gates over the identification (manuscript × canonical work), not by a score and not by a
band-derived confidence scale. Recomputing coverage, competition and manuscript aggregation
inside a request is not viable — a representative ordering measured 3.41–3.55 s against a 1.5 s
cap, and the deduped identification count alone measured 16 s.
Output: `shared/discovery_main_pool.py`, two new tables, and a benchmark with a known failing
baseline it must now beat.
</objective>

    - An identification whose best band is only a screening band returns not-main with reason `overlapping_tie` is NOT used; it returns reason for the screening exclusion.
    - An identification with an unresolved near-tie competitor on EVERY matched page returns not-main with reason `overlapping_tie`; one clean page is enough to survive the gate.
    - A single-page identification with page coverage below the floor returns not-main with reason `low_coverage`; the same identification across two pages returns main with reason `main_multifolio`.

    - An identification with `adjudication_status='human_confirmed'` on any claim returns main with reason `main_human_confirmed`, evaluated BEFORE every gate, including when routing demoted it.
    - An identification below the ratified short-evidence threshold returns not-main with reason `insufficient_length`.
    - An identification missing a signal the gates need returns not-main with reason `missing_signal` — never main by default.
    - Gates are evaluated in fixed order and are non-compensating: no combination of weaker signals promotes an identification that any gate rejected.
