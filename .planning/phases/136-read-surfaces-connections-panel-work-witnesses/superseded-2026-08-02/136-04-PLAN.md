    (1) THREE LEVELS OR TWO. The middle bucket holds passages where several works claim byte-identical
    text — the signature of a shared verse-chain or a liturgical formula rather than a witness. Under

    (2) RELATION FILTER ON THE FINDINGS PAGE. Deleting the tier filter leaves no way to filter by KIND
    of match on the corpus-wide page. The kinds split roughly 78 / 9 / 13. Adding the filter is small;
    omitting it means a reader browsing 65,200 rows cannot separate "this fragment IS the work" from
    "this fragment shares wording with it".

    (3) SHORT-EVIDENCE THRESHOLD. Below the threshold a row moves behind "show more matches" — it is
    never deleted and stays reachable. The honest counter-argument: for a prayer book a 66-letter
    liturgical passage may be exactly the right identification, and the thinnest shipped direct match
    in the whole asset is 37 letters. Show the per-threshold counts and the "only identification on

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live asset → evidence pack (committed) | A reporting script reads a masked asset and writes a public-repo markdown file |
| owner decision → build artifact | A ratified alias list becomes a pinned build input that changes what the panel renders |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-136-04-01 | Information disclosure | Evidence pack printing work titles, loci or a restricted corpus name | mitigate | Script prints `w000xxx` ids and counts only; `--scan-asset --strict` gates the commit |
| T-136-04-02 | Tampering | The evidence script writing to the live asset | mitigate | Open with `mode=ro`; acceptance criterion asserts no `.db` change in `git status` |
| T-136-04-03 | Repudiation | A threshold shipped with no recorded rationale, unreviewable later | mitigate | Decision record requires reasoning and declined alternative per decision, with a provisional flag |
| T-136-04-04 | Tampering | An unratified alias pair silently collapsing two genuinely different works | mitigate | Every pair carries an explicit owner ratification flag; unratified pairs go to `undecided` and are not consumed |
| T-136-04-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs; stdlib sqlite3/json only |

</threat_model>
