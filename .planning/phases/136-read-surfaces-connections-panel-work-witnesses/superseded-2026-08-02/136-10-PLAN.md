<objective>
Give the findings page its domain facet: a one-time curated assignment of an FJMS domain to each
of the ~1,088 works carrying shipped claims, plus the small author-alias fill — and fix the
routing audit so `kept_tie` rows name what they demoted.

Purpose: `works.genre` is entirely NULL, so the domain facet has no data at all. The facet must key
on the IDENTIFIED WORK's domain, never the manuscript's catalogue domain: one manuscript catalogued
as court records carries a verifiably correct Rashi finding, and 338 tier-A findings sit on
manuscripts catalogued documentary or legal — filtering on the catalogue axis would hide exactly
the findings that disagree with the catalogue, which are the valuable ones.
Output: a hash-pinned curation artifact, its ingestion, and a closed-vocabulary build gate.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| curated artifact → shipped asset | A hand-curated file becomes a facet on a public-facing surface |
| FJMS vocabulary → discovery works | A closed vocabulary crossing corpora, where an invented leaf would look authoritative |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-136-10-01 | Tampering | An invented domain leaf entering the vocabulary through the artifact | mitigate | Build gate aborts on an out-of-vocabulary leaf; verifier re-asserts on the built asset |
| T-136-10-02 | Information disclosure | Work titles in the artifact's reason/provenance fields, in a public repo | mitigate | Ids only; `--scan-asset --strict` gates the commit |
| T-136-10-03 | Spoofing | The facet quietly filtering on the manuscript's catalogue domain, hiding the findings that disagree with the catalogue | mitigate | Wrong-axis guard test naming the forbidden accessor |
| T-136-10-04 | Repudiation | A silent `Unassigned` disappearance making the corpus look smaller than it is | mitigate | `Unassigned` is a real value with a verifier check and a test |
| T-136-10-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs |

</threat_model>
