<objective>
Build the rebuild-preservation gate and pin its expectations from the currently-live asset —
BEFORE the rebuild exists. Ordering is load-bearing: an expectation derived after the fact
proves nothing, and the existing deploy verifier reads its expected frame from the candidate's
own manifest, which cannot detect a wrong rebuild.

Purpose: this phase's dominant risk is an unverified rebuild silently losing or corrupting
268,361 claims / 297,415 evidence rows. Population-hash equality is necessary but not
sufficient — it keys only on `(page_id, canonical_work_id, stratum)` and omits novelty,
routing, precision, snapshot hash and `matched_letters`.
Output: a new offline verifier, a committed expectation file, and tests that prove the
verifier can fail.
</objective>

    `verify()` accumulator, exit 0 on empty, exit 1 otherwise.

    `discovery_evidence`, `witness_units`, `witness_unit_members`, `discovery_routing_audit`:

    (`coverage_ppm`, `coverage_validity`, `band_rank`, `w_start`, `w_end`, `novelty_status`,

    `demoted_work_id` for `kept_tie` rows only), and feed a running `hashlib.sha256` over each row's
    remaining values joined by a fixed delimiter with an explicit NULL sentinel. Never hold a table
    in memory. Compare old-hash vs new-hash per table; unequal is a hard fail. Also compare row
    counts per table and report the delta without echoing any cell value.

    Group B — `band_precision`. Every row identical except the single authorized `tier_a` row,
    where only `measurement_status` and `ci_low` may differ; a differing `precision` on ANY row is
    a violation. Assert the new `tier_a` values are exactly `measured_pass` / `0.9084`.

    Group C — hash recomputation. Recompute `population_hash` and `cluster_map_hash` on the NEW
    asset using the imported `cert01_frame` functions, and compare against the values pinned in
    `--expected`. Never read an expectation from the new asset's own `meta` or manifest — state
    this in the module docstring as the F-04 fix.

    Group D — CERT-01 card binding. Load the graded deck's card list from `--cards` (default path
    resolved at run time by grepping `scripts/verify_cert01_grading.py` for its verdicts-file

    `span_end` and `snapshot_hash` are byte-identical old vs new.

    Masking discipline throughout: a violation message names only a primary key, a table name and a
    column name — never a cell value, never a title, never a locus.

    Also provide `--pin <out.json>` mode that writes the expectation file from a single database, so
    Task 2 uses this same code path rather than a second implementation.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-136-03-01 | Tampering | Silent row loss or in-stratum value drift in the rebuild | mitigate | Per-table streamed content hash + row counts; scenario 2 proves in-stratum drift is caught |
| T-136-03-02 | Spoofing | A wrong rebuild passing by supplying its own expectations | mitigate | `--expected` is an externally pinned committed file; scenario 7 proves manifest self-attestation fails |
| T-136-03-03 | Information disclosure | Violation messages echoing reference text or a restricted locus | mitigate | Messages carry primary keys only; tests assert the mutated value is absent from stderr |
| T-136-03-04 | Repudiation | Card binding skipped because the gitignored deck is unavailable | mitigate | Missing deck is a loud violation unless `--cards SKIP` is passed explicitly, and the skip is recorded in the summary |
