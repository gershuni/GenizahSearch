## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| every surface → every output channel | Display, payload, clipboard and error text are four separate exits |
| interaction-created DOM → masking scan | Only a browser-level capture sees them |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-136-31-01 | Information disclosure | A restricted name in a JSON payload the template never renders | mitigate | Payload coverage is a separate assertion class with its own positive control |
| T-136-31-02 | Information disclosure | A restricted name in a copy or clipboard string, bypassing the template | mitigate | Every copy affordance enumerated and asserted, with the list recorded |
| T-136-31-03 | Information disclosure | A restricted value in an exception message or a log line | mitigate | Forced-error coverage across at least three error kinds per surface, with a positive control |
| T-136-31-04 | Repudiation | The interaction-level capture silently skipped again | mitigate | A skip must name the prerequisite, the lost coverage and the residual risk, in the committed record |
| T-136-31-05 | Spoofing | Novelty reading differently on three surfaces | mitigate | One shared row primitive and one string source across all three |
| T-136-31-SC | Tampering | npm/pip/cargo installs | mitigate | Browser automation may be required; if installed, verify the package on its registry page first and record the verification — otherwise record the skip |

</threat_model>
