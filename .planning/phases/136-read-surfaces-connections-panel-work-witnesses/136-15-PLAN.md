<objective>
Build the panel's display model as a pure, fully testable function over the LIVE service envelopes —
every display rule in one place, none of them inside a NiceGUI render function.

Purpose: the display rules are where this surface is most likely to be quietly wrong, and every one of
them was found by looking at real data rather than by reasoning. The same work appeared twice under
two titles on a real page. One 66-letter span produced four separate liturgical "identifications". A
verse-chain pulled in three unrelated works on byte-identical offsets. Two rows a human had confirmed
were treated differently on the same manuscript. Rules that subtle belong in a function with tests,
not in a render loop.
Output: one pure module the panel renderer consumes without making a single judgement of its own.
</objective>

<revision_note>
**Revised 2026-08-04 after Codex pre-flight round 5 (findings 3, 9, 13).** This plan was written against
a repo where the discovery service layer did not exist. Plan 136-14 has since shipped it, and its shape
is not the one this plan assumed:

- **Finding 3 (HIGH).** The model's input was specified as `build_panel_rows(service_rows, ...)` — bare
  rows — while the model is simultaneously required to distinguish four service states. Bare rows cannot
  carry a status, cannot distinguish `ok`-with-zero from an outage, and cannot carry `meta.resolved`.
  Live `web/discovery.py` supplies FIVE separate envelopes. Synthetic row fixtures would therefore have
  passed while real composition was broken. The input is now an explicit `PanelServiceBundle`.
- **Finding 9 (HIGH).** Nothing in this plan required `display_work_title()`, and live service rows
  deliberately carry RAW `neutral_title` (`discovery_service.py` `_present_claim_row` /
  `get_manuscript_works_enveloped`). A "plain text, not a link" test passes with the wrong title. Ruling
  R binds every title-rendering surface; the routing is now a behavior with a curated bilingual fixture.
- **Finding 13 (LOW).** The 14/116 and 19/121 population figures are PRIVATE-rebuild values. The
  deployed PUBLIC artifact carries a different population. Every population is now labelled by
  artifact and audience, and fixtures stay behavioral rather than count-derived.

**Revised again 2026-08-04 after Codex pre-flight round 6 (finding 3)** — a defect the round-5 revision
itself introduced. `PanelServiceBundle` required all FIVE envelopes while 136-17 fetches FOUR, because
the fifth (`get_related_pages_enveloped`) is LAZY by this plan's own design: the related-pages rows load
only when the reader opens the toggle. Requiring it eagerly would either force a fifth read onto every
browse page load — against the enrichment budget and against this plan's own "rows only when the toggle
is on" behaviour — or invite the executor to fabricate an `ok`-with-zero for a section nobody has asked
for, which is the false-zero class in a new costume. The related-rows field is now explicitly OPTIONAL,
with `None` meaning **not requested**: a fourth, honest state that is neither an outage nor an empty
section.

From `shared/discovery_surface_projection.py` — the ONE envelope every discovery read returns:
```python
{"status": str, "items": list, "total": int, "meta": dict}     # FOUR keys, always
SURFACE_STATUSES  = {"ok", "unavailable", "timeout", "busy"}   # closed
OUTAGE_STATUSES   = {"unavailable", "timeout", "busy"}
def is_outage(envelope) -> bool                                # the hide-on-zero rule reads THIS
```
A NON-`ok` envelope ALWAYS carries `items == []` and `total == 0`. A caller reading `total` without
checking `status` therefore cannot render an outage as a count — but it also cannot tell the two apart
without `status`, which is exactly why bare rows are not an acceptable model input.

From `web/discovery.py` — the FIVE envelopes the panel path produces, with their exact `meta` keys:

| callable | items | meta on `ok` |
|---|---|---|
| `get_manuscript_page_ids(sys_id, volume_ie=, limit=)` | page-id strings | `sys_id`, `resolved`, `truncated`, `volume_ie` |
| `get_claims_for_page_enveloped(page_id, page=, page_size=, include_review=, lang=)` | `surface_safe_claim` rows | `page_id`, `include_review` |
| `get_manuscript_works_enveloped(page_ids, page=, page_size=, lang=)` | `surface_safe_work_summary` rows | `page_scope_resolved`, `lang` |
| `get_related_page_count_enveloped(page_id, include_review=)` | `[]` always | `unit: "distinct_opposite_pages"` |
| `get_related_pages_enveloped(page_id, page=, page_size=, include_review=)` | `surface_safe_related_page` rows | `unit: "distinct_opposite_pages"` |

The fifth read is **LAZY**: the panel loads related-page ROWS only when the reader opens the toggle, so
on a normal page load 136-17 supplies four envelopes and the fifth is absent. "Absent" is a state in its
own right — see the `not_requested` rule in Task 1 — and must never be represented as an `ok` envelope
with zero items.

Every outage envelope carries `meta["reason"]` — one of `sidecar_not_serving`, `query_timeout`,
`bounded_concurrency`, `query_failed`. `get_manuscript_works_enveloped` additionally returns
`ok / items=[] / total=0 / meta={"page_scope_resolved": False}` when the page list is empty: an
`ok` envelope that is NOT a fact about the manuscript.

From `shared/discovery_surface_projection.py`, the row key sets (allowlists — every projected row
carries EVERY key, missing values as `None`): `SURFACE_CLAIM_FIELDS`, `SURFACE_WORK_SUMMARY_FIELDS`,
`SURFACE_RELATED_PAGE_FIELDS`.

From `shared/discovery_display_strings.py` (plan 136-10 + ruling R):
```python
def display_work_title(work_id: str, neutral_title: str, lang: str = "en") -> str
CURATED_WORK_TITLES = {"w000176": {"he": "משנה תורה, ספר אהבה / סידור",
                                   "en": "Mishneh Torah, Sefer Ahava / Siddur"}}
```
`work_id` here is the **DISPLAY** work id (`display_work_id`), which is the id the curated table is
keyed on and the id the service's identity join already resolved.
