<offload_contract>
<!-- Replaces the pre-revision "one synchronous enveloped callable via run.io_bound" paragraph.
     This is the integration contract; it is not negotiable at execution time. -->

**Every discovery read on this path is a direct `await` on a `web.discovery` async wrapper. This plan
adds NO `run.io_bound`, makes no synchronous service call, and never imports `web.discovery._service`.**

The wrappers already dispatch off the loop internally (`DiscoveryService._enveloped_off_loop` →
`_run_off_loop` → `run_in_executor` + `asyncio.wait`, never `wait_for`, because executor threads are not
cancellable). Handing an async wrapper to `run.io_bound` returns a coroutine object to a sync worker and
never executes the query; calling one from inside a `run.io_bound` worker is a NESTED offload that burns
two threadpool slots per panel load on a single-worker server.

The four EAGER reads and their dependency shape, plus the one LAZY read:

| read | when | depends on | cached |
|---|---|---|---|
| `get_manuscript_page_ids(sys_id, volume_ie=page.volume_ie)` | eager | — | no |
| `get_claims_for_page_enveloped(page_id, lang=)` | eager | — | yes |
| `get_manuscript_works_enveloped(page_ids, lang=)` | eager | page ids | yes |
| `get_related_page_count_enveloped(page_id)` | eager | — | yes |
| `get_related_pages_enveloped(page_id, page=, page_size=)` | **LAZY — only when the reader opens the related-pages toggle** | — | yes |

Issue the three independent eager reads under one `asyncio.gather`, then the manuscript-works read once
the page ids resolve. Two sequential rounds, not four.

**The LAZY related-pages read is not part of the page load.** (It is not the same thing as Task 1's
fifth enrichment PLACEHOLDER, which is a container in the browse render seam.) Build the
`PanelServiceBundle` from the four eager envelopes and leave its related-ROWS field as `None`, which
136-15 defines as NOT REQUESTED — a state distinct from an `ok` zero and from an outage. When the reader
opens the toggle, issue the lazy read, install its envelope on the bundle and re-render that section. **Never fill the slot with a synthesised
`ok`/`items=[]`/`total=0`:** that tells a reader this page has no related pages on the strength of a
query nobody ran. The section's header COUNT comes from the eagerly-fetched count envelope, so the
default view has a real number without the rows.

**How many executor crossings this costs, plainly.** A cold panel load crosses the offload boundary
**four** times — one per eager read — not once. Opening the related-pages toggle adds a **fifth
crossing**, once, and only for readers who ask for it. That is the accepted design rather than an oversight: the reason is
the deviation recorded directly below, and the per-state dispatch counts Task 1 asserts are derived from
it. Any plan or test that expects a single composite dispatch is expecting the design this contract
rejects.

The `cached` column is `_enveloped_off_loop(..., cache_name=…)`'s version-keyed LRU, whose key includes
the call arguments. That matters for the measurement in Task 1: on a page turn within one manuscript the
claims and related-count entries miss (their key carries `page_id`) while the manuscript-works entry
hits (its key carries the stable page-id tuple), and `get_manuscript_page_ids` has no cache at all.

**Deliberate deviation from finding 4's remedy, with its reason.** Finding 4 asks for "a public
synchronous bundle callable that executes the raw page-ID accessor and all panel reads inside one
worker". I am not specifying that, because three of the four reads are already served by
`_enveloped_off_loop(..., cache_name=…)` — a per-argument, sidecar-version-keyed LRU
(`claims_for_page_enveloped`, `manuscript_works_enveloped`, `related_page_count_enveloped`). A single
composite callable would be keyed on the whole argument tuple, which includes `page_id`; `page_id`
changes on every folio turn while the manuscript-scope query's inputs do not. Bundling would therefore
invalidate the manuscript-works cache on every page turn and re-run all four queries each time — a
measurable regression on the browse hot path, which is exactly what this plan's own enrichment-budget
criterion measures. The SUBSTANCE of finding 4 is adopted in full: do not nest the async wrappers, do
not import the private `_service`, pass `page.volume_ie`, and unpack and branch explicitly on `status`
and `meta['resolved']`. Record this deviation and its reason in the summary.

**Per-user state.** Capture every per-user value into a plain local BEFORE any await, and bind
`page_client` at render time. `run.io_bound` silently degrades `safe_user_*` to `{}` and `ensure_future`
empties the slot stack so `ui.context.*` raises — this project has been bitten by both.
</offload_contract>
