Render the findings page's rows and its novelty switch, measure the full filter/sort/count combination
space against the versioned caps, prove the surface against rendered-output invariants, and ship it.

**Wave note (Codex round 2, finding 13):** this plan sits one wave AFTER the panel plan even though
their repository file lists do not overlap, because both mutate the same external resource —
**production**. A `files_modified` check cannot see that contention by construction, which is why two
concurrent deploys survived three verification rounds. The dependency on 136-17 is a deploy-ordering
edge, not a code edge.

Purpose: the novelty axis is the reason this surface is worth using and also the place it is easiest
to overclaim. The line deliberately not crossed is "new discovery": that stacks two unearned claims —
that the match is correct, and that it is new — on a row carrying no human review until a later phase.
A wrong match that no catalogue records is not a discovery. The shipped wording asserts candidacy, and
only candidacy.
Output: the completed findings page, measured, proven and live behind the flag.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| novelty verdict → reader claim | The most reputationally loaded statement either surface makes |
| user filter/sort/unit selection → SQL | The largest combination space in the system, on a one-worker server |
| local build → production | The phase's second deploy |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-136-18-01 | Spoofing | A row asserting a new discovery rather than candidacy | mitigate | Candidacy wording only, sourced from the shared strings module; a positive control seeds "New discovery" and asserts the suite fails |
| T-136-18-02 | Spoofing | Novelty ordering or styling a row, implying it is evidence of correctness | mitigate | Novelty absent from the sort options, asserted; no row-level accent keyed on novelty, asserted by grep |
| T-136-18-03 | Spoofing | The facet described as the identified work's domain while filtering on the manuscript's | mitigate | Header assertion scoped to the header element; a positive control seeds the mislabelled header |
| T-136-18-04 | Denial of service | An unmeasured filter/sort combination scanning the corpus and stalling the single worker | mitigate | Full combination space benchmarked with a hard PASS/FAIL and a stop on failure; prod-box numbers recorded |
| T-136-18-05 | Information disclosure | A restricted-corpus name reaching rendered output, a JSON payload or an error path | mitigate | Masking scan over captured output for every state and both languages |
| T-136-18-06 | Tampering | A local bucket reimplementation diverging from the shared rule | mitigate | Rendered-row bucket membership asserted against the shared rule, with a disagreeing-row positive control |
| T-136-18-07 | Spoofing | A missing matched-letter value rendered as zero, understating the evidence | mitigate | Absence renders as omission; a test asserts no zero and no failed-lookup placeholder |
| T-136-18-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan |

</threat_model>
