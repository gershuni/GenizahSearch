<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| finding-aid sources → novelty verdict | Untrusted, incomplete external metadata deciding a reputationally loaded public claim |
| model provider → committed tree | Prompts, responses and raw provenance must not cross this boundary |
| verdict cache → shipped asset | A build-time artifact that must never be shipped |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-136-04-01 | Spoofing | A failed check rendering as "not found in the finding aids checked" | mitigate | Tri-state with `not_checked` as the fail-closed default; structured abstention maps to it; a test asserts no path returns a positive verdict on failure |
| T-136-04-02 | Information disclosure | A restricted corpus named through the novelty provenance | mitigate | `masked_provenance_label` with an adversarial-input test; masking scan on the module, the contract doc and the run record |
| T-136-04-03 | Information disclosure | Prompts or raw provenance committed with the run record | mitigate | Acceptance criterion asserts none appear in the committed diff; the cache stays uncommitted and is referenced by hash |
| T-136-04-04 | Tampering | The model silently downgraded to cut cost, changing verdict quality | mitigate | Model, version and effort pinned as literals in `shared/discovery_novelty.py`; the scripts import them; a grep asserts no second model name |
| T-136-04-05 | Repudiation | An estimated cost recorded as if measured | mitigate | Real `usage.cost` required; acceptance criterion asserts the run record names it |
| T-136-04-06 | Denial of service | A corpus-scale run failing late and being paid for twice | mitigate | Checkpointed, resumable run; the summary records that resume was exercised |
| T-136-04-SC | Tampering | npm/pip/cargo installs | mitigate | If the run requires a new client package, verify it against `docs/specs` policy and a blocking human check before install; otherwise no installs |

</threat_model>
