<objective>
Extend the work-witness read path with the display fields, the count query and the sort and filter
modes `/work/{id}` needs.

Purpose: the work query today exposes only unit, page, work, claim and manuscript ids plus family
and band — no total, no shelfmark, no library sort key, no coverage, no novelty. Server-side sorting
by library and a visible real total are therefore impossible. Terminology matters too: the heaviest
work has 13,038 claim ROWS but 4,796 distinct manuscripts and 4,637 witness units, and the page's
totals must count units.
Output: an extended CTE, a predicate-identical count query, and stable pagination.
</objective>

| count query → displayed total | A drifted predicate makes a visible number a lie |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-136-24-01 | Tampering | SQL injection through a sort or filter parameter | mitigate | Sort modes are a closed enum mapped to fixed key lists; filter values are bound parameters; an unknown parameter is rejected |
| T-136-24-02 | Spoofing | A total that does not match the list it labels | mitigate | The count wraps the paginated query's own predicate expression; a test pages through and compares |
| T-136-24-03 | Spoofing | Claim rows presented as carriers | mitigate | Unit-count tests on a fixture where all three counts differ |
| T-136-24-04 | Denial of service | An unbounded client page size | mitigate | Clamp to the versioned maximum, asserted by a test |
| T-136-24-05 | Denial of service | A heavy count query on the single event loop | mitigate | Off-loop dispatch with the work timeout; never `asyncio.wait_for` over an executor future |
| T-136-24-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs |
