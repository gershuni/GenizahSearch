<objective>
Land the D-02a lockstep: the one authorized `band_precision.tier_a` change, applied in step across the
builder, the validator, the release verifier and the schema tests, so tier A goes default-visible
without any measured percentage entering the asset.

Purpose: `tier_a` is 81% of the corpus and carries no measured precision in the deployed asset, so the
default-shown gate hides it and the main pool collapses to roughly 2,241 identifications instead of
tens of thousands. Codex proved the naive fix cannot be built — the builder's validator REQUIRES
`tier_a` precision to be NULL and the release verifier independently rejects a non-null value. The
owner's resolution is to store the authorization (`measurement_status` + `ci_low`) and never the
number, which is exactly what `is_default_eligible()` reads.
Output: a two-key change guarded on both branches, with the point estimate provably absent.
</objective>
