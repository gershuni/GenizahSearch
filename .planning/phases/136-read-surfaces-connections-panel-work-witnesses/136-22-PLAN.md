<objective>
Build the launch-statistics reader ruling U requires: the main-pool contribution total and its three
shades, computed from the LOADED ARTIFACT at request time, on the single consistent basis
`main_pool = 1`, returned through the same four-key envelope the rest of the service uses — with the
numbers provably absent as literals from both code and translations.

Purpose: the owner chose contribution as the launch headline over the larger coverage figure because it
is the harder number to dismiss with "we knew that already". That choice only survives if the number is
true of the artifact actually being served. It already is not stable: Codex measured **9,523** in the
deployed public artifact against **10,432** on the private rebuild — two different, both-correct answers
to the same question about two different databases — and an earlier draft quoted **13,285** because it
added a main-pool count to two unfiltered ones. A hardcoded launch number is not a shortcut; it is the
same defect as the 13,285, deferred to the next bake.
Output: one enveloped, version-aware reader, and a test that fails if any of its numbers ever becomes a
literal.
</objective>
