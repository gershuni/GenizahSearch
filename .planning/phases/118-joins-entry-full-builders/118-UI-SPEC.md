## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, tight inline spacing |
| sm | 8px | Compact element spacing — between row-level controls, gap between badge and label |
| md | 16px | Default element spacing — builder row padding, card internal padding |
| lg | 24px | Section padding — between builder and candidates, inside work column |
| xl | 32px | Layout gaps — between anchor pane and work column (inherited from Phase 117) |
| 2xl | 48px | Major section breaks — above candidate grid heading |
| 3xl | 64px | Page-level spacing — inherited from Phase 117 header height |

**Exceptions:**
- Gap control widget between builder rows: 24px vertical spacing is required around it so the "distance" metaphor is visually clear. Use `gap-6` (24px) as the inter-row gap that contains the gap control.
- Touch targets (mobile): minimum 44px height for all interactive elements per the existing `common.css` rule (`button { min-height: 44px }`).
- Known-joins group row height: 36px compact row (8px vertical padding × 2 + 20px content).

## Component Inventory

All components referenced here are NiceGUI / Quasar built-ins or existing project components in `web/components/`. No new third-party components introduced.

### New / Extended Components This Phase

#### 1. Line Builder Widget (replaces Phase 117 textarea, BLD-01/BLD-03/BLD-04)

**Shape:** Vertical stack of builder rows. Each row:
- A full-width `ui.input` (outlined, RTL, Hebrew serif, 16px) with placeholder `tr('Words on this line (space = sequence, a/b = alternatives)')`.
- A "more" affordance: flat icon button `icon=tune` (dense, 24px) opening a `ui.menu` popover with the per-line modifier toggles: Line-start (⊢), Line-end (⊣), Plene/Defective, Prefix, Suffix, Wildcard, Negation. Each modifier is a `ui.checkbox` with its label. Popover closes on outside click.
- An "×" remove button (flat, dense, `icon=close`, `color=negative`) — not shown on the last remaining row.
- A row number label (right-aligned, 12px, `--text-muted`) showing the line index (`1`, `2`, ...).

**Gap control between rows (D-07):** Between each pair of adjacent rows, render a compact inline gap control:
- A `ui.row` with a small label `tr('↕ gap')` (12px, `--text-tertiary`) and a `ui.number` input (dense, outlined, width 56px, min=0, max=20, step=1, default=0).
- Maps to `BuilderRow.gap_to_next`. Visual metaphor: the control sits IN the space between rows, suggesting "distance to the next line."
- When gap=0: control renders with `--neutral-300` border (de-emphasised). When gap>0: border switches to `--border-focus` (green) to make active gaps visible.

**Add row button:** Below the last row: `ui.button(tr('+ Add line'), icon=add)` — flat, small, `--text-secondary` color.

**Text Position control (D-08, prominent placement):**
- A `ui.select` with the 5 options from `web/pages/search.py:646-655`: Anywhere / Start / End / Line Start / Line End — placed directly above the builder rows with a label `tr('Text Position')` (12px semibold uppercase). Not buried in advanced.

**Mode selector (D-09):**
- A `ui.button_group` or three flat `ui.button` toggles: Exact / Variants / Fuzzy.
- The active mode has `color=primary` (filled); inactive modes are flat `color=default`.
- Placed in the same header row as Text Position, to the right/end in LTR (left/end in RTL).

#### 2. Collapsed Summary Bar (D-14)

On search start, the builder area collapses to a single `ui.row` summary bar:
- Content: `"{mode} · {N} lines · Text Position: {position} · {toggles}"` — e.g. `"Variants · 3 lines · Text Position: line ends · flex-spacing on"`.
- An "Edit" flat button (`icon=edit`, `color=primary`) on the trailing end re-expands the builder.
- Background: `--bg-tertiary`, border: `--border-light`, border-radius: 8px, padding: 8px 16px (sm/md).
- The summary text is 14px body weight 400, `--text-primary`.

**Empty builder guard (D-14):** When ALL builder rows are empty, the Run Search button is disabled and shows a tooltip `tr('Enter at least one search line to run')`.

#### 3. Advanced Search Options Disclosure (D-12)

A `ui.expansion_item` with header label `tr('Advanced search options')` (label 13px semibold), collapsed by default. Contains:
- **Global toggles (D-10/D-11):** Two `ui.checkbox` controls — Flexible Spacing (`tr('Flexible spacing')`), Bidirectional (`tr('Bidirectional')`). Judeo-Arabic is NOT surfaced (D-10 divergence — intentional, no toggle).
- **Other-side builder (BLD-02, D-13):** A `ui.checkbox` labelled `tr('Search the other side of the leaf')` — OFF by default. When checked, expands to reveal the full other-side builder (same row-based widget as the anchor side, but `allow_page_position=False`) plus a Narrow/Widen combine mode select: `tr('Narrow (AND)')` / `tr('Widen (OR)')` defaulting to Narrow.

The disclosure panel background is `--bg-tertiary`, 1px border `--border-light`, border-radius 8px.

#### 4. Known-Joins Group (ANC-04/ANC-05, D-15/D-16)

**Placement:** A collapsible section rendered below the anchor transcription inside the sticky anchor pane. Uses `ui.expansion_item` with header `tr('Known Joins') + ' (' + str(count) + ')'`.
- Collapsed by default when count = 0. Expanded by default when count > 0.
- Max-height: 240px with `overflow-y: auto` so a long list doesn't push the pane off screen.

**Member row layout (compact, 36px):** Each join member is a `ui.row` containing:
- Source attribution badge: outlined Quasar badge (12px), color per source badge map above.
- Shelfmark label: 13px, `--text-primary`, font-weight 600.
- Two action icon buttons on the trailing end:
  - Re-anchor: `icon=push_pin` (flat, dense, 20px) — tooltip `tr('Re-anchor to this fragment')`.
  - Open in Browse: `icon=open_in_new` (flat, dense, 20px) — tooltip `tr('View in Browse')`.
- Hover state: `--bg-hover` background on the row.

**Multitenant safety (ANC-05):** Only public/confirmed joins are fetched (D-17). No user-specific joins shown. The section heading for an empty result is `tr('No known joins')` with a muted sub-label `tr('Only confirmed public joins are shown')` (12px, `--text-muted`).

**Loading state:** While the async fetch runs, show `ui.spinner(size='sm')` in the section header.

#### 5. "Find Joins" Entry Points (FND-04/FND-05, D-18/D-19/D-20/D-21)

**Joins icon on /search result cards (D-21):**
- Icon: `link` (Material Icons chain-link). Placed in the card action row alongside the existing Browse / Quick View icons.
- Color: green (`--primary-600`) when joins exist; neutral (`--neutral-400`) when no joins.
- Click when joins EXIST: opens the existing joins dialog (`create_joins_dialog`) which gets a new "Find more joins" button below "View all fragments" — flat button, `icon=science`, label `tr('Find more joins')`, tooltip `tr('Go to Joins Lab to find more joins')`, opens `/joins-lab?sys_id=...` in a new tab.
- Click when NO joins: opens `/joins-lab?sys_id=...` (+ `volume_ie` for multi-IE) in a new tab directly — no near-empty dialog.
- Present on every search result card (every fragment).

**On /browse (D-19):**
- The existing `create_joins_button` in `web/components/joins_panel.py` is the insertion point — do NOT add a separate button.
- When joins EXIST: existing dialog opens; add the "Find more joins" flat button at the bottom of the dialog (below "View all fragments").
- When NO joins: recolor the button to flat `color=default` with `--neutral-500` icon tint; tooltip `tr('Find Joins in the Joins Lab')`; click opens new tab directly.

**On Quick View (D-20):** Same logic as /browse — reuse the same joins button/dialog component.

## Interaction Contracts

### Builder: expanded ↔ collapsed lifecycle

1. **Default state:** Builder is expanded, showing the Text Position select, mode selector, at least one empty builder row, the advanced disclosure (collapsed), and the "Run Search" button.
2. **On "Run Search" click (non-empty builder):** Builder area auto-collapses to the summary bar. Candidates load below. The summary bar is always visible during search and after.
3. **On "Edit" click in summary bar:** Builder re-expands to full form with the prior values intact.
4. **On "Run Search" click (empty builder):** Button is disabled; tooltip explains why. No collapse.

### Builder: per-row modifier popover

1. User clicks the `tune` icon on a row.
2. A `ui.menu` opens anchored to that icon, listing all modifier checkboxes.
3. Active modifiers display a small colored indicator dot on the `tune` icon (using `--primary-600`) so the user can see a row has modifiers without opening the popover.
4. Popover closes on outside click or Escape key.

### Gap control

1. Default gap=0 on every new row. Rendered between each pair of adjacent rows.
2. Gap number input accepts integers 0–20. Values outside range are clamped.
3. When gap > 0, the inter-row separator shows the gap value prominently: `"↕ {N} lines"` label at 12px with a `--border-focus` left border accent (4px width) to visually signal a configured gap.

### Known-joins: re-anchor

1. User clicks `push_pin` on a known-join member row.
2. The anchor pane reloads with the new fragment's image and transcription.
3. The `safe_storage` anchor state is updated.
4. The builder state is NOT reset (per D-16 — re-anchoring within known joins is a navigation action, not a session reset).
5. The known-joins group reloads for the new anchor.

### "Find joins" deep link

1. All deep links use the format `/joins-lab?sys_id={encoded_sys_id}` with `volume_ie={ie}` appended when applicable (FND-08 contract).
2. All "Find joins" actions open the URL in a new browser tab (`target='_blank'`).
3. The new tab opens to Phase 117's cold-start resolver, which reads the `sys_id` param and loads the anchor automatically.

### Mode selector

1. Clicking a mode button updates the active mode immediately (visual feedback: filled vs flat button state).
2. The mode choice persists in the in-memory builder state for the session duration (Phase 120 handles cross-refresh persistence).
3. Fuzzy mode: on selecting Fuzzy, show a `ui.tooltip` (or inline hint at 12px `--text-muted`) reading: "Fuzzy search is slower and uses more server resources."

### RTL / bilingual layout

1. All builder rows use `direction: rtl; text-align: right` on inputs (matching existing `search_textarea` style).
2. The per-row action buttons (tune, remove, row number) are placed on the LEFT side of the input in LTR layout (i.e., the START side in RTL terms — visually at the far left of the row when the text flows right-to-left).
3. The known-joins group section is direction-aware: in Hebrew interface mode, shelfmark text is right-aligned, badges on the right.
4. The summary bar respects `--text-secondary` and shows the query text with `direction: rtl; text-align: right` when the interface is in Hebrew mode.
5. All new strings pass through `tr()` from the first line of implementation (every string bilingual — Phase 121 will audit, but Phase 118 starts compliant).
