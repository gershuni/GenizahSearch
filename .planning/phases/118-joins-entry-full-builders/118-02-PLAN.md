<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| logged-in scholar (User A) → process-global `_joins_cache` → other session (User B) | The cache is module-level in the Python process; without isolation a cached payload from one user's request serves another's |
| browser/client → public `fragment_joins` RLS path | RLS policy `USING (true)` makes every row publicly readable to all roles |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-01 | Information Disclosure | `fetch_connected_fragments` process-global `_joins_cache` + `get_fragment_joins` public RLS | mitigate | Confirmed-only path uses ISOLATED cache key `doc:{id}:pgp:{pgpid}:confirmed`; the Lab's known-joins fetch never shares a cached payload with the browse dialog's full-joins fetch; only public/confirmed sources surface (D-17), so a not-yet-confirmed creator-only join structurally cannot reach another user's Lab session. Proven by `tests/test_joins_anc05_rls.py::test_no_cross_user_poisoning` |
| T-118-02 | Information Disclosure | known_joins_group.py per-user state | mitigate | Component holds zero per-user state; no `app.storage.user`. Guarded by `tests/test_no_raw_storage_access.py` (allowlist stays `[]`) |
| T-118-03 | Tampering | member shelfmark → on_open_browse/on_reanchor callbacks | accept | Callbacks navigate within the app to existing routes; shelfmark/sys_id are read-only identifiers, no injection surface (URL-encoding handled by the Plan-04 caller) |
</threat_model>
