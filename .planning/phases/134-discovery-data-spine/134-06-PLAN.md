<objective>
Build the single async `DiscoveryService` chokepoint (`shared/discovery_service.py`): a synchronous indexed/bounded/paginated SQLite core wrapped in async methods that run off the event loop (`run_in_executor` + `asyncio.wait(timeout)`, NOT `wait_for`), gated by a bounded-concurrency semaphore whose slot is released via `future.add_done_callback` (NOT `finally`) so a timed-out worker cannot recycle capacity while its thread still runs, returning "temporarily unavailable" under overload, with LRU caching on the browse-enrichment path and graceful no-op when the sidecar is unavailable. The service is INJECTED with its (path-or-provider, availability_callable, sidecar_version_token) so `shared/` never imports `web/` — enforced by an AST layering guard.

Purpose: DATA-06 requires every web read to go through one chokepoint that never blocks the loop and never hangs under load. The exact off-loop + overload pattern shipped in `web/search_api.py`; reuse it (threads are not cancellable, so `asyncio.wait` + abandon-the-future + release-the-slot-on-done-callback is the load-bearing choice — releasing in `finally` would free the budget while the abandoned thread still holds a real threadpool worker, over-committing). No UI consumes it this phase — it is proven by the overload + slot-recycling + pagination tests.
Output: `shared/discovery_service.py`, `tests/test_discovery_service.py`, `tests/test_no_back_edges_discovery.py`.
</objective>
