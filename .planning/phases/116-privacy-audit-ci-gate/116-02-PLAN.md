<objective>
Add a SYNCHRONOUS, RETURN-VALUED self-test send path and wire it to a headless `--telemetry-selftest`
(and `--telemetry-selftest-offline`) CLI flag in `genizah_app.py __main__`, modeled on the existing
`--self-test-pymupdf` block (parsed BEFORE `QApplication`).

The success signal is the RESULT of one real synchronous `requests.post` (HTTP-status-checked), NOT
the queue-saturation drop counter. `shared.posthog_server.get_dropped_event_count()` ONLY counts
`queue.Full` (`shared/posthog_server.py:88-96`, `:228-230`); the daemon's real POST
(`requests.post(..., timeout=2.0)` at `:258`) is wrapped in a bare `except Exception` (`:259`) that
swallows SSL/network errors, and a missing key drops silently at drain time (`:248-249`). Keying
SSL_OK off the drop counter + a `sleep` would FALSELY pass when nothing was delivered (REVIEWS HIGH
#1, confirmed against code). So this plan introduces a new helper `send_selftest_event_sync()` that
performs exactly one POST and returns `SSL_OK` / `SSL_FAIL` / `NO_KEY`.

This is the on-device tool that verifies ROADMAP SC#3 (frozen-binary SSL + offline degradation). The
gold-standard proof - a clean no-Python Windows VM run - is captured as a HUMAN-UAT verification item
(D-06), which ALSO closes Phase 114's still-open "live PostHog event delivery" UAT.

Purpose: Give release engineers a one-command probe that DETERMINISTICALLY proves certifi/SSL works
inside the frozen binary (a real keyed POST succeeds) and that telemetry degrades silently offline -
without writing consent to disk (D-04/D-05).
Output: a new `send_selftest_event_sync()` in `shared/posthog_server.py` + ~35 lines in
`genizah_app.py __main__`; documented in the runbook (plan 116-03, D-08d).
</objective>
