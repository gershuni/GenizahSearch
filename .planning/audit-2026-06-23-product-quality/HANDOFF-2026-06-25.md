# NEXT: SEED-015 — image-loading / NLI resilience (MINIMAL), incl. desktop TLS

**Findings:** #1 (HIGH), M2 (MED). **Mode:** CLOUD-AUTO (self-contained, testable). **Effort:** MED. Desktop-side.

### Decision gate (ANSWERED 2026-06-23 — do NOT reopen)
> "**MINIMAL NOW** — wire desktop loader into the NLI breaker + short timeouts; **defer** the full 4-path
> unification. **TLS:** keep `verify=False` but **restrict to known NLI/Rosetta hosts** + suppress warnings
> explicitly + document (don't chase the cert chain now)."
>
> → IN SCOPE: **#1** (breaker-wire desktop), **M2** (TLS host-restrict + document), small resilience hygiene.
> → **DEFERRED** to a later milestone: **#2** (4 divergent cache impls), **M1** (web-puzzle browser-side
> direct-NLI fallback), **M4** (unify failure taxonomy). Do NOT attempt these in SEED-015.

### The problem (plain version)
NLI's image servers (`iiif.nli.org.il`, `rosetta.nli.org.il`) sometimes go slow/down. The **web** app was
hardened in Phase 98 with a shared **circuit breaker** (`shared/nli_circuit_breaker.py`): after 3 consecutive
failures it "trips" and makes further NLI calls fail instantly for 60s, so the app doesn't hang. The
**desktop** image loader was never wired into it — so during an NLI outage the desktop app waits the full
10s (30s for Rosetta) on every image, feels frozen, and its failures never feed the breaker. Same code also
sets `verify=False` (TLS cert checking off) blanket-style, which a security review flagged (M2).

### Exact code to change
1. **`desktop/image_loader.py` → `_download_bytes()` (~lines 123-135).** Current:
   ```python
   timeout = 30 if 'rosetta.nli.org.il' in target_url else 10
   resp = requests.get(target_url, headers=headers, timeout=timeout, stream=True, verify=False)
   ...
   except Exception as e:
       logger.warning("Image download failed for %s: %s", target_url, e)
   ```
2. **`desktop/join_workbench.py` (~lines 731-735).** A direct `requests.get(url, ..., timeout=5, verify=False)`
   in the workbench image fetch path. Same treatment.

### The breaker API + the pattern to copy
`shared/nli_circuit_breaker.py` public API: **`is_open() -> bool`**, **`record_failure(failure_type, path)`**,
**`record_success(path)`** (+ `FailureType`). The **canonical call-site pattern is already in
`genizah_core.py::fetch_iiif_manifest` (~lines 4321-4408)** — copy it:
```python
from shared.nli_circuit_breaker import is_open as _nli_circuit_is_open, \
    record_failure as _nli_record_failure, record_success as _nli_record_success

if _nli_circuit_is_open():          # NLI flagged down → fail fast, no network
    return None
try:
    resp = requests.get(...)
    if resp.status_code == 200:
        _nli_record_success(path='desktop_image_loader')
        return resp.content
    elif resp.status_code == 429:
        _nli_record_failure(failure_type='429', path='desktop_image_loader')
    elif resp.status_code >= 500:
        _nli_record_failure(failure_type='5xx', path='desktop_image_loader')
    return None
except requests.Timeout:
    _nli_record_failure(failure_type='timeout', path='desktop_image_loader')
except requests.ConnectionError:
    _nli_record_failure(failure_type='connection_error', path='desktop_image_loader')
```
**Only count NLI hosts** toward the breaker — guard with a host check (the breaker is NLI-specific; don't
let a Cambridge/Oxford failure trip it). Mirror how `web/api.py` does host-conditional breaker calls
(D-host-conditional, see CLAUDE.md Phase 98 notes — 10 wired sites).

### Timeouts + TLS (the two concrete fixes)
- **Timeouts:** replace the magic 10/30/5 with the existing **env knobs** (already defined, see CLAUDE.md
  "Phase 98 NLI Resilience env knobs"): `NLI_CONNECT_TIMEOUT` (3), `NLI_IMAGE_READ_TIMEOUT` (5),
  and for Rosetta TIFFs a longer read timeout is legitimate — keep a generous *read* timeout but a short
  *connect* timeout (use a `(connect, read)` tuple). The point: a dead host fails in ~3s, not 10-30s.
- **TLS (M2):** keep `verify=False` **only when the host is in a known-NLI allowlist**
  (`iiif.nli.org.il`, `rosetta.nli.org.il`, and any other NLI host the code already hits); otherwise
  `verify=True`. Suppress the `urllib3` `InsecureRequestWarning` **explicitly** (not globally) and add a
  comment explaining *why* (legacy NLI cert chain). Consider a tiny shared helper
  `shared/nli_fetch.py::nli_verify_for(url) -> bool` so web + desktop share the host policy — but keep it
  minimal; do NOT expand into the deferred unification.

### Tests (new file, e.g. `tests/test_desktop_image_loader_breaker.py`)
- `is_open()` True → `_download_bytes` returns None **without** calling `requests.get` (monkeypatch/mocked).
- 200 → `record_success` called; 5xx/429/timeout/connection-error → matching `record_failure`.
- TLS: NLI host → `verify=False`; non-NLI host → `verify=True` (assert the `verify=` kwarg passed to a
  mocked `requests.get`). Assert the `InsecureRequestWarning` suppression is host-scoped, not global.
- Non-NLI failure does NOT trip the breaker.

### Done-when
Desktop image fetches consult + feed the shared breaker, fail fast on dead NLI, and disable TLS verify only
for NLI hosts (documented). `OPEN_ISSUES.md` updated; Codex-reviewed; CI green; PR squash-merged. Note in the
PR that #2/M1/M4 remain deferred.
